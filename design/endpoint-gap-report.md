# RoadBook × DSH 验收终点差距报告

> 日期：2026-10-05 ｜ 被测对象：RoadBook V6 母版（`D:\Code\RoadBook`，41 张卡 + 双语 + DSH 插件 + skill + 项目模板）＋ DSH 自带能力面
> 口径：所有数字来自本仓库现盘文件（`playbook/`、`playbook_EN/`、`template/`、`skills/`、`plugin/`）的机器统计与 `file:line` 引用；无命令输出支撑的判断一律标注为「推测」。
> 本报告是**评估报告**，不是流程卡；它不改判据，判据仍以 `playbook/` 卡内原文为准。

---

## 0. 一句话结论

终点（一个「只懂得使用 agent」的人，用 RoadBook + DSH 系统地做出一个能上线的程序）目前**差在三处**：

1. **认知负荷的入口错了**：路由是 41 行散文 + 11 条分支，判断权在 agent 手上；而真正决定工作量的是「装不装一个库」这类用户无法预判的判据。
2. **资源开销的重心反了**：流程文本量是交付物代码量的 **4.6～18 倍**；且 RoadBook 手写的压缩纪律与宿主 dsh-dcp 的确定性压缩在**最重的场景里互相拆台**（源码级已确认）。
3. **「上线」不在任何一条链里**：文档定义的 S 档快速路 `2-2→4-1→4-3→5-1` **终结于归档、不含发布**；让程序真的上线要额外并入 5 张卡（+30% 文本），这 5 张卡的触发全靠 agent 自觉。

## 2. 方法（可复核）

1. **逐卡量化**：对 41 个文件按同一组正则统计——行数、字符数、`- [ ]` 自检框、`^```powershell` 命令块、行级停下标记（`停下等|等待你裁决|等用户(说|确认|裁决|放行)|停下升级|停下，输出|等用户处理`）、`^\*\*动作`。
2. **从卡自身拼链**，不靠外部定义：`grep '^> 触发：'` 取出 41 张卡的「触发 / 产物 / 下一张」三字段，按它们构成的有向图拼出场景链。
3. **跨文件核对**：双语同批义务（`playbook/` ↔ `playbook_EN/` 按卡号对齐）、宿主插件源码（dsh-dcp）语义回读。

> ⚠️ 统计口径差异：行级「停下标记」是**正则命中行数**，不等于实际停顿次数；换更宽/更窄的正则数字会变（同一批卡两种口径分别得 55 与 74）。本报告凡引用都带口径。

## 4. 差距一：认知负荷——负荷线性，但卡数由 agent 裁量

### 4.1 每卡恒定 ≈6.5k 字符
见上表最后一列。**不是超线性增长**，是「卡数 × 常数」。这条否掉了「档位越高单卡越重」的直觉，也说明优化方向应该是**减卡**而不是「把卡写薄」。

### 4.2 用户要回答的问题：9 个是非题 vs 11 条散文路由
现有入口 `playbook/0-1-驱动卡.md:25-42` 是 11 条分支的散文路由（①闲聊 ②入池 ③继续 ④新功能 ⑤Bug ⑥改界面 ⑦升级/清债/发布/下线 ⑧界面设计 ⑨重构 ⑩体检 ⑪澄清），判定「命中即停」由 agent 现场执行。而同样的信息，用**事实**表达只需 9 个是非题（见 §7 P1 的事实表）。散文路由每会话重读、每次可能给出不同答案；事实表同一输入必得同一链。

### 4.3 最重档的实际待办面（F 链 26 张卡）
97 个自检框 · 79 个可粘贴命令块 · 37 处停下标记 · 184 个「动作」标题。对「只懂得使用 agent」的人，这 184 个动作是**不可预读**的——他不知道第 14 个动作会问什么。

## 5. 差距二：资源开销——流程文本压倒交付物，且两套压缩制度打架

### 5.1 流程文本 : 交付物代码
终点举例的单页应用上限是 ≤400 行（`2-1-功能调研.md:72` 单页静态应用特例：≤5 文件 ≤400 行）：

| 对比项 | 字符 | 倍数 |
| :-- | --: | --: |
| 链 B 流程文本 | 72,990 | — |
| ≤400 行代码（按 40 字符/行估） | ≈16,000 | **4.6×** |
| ≤100 行代码（S 档下限） | ≈4,000 | **18×** |

### 5.2 固定开销：每会话 7.1k tokens，与卡数无关
`0-1 驱动卡` 4,608 + `template/AGENTS.md` 8,197 + `STATE.md` 1,326 = **14,131 字符 ≈ 7.1k tokens**。`0-1-驱动卡.md:2` 规定「每次会话第一次发消息时**整卡粘贴**」——多会话任务每会话重付一次。

### 5.3 削峰线：L 链判据文本几乎单独吃满
`0-1-驱动卡.md:66` 自设预算：「smart zone（约 150k tokens）以内，**到 75% 就开削**」= 112.5k。

- F 链卡文本 ≈ **77k tokens = 削峰线的 68%**（还没算工具输出、代码、STATE 回写）
- E 链 ≈ 57k = 50% ｜ B 链 ≈ 36k = 32%

### 5.4 两套压缩制度互相拆台（源码级已确认）
dsh-dcp 的去重键（`node_modules/@aiwayds/dsh-dcp/lib/summarizer.js:370`）：

```js
const key = `${block.name}\u0000${block.arguments}`   // 工具名 + 参数，不含结果
```

- `protectedTools` 默认 `['write','edit','apply_patch']`（只保写侧工具）
- i18n 文案（同文件 `:142`）：「执行了 N 次 —— 重复调用，**仅保留最近一次结果**」

而 RoadBook 的两条核心证据纪律，本质就是**同一条命令、两次相反结果**：

| 卡内纪律 | 动作 | 压缩后果 |
| :-- | :-- | :-- |
| 4-1「TDD 红先行」（`playbook/4-1-分批编码.md:45`） | 跑测试→必须红→写实现→再跑同一条命令→绿 | 两次调用同名同参 → 折叠成一行，**红被删、绿保留** |
| 4-3「变异体证伪」（`playbook/4-3-验证.md:49`） | 改坏→红→还原→复跑→绿 | 同上，抹掉「红了哪条」 |

触发条件恰好落在最重链上：L 档 77k tokens 几乎必然越过 75% 削峰线。

**两处修法**：
- **（主，RoadBook 侧）** 红/绿两份输出**先落盘**（写进 `VERIFY.md` / 回归记录）再允许压缩——落盘的东西压缩吃不到，与它自己「先落证据再压缩」同源。
- **（辅，dcp 侧）** `protectedTools` 追加 shell 工具名（`pwsh`/`bash`），代价是所有 shell 去重失效，粗但一行生效。

## 6. 差距三：可上线性——没有一条链覆盖「上线」

### 6.1 文档定义的快速路不含发布
`playbook/2-1-功能调研.md:85` 原文：

```
S 档简版链：2-2（简版）→ 4-1 → 4-3 → 5-1
```

**它终结于归档。** 0-1 的 11 条路由里只有「⑦ 发布 → 5-2」沾边。

### 6.2 让程序真的上线要并入 5 张卡（+30%）

| 卡 | 触发原文（`playbook/*.md:2`） | 为什么「上线」必然踩到 |
| :-- | :-- | :-- |
| 4-5 环境与配置 | 「需要新环境（staging/prod）或新增配置项」 | 上线 = 要有 prod 环境与密钥来源 |
| 5-2 发布 | 「用户说发布/上线/让别人用」 | 产物含 tag（**人打**，不可委托） |
| 5-4 运行期观测 | 「5-2 发布完成」 | 发完必进观测窗（默认 24h） |
| 7-5 合规与隐私 | 「收个人信息 / **上线公开服务**」 | 公开服务即触发 |
| 7-6 国际化与可访问性 | 「**上线面向公众**」 | 面向公众即触发 |

B → C 的代价：**+5 卡 / +22,085 字符 / +32 动作 = 文本 +30%**，且**没有一张能从 S 简版链推出来**。

**旁证三条**：
1. 本报告上一版的算账人（我）在手工拼 S 链时**自作主张塞进了 5-2** 才凑出「上线」——说明缺口是真实的。
2. `grep '上线判定|上线前'` 在整个 `playbook/` 里**没有任何跨卡闸门**，只有卡内局部提及。
3. `design/vibe-coding-failure-modes-report.md:199,227` 已指向外部 69 项 pre-launch checklist（boxed-dev/vibe-coding-security）——**知道缺，但从未内化**。

### 6.3 依赖悬崖：S → L 是台阶，不是坡
`playbook/2-1-功能调研.md:74` 判据表 L 行：`引入新依赖 / 跨模块 / 破坏性表结构 / 新页面体系 → 3-1 设计 + 5-2 发布强制`；并注明第三方技能/插件/MCP server 按「引入新依赖」计入 L，且必须先走 7-9 准入（人裁决）。

终点举的例子——「点一下记录喝了几杯水，看本周柱状图」——因此分岔：

| 做法 | 档位 | 卡数 | 文本 |
| :-- | :-- | --: | --: |
| 手写 CSS 条形 | S | 7 | 44k 字符 |
| `npm i chart.js` | **L** | **26** | **153k 字符** |

**同一个用户眼里「一样的东西」，3.7× 卡数、3.5× 文本。** 更麻烦的是判据用的是「≤3 文件 ≤100 行」「无新依赖」这类**开工时用户不可能知道**的量；而 `SKILL.md:93` 与卡内均规定档位「**只升不降**」——估高即永久锁在重链上。

## 7. 提案（六条，全部落在 DSH 现有面上）

### P1 · `skills/roadbook/bin/route.mjs`：把散文路由变成确定性函数
**状态：本轮已落原型文件，未能运行验证**（见 §8 环境故障）。

照 `skills/roadbook-atlas` 的成熟先例（skill + `bin/*.mjs` CLI + 可核对回执），**不需要新增宿主 API**；`plugin/roadbook-autoload` 保持只做注入与触发，不要动它。

设计要点：
- **事实用「用户能回答的问题」**，不用文件数/行数：全新还是已有代码 / 有界面吗 / 要放到网上吗 / 不认识的人也能访问吗 / 会存别人的个人信息吗 / 要装库或插件吗 / 碰登录·收钱·删数据·改表·对外接口吗 / 除你之外还有别人吗 / 需求说得清吗（9 问；另有 2 项由 agent 回填）。
- **不新增第二处真相**：每张卡的进入条件带 `anchor`（该卡前 3 行的原话片段），`--audit` 回读校验；卡改了而镜像没改 = **判红退出 1**。这与母版既有的「幽灵引用判红」契约同源。
- **输出**：有序卡链 + 每卡门禁级别（轻确认 / 裁决 / 人执行）+ 现盘复算的账本 + 需要在场的次数。
- **`goLive` 作为一件事实**，而不是一句自觉：为真即强制并入 4-5 / 5-2 / 5-4（公开服务再加 7-5 / 7-6），**§6 的缺口由此关上**。

### P2 · 硬规则 11 接到 dsh-dcp，而不是手写流程
卡里描述的「先削已贴过结论的工具输出 / 重复文件读取，后保用户原话 / 当前卡清单」几乎是 dcp `dedup` + `retainRatio` 的手工版；「75% 就开削」就是 `thresholdRatio: 0.7`（bundle 默认值，正好一致）。建议在 profile 的 `cordis.patch.yml` 显式写 `language: zh`、`tokenEstimate: cjk`、`thresholdRatio: 0.7`，并把 §5.4 的「红绿对先落盘」补成一条硬规则。

### P3 · 档位允许「用实测降档」
保留「只升不降」的反刷分意图，补一条确定性出口：**用实测文件数 / 行数 / 依赖清单**（不是预估）申请降档，附证据行。规则从「预估锁死」变成「事实可复核」。

### P4 · `Expected：` 变成可判
`grep 'Expected[:：]' playbook/*.md` 在 41 张卡里只命中 **1 行**，且那一行就是规则本身（`4-1-分批编码.md:51` 六查⑥）——**规则要求的东西在自己文档里出现 0 次实例**。修法：挑 3 个命令块改成带 `Expected：` 的范例 + 校验器断言「每个命令块后 5 行内必须有 `Expected：` 或 `要求…` 行」（零 token）。

### P5 · S 档瘦身 + 门禁合并
S 档自检框集中在 3-4/3-5/3-6（12+13+13 = 38 个），其中色彩卡占 13（色相偏移、z-index 七档、60-30-10）。S 档决定能不能上线的是「入口能不能点、数据存不存得住」——流程却给了色相与缓动曲线同等注意力。建议：plugin 提供按档位裁剪的判据渲染（同一份 md，只在渲染层过滤，不新增事实源）；门禁从 17 处合并到 ≤6 处（开工、SCOPE 批准、每批知会、验收、归档）。

### P6 · 「上线判定」进入 route 输出
把 §6.2 五张卡做成 `goLive` 事实的闭包，并补一条跨卡闸门：**没有 4-5 与 5-4 的产物，5-2 不许判完成**。这条与既有「完成的唯一定义」同构：`check.ps1` 退出码 0 + 真实输出。

## 8. 现状与边界（诚实清单）

- **本轮环境故障**：pwsh 工具自本轮起对**任何**命令返回 `exit code 3221225794`（`0xC0000142` = `STATUS_DLL_INIT_FAILED`），连 `Get-Location`、`node --version`、`cmd /c echo ok` 都无输出。因此 `skills/roadbook/bin/route.mjs` **只有写盘证据、没有运行证据**——按母版口径它属于「未完成」，不得当作已验证工具使用。
- **行级标记 ≠ 停顿次数**；停下标记 55（全库）/ 17（A 链）是正则命中行数。
- **token 折算**用 CJK 2 字符/token，中英混排会低估；未计入工具输出与 STATE 回写。
- **链上的条件项**（2-3 需求模糊、2-5 多方、4-4 CI、5-5 90 天、7-9 引外部件）是否在链上取决于事实取值，本报告按「终点场景」取真值；换场景数字会变。
- **§5.4 的折叠行为**由源码与 i18n 文案推定（`summarizer.js:370,142`），**未实跑一次压缩观察**；若要变成结论，需要一个实验：同一条命令跑两遍 → `/dcp` → 看第二次结果是否还在。
- **双语等负荷**：此前一轮测得 41 对卡在「自检框 / 硬门禁 / 命令块」三项上一一对应、**零分歧**（CN 125 / 74 / 138）。本轮复算 CN 侧自检框 125、命令块 138 与之一致；EN 侧同批复算未在本轮重跑。
- 外部研究数据引自仓库内既有报告 `design/vibe-coding-failure-modes-report.md`（METR RCT 实测慢 19% / 自认快 20%；CMU TheAgentCompany 最强 agent 自主完成 24%；UT Austin 19.7% 幻觉包名可信；Veracode 2025 约 45% 任务含安全缺陷、2026 通过率停滞 56%；Lovable 1,645 个应用扫出 170 个泄露密钥 CVE-2025-48757；Addy Osmani「最后 30% 墙」），本报告未重新检索复核。
