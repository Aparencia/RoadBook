## 4. 本版唯一的新数据流

**结论先行**：宿主侧全部提醒通道都是 **model-facing**（`systemPrompt.section` / 注入 user 消息 / `ctx.schedule.create`）——它们提醒**模型**；而 GUI 的 `session.new`(KeyN) / `session.fork`(Ctrl+Alt+F) / `session.archive`(Ctrl+Shift+A) 三个动作入口**本来就都有**（`dsh-client-ui-workspace/lib/client.js:140/:172/:193`）。⇒「新建 / 归档 / 分支对话」缺的**不是按钮，是提醒**；唯一能真提醒人的层是**网页端**——与裁决 1 合成同一件事。

```
读侧（零渲染）
  ctx.sessionProjections.snapshot(session,['contextPressure']) → {contextWindow, pressureTokens, projectedTokens}
  systemPrompt.section 的 text 运行期实参 {agent,scope,signal}（dsh-agent/lib/types/dispatch.js:92）
  ctx.workspaceRegistry.archivedSessionIds（dsh-workspace/lib/index.js:504）
        ↓
判据层（纯函数、可离线单测）  lib/session.js
  budgetState() / lifecycleAdvice() / sessionPayload()
        ↓
两个消费端
  ① 宿主侧 systemPrompt.section（order: 710）—— 对模型 1 行，含"该提醒用户做什么"
  ② 网页端第三张标签页「会话」+ GET /roadbook/session/status —— 对人说话
```

**防第三处真相**：`lib/session.js` 只回**读数 + 建议**，**不复刻** 0-2 卡的判据全文（同 `roadbook-evolve` S5/S6 只记退出码的口径）。**平台事实**：归档与分叉**都没有宿主事件**，只能读 getter ⇒ 走轮询式读数，**不假装有事件**。

### 11.1 chunk 契约已直读 —— 解 §8「待核实 ③」，假设 1 置信 0.6 → 0.9

读的是**本机已安装的** `dsh-better-sidebar@0.24.1`（先例实现）源码：`src/client/chunk-loader.ts`（348 行，含契约注释）+ `lib/client-locale.js` / `lib/client-editor.js` / `lib/client-mermaid.js` 的首两行。契约是**读出来的，不是猜的**：

1. chunk 是**普通同源脚本**，首两行即登记：`globalThis.__dshChunks__ = globalThis.__dshChunks__ || {};` + `globalThis.__dshChunks__["<名>"] = (require) => { ...exports };`
2. 装载三步：注入 `<script src="…/bundle/<名>.js">` → 从**插件自有**的全局注册表取工厂 → `factory(require)`。
3. **不能用 `window.__ModuleLoader__.load` 去取 chunk** —— 源码注释原文：module loader 的 `import()` 只解析 seed words / shell-own modules / registered factories / boot graph rows，chunk id 一个都不是 ⇒ **必须自建路由 + 自建注入**（官方 `/plugins/<id>/client.js` 路由不能服务任意文件名）。
4. 外部件（`react` / `react/jsx-runtime` / `react-dom` / `react-dom/client` / `cordis` / `@deepseek-ai/dsh-client-ui-slots` / `@deepseek-ai/dsh-client-ui-primitives`）由插件自己经 `ctx.modules.import(spec)` 解析；DSH 0.1.0-rc.8 起页面全局没了，better-sidebar 用自有全局 `__dshSidebarModuleSystem__` 跨 bundle 传。
5. 缓存三层 + 每层失败路径、`cache-control: no-cache` + ETag 的 HEAD 复验（HMR 用，5s 超时 fail-open）。

**对 RoadBook 的施工约束（本版照此做，差异点写明理由）**：

- `package.json` 的 `"./client": "./lib/client.js"` 不动 —— 核心 bundle 必须保持 `window.__ModuleLoader__.load({ id: "roadbook", factory: (require) => {…} })` 这个外形（DSH 只认它）。
- chunk 装载器与注册表**自建**（`__roadbookChunks__`），宿主半新增 `webServer` 路由 `/roadbook/bundle/<名>.js`（与既有 `/roadbook/update/*` 两条同源守卫同一套写法）。
- **外部件不走 `ctx.modules`**：核心 bundle 里的 `require` 本来就是 ModuleLoader 给的，挂到自有全局再传给 chunk，比多接一个服务少一层假设（与 better-sidebar 的差异点，理由是"宿主契约变化面更小"）。

## 11.8 批 3 第三步：仪器自检的变异集 4 类 → 15 条（成功标准 4，2026-10-07）
