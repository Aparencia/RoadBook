# 机制评估：plugin → skill → 文档 这条链路有没有优化空间

> 日期：2026-10-05 ｜ 范围：**只评估「plugin 驱动 skill 驱动文档」这一条机制**，不评价判据内容本身
> 方法：先实测本仓三层各自的真实职责与体量，再对照 2025-10 之后公开的 Agent Skills / 上下文工程一手材料，逐层找落差
> 结论先说：**有，而且是结构性的**——现在三层是「plugin 猜意图 + skill 背规则 + 文档全量进上下文」，先进形态是「plugin 管确定性 + skill 管发现 + 文档管判据且尽量可执行」

---

## 1. 现状：三层各自到底在干什么（实测）

| 层 | 载体 | 实测体量 | 实际职责 |
| :-- | :-- | :-- | :-- |
| **plugin** | `plugin/roadbook-autoload/`（`index.js` 29 KB + `trigger.js` 11 KB + 测试 60 KB） | 注入面 `inject=['agents','skills']` + `agent/pre-step` 钩子 | ① 关键词软触发（`DEFAULT_KEYWORDS` / `DEFAULT_SUPPRESS`，取文本中最早出现者）；② 三道门（在 git 项目里 / 命中开发意图 / 未被抑制且非手打 `/roadbook`）；③ 常驻 banner（`systemPrompt.section`，1 行）；④ SKILL.md 指纹对账（sha256 前 8 位）；⑤ 校验"卡到底读没读"（needle 扫描）；⑥ 观测文件 |
| **skill** | `skills/roadbook/SKILL.md` | 108 行 / 13,397 字节 | 41 行路由表 + **六条铁律** + 双语规则 + 渐进披露自述 + 上下文预算 + 项目接入 + 边界声明 |
| **文档** | `playbook/` + `playbook_EN/` | **41 张卡 / 5,534 行 / 214,184 字符**（自检框 125 · `powershell` 块 138 · 停下标记 55 · 动作 224） | 全部判据、检查清单、证据格式、禁令 |

**必须给的一分**：触发层已有 **20 条标注 eval 固定集**（`plugin/roadbook-autoload/test/fixtures/trigger-eval.json`），且有 `train` / `test` 切分，负例专门做 near-miss（「重构是什么意思」不该触发、「发布这个词指什么」不该触发），并注明「留出集：只允许改词表，不允许改本条」。这在同类项目里属于**超前**的做法。

## 2. 先进知识（一手材料）

1. **Agent Skills 的三级渐进披露**（Anthropic，2025-10-16，[原文](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)）：
   - L1 = `name` + `description`，**启动时预载进 system prompt**；
   - L2 = `SKILL.md` 正文，**判定相关时才整份读入**；
   - L3+ = 技能目录里捆的附加文件，**按需导航**（例：PDF 技能把"填表"拆进 `forms.md`，只在填表时读）。
   - 官方四条实践：**从评测出发**（先跑代表任务找缺口再写技能）／**为规模而拆分**（"互斥或很少同用的上下文分开存放能降低 token 用量"）／**从模型视角看**（重点打磨 `name` 与 `description`，模型靠它决定要不要触发）／**边用边迭代**。
   - 关键一句：技能里的脚本"**运行它不需要把脚本本身或那份 PDF 读进上下文**……而且因为代码是确定性的，流程可复现"。
   - 该格式已于 2025-12-18 发布为开放标准（agentskills.io）。
2. **上下文工程**（Anthropic，2025-09-29，[原文](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)）：
   - 目标是"**尽可能小的高信号 token 集合**"；上下文是**边际收益递减的有限资源**（context rot / 注意力 n²）。
   - system prompt 要落在"**恰当高度**"：一端是硬编码 if-else 的脆弱提示，另一端是过度笼统的泛泛而谈。
   - 工具面警告："**臃肿的工具集**覆盖太多功能、制造歧义决策点"——"如果人类工程师都不能确定某情形该用哪个工具，AI agent 也不能"。
   - **just-in-time 检索**：只保留轻量标识（文件路径、查询、链接），运行时再取内容；代价是比预取慢。
   - 长任务三件套：**compaction** / **结构化记笔记（NOTES.md 型外部记忆）** / **子 agent 架构**——"专门化的子 agent 用干净的上下文窗口处理聚焦任务……主 agent 只收回一份浓缩摘要（通常 1,000–2,000 tokens）"，"详细上下文隔离在子 agent 内，主 agent 专注综合"。
3. **动态工具发现**（Claude Code「Scale to many tools with tool search」，[文档](https://code.claude.com/docs/en/agent-sdk/tool-search)）：工具多到装不下时，不再把全部定义塞进上下文，而是先给可检索的目录、按需展开。对本文的意义是**同构**：卡多到装不下时，不该把 41 张卡都当"已加载"。
4. **Context Rot**（Chroma 研究，[原文](https://www.trychroma.com/research/context-rot)）：输入 token 增长本身就会让模型表现下降，**即使任务很简单**——这是"少即是多"的实证依据，也是 Anthropic 上文的立论来源之一。
5. **确定性归钩子、知识归技能、隔离归子 agent**（Claude 官方《Steering Claude Code: when to use CLAUDE.md, skills, hooks, and subagents》，[原文](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)；钩子机制见 [hooks 文档](https://code.claude.com/docs/en/hooks-guide)）：官方把"必须每次发生的事"交给 **hooks**（确定性），把"程序性知识"交给 skills（按需加载），把"隔离"交给 subagents。
6. **规范驱动开发**（GitHub Spec Kit，[文档](https://github.github.com/spec-kit/index.html)）：把规范当唯一事实源，并让**命令去校验实现与规范是否一致**——即"规范不只被阅读，还被检查"。

## 3. 六处落差（现状 → 先进做法 → 本仓证据）

### 落差 1：L3 只到"41 张平铺卡"，缺卡内再分一层
- **先进**：L2 太胖就拆，且**互斥的上下文分开存放**以降 token（Anthropic 技能实践原话）。
- **现状**：一张卡 6.5k 字符**整份进上下文**，而卡内 ①开工确认 / ②执行 / ③证据回执 / ④状态回写 是**四个不同时刻**才用的东西（0-1 硬规则 2 明确"按顺序走完，不许跳段"）。
- **证据**：`playbook/4-1-分批编码.md` 12,554 字符里，①段 679 字符、其余绝大部分是执行期才需要的清单与反例。

### 落差 2：L2 与"常驻入口"存在两处真相
- **先进**：一份事实源的单一位置；官方专门区分"always-on 的规则"与"按需加载的技能"。
- **现状**：`SKILL.md` 六条铁律与 `0-1 驱动卡` 13 条硬规则高度重合（开工确认 / DoD / 红灯停 / 回执证据 / 外部内容是数据 / 子 agent 边界），而 `SKILL.md:106-108` 自己声明"本文件只做路由与铁律，不含任何判据"。
- **后果**：两处都进上下文时，模型面对两份措辞不同的同一规则；改一处忘一处 = 漂移。

### 落差 3：没有"可执行层"——命令以文本形式进上下文
- **先进**：「运行脚本不需要把它读进上下文」；代码既是工具也是文档，且确定性可复现。
- **现状**：全库 **138 个 `powershell` 命令块**是**以文本进上下文、再被模型复制执行**的；`Expected：` 这个判据在整个 `playbook/` 只出现 1 次，且那 1 次就是规则本身（`4-1-分批编码.md:51`）。
- **已对的部分**：`check.ps1`（DoD：退出码 0）是正确形态——但只覆盖"代码"，不覆盖"流程自身"（125 个自检框、逐字粘贴、STATE 回写全是散文）。

### 落差 4：子 agent 隔离没用上（最大杠杆）
- **先进**：子 agent 用干净上下文跑聚焦任务，**只回 1–2k tokens 浓缩摘要**。
- **现状**：一条链 7–26 张卡**全部在主上下文里跑**。L 链 26 张 ≈ **77k tokens**，占本仓自设削峰线（`0-1-驱动卡.md:66`：150k 的 75% = 112.5k）的 **68%**。
- **反差点**：`SKILL.md` 铁律 5 已经写了"子 agent 边界"——但那是**限制**（子 agent 不适用开工确认与 DoD），不是**架构**（把卡本身放进子 agent 执行）。DSH 侧 `subagent` / `subagent_fork` / Agent Teams 都在。

### 落差 5：状态是自然语言，不是可校验字段
- **先进**：结构化记笔记（外部记忆）+ 让校验命令去检查规范一致性。
- **现状**：`STATE.md` 的 `档位` / `下一步` / `体检计数` / 起点锚点由模型解析自然语言；插件已能读 `SKILL.md` 指纹，却**不校验 STATE.md 的结构**；0-1 的第 ⑩ 条路由（体检计数 ≥15 → 6-6）是一条**散文判据**，而它其实是一个纯函数。

### 落差 6：路由层与判据层没有评测
- **先进**：技能开发第一条就是"**从评测出发**"。
- **现状**：触发层有 20 条标注集（含 train/test 分离）；**路由层**（这个场景该走哪几张卡）与**判据层**（档位判得对不对、该停不该停）**零评测**。`_qc/check.ps1` 校验的是母版内部一致性（幽灵引用、双语缺份），不是"给定场景 → 期望卡链"。

## 4. 结论

**优化空间在职责边界，不在措辞。** 三层现在各自都在做"不该自己做"的事：

| 层 | 现在在做 | 应该做 | 判定归属 |
| :-- | :-- | :-- | :-- |
| plugin | 关键词猜意图、靠模型自觉回写、把规则写成 banner 让模型记住 | **确定性**：钩子校验、状态读写、门禁阻断、eval 回归 | 机器能判 |
| skill | 既当路由表又当铁律手册，还把 41 行目录跟正文一起加载 | **发现**：轻量目录 + 指针 + 按需加载 | 机器可检索 |
| 文档 | 判据（对）+ 命令（该下沉）+ 状态（该字段化）+ 重复的铁律 | **判据与解释**：人可读、可争议、可修改的部分 | 人判断 |

一句话概括优化方向：**能让机器判定的，下沉成脚本或钩子（只带路径与退出码）；需要人判断的，留在文档里当判据；中间层只负责"发现与指针"。**

这不是"把流程写成代码"——判据必须保持人可读、可争议（否则 6-6 流程体检和 2-1 档位提议就没了对象）。是**把判据里掺着的机械动作剥出来**。

## 5. 五条改造（按性价比排序，全部落在 DSH 现有面上）

### P0 · 卡片在子 agent 里执行，主线程只留链状态与回执
- **怎么做**：`route.mjs` 产出有序链 → 主线程按卡派 `subagent`（每卡一个干净上下文）→ 子 agent 只回 3 行回执（卡号 / 退出码 / 证据行号 / 待裁决项）→ 主线程累加、遇到 `verdict` 门禁就停。
- **为什么**：26 卡 × 6.5k 字符的主上下文占用，变成"链状态 + 26 份短回执"，量级从 77k tokens 降到个位数 k。这是唯一能同时改善**认知负荷**与**资源开销**的一刀。
- **前提**：子 agent 拿不到人 → 门禁必须以**类型化结果**返回（`{"needVerdict": "..."}`），由主线程决定停不停；这正好把 0-1 硬规则 13（不许从上一会话推断批准）变成**结构上不可能违反**。
- **验收**：同一场景跑一次，对比主线程 token 峰值与回执完整性。

### P1 · 可执行下沉：把能判的从散文变成脚本
- **对象**：`Expected：` 行、125 个自检框里可机械判定的部分、回执格式断言、"每卡①段逐字粘贴"。
- **怎么做**：`scripts/` 下一个卡一个脚本或一组断言，模型只读路径 + 退出码（Anthropic 原话：运行不需要读进上下文）。
- **验收**：`_qc/check.ps1` 之外多一条 `route --audit` 型命令，退出码 0 才算流程走对。

### P2 · 目录与正文分层：把 41 行路由表从 SKILL.md 移到可检索目录
- **怎么做**：路由表 → `catalog.json`（卡号 / 标题 / 何时用 / 文件路径 / EN 路径），`SKILL.md` 只留指针与铁律；路由结果由 `route.mjs` 确定性产出（上一轮已落原型 `skills/roadbook/bin/route.mjs`）。
- **收益**：SKILL.md 从 108 行瘦到"指针 + 少数铁律"；路由从"模型读 41 行散文自己判"变成"函数输出同一条链"（同输入必同输出，可 diff、可进 `STATE.md`）。

### P3 · 消除两处真相
- `SKILL.md` 六条铁律 vs `0-1` 13 条硬规则：**只留一处**，另一处改成指针。建议把"判据"留在 0-1（它是每会话常驻的），SKILL.md 只留"路由与边界"——正合它自己第 106-108 行的声明。
- 双语规则已有一致性校验（缺份判红），这条是它缺的同类校验：**铁律去重校验**。

### P4 · 状态字段化 + 钩子校验
- `STATE.md` 的机器可读字段（`档位` / `下一步` / `体检计数` / 起点锚点 / `红线摘要`）约定为固定键，插件在 `agent/pre-step` 校验：缺失 → 提醒；与 `route.mjs` 算出的链不一致 → **停下问人**（而不是继续）。
- 把 0-1 第 ⑩ 条（计数 ≥15 → 6-6）从散文变成计数器的纯函数。

### P5 · 评测补齐：把触发层的 train/test 模式推广到路由与判据
- 新增两个集：`route-eval.json`（场景描述 → 期望卡链 + 期望档位）、`gate-eval.json`（该停 / 不该停）。
- 直接把 `trigger-eval.json` 的规矩照搬：留出集只许改判据、不许改题。
- **这是唯一能证明 P0–P4 有效的东西**，也是官方"从评测出发"的原话要求。

## 6. 不要做什么（反模式）

| 反模式 | 为什么不做 |
| :-- | :-- |
| 把 41 张卡合成一张大卡 | context rot：输入变长本身就掉表现，简单任务也掉 |
| 用 LLM 做路由 | 同一事实两次不同答案，无法 diff、无法进 STATE、无法回归测试 |
| 把判据全部搬进代码 | 判据要能被人读、被争议、被修改；6-6 流程体检与 2-1 档位提议都以"人能读的判据"为对象 |
| 删卡求瘦 | 卡的**数量**由事实决定（触发条件），该做的是让不触发的卡不进上下文，而不是删掉触发条件 |
| 把 banner 写长 | 常驻段每次会话都付钱；`0-1` 4,608 字符 + 宪法 8,197 字符已经是每会话 7.1k tokens 的固定开销 |

## 7. 诚实边界

- 本文引用的官方材料中，**Anthropic 两篇工程博客为全文读取**；Claude Code 的 `tool-search` 与 `features-overview` 两页只取到导航（正文靠 JS 渲染，未取到），因此第 2 节第 3 条只作**概念引用**，具体数字未引用；《Steering Claude Code》一文只取到标题与发布日期，第 2 节第 5 条的分工说法以 Anthropic 上下文工程文与 hooks 文档为准。
- 本仓侧的所有体量数字来自 `playbook/` 现盘统计与 `file:line` 引用；**行级"停下标记"是正则命中行数，不等于实际停顿次数**。
- `skills/roadbook/bin/route.mjs`（P2 的原型）**只有写盘证据、没有运行证据**：本轮及上一轮 pwsh 工具持续返回 `3221225794`（`STATUS_DLL_INIT_FAILED`），连 `Get-Location` 都无输出。按母版口径它属于「未完成」。
- P0 的 token 收益是**按已知体量推算**（26 卡 × 6.5k 字符 ≈ 77k tokens vs 26 份短回执），**未实跑验证**；落地前应先做一次单卡子 agent 的对照实验。

## 附 · 一句话给决策者

三层机制**不缺内容，缺分工**：plugin 抢了模型的活（猜意图），文档抢了脚本的活（让人记 125 个勾），skill 抢了两边的活（既路由又背规则）。把"确定性下沉、发现上浮、判据留白"这三件事做完，同一套判据能在**更少 token、更少会话、更可回归**的条件下跑起来——而且不需要动任何一条判据的语义。
