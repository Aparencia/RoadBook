# Roadbook（路书）· V6「磁盘即流程」设计文档

> 状态：已定稿（2026-09-11，与用户逐节审阅通过）
> 本文档是新体系构建的**唯一事实源**。所有 playbook、模板、校验脚本与本文件冲突时，以本文件为准；改设计先改这里。

## 0. 一句话定义

把流程知识全部放磁盘，agent 自己取用；人只做三件事：**表达意图、裁决 gate、行为验收**。
目标函数：个人 + 无状态 AI 的开发效率最大化 = 减少返工 + 避免做垃圾 + 补偿 AI 无记忆。

**项目名**：**Roadbook（路书）**（2026-10-03 定名；英文名 Roadbook 为准，中文名「路书」）。仓库名 / skill 名 = `roadbook`；`V6` 是版本号，不是名字。
名字只写在身份文件里（`README.md`、`START-HERE.md`、本文件标题、`playbook/00-驱动卡.md` 首段一次），外加项目模板的入口（`template/README.md`、`template/AGENTS.md` 各一次，`template/docs/README.md` 一句，让未来项目知道自己的流程出处），不散落到卡内判据。

## 1. 设计公理（全部来源已验证：两份外部研究 + V5 新手模拟实测）

1. **状态在磁盘，不在聊天**——聊天是缓存，STATE.md 是唯一事实源
2. **证据式完成**——"完成"唯一合法定义 = guardrail 脚本退出码 0 + 粘贴真实输出
3. **单一变更入口**——改需求改上游文档（SCOPE/决策卡），禁止手改中间产物
4. **新鲜上下文复核**——实现者不复核自己；审查天然在独立会话/子代理
5. **右倾化流程深度**——档位 S/M/L，小事直通，大事全流程；只许上调不许下调
6. **用户只做裁决，不做检索**——人读的只有 START-HERE 和 STATE.md；判据全在卡内
7. **本地写作三招是硬规范**：给反例、给照着念的清单、给可复制命令

## 2. 架构：母版与项目的关系

```
母版（本工作区）                          每个项目（11 号卡生成）
├── START-HERE.md    人唯一要读          ├── AGENTS.md      宪法（agent 自动读）
├── playbook/        21 张卡             ├── STATE.md       状态仪表盘
├── template/        项目模板             ├── README.md / CHANGELOG.md / .tool-versions / check.ps1 / doctor.ps1 / gate.ps1 / orphans.ps1 / .env.example
├── design/          本设计文档+契约      ├── src/ tests/ …（按栈生成）
├── _qc/check.ps1    一致性校验           └── docs/          机制配套文档（见 §5）
└── _archive/V5/     旧版封存，不维护
```

**双接口**：
- **驱动卡接口（默认）**：用户复制一次 00-驱动卡（内容永久不变），之后每步只发一句话意图 + 一个词裁决。agent 读 STATE.md → 回执将执行的卡与检查清单原文 → 执行 → gate 停 → 回写状态 → 指明下一步。
- **单卡直复接口（兜底）**：网页版无文件能力的 agent、或用户想亲自控制某步时，打开单张卡全选复制。同一套文件两用，零额外维护。

**防绕过**：agent 任何开发动作前必须回执"正在执行哪张卡 + 检查清单原文"；引不出原文 = 该轮输出作废。

## 4. playbook 全集（21 张：00 驱动卡 + 20 张动作卡）

**档位**（20 卡提议、用户确认，只升不降）：
- **S**（≤3 文件 ≤100 行、无依赖无表结构）：21→23→25→40 四步直通
- **M**（普通功能）：功能线全走
- **L**（新依赖/跨模块/破坏性表结构/新页面体系）：功能线+22 设计+41 发布强制
- **测试分级**：S=guardrail 即可；M=核心路径 1~2 条测试+场景走查；L=核心+负面测试，不许零测试+场景走查（25 卡动作 2.5：正常/空态/边界/异常/数据一致性/回归，逐条附证据——agent 补执行反馈，人工验收清单仍是最终 gate；2026-09-11 补）

**gate 三形态（按风险分配，成本∝风险；2026-09-11 修订 6）**：**信号**（一行知会不等人——批级知会）｜**轻确认**（人回一个词，agent 证据=diff 本身——24 卡人审替代车道：M 档以下 diff ≤150 行且非红线域）｜**裁决**（完整证据链+结构化回执——范围/设计/L 档审查）。裁决形态只留给"错了会返工半天以上"的 gate；机械检查一律下沉 `gate.ps1`（锚点/范围/行数/lockfile，零 token）。配套：宪法回执契约加"会话内已读声明制"（禁重复粘贴）；S 档回执一行制。**裁决型 gate 的粘贴义务保留**（防绕过）。

## 5. 项目模板与 docs/ 结构

```
<项目根>/
├── README.md            ≤40 行：一句话+3 行启动命令+指向 AGENTS/STATE
├── AGENTS.md            宪法 ≤200 行（内容见 §6）
├── STATE.md             状态仪表盘（内容见 §7）
├── CHANGELOG.md         版本索引：未发布节+倒序四小节（"版本文档三落点"见 §5）
├── .tool-versions       环境版本锁定（与产品版本无关）
├── check.ps1            guardrail：typecheck+lint+test+build 一条命令 + 文件数预算断言（STATE.md 文件数基线 + 20）
├── doctor.ps1           环境自检：每项输出版本号=通过
├── gate.ps1             机械检查下沉：锚点有效性/越界/行数/lockfile（零 token，见 §4 gate 三形态）
├── orphans.ps1          孤儿与幽灵三查清单（文件级/零引用导出/文档幽灵/反向幽灵/未登记），只报不拦、退出码恒 0
├── .env.example         只放键名+一行注释；真实值进 .env（.gitignore 挡）
└── docs/
    ├── README.md        机制文档地图（什么在哪/三层读取节奏/防膨胀，≤35 行）
    ├── ARCHITECTURE.md  ≤100 行：模块图(mermaid)+分层+数据流——agent 动代码前必读
    ├── RUNBOOK.md       ≤80 行：部署/回滚/备份/.env 键含义/故障先看哪
    ├── registry/        现行状态层（防重复三件套）
    │   ├── COMPONENTS.md  组件注册表：页面→界面元素→人话标识→程序名→文件→搜索词→影响面
    │   ├── DATA_DICT.md   数据字典：表/字段/类型/校验/敏感度 D1~D4
    │   └── APIS.md        接口清单：路径/方法/用途/错误码/鉴权
    ├── pool/IDEAS.md    需求池：想法先进池（状态+复活条件）
    ├── specs/           工作区：一个任务一个目录 <日期>_<slug>/（RESEARCH/SCOPE/RCA/VERIFY）
    ├── decisions/       决策卡 ≤60 行：IDEA_*/STACK_*/…（为什么+被否案+复活条件）
    ├── reviews/         CODE_*.md 审查报告（留存历史）
    ├── versions/        vX.Y.Z.md 版本详情（含发布记录与回滚点）
    ├── lessons/          教训卡 ≤12 行：现象→根因→修法→下次怎么定位（**模板预置 7 张跨项目通用种子卡**；两层累积：项目教训留在项目，跨项目复发的升格回模板种子——升格由 43 流程体检提案、人裁决）
    ├── TECH_DEBT.md     唯一债务台账（open/carried/closed，关闭附证据）
    └── archive/         <日期>/ 子目录：specs 快照+tech-debt 滚动（git mv 保历史）
```

**三层读取模型**（控制 token 税）：
- 常驻层：AGENTS.md+STATE.md（每会话必读）
- 现行状态层：registry/+TECH_DEBT+pool/+.tool-versions（按需查；**找不到先查再建，禁止平行新建**）
- 留存历史层：specs/reviews/decisions/lessons/versions/archive（归档后不读；教训卡按症状检索）

**版本文档三落点**：索引=根 `CHANGELOG.md`（行业惯例位置，倒序四小节+未发布节）；详情=`docs/versions/vX.Y.Z.md`；锚点=`git tag vX.Y.Z`（人执行）。三处对齐是 41 卡门禁。版本号：0.x 随意；1.x 起破坏性变更升 MAJOR 并写升级注意。CHANGELOG 与 versions 只追加不改写。

**防膨胀**（40 卡执行，用户不记）：specs 超 30 天未动提示归档；lessons/decisions 超 30 张时最旧且 90 天无引用的移入 archive；COMPONENTS 单页 ≤30 行；README/ARCHITECTURE/RUNBOOK 过期检查（启动命令跑得通？模块图与目录一致？.env 键全有解释？）；**文件数预算**：STATE.md `文件数基线` + 20 = 本项目文件数红线（check.ps1 判红；23 卡每批收尾把基线更新为当时的 `git ls-files` 计数）；`orphans.ps1` 汇总行连续两轮不减 → 43 卡提案（防"清单永远在报、没人处理"）。

**条件文档**（触发才建）：USER_GUIDE/PRIVACY(D3D4 字段触发)/LICENSE/openapi.yaml——由 41/22 卡检查项触发。

## 6. 宪法 AGENTS.md 要点（≤200 行）

项目一句话+技术栈+.tool-versions 引用+启动命令｜**DoD**=check.ps1 退出码 0+粘贴输出｜**范围四禁**：禁越任务范围/禁未说明新建文件（先查 registry 与 ARCHITECTURE）/禁升依赖/禁顺手重构｜**停问规则**：同一错误第二次→停+输出诊断+问人；不确定→问｜**不可委托清单**：执行 SQL/发布/删数据/打 tag/门禁裁决｜**防幻觉三查**：引用必回指、路径必实存校验、数字必来自命令输出｜**回执契约**：引卡名+检查清单原文、证据回指｜**回写义务**：改 UI→COMPONENTS、改表→DATA_DICT、改接口→APIS、决策→decisions、踩坑→lessons、欠债→TECH_DEBT、**新建文件→当批登记 COMPONENTS（未登记 = 孤儿）**｜**密钥卫生**：只进 .env，泄露即轮换｜**红线**：auth/billing/删数据 必停等人｜**代码生成硬标准（§11）**：结构/命名/注释 Why/防御/可测试/环境注入六条——23 卡生成时自检、24 卡审查时复核（源自 ai-coding.md 七维度持久内核，2026-09-11 补）

## 7. STATE.md 要点

项目名+一句话｜技术栈（链 STACK 决策卡）｜当前阶段+当前任务（链 SCOPE）+档位｜**下一步：执行哪张卡**｜起点 commit 锚点（当前任务）｜**文件数基线**（check.ps1 预算断言的基准，23 卡每批更新）｜**并行态登记簿**（并行态/旧实现/新实现/删除条件（可判定）/到期/登记批次）｜体检计数（40 卡累计，≥15 触发 43 流程体检）｜未决问题（等裁决）｜最近完成（滚动 5 条）｜未来 3 步（路线图）｜红线摘要

## 8. 硬性写作规范（playbook-contract.md 详述）

1. 只写可执行动作，不写"要求/原则"——凡是"给要求"的地方新手必卡住
2. 每个判断给 ❌反例/✅正例 对照
3. 每个人要做的判断给照着念的清单
4. 每个命令给可直接复制的一行
5. 每张卡 ≤150 行；宪法 ≤200；START-HERE ≤60；ARCHITECTURE ≤100；RUNBOOK ≤80——超了就是设计错误，回去砍
6. 全部脚本一律 .ps1（Windows 优先）；必须用 .sh 时卡内附一行 Git Bash 跑法
7. 卡内对母版内部文件的引用 = 0（判据内联）；对项目文件的引用 = 具体路径

## 12. 生成多删除少的治理（2026-10-03 增补）

**问题**：agent 天然偏向新增——新建文件、新建 `_v2` 实现、新建分支，旧的不敢删也不会删。结果是新旧并存、registry 与代码脱钩、文件数单调膨胀，最后没人敢删。**只靠"要求 agent 记得删"无效，必须让"没删"变成可判定的信号。**

**机制链（预防 → 记账 → 同批处置 → 登记 → 发现 → 审查 → 清理 → 体检）**：

1. **预防（22 卡）**：设计阶段先算改动面（= 需改动行数 ÷ 目标文件现有行数）。<40% 就地改；≥40% 选重写须写明理由并获用户确认；重写必须同时交付①等价性证据计划②旧实现退役计划（哪批删、删除条件可判定）。从源头掐掉"新建 v2、旧的留着"。
2. **记账（23 卡）**：每批回执净增量五数字（新增/删除文件数、新增/删除行数、净行数），基线 = 开工记的起点锚点。**改存量批次"删除行 = 0 且新增行 > 50" → 红灯**；纯新建批次豁免但必须写"本批为纯新增"。看不出减少的批次 = 腐化在累积。
3. **同批处置（23 卡）**：新实现落地的那一批必须删掉被取代的旧实现；删不掉的登记 `STATE.md` **并行态登记簿**（`并行态 / 旧实现 / 新实现 / 删除条件（可判定） / 到期 / 登记批次`）。合法保留理由只有三种：灰度或回滚带期限、对外兼容契约带弃用期、证据留存（= git 历史）。`.bak`、`旧版/`、`副本 2` 一律违规。
4. **登记（23 卡）**：新增任何文件必须在同批登记 `docs/registry/COMPONENTS.md`（路径+用途+归属批次）；单批新增 >20 文件 → 红灯。
5. **发现（40 卡第 ⑧ 查）**：归档时跑 `orphans.ps1` 出五张清单（文件级孤儿 / 零引用导出 / 文档幽灵 / 反向幽灵 / 未登记），每条孤儿必须落进 **删除 / 登记为技术债 / 补登记** 三类之一——"什么都不做"不允许；处置随同一次归档提交走。工具只报不拦（判据是启发式，"删哪个"属人的裁决）。
6. **审查（24 卡）**：本批触及文件里有被取代却未删的旧实现、且登记簿无对应行 → 红灯；本批新增行命中 `_old / _legacy / _v2 / Deprecated / 暂时保留 / 废弃 / TODO: 删` 未申报理由 → 红灯。
7. **清理（52 卡 P 批）**：开工写死减少目标（净减 ≥200 行 或 ≥3 个文件，不许中途改），dry-run 清单 + 路径白名单化、人过一眼才删；收敛动作白名单（删死代码与孤儿文件/合并重复实现/统一术语/收敛配置目录）；验收四件齐。P 批触发：每 3–5 个功能批次 / 43 卡体检 / 腐化类台账 ≥5 条。
8. **体检（43 卡信号 6–8）**：并行态到期未清、孤儿三查两轮不收敛、文件数超预算——把"慢慢发生的腐化"变成可判定信号 + 提案。

**阈值一览（内联进卡，不靠记忆）**：改动面 40%/60%｜改存量批次删除行 0 且新增 >50 行 = 红灯｜单批新增文件 >20 = 红灯｜文件数 > `STATE.md` 文件数基线 + 20 由 `check.ps1` 判红｜P 批净减 ≥200 行 或 ≥3 文件｜`orphans.ps1` 汇总行两轮不减触发 43 卡提案。

**为什么分三道闸而不是一道**：预防（22）管"别多建"，记账与同批处置（23/24）管"建了要交代"，发现与清理（40/43/52）管"漏了兜底"。任何一道单独存在都会被绕过：只有审查没有账本 → 审查凭印象；只有账本没有清理批 → 红灯永远亮着没人处理。
