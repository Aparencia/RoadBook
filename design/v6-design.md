# Roadbook（路书）· V6「磁盘即流程」设计文档

> 状态：已定稿（2026-09-11，与用户逐节审阅通过）
> 本文档是新体系构建的**唯一事实源**。所有 playbook、模板、校验脚本与本文件冲突时，以本文件为准；改设计先改这里。

## 0. 一句话定义

把流程知识全部放磁盘，agent 自己取用；人只做三件事：**表达意图、裁决 gate、行为验收**。
目标函数：个人 + 无状态 AI 的开发效率最大化 = 减少返工 + 避免做垃圾 + 补偿 AI 无记忆。

**项目名**：**Roadbook（路书）**（2026-10-03 定名；英文名 Roadbook 为准，中文名「路书」）。仓库名 / skill 名 = `roadbook`；`V6` 是版本号，不是名字。
名字只写在身份文件里（`README.md`、`START-HERE.md`、本文件标题、`playbook/0-1-驱动卡.md` 首段一次），外加项目模板的入口（`template/README.md`、`template/AGENTS.md` 各一次，`template/docs/README.md` 一句，让未来项目知道自己的流程出处），不散落到卡内判据。

## 1. 设计公理（全部来源已验证：两份外部研究 + V5 新手模拟实测）

1. **状态在磁盘，不在聊天**——聊天是缓存，STATE.md 是唯一事实源
2. **证据式完成**——"完成"唯一合法定义 = guardrail 脚本退出码 0 + 粘贴真实输出
3. **单一变更入口**——改需求改上游文档（SCOPE/决策卡），禁止手改中间产物
4. **新鲜上下文复核**——实现者不复核自己；审查天然在独立会话/子代理
5. **右倾化流程深度**——档位 S/M/L，小事直通，大事全流程；只许上调不许下调
6. **用户只做裁决，不做检索**——人读的只有 START-HERE 和 STATE.md；判据全在卡内
7. **本地写作三招是硬规范**：给反例、给照着念的清单、给可复制命令
8. **双语双份，判据唯一**（2026-10-03 增）：`playbook_EN/` 是 agent 默认执行版（表达准确性优先，含糊中文必须显式化），`playbook/` 是中文判据权威版；两者冲突时**判据听中文、措辞歧义听英文**；改判据必须两份同改，只改一份 = 校验器判红
9. **覆盖全生命周期，深度右倾**（2026-10-03 增）：对标准 SDLC（ISO/IEC/IEEE 12207、ISO/IEC 25010、SWEBOK、ISTQB、DORA）做显式对照并补齐真缺失（见 §16）；但每张卡只保留"能防止一次真实返工"的判据，补的是**覆盖面**不是**文档量**

## 2. 架构：母版与项目的关系

```
母版（本工作区）                          每个项目（1-2 号卡生成）
├── START-HERE.md    人唯一要读          ├── AGENTS.md      宪法（agent 自动读）
├── SKILL.md         DSH skill 入口      ├── STATE.md       状态仪表盘
├── playbook_EN/     ★agent 默认执行版   ├── README.md / CHANGELOG.md / .tool-versions / check.ps1 / doctor.ps1 / gate.ps1 / orphans.ps1 / security.ps1 / .env.example / .gitignore / .gitattributes
├── playbook/        中文判据权威版      ├── src/ tests/ …（按栈生成）
├── template/        项目模板             └── docs/          机制配套文档（见 §5）
├── design/          本设计文档+契约+英译口径
├── _qc/check.ps1    一致性校验
├── LICENSE          MIT 许可（可自由复用）
└── plugin/           DSH 自动加载插件（可选装，见 §15）
```

**双接口**：
- **驱动卡接口（默认）**：用户复制一次 0-1-驱动卡（内容永久不变），之后每步只发一句话意图 + 一个词裁决。agent 读 STATE.md → 回执将执行的卡与检查清单原文 → 执行 → gate 停 → 回写状态 → 指明下一步。
- **单卡直复接口（兜底）**：网页版无文件能力的 agent、或用户想亲自控制某步时，打开单张卡全选复制。同一套文件两用，零额外维护。
- **读哪一份（2026-10-03 增）**：有文件能力的 agent **先读 `playbook_EN/<卡号>-*.md`**（英文执行版），中文版作为判据权威与人类阅读版；冲突裁决见 §1 公理 8、映射表见 §4.1。两份卡的四段结构与收尾语**逐字对应**，所以回执格式不因语言而变。

**防绕过**：agent 任何开发动作前必须回执"正在执行哪张卡 + 检查清单原文"；引不出原文 = 该轮输出作废。

## 3. 生命周期总图

**卡号 = 阶段号 + 分配序号**（`x-x-xxx`：第一位=阶段、第二位=该卡在**本阶段内的登记序号**、第三位=卡名）。**第二位不是执行顺序**——补卡一律追加到阶段末尾（`2-6` / `3-7` / `4-6` / `5-6` / `5-7` / `6-8` 全是补出来的），所以「号小」不等于「先跑」；执行顺序只认下面这张总图与 §4 的档位线/专线，机器口径 = `skills/roadbook/bin/route.mjs` 的 `STEPS` 数组顺序。阶段号本身是流程的一部分，所以看第一位就知道现在处于哪一期。

| 阶段 | 名称 | 阶段出口（进入下一期的条件） |
| :-: | :--- | :--- |
| 0 | 驱动层 | 无（常驻：每次开口都先过驱动卡；`0-2` 会话生命周期随时可插入） |
| 1 | 立项期 | 项目骨架生成 + 首次 gate 绿 |
| 2 | 需求期 | SCOPE 范围确认（+ NFR 阈值确认） |
| 3 | 设计期 | 设计批准 / 测试策略确认 |
| 4 | 实现期 | VERIFY 照单验收通过 |
| 5 | 交付期 | 归档勾选 + 版本与基线（`5-6` 定号 → `5-7` 钉基线）+ 发布批准 + 观测窗收尾 |
| 6 | 运行与治理期 | 无（常驻：缺陷与治理循环） |
| 7 | 特殊变更期 | 无（按需触发，各自闭环） |

## 4. playbook 全集（49 张：0-1 驱动卡 + 0-2 会话生命周期 + 47 张动作卡）

**每张卡固定四段结构**（详细契约见 `playbook-contract.md`）：
① 开工确认（复述任务+列假设+提≤5个澄清问题+引用本卡检查清单原文）→ ② 执行（带禁令的动作序列，分批+停下点）→ ③ 证据回执（guardrail 输出/文件路径/提交哈希）→ ④ 状态回写（更新 STATE.md+指明下一张卡+等裁决）。

**本表就是卡清单的唯一事实源**：`_qc/check.ps1` 从本表解析卡号与卡名，与 `playbook/` 磁盘逐张对齐、与 `playbook_EN/` 逐张对齐。新增/删除卡必须同时改本表、`README.md` 与 `SKILL.md` 路由——三处任缺一处，校验器判红。

- **架构线（2026-10-06 增，用户裁决补卡）**：**项目首次成型**（`1-2` 生成骨架之后 / `1-3` 接入已有项目时反推结构）或**结构发生变更**（新增或移除模块、换存储、拆或合服务，含 `7-8` 与 `7-10` 中途）走 `3-7 架构定义 → 3-1 设计（L 档）→ 4-1 分批编码`；判据是**形状变了就得回来改一次**——结构变更而架构文档不动，等于把文档和代码分家。S 档裁剪：单页应用的结构即文件清单，在 `裁剪记录` 写一行即可。架构**不占每次改动**：日常功能改动只读它，不改它（要改形状才回来）。
- **界面线（2026-10-03 增；2026-10-06 增可用性收口）**：只要这次改动**看得见**（新页面/新组件/改按钮样式），M 档起就连走 `3-4 界面与交互设计 → 3-5 色彩与风格 → 3-6 动效与微交互`；纯后端/脚本改动不走（在 `裁剪记录` 写一行"本次无界面"）。
- **可用性线（2026-10-06 增，用户裁决补卡）**：本次改动**要交给人自己用它完成任务**时，交付前走 `4-6 可用性验证 → 5-1 归档`。触发不是"改了界面"（那是界面线），而是"有一个不是写代码的人要拿它做事"；判据是**有没有人真的用它**——没有使用者就没有这一线。S 档：`4-3` 走完后自己冷启动走一遍并逐屏截图，在 `裁剪记录` 写一行。

- **迁移线（2026-10-05 增，用户裁决拆卡）**：换语言/框架/存储/运行时/托管平台走 `7-10 技术栈迁移→4-3 验证→5-2 发布→5-4 运行期观测→5-1 归档`；与重构线的区别是**行为可变**，安全带是"旧系统当 oracle"的黑盒契约 + 数据双跑对账 + 回滚窗口。
- **决策线（2026-10-06 增，用户裁决补卡）**：**没出事也开**的一条线——决策卡满 5 张 / 里程碑发布后 / 决策卡的复核日到期，走 `6-8 决策复盘`（只读，不改产品代码）；它的产出接到 `6-6 流程体检`（流程级信号）或回 `2-1` 立项（要改的东西）。与事故线的区别：事故线由**故障**触发，决策线由**时间**触发。

**三层读取模型**（控制 token 税）：
- 常驻层：AGENTS.md+STATE.md（每会话必读）
- 现行状态层：registry/+TECH_DEBT+pool/+.tool-versions（按需查；**找不到先查再建，禁止平行新建**）
- 留存历史层：specs/reviews/decisions/lessons/versions/archive（归档后不读；教训卡按症状检索）

**版本文档三落点**：索引=根 `CHANGELOG.md`（行业惯例位置，倒序四小节+未发布节）；详情=`docs/versions/vX.Y.Z.md`；锚点=`git tag vX.Y.Z`（**agent 在发布流程内执行**，自 `2026-10-05.2` 起；已发布的 tag 不许移动或删除）。三处对齐是 5-2 卡门禁；版本号判据（MAJOR/MINOR/PATCH、0.x→1.0、预发布、升级注意模板）见 5-6 卡。版本号：0.x 随意；1.x 起破坏性变更升 MAJOR 并写升级注意。CHANGELOG 与 versions 只追加不改写。

**防膨胀**（5-1 卡执行，用户不记）：specs 超 30 天未动提示归档（机械读数 = `orphans.ps1` 的 `[归档候选]` 清单，不再靠 `LastWriteTime` 人肉比对）；**淘汰 ≠ 归档**（2026-10-06 裁决）：`lessons/` 超 30 张 → 同症状**合并或删除**，**不搬进 archive**（搬进去 = 永久保留，那不是淘汰）；`decisions/` **不按张数淘汰**——决策卡的价值随时间上升，半年后正是要读它的时候，只在被取代时行内标注；COMPONENTS 单页 ≤50 行；README/ARCHITECTURE/RUNBOOK 过期检查（启动命令跑得通？模块图与目录一致？.env 键全有解释？）；**文件数预算**：STATE.md `文件数基线` + 20 = 本项目文件数红线（check.ps1 判红；**基线只在初始化时设置一次，4-1 卡每批只更新「当前文件数」，膨胀判定 = 当前文件数 − 基线 > 20**——每批重置基线会让这条阈值永远不触发）；`orphans.ps1` 汇总行连续两轮不减 → 6-6 卡提案（防"清单永远在报、没人处理"）。

11. **形态选择**（2026-10-03 补，源自 superpowers `writing-skills` 内化）：先判这张卡要防的失败长什么样，再选写法——**知道却违反** → 禁令 + 合理化红旗表；**输出形状不对** → 正向配方（照抄一遍这个输出长什么样）；**漏必需元素** → 结构槽位（REQUIRED 字段，缺了脚本报错）；**依赖条件的规则** → 写成可观测谓词的条件句。硬禁令：禁写"除非确实需要""一般情况"这类细微差别条款——例外的唯一写法是可观测谓词。判定顺序 = 先看失败类型选形态，再看禁令/配方/槽位是否落地；形态选错的卡，写得再全也拦不住
12. **子 agent 边界**（2026-10-03 补，源自 superpowers `using-superpowers` 内化）：被派去执行具体任务的子 agent **不适用**开工确认与 DoD 粘贴输出（它只拿到派单，没读卡正文，要求它粘贴检查清单原文 = 逼它编）——这两条是对主线程/读卡者的要求；但**必须遵守**"红灯 = 停"与"回执只认三种证据"，且**返回里必须给出它读过的卡路径与行号**（没读过卡就写"未读卡，仅按派单执行"，不许默不作声）
13. **并行准入先判相关性**（2026-10-03 补，源自 superpowers 内化）：拆片前先判两件，**顺序不许颠倒**——① **相关性**：多个工作单元是否同一契约（一个改被调用方、一个改调用方）、同一可观察行为、或同一根因？命中任一 = **禁止拆片**（拆了就要合并，且写者互相看不见对方的判据）；② **文件域**：相关但文件域不互斥的，由主线程独占共享文件（写作用域互斥见宪法 §12）。两份工作各自有独立证据、独立回执，才是可并行的信号
14. **探针分支**（2026-10-03 补，源自 superpowers `brainstorming` 内化）：用户只问"这能不能做 / 可不可行"时走探针分支，**不立项**——先给三句（要回答的问题 / 怎么试 / 预期花多久）→ 停下等一个点头；在系统临时目录做，禁止在项目仓库新建业务文件、禁止拷贝母版模板骨架、禁止 `git init`；产物是**答案不是代码**，留了代码就标"一次性探针，结论已入 <文件>，代码不保留"
15. **门禁三条**（2026-10-03 补，源自 superpowers `brainstorming` 内化）：① **可分解性先判**——≥2 个互不依赖的子系统先拆再问，本张卡只研究第一个；② **单向棘轮**——中途发现隐藏复杂度（新依赖 / 跨模块 / 破坏性表结构）立即停下声明升档，**只升不降**，不许闷头做完再补；③ **批准不跨段、展示与开工分两条消息**——门禁是"用户说了确认"，不是文档长短，S 档同样适用

16. **正说优先**（2026-10-04 补，源自 mattpocock/skills `writing-for-agents` 内化）：先写要做什么，再考虑禁令。**否定式本身是失败模式**——禁令会把被禁行为拉进上下文；只有无法正说的硬护栏才写禁令，并同时给正面目标。配套 **no-op 测试**：一句规则删掉之后 agent 行为不变 = 该删，或改写成可执行判据；"读起来有道理"不算数。同义触发词只留一个（一个分支写两个同义触发词 = 同一分支写两遍）
17. **信息阶梯与就近放置**（2026-10-04 补，源自 `writing-for-agents` 内化）：能写进步骤的不另开一节；要引用就先给步骤再给引用；同一事实只写一处——**文档是 cache，命令与文件是事实源**（文档与实测冲突时以实测为准并回来改文档）
18. **调用轴 = 上下文预算分配器**（2026-10-04 补，源自 mattpocock/skills `invocation.md` 与 `SKILL.md` 内化）：常驻入口（`SKILL.md`、0-1 驱动卡）只放**一行触发词 + 路由**，判据一律留在被路由到的卡里；卡号/卡名/文件名变更必须**同批**改路由——路由指向不存在的卡 = 路由在骗人（6-6 信号 13 路由漂移）
19. **上下文预算与阶段边界**（2026-10-04 补，源自 `ask-matt` 的 smart zone 口径）：单会话保持在 smart zone（约 150k tokens）以内；出现任一情形先落证据再压缩或交接——① 接近上限、② 跨阶段（一张卡走完进下一张）、③ 换机器/隔天继续。交接条写系统临时目录、**只放指针不复述**（复述必然漂移）、敏感值脱敏。8-x 运行时工具卡删除后，这条判断由 0-1 驱动卡硬规则承载
20. **产物寿命三分类**（2026-10-04 补，源自 mattpocock/skills 各技能对产物去向的显式声明）：任何产物开头写明属哪一类——**持久**（进仓库）/ **会话内**（临时目录，随时可删）/ **永不入库**（只贴回执）；没有声明按"会话内"处理。防止临时报告被当成事实源长期引用
21. **证据分档与 Merge Danger**（2026-10-04 补，源自 mattpocock/skills `pr` 内化）：证据分 **S 档**（截图/录屏，人看得懂、机器验不了）与 **A 档**（命令执行输出，可复验）；声明"完成"至少要有 A 档证据，只有 S 档 = 未完成。发布前逐项标 **Merge Danger**：① 门是**单向门**还是双向门（单向门 = 出错无法原样回退）；② **爆炸半径**（影响几个用户/几个模块）——单向门 + 大半径 = 红线裁决，且回滚预案必须先演练过。"**没有能变红的命令，就没有第二阶段**"（6-2 第一阶段即复现、4-3 判据必须能被打红）
22. **拒绝台账与决策记录三要件**（2026-10-04 补，源自 mattpocock/skills `.out-of-scope/` 与 `domain-modeling` 内化）：每个被否方案留一行 `日期 | 提案 | 否决理由 | 既往请求编号`，重审同一提案时**先读台账**再讨论；决策记录只在**难以回退 且 出人意料 且 真有权衡**三条同时成立时才写，缺一条不写。被否方案属"拒绝台账"，已实现的 wontfix 不许混进去
23. **接缝判据**（2026-10-04 补，源自 mattpocock/skills `codebase-design` 内化）：**一个适配器 = 假设的接缝；两个适配器 = 真接缝**——只有一个实现时抽出的抽象层是猜测，登记为技术债；第二个实现出现时才抽接口/适配器

## 11. 维护规则（写进 START-HERE）

1. **改判据必须两份同改**：动 `playbook/X.md` 的判据行，就必须在同一提交里动 `playbook_EN/<同卡号>-*.md` 的对应行；只改一份 = `_qc/check.ps1` 判红（按 §4.1 表逐张对齐 + 四段结构与收尾语逐字断言）。

## 12. 生成多删除少的治理（2026-10-03 增补）

**问题**：agent 天然偏向新增——新建文件、新建 `_v2` 实现、新建分支，旧的不敢删也不会删。结果是新旧并存、registry 与代码脱钩、文件数单调膨胀，最后没人敢删。**只靠"要求 agent 记得删"无效，必须让"没删"变成可判定的信号。**

**机制链（预防 → 记账 → 同批处置 → 登记 → 发现 → 审查 → 清理 → 体检）**：

1. **预防（3-1 卡）**：设计阶段先算改动面（= 需改动行数 ÷ 目标文件现有行数）。<40% 就地改；**≥40% 一律需写明理由并获用户确认**（就地改与重写都要写）；>60% 且旧逻辑无复用价值才允许重写，重写必须同时交付①等价性证据计划②旧实现退役计划（哪批删、删除条件可判定）。从源头掐掉"新建 v2、旧的留着"。
2. **记账（4-1 卡）**：每批回执净增量五数字（新增/删除文件数、新增/删除行数、净行数）。**分母口径**：本批 = `git diff --numstat <上一批末提交>..HEAD`（首批 = 起点锚点）；任务累计另记一行 `<起点锚点>..HEAD`——**若每批都用起点锚点做分母，则第一笔删除之后"删除行 > 0"恒成立，红灯判据"删除行 = 0 且新增行 > 50"此后再不触发**。**改存量批次"删除行 = 0 且新增行 > 50" → 红灯**；纯新建批次豁免但必须写"本批为纯新增"。看不出减少的批次 = 腐化在累积。
3. **同批处置（4-1 卡）**：新实现落地的那一批必须删掉被取代的旧实现；删不掉的登记 `STATE.md` **并行态登记簿**（`并行态 / 旧实现 / 新实现 / 删除条件（可判定） / 到期 / 登记批次`）。合法保留理由只有三种：灰度或回滚带期限、对外兼容契约带弃用期、证据留存（= git 历史）。`.bak`、`旧版/`、`副本 2` 一律违规。
4. **登记（4-1 卡）**：新增任何文件必须在同批登记 `docs/registry/COMPONENTS.md`（路径+用途+归属批次）；单批新增 >20 文件 → 红灯。
5. **发现（5-1 卡第 ⑧ 查）**：归档时跑 `orphans.ps1` 出七张清单（文件级孤儿 / 零引用导出 / 文档幽灵 / 反向幽灵 / 未登记 / 未登记文档 / 归档候选），每条孤儿必须落进 **删除 / 登记为技术债 / 补登记** 三类之一——"什么都不做"不允许；处置随同一次归档提交走。清单里的发现项只报不拦（判据是启发式，"删哪个"属人的裁决）；但**未跟踪文件或读取失败 = exit 1**（清单不完整时结论不可信，先 `git add` 再跑）。
6. **审查（4-2 卡）**：本批触及文件里有被取代却未删的旧实现、且登记簿无对应行 → 红灯；本批新增行命中 `_old / _legacy / _v2 / Deprecated / 暂时保留 / 废弃 / TODO: 删` 未申报理由 → 红灯。
7. **清理（7-3 卡 P 批）**：开工写死减少目标（净减 ≥200 行 或 ≥3 个文件，不许中途改），dry-run 清单 + 路径白名单化、人过一眼才删；收敛动作白名单（删死代码与孤儿文件/合并重复实现/统一术语/收敛配置目录）；验收四件齐。P 批触发：每 3–5 个功能批次 / 6-6 卡体检 / 腐化类台账 ≥5 条。
8. **体检（6-6 卡信号 6–8）**：并行态到期未清、孤儿清单两轮不收敛、文件数超预算——把"慢慢发生的腐化"变成可判定信号 + 提案。

**阈值一览（内联进卡，不靠记忆）**：下表列出全部七条"数字型"判据 + 一条"机检型"判据与**执行者**——执行者一列是这张表的重点：写了"人工核算"的，没有任何脚本会替你拦下来（E1，2026-10-04 补列）：

| 阈值 | 卡 | 执行者 |
| :-- | :-- | :-- |
| 改动面 40%/60%（<40% 就地改 / ≥40% 写理由并经用户确认 / >60% 且无复用价值才重写） | 3-1 | **无**（人工判断） |
| 改存量批次删除行 = 0 且新增 > 50 行 = 红灯 | 4-1 | **无**（人工核算净增量账本） |
| 单批新增文件 > 20 = 红灯 | 4-1 | **无**（人工核算） |
| 文件数 > `STATE.md` 文件数基线 + 20 | 1-3、5-1 | **`check.ps1`**（机械判红） |
| 业务文件 > 500 行 / 测试 > 1000 行 | 4-1、4-2 | **`gate.ps1`**（机械判红，见 §8） |
| 明文密钥 / `.env` 泄露 / 危险执行链 / `.ps1` 无 BOM | 1-2、4-1、5-1、7-9 | **`security.ps1`**（机械判红，退出码 1）+ 人工复核 |
| P 批净减 ≥ 200 行 或 ≥ 3 文件 | 7-3 | **无**（人工核算，开工冻结目标） |
| `orphans.ps1` 汇总行两轮不减 → 6-6 提案 | 5-1、6-6 | **`orphans.ps1`** 出数 + **人工比对**（脚本不判"该不该提案"） |

**七条数字型里只有「文件数预算」与「行数 500/1000」由脚本独立判红，机检型那条由 `security.ps1` 独立判红；`orphans.ps1` 只出数不判决；其余四条是卡内清单的人工核算——不要以为它们会自动拦下来。** 新增任何"数字型"判据时，必须同时在本表写明执行者；写"人工核算"就必须在对应卡的检查清单里给出可复制的统计命令（否则等于把判据交给记忆）。

**为什么分三道闸而不是一道**：预防（3-1）管"别多建"，记账与同批处置（4-1/4-2）管"建了要交代"，发现与清理（5-1/6-6/7-3）管"漏了兜底"。任何一道单独存在都会被绕过：只有审查没有账本 → 审查凭印象；只有账本没有清理批 → 红灯永远亮着没人处理。

## 13. skill 分发（2026-10-03 增补）

**形态**：仓库根新增 `SKILL.md` → 装成 DSH 用户级 skill：

```powershell
git clone https://github.com/Aparencia/RoadBook.git "$env:USERPROFILE\.dsh\skills\roadbook"   # 安装
git -C "$env:USERPROFILE\.dsh\skills\roadbook" pull --ff-only                                  # 更新
```

**为什么必须是"目录型"**：DSH 有两种布局——`<skills根>/roadbook/SKILL.md`（目录型，资源基目录 `resourceBase` = 该目录本身）与 `<skills根>/roadbook.md`（平铺型，基目录 = skills 根，源码 `packages/skill/skill-filesystem/src/index.ts:723-748 discoverRoot()`）。只有目录型能让 `SKILL.md` 里的 `playbook/xx.md` 相对路径落回母版根，所以 skill 目录必须**就是仓库的 clone**，正文一个字都不写绝对路径（换机器、换用户名都不用改）。

**机制要点（决定 SKILL.md 怎么写）**：① 会话目录只注入 `name` + `description`，`description` 截断到 `catalogDescriptionMaxLength`（默认 500）——所以 description 必须写"什么时候用"而不是"是什么"；② 正文按需加载（`skill` 工具），frontmatter 首行必须严格是 `---`，**前置 BOM 或空行会被静默忽略**（`skill-filesystem/src/index.ts:917-929 parseFrontmatter()`）——**且它必须是合法 YAML**：值里出现未加引号的 ASCII「: 」会被读成嵌套映射，`parse` 抛错后该文件被**整份静默丢弃**（2026-10-06 实例：`description` 里的 `wanted: a one-off` 让 `roadbook` 技能两天没进技能目录，插件侧只表现为 `skip/no-skill`、`inject` 事件 0 条，而 `_qc/check.ps1` 原有九条 frontmatter 断言全走正则、读得懂非法 YAML ⇒ 全绿；现已加断言）；③ 用户消息首行 `/roadbook` 时宿主直接把正文注入为 user 消息（`tool-skill/src/index.ts:163-204`），所以本卡体系在装了 skill 的会话里可以一步唤起；④ 发现根优先序：项目 `.dsh/skills` → 项目 `.agents/skills` → `customSkillDirs` → 用户 `~/.dsh/skills` → `~/.agents/skills`。

**纪律（防两处真相）**：`SKILL.md` 只做**路由 + 六条铁律 + 红线**，不复制任何判据；判据只在 `playbook/` 卡内，冲突以卡为准并回来修 SKILL.md。`_qc/check.ps1` 用机械断言兜住两点：引用的每张卡必须存在（防卡改名后路由指空）、`description` ≤500 且 `name` 合法（防目录里被截断成看不懂的半句或被 DSH 直接忽略）。

**版本口径**：`V6` 是**世代号**（第 6 代流程），**自 2026-10-05 起不再用于打 tag**（用户裁决：世代号只作流程代际标识，标签线唯一）。发布一律用插件版 semver，唯一事实源 = 根 `package.json` 的 `version`；当前标签线 `v0.4.1 → v0.5.0 → v0.6.0`。判据变更必须重新打 tag——**打 tag 自 `2026-10-05.2` 起由 agent 在发布流程内执行**（用户裁决；见 §4 的 5-6 卡与 5-2 卡），**已发布的 tag 不许移动或删除**（禁 `git tag -f`）。

> **唯一例外（2026-10-05，用户裁决，记录在案）**：历史世代号 tag `v0.6.0`（2026-10-03 世代首发，带 GitHub Release）**被删除并改指插件线 v0.6.0**。理由：它已被裁决为「不再作版本号参考」，却仍占着插件 semver 线马上要用的号；删除优于让插件线永久跳过 0.6.0。**这是一次性例外，不是新的通行做法**——上一条「已发布 tag 不许移动或删除」继续对今后每一个 tag 生效；本节的记录与 `CHANGELOG.md` [0.6.1] 节「tag 例外」互为印证，防止后人看到「规则说不许删、历史上却删过一个」时误判规则已废。

## 14. 版本管理主动性（2026-10-03 增补）

**问题**：这套流程把 git 当"记录载体"（5-1 卡以 git 为基准、4-1 卡记起点锚点、§9 git 历史即版本记录），但**没有任何机械检查要求"真的提交了"**。于是出现三个空洞：完成任务可以不提交（`check.ps1` 照样退出码 0）；门禁在提交前跑等于没跑（只看 `锚点..HEAD`）；未跟踪的新文件在文件清单里隐形（`git ls-files`）。再加上"新项目默认不配远端"，结果是**流程看起来在版本管理，实际历史可能只存在于本机、且一层都没落**。

**机制（六道）**：

1. **完成必已提交**（`template/check.ps1`）：工作树不干净 → `[FAIL]`（列出前 10 个文件）；STATE.md 有 `起点锚点` 时 `git rev-list --count <锚点>..HEAD` = 0 → `[FAIL]`（锚点未前移 = 做完没落历史）。**非 git 仓库 → `[FAIL]`（先 `git init`）；`$STEPS` 为空 → `[FAIL]`（没填就是没检查）；文件数基线缺失或为 0 → `[FAIL]`**——这些原先是 `[--]` 静默跳过，等于门禁空转（"零提交也能绿"就是这么来的），2026-10-03 修复批次改为硬断言。
2. **门禁有牙**（`template/gate.ps1`）：变更清单 = 已提交(`锚点..HEAD`) ∪ 未提交(`status --porcelain`)，去重——"提交前后跑"都成立，不再有"打印 GREEN 却什么都没查"。
3. **会话边界有主**（0-1 卡 + STATE.md）：开机报告加一行 git 现状（`git status --short` + `git log --oneline -3`），不干净必须让用户三选一（提交 / 登记技术债后搁置 / 丢弃）；用户说"今天到这 / 暂停"时跑同一条收尾仪式。STATE.md 加 `工作树状态`（收尾必须"干净"）与 `远端仓库`。
4. **提交可回溯**（9 张卡的示例统一）：提交信息 `<卡号> <type>(<scope>): <摘要>`；`git log --oneline` 里 `4-1 ` 开头的即某任务的全部批次。
5. **远端不是可选项**（1-2 / 1-3 / 5-1 卡）：1-2 卡动作 8 = 远端三选一（`gh repo create … --push` / `remote add` + 首推 / 明确裁剪为本地-only 并写风险），**可见性（私有/公开）由人裁决**；1-3 卡动作 8.5 先 `git remote -v`；5-1 卡归档收尾必 `git push`（无远端记一行）。首推/推送前用 `git check-ignore -v .env` 确认敏感文件**确实被 .gitignore 挡住**，并用 `git log --all --oneline -- .env` 确认历史上没提交过——**别用 `git status --porcelain` 判断（被忽略的文件在 porcelain 里看不到，那是个空判据）**。推出去不可逆。
6. **体检兜底**（6-6 卡信号 9/10）：提交节奏失效（锚点两轮未前移、工作树跨会话非空）、远端与推送滞后（无 remote、STATE 写本地-only、连续两轮 `ahead N`）。

**边界：push 不进 DoD。** DoD 必须本机可判定、不受网络与凭据影响（`check.ps1` 退出码 0）；把 push 塞进 DoD 会让断网变成"没完成"，那是假红。所以推送挂在**归档收尾**（任务闭环的自然同步点）与**体检信号**上，不挂完成定义。

**为什么这三处"失明"危险**：门禁与完成定义是这套流程仅有的两个机械真相来源。它们一旦对上层的 git 状态失明，"绿灯"就只证明"命令跑过了"，不证明"东西存在过"——这正是失败模式报告 A 类（伪验证）的机制版本。

## 15. 自动加载插件（2026-10-03 增补）

**问题**：skill 的自动加载是**模型侧判断**——会话目录里只有 `name` + `description`，是否调用 `skill` 工具由模型自己决定（§13 机制要点①）。于是"流程卡有没有进入上下文"没有机械保证；用户实测遇到的现象正属此类（技能装好后旧会话仍调不到，因为该会话的技能目录缓存为空且监视器挂不上）。

**形态**：仓库根新增 `plugin/roadbook-autoload/`，一个 DSH **组合包（bundle）**：

> 2026-10-04 主插件化后：本包仍是**可独立安装**的组合包（「只想装自动加载」的场景），但推荐路径是装主插件（仓库根 `roadbook`）——根 `cordis.patch.yml` **平铺**的一行以 `roadbook/autoload` 声明本行，见 §17.2 与 §10 第 31、32 条。

- `package.json`（`dsh.bundle.patch` → `cordis.patch.yml`，声明 `dsh.compatibility.dshReleases`）＋ `cordis.patch.yml`（`- insert:` 一行把包挂进宿主）
- `index.js` = Host 半区插件（`export function apply` / `export const inject = ['agents','skills']` / `export const Config`），只做接线
- `trigger.js` = 纯逻辑（**不 import 任何 dsh 包**，可 `node plugin/roadbook-autoload/test/trigger.test.mjs` 离线单测，13 例）
- `locale/zh.json`、`locale/en.json`、`icon.svg`（插件页展示）、`README.md`（配置表 / 安装 / 验证）

**机制**：挂 `agent/pre-step`（waterfall，镜像内置手势 `dsh-tool-skill` 的实现）——命中就 `return { ...decision, messages: [...decision.messages, createUserMessage({ content, source: { kind: 'skill-invocation', name, form: 'instructions' } })] }`（spread 决策以保留 `startsRequestSeries`），正文由官方 `renderSkillContent()` 渲染。**这与用户手打 `/roadbook` 走同一条路**，模型看到同一份 `<skill_content>`，也让"自动注入"与"显式调用"在会话日志里可区分（`source.kind`）。

**三层门控（全部可判定，不靠模型）**：① 会话 cwd 向上能找到 `.git`（`requireGitRoot`）；② 用户消息命中开发意图关键词且**未**命中抑制词（"只讨论 / 不要动代码 / 不用流程"一类，抑制词优先）；③ 去重：本会话可见面（`session.surface`）上没有同名注入、本回合无同名注入、用户没手打 `/<skill>`（让路给内置手势）。另：子代理会话默认不注入（`includeSubagents`；判据是 `delegationDepth > 0` —— **分叉 / 续接出来的用户会话 depth = 0、不算子代理**，2026-10-06 实测修正：只看 `parentSession` 会把用户会话误判成子代理而整轮不注入）、`note` 在正文后附一行透明说明（为什么加载 / 怎么关）、`mode: off` 整体关闭、`mode: always` 改成"只要在 git 项目里就注入"。

**压缩感知（2026-10-03 增补）**：上下文压缩会把已注入的消息 shadow 出可见面——日志里还留着，模型却看不到了。所以 ③ 的判据问**可见面**而不是问历史：`surfaceInjectionState()` 读 `session.surface.nodes` + `session.eventAt(seq)`，返回 `present`（还在 → 跳过）/ `absent`（已被 shadow → 重注入，观测里 `reason: reinject-shadowed`）/ `unavailable`（读不到面 → 退回旧的"一次会话一次"保守行为，绝不猜）。会话日志只作 `unavailable` 时的兜底。**不这么做的代价**：长会话被压缩一次后，后半程完全失去流程卡，而 `oncePerSession` 会让它静默失效。

**自进化三环（只观测、只提示，绝不改卡）**：A **命中观测**——`reportPath` 落 JSONL（时间/会话/cwd/技能/命中词/指纹/消息摘要/可见面判据），默认**开**（`report: false` 关），开了供 6-6 卡体检抽样；B **版本对账**——`skillDigest` 与 SKILL.md 当前指纹比对，不一致就在注入说明里提示"技能已更新"，默认开（基线为空则不提示）；C **空转观测**——"注入了但整轮没读 `playbook/*.md`"记为疑似空转，**暂不做**（避免为观测再挂钩子）。**边界**：插件不自动改卡、不自动改配置、不替用户裁决门禁；流程卡变更仍走 6-6 卡体检 + 用户裁决。

**代价与脆弱面（明说）**：① 误命中成本 ≈ 1.2K tokens/会话，三层门控把它压到"开发意图明确"才发生；② 依赖 DSH 的 `agent/pre-step` 决策形状、`session.surface` 与 `session.eventAt`（压缩感知的可见面判据；读不到就退回保守行为）、`ctx.skills.get`、`renderSkillContent` 四处——DSH 升级后若改动它们，插件可能静默失效，先跑离线单测再按四条验证核对；③ 组合包**自带自动更新（0.4.0 起）**：主行开机查一次上游版本（默认 `update: notify` 只提示，`auto` 才自动替换），在「图册」标签页点「更新」由插件自己跑安装命令（`dsh plugin add` → 退到 `$DSH_HOME/dsh-runtimes/` 自带的 node + pnpm），替换完**必须重启 DSH**（桌面宿主持有重启权，插件不自己重启）；判定不由 dshmarket 代劳——实测它对 `github:` 来源的当前 commit 读不出来（`current === null` ⇒ `updateAvailable` 恒为 false），转发这种结论就是假绿；④ 运行时依赖（`@deepseek-ai/dsh-*` 一类宿主包）以 `peerDependencies` 声明、由**宿主提供**，插件内不装、不打包——宿主大版本升级后先看 peer 范围是否仍满足，不满足要同步改 `package.json` 再重装；⑤ `includeSubagents: false` 意味着**子 agent 拿不到卡正文**，而 SKILL.md 允许并发写者 ≤5 —— 并发越高，未受卡约束的执行比例越大；缓解 = 子 agent 至少遵守红灯与证据两条（边界见 §8 第 12 条、`SKILL.md` 第 5 条）；⑥ 自动更新自己跑安装命令，**没有** dshmarket 的并发锁、兼容性验证与自动回滚——现有的三道闸只有：单飞锁文件（`<profile>/.roadbook-update.lock`，30 分钟视为陈旧）、有 agent 在跑就拒绝（判据同市场）、超时 300s 后 SIGTERM/SIGKILL；失败时保留命令输出尾部作证据并提示按原来源重装，不承诺回滚；⑦ 上游检查每次开机一次对 `raw.githubusercontent.com` 的 GET（除 URL 外不发送任何本机信息），断网/被墙时如实退化为 `unknown` 而不是「已是最新」。

**为什么不用另两条路**：写 `~/.dsh/AGENTS.md` 或改 `template/AGENTS.md` 都是"请遵守"的**软指令**，仍由模型服从（用户要的正是 100% 自动）；且后者只影响装了模板的新项目，还会让项目宪法带上母版依赖。插件是唯一在"每回合注入"这一层生效、又不污染任何项目文件的形态。**两层的实际强度差在量级上（E3，2026-10-04 补数）**：skill 形态（含本插件的 keyword 命中路径）是"意图命中才注入"，实测触发命中率约 **50–80%**，漏了就是漏了，一整轮不受约束；hook / 每回合注入形态（DSH 的 `agent/pre-step`）是**确定性 100%**——不依赖模型是否想起来、也不依赖措辞是否踩中触发词。所以本项目的分工是：**必须 100% 发生的规则（红灯、证据、回执）走插件注入；需要判断力的判据留在卡里由模型读。** 反过来，任何"大概会触发"的机制都不能当门禁用——它只能当提示。
