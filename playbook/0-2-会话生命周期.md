# 卡 0-2 · 会话生命周期
> 触发：收会话 / 新开会话 / 要 fork 或派子代理 / 长任务要不要用 goal ｜ 产物：证据落盘 + STATE.md 回写 + 需要时交接条 ｜ 下一张：由 STATE.md 决定
> 过程域：AGENT, PLAN

---

## ① 开工确认

收到开工指令后，先回执：

1. **任务复述**：本卡管一轮会话从开工到收尾怎么活——什么时候收、什么时候新开、什么时候分叉、什么时候用 goal 持续轮次。不碰任何业务产物。
2. **假设清单（每条带置信度，写不出置信度就是没查过）**：
   - 假设 D8 的 75% 阈值与"压缩前证据先落盘"是本卡触发线的依据（置信 0.9；依据：项目根 AGENTS.md D8 原文）。若错则收会话触发线失效。
   - 假设 `STATE.md` 的 `起点锚点` / `最近完成` / `工作树状态` 三字段在位（置信 0.8；依据：读 STATE.md）。若错则先补字段再走本卡。
   - 假设本轮不产生业务文件，产物寿命全是"会话内"（置信 0.9；依据：本卡只做落盘、回写与指针）。
3. **澄清问题（≤5 个，各带推荐答案，用户回一个词即可）**：
   - 这轮收不收？**推荐：收**——命中下方任一收会话触发就收，别等上下文满。
   - 要不要写交接条？**推荐：要**——需要跨会话或换机器就写，同会话继续就不用。
   - 长任务开不开 goal 持续轮次？**推荐：开**——跨多张卡、跨多个会话才开。
   - 下一轮的新会话要不要另派子代理？**推荐：不派**——同一契约、同一可观察行为、同一根因一律留在主线程。
4. **逐字引用本卡 §② 检查清单原文**（引不出 = 本轮作废）：
   - "**会话收尾四步：证据落盘 → 工作树三选一 → 回写 STATE.md → 需要跨会话时写交接条。四步按序走完。**"
   - "**压缩前必须先落盘**：同一条命令的红/绿两次输出，在压缩发生之前写进文件。"
   - "**会话归档只做三件：证据落盘、状态回写、交接条。不新建仓库文档。**"
5. 声明：产物落点 = 本批知会或 `docs/specs/<日期>_<slug>/VERIFY.md` + `STATE.md` + 需要时系统临时目录的 `handover_<日期>.md`；下一张由 `STATE.md` 的 `下一步` 决定。

## ② 执行

**合理化红旗表（命中任何一行 = 停下，按"事实"列执行）：**

| 你会想 | 事实 |
| :-- | :-- |
| "聊得正顺，先不打断" | 顺不顺与本卡的触发线无关；四条触发命中任一条就收 |
| "上下文还够，不用收" | 到 75% 就要主动开削（D8）；等满了，削与落盘的顺序已经不受你控制 |
| "反正 STATE.md 里有了，我凭记忆接着干" | 记忆不是事实源；下一轮只从 `STATE.md` 与 git log 恢复，凭记忆续跑 = 重做上一轮的活 |
| "脏工作树留给下次会话" | 未提交的改动不进历史；三选一当场处置，处置结果写进 STATE.md |

**零、四个对象（各一句边界）：**
- **一轮会话**：一次开工确认到一次收尾=一轮会话；收尾动作见"二"。
- **一个任务**：`STATE.md` 的 `当前任务` 从建立到归档；归档动作不属本卡（见"六"）。
- **一张卡**：从本卡或别卡的四段走完算一张卡；一张卡走完可以留在同一会话。
- **一个 goal 轮次**：goal 持续轮次里的自动续跑=一个 goal 轮次；只跨多张卡的长任务才开（见"八"）。

**一、该收会话的触发（六条，命中任意一条就收；agent 侧自己判，不许只等用户开口）：**
1. 用户说"先这样 / 今天到这 / 明天继续 / 暂停"。
2. 上下文接近预算：按 D8，到 smart zone 的 75% 就主动开削，削不动就收。
3. 一张卡走完、要进下一张卡（收一次，再按下一张卡开工）。
4. 换机器，或隔天继续。
5. 任务已归档，且没有新意图。
6. agent 侧自判：同一条命令连续两次红、或同一个错误第二次出现（C2）时，先收尾再重新开工。

**二、会话收尾四步：证据落盘 → 工作树三选一 → 回写 STATE.md → 需要跨会话时写交接条。四步按序走完。**

**① 证据落盘（压缩前必须先落盘）**：同一条命令的红/绿两次输出，在压缩发生之前写进文件——压缩会把"同一条命令的两次结果"折叠成一条，折叠后再落盘就没有证据了。落点 = 本批知会或 `docs/specs/<日期>_<slug>/VERIFY.md`。
```powershell
$date = Get-Date -Format 'yyyy-MM-dd'
$slug = 'session-close'
"证据落盘 = docs/specs/${date}_$slug/VERIFY.md"
```
Expected：打印一条落盘路径；文件里红/绿两次输出各一段，段前写命令原文。

**② 工作树三选一**：跑 `git status --short`，不干净 → 让用户三选一（现在提交 / 登记 `docs/TECH_DEBT.md` 后搁置 / 丢弃改动），处置完才允许收尾。
❌ 反例：跑出三行改动，回执写"下次一起提交"｜✅ 正例：三行 → 用户选"登记后搁置" → 三行进 `docs/TECH_DEBT.md` 各一条 → 再跑 `git status --short` 已干净。

**③ 回写 `STATE.md`**：`工作树状态` 写"干净"或写清未提交项数；`下一步` 写下一张卡号-名称或"待新意图"；`最近完成` 顶部插入一行（日期 + 一句话 + 提交哈希）。顺序铁律：先回写状态 → 再提交 → 最后复跑 `check.ps1` 取退出码 0。

**④ 写交接条（需要跨会话时）**：见"七"。

**三、该新开会话的触发（四条）：** 上下文接近预算且本卡没走完；换机器；隔天继续；一类工作做完、换另一类。

**四、新会话第一件事（四步，禁止跳过）：**
1. 读 `AGENTS.md` 与 `STATE.md`。
2. 读 `STATE.md` 的 `起点锚点` 与 `最近完成`。
3. 对账：先读锚点，再对 git log。
```powershell
$anchor = (Select-String -Path STATE.md -Pattern '起点锚点').Line -replace '.*?([0-9a-f]{7,40}).*', '$1'
"锚点 = $anchor"
git log --oneline "$anchor..HEAD"
```
Expected：打印 `锚点 = ` 后跟 7~40 位哈希；随后逐行列出该锚点之后的提交。两处不一致以 git log 为准，并当场补 `最近完成` 台账。
4. 需要裁决的动作按"不许从上一会话推断批准"重问一句：用户没在本会话说过 = 没批准（C5）。
❌ 反例："上次会话你已经同意改表结构了，我直接改"｜✅ 正例："上一会话记的是'待你确认改表结构'；本会话还没听你说过，重问一句：改不改？"

**五、该分叉的三分法（每条给负例）：**
1. **互不相关**的独立任务 → 新开会话；只回浓缩摘要的用 `subagent`。❌ 负例：不相关的任务塞进一个会话，上下文互相挤占。
2. **同一契约 / 同一可观察行为 / 同一根因** → 禁止拆片，留在主线程。❌ 负例：同一个契约的实现与验证分给两个子代理，各自只看到一半。
3. 需要**继承当前上下文的一次性分析** → `subagent_fork`。❌ 负例：需要上一会话裁决记录的一次性分析用 `subagent` 派单，等于让它从零猜。

**六、会话归档 ≠ 任务归档：**
- **会话归档只做三件：证据落盘、状态回写、交接条。不新建仓库文档。**
- **任务归档**另有卡走（下一张：5-1 归档）：产物进 `docs/archive/<日期>_<slug>/`，属那个任务的收尾。
- 边界一句话：会话归档收的是"这一轮别丢"，任务归档收的是"这个任务完结"；两者互不代替。
❌ 反例：会话收尾时新建 `docs/SESSION_LOG.md` 记流水｜✅ 正例：证据进 `docs/specs/<日期>_<slug>/VERIFY.md`，指针进交接条，仓库里不多一份文档。

**七、交接条（六字段，写给下一个会话）：** 仓库路径 / 当前卡号 / 起点锚点 / 下一步 / 未决问题 / 要读的文件与行号。
```powershell
$tmp = if ($env:TEMP) { $env:TEMP } else { '/tmp' }
$h = "$tmp/handover_$(Get-Date -Format 'yyyy-MM-dd').md"
"交接条路径 = $h"
Test-Path $h
```
Expected：打印形如 `.../handover_2026-10-05.md` 的路径；写完 `Test-Path` 回 `True`。
- 固定放**系统临时目录**，文件名固定 `handover_<日期>.md`。
- **只放指针不复述**：`STATE.md`、`VERIFY.md` 的正文一律给路径与行号，不复制段落（复述必然漂移）。
- 敏感值脱敏：token / 密码 / 手机号 / 邮箱 / 真实姓名一律写成"见密码管理器 X 条目 / 问用户"。
- **交接完成后删除**该文件：`Remove-Item $h`；字段自查用上面六字段逐个数，缺一个就补。

**八、goal 与 plan 模式的时机：**
- 跨多张卡、跨多个会话的长任务 → 用 goal 持续轮次；**用 goal 时每个里程碑仍要回执**（里程碑回执 = 那一轮的四段照走）。
- ❌ 负例：开了 goal 就连着跑，中途不回执，等全部做完再报。
- 只影响本会话的一次性分析 → 不用 goal（会话内做完就结束，开了只会多一层状态）。
- plan 模式在两处：开工确认里给计划（本卡段 ①）；跨会话的长任务把计划写进 `STATE.md` 的 `未来 3 步`，别只留在对话里。

## ③ 证据回执

逐条给出，缺一条 = 收尾未完成：
1. 收会话触发：命中了六条里的第几条（原文照抄那一条）；未命中就说"本轮不收"。
2. ② 的证据落盘路径 + 同一条命令**红/绿两次输出**原文（红在前）。
3. `git status --short` 真实输出 + 三选一的处置结论；处置后再跑一次的 `git status --short`。
4. `STATE.md` 回写字段逐条：`工作树状态` / `下一步` / `最近完成` 新行原文。
5. 交接条：路径 + `Test-Path` 输出（`True` / `False`）+ 六字段逐条。
6. **「本轮零改动」与「没跑门禁」必须分开说**：零改动的一轮 = `git status --short` 的**空输出** ＋ `powershell -NoProfile -File check.ps1` 的**退出码 0 原文**，两者都给才算"零改动的一轮"；只给前者 = 没跑门禁 = 未完成（常设 DoD 第 ① 条不因"没改动"豁免）。

## ④ 状态回写

更新 `STATE.md`：
- `工作树状态` = 干净（非空 = 这一轮还有改动没落历史，先按 ② 三选一处置）。
- `下一步` = 下一张卡号-名称，或"待新意图"。
- `最近完成` 顶部插入一行：日期 + 一句话 + 提交哈希。
- `未决问题` = 收尾时发现、但本轮不裁决的事项（没有就写"无"）。

顺序铁律：**先回写状态 → 再 `git add` + `git commit` → 最后复跑 `powershell -NoProfile -File check.ps1` 取退出码 0。**

固定收尾语：
`等待你裁决。回复"继续"执行下一张卡，或说新指令。`
