# 卡 5-6 · 版本与变更日志管理
> 触发：要定版本号 / 要写升级注意 / 归档要往"未发布"节追加一行 / 该打 tag 了 ｜ 产物：根 CHANGELOG.md（"未发布"节或正式节）+ docs/versions/vX.Y.Z.md ｜ 下一张：5-7 配置管理与基线（L 档发版前基线先行，两卡同批）→ 5-2 发布（本次要部署时）
> 过程域：REL, CM

---

## ① 开工确认

1. **复述任务（四选一，不混做）**：①给刚归档的改动往"未发布"节追加一行；②把"未发布"整理成正式版本节；③判定这次改动升不升版本、升哪一位；④写本次"升级注意"四行。
2. **假设清单**：你替用户做的 3~5 条默认假设（例："本次只换实现，外部行为不变"），每条带置信度数字与依据（`git diff` 读过哪些文件）。
3. **澄清问题（≤5 个，能省则省；每个自带推荐答案）**：
   - 升到哪个具体版本号？（推荐：按升版判定表算出来的号，如 v0.4.0——不接受"最新"）
   - 外面的人看得出本次差别吗？（推荐：先用 `git diff` 看外部行为面；看不出 → 不升版本）
   - 要不要先发预发布给人试用？（推荐：不发——没有真实试用对象时 rc 只多一层版本号）
   - CHANGELOG 与 `git log` 里查得到的禁止问人。
4. **引用检查清单原文**（逐字粘贴本卡 §② 的"升版判定表"四行与"未发布节四类"）。
5. 并声明：产物落点 = 根 `CHANGELOG.md`（"未发布"节或正式节）+ `docs/versions/vX.Y.Z.md`；下一张卡 = 5-2 发布（本次要部署时）。

## ② 执行

**合理化红旗表（开工逐条念；命中任一行 = 停下，按"事实"列做）**

| 你会想 | 事实 |
| :-- | :-- |
| 现在还 0.x，改动随便来 | 0.x 允许改接口，但破坏性变更照样必写"升级注意"四行；不写 = 拿到新版的人只能自己猜 |
| CHANGELOG 回头一起补 | 每次归档就往四类里追加一行；攒着补 = 那时已想不起行为变化，写出来全是文件名 |
| tag 打错了，删掉重打一个 | 已发布的 tag 不许移动或删除（禁 `git tag -f`）；打错就发新版本号，历史不动 |
| 自己用的项目，版本号记不记无所谓 | 回滚按 tag 退（`git checkout v0.3.0`）；版本链断了，回滚时不知道该退到哪 |
| 只是换了个写法，顺手升一位 | 只换实现、外部行为不变 → 不升版本（改走 7-8 项目重构，不发版） |

**升版判定表（照表判，不凭感觉）**

| 改动长什么样 | 版本号怎么变 | 必做动作 |
| :-- | :-- | :-- |
| 破坏性变更：旧数据 / 旧接口 / 旧配置不能直接用 | 1.x 起升 MAJOR；0.x 阶段升 MINOR | 必写"升级注意"四行 |
| 加能力：新功能 / 新页面 / 新命令 / 新配置项 | 升 MINOR | "未发布"节追加"新增"一行 |
| 修 bug / 改文案 / 改文档 | 升 PATCH | "未发布"节追加"修复"或"变更"一行 |
| 只换实现，外部行为不变 | 不升版本 | 不发版；改走 7-8 项目重构 |

❌ 反例："重构了一遍，顺手发个 v1.0.0"（外部行为没变却升版 = 所有下游白跟一轮）
✅ 正例："导出接口入参 `path` 改名 `filePath`：老调用方会报错 → 0.x 阶段升 MINOR（v0.3.0 → v0.4.0），并在"升级注意"里给替换命令"

**0.x 阶段与 1.0.0 晋升判据**
- 0.x 阶段接口随时可变，但每次破坏性变更仍必写"升级注意"；版本号按上表从 v0.1.0 起递增。
- 进 1.0.0 的两个判据（满足任一即可提名，**由用户裁决**）：①出现第一个真实外部使用者；②你承诺不再破坏（愿意为破坏性变更付 MAJOR 的代价）。
- 判据不满足就留在 0.x；"看着该 1.0 了"不算判据。

**预发布 vX.Y.Z-rc.N**
- 只用于"发给别人试用"；CHANGELOG 单开一节 `## [X.Y.Z-rc.N] - YYYY-MM-DD`，**不进正式版本节**。
- N 从 1 起递增（v0.4.0-rc.1 → v0.4.0-rc.2）；试用通过 → 正式节 `## [0.4.0] - YYYY-MM-DD`；试用有问题 → 修完发下一个 rc，已发出的那一个不动。

**「未发布」节维护（每次归档的固定动作）**
- 往根 `CHANGELOG.md` 的"未发布"节追加一行，四类选一：新增 / 变更 / 废弃 / 修复。
- 一行写"对使用者有什么变化"，不写"改了哪个文件"；只追加，不改写历史条目。
- 发布时才整理成正式节，标题逐字：`## [X.Y.Z] - YYYY-MM-DD` —— **标题不带 v**（v 只出现在 tag 与 `docs/versions/vX.Y.Z.md` 文件名里）。
❌ 反例：`## [v0.4.0] - 2026-10-05`（标题混进 v，与 tag 的口径打架）
✅ 正例：`## [0.4.0] - 2026-10-05`；tag 是 `v0.4.0`；详情文件是 `docs/versions/v0.4.0.md`

**升级注意（迁移说明）四行槽位（四行缺一 = 本次不算完成）**

| 行 | 写什么 |
| :-- | :-- |
| 影响谁 | 哪些使用者 / 哪个环境 / 哪份旧数据或旧配置受影响，列成能对照的清单 |
| 怎么迁移 | 可复制的命令，一行一条，先赋值再调用 |
| 不迁移会怎样 | 具体故障现象（报错原文或数据对不上的表现），不写"可能有问题" |
| 回滚方式 | 退到哪个版本号 + 具体命令 + 数据要不要一起退 |

❌ 反例："升级注意：有破坏性变更，请注意兼容"（四行槽位一行没填，读者无从下手）
✅ 正例："影响谁：调过导出接口的 2 个脚本 ｜ 怎么迁移：`git grep -n 'path=' -- src` 逐处改名 ｜ 不迁移：启动即报 `TypeError: unexpected keyword argument 'path'` ｜ 回滚：`git checkout v0.3.0`，本次无数据结构变更，数据不用退"

**三对齐核对（前两项在打 tag 之前机械判）**

```powershell
$ver = 'v0.4.0'                 # 本次版本号；三处必须一致
$num = $ver.TrimStart('v')      # CHANGELOG 标题用不带 v 的号
Select-String -Path CHANGELOG.md -Pattern ('^## \[' + $num + '\] - ')
Get-ChildItem -Path docs/versions -Filter ($ver + '.md')
```
Expected：两条命令各命中 1 处（节标题 1 行 / 详情文件 1 个）；任一为空 = 三对齐没对上，补齐再往下走。

**打 tag（agent 在发布流程内执行：提交跑绿 + 三对齐前两项通过之后）**

```powershell
$ver = 'v0.4.0'                      # 与上一步同一个号
$topic = '0.4.0 导出接口入参改名'      # 版本主题，一句话
git tag -a $ver -m $topic
git tag -l $ver
git push origin $ver
```
Expected：`git tag -l $ver` 回显 1 行 `v0.4.0`；推送输出里出现 `[new tag]`。
- 用注解式 tag（`-a`）；**已发布的 tag 不许移动或删除**——禁 `git tag -f`，禁 `git push origin --delete`。
- 打错位置的处置：发新号（如 `v0.4.1`）重打一次，旧 tag 留着不动；已推出去的 tag 改不了别人手里的副本。

**版本号的唯一事实源**
- 根清单文件的 `version` 字段是唯一事实源：Node 项目 = `package.json` 的 `version`；Python 项目 = `pyproject.toml` 的 `project.version`。
```powershell
(Get-Content -Path package.json -Raw | ConvertFrom-Json).version
```
Expected：输出的号与 `$num` 逐字相同；不同 = 版本号有第二处副本，先合并成一处。
- 健康检查若返回版本号，读那个字段（或由它生成的常量），不许在响应里再硬编码一份。
- `.tool-versions` 锁的是工具链版本（装哪个 node / python / pnpm），与产品版本**无关**：改它不算升版，也不拿它当版本号来源。

**禁令：**
- 禁止升了版本号却不追加"未发布"节那一行（版本号与 CHANGELOG 同批改）
- 禁止正式节标题带 v（口径见上）
- 禁止移动或删除已发布的 tag（`git tag -f` 与远端删除都不许）
- 禁止用轻量 tag（`git tag $ver` 不带 `-a`）
- 禁止绕过晋升判据自行宣布 1.0.0（由用户裁决）

## ④ 状态回写

**顺序铁律：先回写状态 → 再提交 → 再复跑 check.ps1 取 0 → 跑绿之后再打 tag、推送。**

更新 STATE.md：`最近完成` 加一行（日期 + 版本号 + 提交哈希）；有版本号待裁决的写进 `未决问题` 并附推荐号；`下一步` = 5-2 发布（本次要部署）或待新意图。S 档纯内部改动 = 只追加"未发布"一行即收工；L 档或要给别人用 = 走完 §② 全流程（含打 tag）。

然后提交与复跑（`$ver` / `$num` 沿用 §② 的赋值）：
```powershell
$detail = 'docs/versions/' + $ver + '.md'
git add STATE.md CHANGELOG.md $detail
git commit -m "5-6 docs(version): $ver 版本与变更日志"
powershell -NoProfile -File check.ps1
```
Expected：退出码 0，末行形如「全部通过（退出码 0）：完成声明成立。」；非 0 = 停下修，不许打 tag。
