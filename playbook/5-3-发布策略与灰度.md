5. 并声明：本次版本号（具体号，如 v0.4.0）、放量阶梯各级的计划时长、以及"回滚路径已演练/未演练"的现状。

## ② 执行

**动作 1：四策略选择（先填表，再选一个；空格 = 没选）**

| 策略 | 适用条件 | 回滚代价 | 成本 | 本次选吗 |
| :--- | :--- | :--- | :--- | :-: |
| 大爆炸（停机换版） | 无真实用户 / 内部工具 / 数据不兼容必须一次性切 | 最高（停机 + 数据回不来） | 最低 | 否 |
| 滚动（逐台替换） | 多实例、接口向后兼容 | 中（再滚一轮回去） | 中 | 否 |
| 蓝绿（两套并存切流） | 需要秒级回滚、有双份资源预算 | 最低（切回旧套） | 最高（双份资源） | 否 |
| 金丝雀（按比例放量） | 有流量分层能力、指标可观测 | 低（停放量 + 切回） | 中（需要分流与观测） | **本次默认** |

选择规则：**除非"无真实用户"或"数据不兼容必须一次性切"，默认选金丝雀**；选大爆炸必须在上表"本次选吗"一列写理由。没有流量分层能力 → 用蓝绿或滚动替代，禁止硬做"假金丝雀"（只切了自己看的那个实例）。

**动作 2：放量阶梯（内部 → 1% → 10% → 50% → 100%，五级不可跳）**

| 级 | 放给谁 | 最短停留 | 本级判据（看哪个指标 / 观测多久 / 超阈值怎么办） |
| :-: | :--- | :--- | :--- |
| 内部 | 自己 / 团队账号 | 30 分钟 | 核心路径手工走一遍全通；错一条 → 停止放量，回滚 |
| 1% | 真实流量的 1% | 2 小时 | 错误率 ≤ 基线 ×1.2；延迟 P95 ≤ 基线 ×1.2；超 → 停止放量并回滚 |
| 10% | 真实流量的 10% | 4 小时 | 同上一行阈值；另看核心业务指标（如成功率）不得低于基线 −1% |
| 50% | 真实流量的 50% | 8 小时 | 同上一行阈值 + 最长观测窗内无 P1 事件 |
| 100% | 全量 | —— | 收尾进观测窗（默认 24 小时；观测窗阈值 = 错误率/延迟 > 基线 ×1.5，比本级 ×1.2 宽一档） |

**每一级的停下判据（写死，不许临场发挥）：看哪个指标 → 观测多久 → 超过阈值怎么办。**
- 指标至少三项：错误率 / 延迟 P95 / 一个核心业务指标（用 `docs/OBSERVABILITY.md` 里定义的键名，没有就先建）
- 观测时长 = 上表"最短停留"；不到时长不许进下一级
- 超阈值动作写死两选一：**停止放量（冻结在当前级）** 或 **回滚**；"再观察看看"不是动作
- ❌ 反例："先放 10% 看看，不对就退"（没写看哪个指标、观测多久、超多少算不对 → 出事时靠感觉）
- ✅ 正例："1% 级观测 2 小时；错误率 > 0.5% 或 P95 > 400ms 触发回滚；回滚命令见版本详情"

**动作 3：特性开关与回滚开关（上线前必须存在且可验证）**
每个新功能背后有一个开关（键名进 `.env.example`，值由环境决定），观测前先验证两件事：
```powershell
# ❌ 假绿写法：只改"当前这个 shell"的环境变量 —— 已经在跑的进程读不到，关完行为根本不变
$env:FEATURE_NEW_CHECKOUT = 'false'
# ✅ 真实关闭 = 改配置所在层 + 让它重新加载。按开关所在层三选一：
#   ① 本地 .env：改文件 → 重启进程   ② 平台后台：改配置 → 重新部署   ③ 配置服务下发 → 进程拉取
$url = 'http://127.0.0.1:3000/api/cart/checkout'          # 被开关控制的入口（换成本项目本地地址）
$on  = (Invoke-WebRequest $url -UseBasicParsing).Content  # 开关开：新行为
Copy-Item .env.canary-off .env -Force                     # 关：换配置
powershell -NoProfile -File doctor.ps1                    # 重启前自检：配置读得到
Get-Process node -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Process -FilePath node -ArgumentList 'dist/server.js' -WindowStyle Hidden
Start-Sleep -Seconds 3                                    # 重启方式按项目实际换（容器/平台用平台的重启）
$off = (Invoke-WebRequest $url -UseBasicParsing).Content  # 开关关：旧行为必须复现
"关前 $($on.Length) 字符 / 关后 $($off.Length) 字符；两条响应原文都贴进回执"
```
- 开关必须在上线**之前**就存在，且**关掉 = 回到旧行为**（关掉报错 = 没有回滚开关）
- 判据只能来自**行为观测**：同一条请求在关前/关后的真实响应差异；配置文本、日志里的开关值、"命令没报错"都不算证据
- 回滚开关的默认值、当前值、谁能改，写进 `docs/RUNBOOK.md`
- ❌ 反例："`$env:FEATURE_NEW_CHECKOUT = 'false'` 执行成功了，所以开关能关"（父会话改环境变量，已运行进程读不到 = 假绿）
- ✅ 正例：改配置 → 重启进程 → 同一条请求从新行为回到旧行为，回执贴出关前/关后两条真实响应

**动作 4：回滚路径必须演练过（没演练过的回滚 = 没有回滚）**
上线前真跑一遍回滚（或至少在 staging 全流程演练），记录三件事：命令、结果、耗时。
```powershell
$prevTag = 'v0.3.9'        # 上一个稳定版本号（先赋值，禁止写 vX.Y.(Z-1) 这类占位）
git checkout $prevTag
# 回滚的部署与数据处置按 docs/RUNBOOK.md 「回滚」节执行（口径唯一，以 RUNBOOK 原文为准；本卡只给"取版本"这一步）
```
- 演练记录写进 `docs/versions/vX.Y.Z.md`，照此形状填真实值：`回滚演练：2026-01-01 ｜ 命令 git checkout v0.3.9 ｜ 结果 成功 ｜ 耗时 4 分钟`
- **未演练的回滚禁止上线**（这是本卡红线）；演练失败 = 先修回滚路径再发布

**动作 5：谁在什么信号下喊停（不可委托：回滚与发布由人裁决）**
- 执行 agent 只能"触发停止放量 + 报证据 + 给出建议"，**回滚/继续的最终判定由人做**
- 喊停信号写死成表：`信号（哪个指标到多少）｜谁发现｜谁喊停｜喊停后第一动作`
- 值班/响应人默认 = 用户本人；写进 `docs/RUNBOOK.md` 的发布策略行（含联系方式或通知渠道）
- 单人模式（个人档）：喊停人 = 你本人，跳过值班排班与通知渠道，改为在 STATE.md `裁剪记录` 写一行理由；喊停信号表仍需逐条写出

**动作 6：收尾落档**
`docs/versions/vX.Y.Z.md` 增一节「放量决策与结果」：策略、阶梯每级实际停留时长、每级指标读数、是否触发停止判据、最终结论。`docs/RUNBOOK.md` 增一行：本次策略 + 喊停信号 + 回滚命令位置。

**禁令（违反任一条 = 本轮输出作废）：**
- 禁止跳过放量阶梯直接全量（除非本次就是大爆炸，且理由写进策略表）
- 禁止回滚路径未演练就上线（红线）
- 禁止用"应该不影响"代替指标读数——每级都要贴真实读数
- 禁止 agent 自行决定回滚或继续放量（不可委托，人裁决）
- 禁止发布后立刻收工：全量后必须进 5-4 观测窗
