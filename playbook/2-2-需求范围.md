## ① 开工确认

收到开工指令后，先回执以下四项再动手（缺项不开始）：

1. **任务复述**：用一句人话说清这个功能做什么、给谁用。
2. **假设清单**：你替用户做了哪些默认决定（如"数据存本地""不做并发"），逐条列出。
3. **澄清问题（≤5 个，能省则省）**：只问项目文件里查不到答案的问题。能从 docs/ARCHITECTURE.md、docs/pool/IDEAS.md、SCOPE 惯例自查的，禁止拿来问人。
   ❌ 反例："这个功能重要吗？"（废话，用户既然开工就是重要）
   ✅ 正例："月度统计需要包含已删除的账单吗？"
4. **引用检查清单原文**（逐字粘贴本卡 §② 的"范围合规五查"）。

并声明：产物落点 `docs/specs/<日期>_<slug>/SCOPE.md`，下一张卡 = 2-4 非功能需求（M/L 档）；S 档 → 4-1 分批编码；L 档 2-4 后 → 3-1 设计。

## ② 执行

**动作 1：MoSCoW 四档清单**（写进 SCOPE.md；文件头部先写三行固定字段）
```text
任务名: <功能一句话> ｜ 档位: <S/M/L> ｜ 预估改动行数: <N>
```
`预估改动行数` = 本任务全部批次的新增+删除行数合计（含测试），是 4-1 卡范围蔓延触发线的数据源：累计变更行数 > N × 1.5 → 停下问用户。

| 档 | 含义 | 判定问句 |
| :-- | :-- | :-- |
| Must | 本期必须有 | 不做这个，功能就不成立？ |
| Should | 应该有，缺了能用但难受 | 缓一周再补，用户能忍？ |
| Could | 锦上添花 | 砍掉不心疼？ |
| **Won't** | **本期明确不做** | 用户容易误以为有的，都放这里 |

**动作 2：Won't Have = non-goals（范围蔓延的解药）**
每个 Won't 项写一行"为什么本期不做"。
❌ 反例：Won't: 找回密码（没写原因→两周后 AI 会"顺手"实现它）
✅ 正例：Won't: 找回密码——单人本地应用，无密码体系，随 v1.1 再议

**动作 3：验收标准（可勾选清单）**
每条 = 可观察行为，写"打开哪页 → 做什么 → 应看到什么"。
❌ 反例："统计功能性能良好、体验流畅"
✅ 正例："打开 /export 页 → 勾选 3 条记录 → 点导出，下载 export.md 内含这 3 条"

**动作 4：UI 描述（有界面才写）**
页面级（哪个页面）+ 元素级（按钮/列表/输入框的名字、位置、状态），写到能给组件注册表建行的粒度。

**动作 5：S 档简版**
S 档（≤3 文件 ≤100 行；**单页静态应用特例**：1 个入口页 + 无后端 + 无依赖 → ≤5 文件且 ≤400 行，含三份设计文档）SCOPE.md 只需三节：Must 清单 / Won't 清单 / 验收标准（2 条即可）。

**范围合规五查（本卡收尾前自检，逐条回答原文写进回执）：**

```text
① SCOPE 里每条 Must 都有对应实现计划吗？
② 有没有混进 Could/Won't 的东西？（混进了就删掉或降级）
③ Won't 清单里的，本期绝对不写代码吗？
④ 验收标准每条都是"可观察行为"吗？
⑤ 用户已说过"确认"吗？（把下面这句话发给用户，回复"确认"即可，不需要逐条复述：`请回复：确认 SCOPE，开始写代码`；没确认不许进入 4-1）
```

**禁令：**
- 禁止在用户确认 SCOPE 前写任何业务代码（个人档：用户回一句"确认 SCOPE"即可，不需要逐条复述清单）
- 禁止把"用户没说不要"当成"可以做"——没列入 Must 的都不做
