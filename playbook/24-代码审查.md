## ② 执行

审查按依赖拓扑分三阶段，每阶段跑完全部适用维度并独立给结论：
阶段 1 数据层与后端 → 阶段 2 前端与接口集成 → 阶段 3 测试、配置、脚本、文档同步。
**阶段无 diff 覆盖 → 覆盖地图声明"无变更，跳过"，不算违规**（纯后端项目没有阶段 2 是正常现象）。

**七个固定维度（审查对象 = 新增**与被修改**的代码；被删除的符号要确认全仓库零残留引用。每阶段跑适用的，逐条给结论）：**

1. **接入性与装配**：每个新增/被修改符号有调用点（文件:行）吗？路由/依赖注入注册了吗？**有 UI 时按 SCOPE 的 UI 描述走查三层链路——①路由/挂载注册 ②入口可达（哪个已有界面能点到它？说不出具体入口 = 断）③交互元素绑定了 handler 且链到业务逻辑吗。任一层断 = P1（核心功能不可用），不是 P2**——"功能写好了但用户进不去"就栽在这。前后端项目加查：接口请求/响应结构与 registry/APIS.md 登记的契约一致吗（字段名/层级/类型）？
2. **逻辑性**：空值/越界/并发重复提交/失败路径（不是空 catch）/入参校验，逐个新增与被修改的函数过一遍；**多步写操作（如创建+扣减）有事务边界吗——要么全成要么全败，禁止半完成状态**；异步竞态与写接口幂等（重试/重复提交不产生脏数据）；时区与日期边界、金额精度（禁浮点存钱）。
3. **牵连性**：`grep -rn "<新符号名>" src` 找全调用方；**被修改符号的既有调用方逐个确认行为兼容（签名变了/默认值变了/返回结构变了 → 调用方跟上了吗）**；被删除符号确认零残留引用；核对**四份文档**需同步未同步：registry/APIS.md（接口与错误码一并）、CHANGELOG.md、registry/DATA_DICT.md、docs/TECH_DEBT.md——**任一不存在 → N/A + 原因**（禁止静默跳过或编造"已核对"）。
4. **性能**：六类典型——N+1 查询/无界查询（缺 LIMIT）/循环内 IO/大列表重复渲染/请求路径里的同步长任务/无索引 WHERE；**资源泄漏——未关闭的连接/文件/定时器/事件订阅，前端 effect 未清理**。
5. **冗余死代码**：grep 每个新增与被修改符号的使用次数（与维度 1 共用同一搜索结果，不重复跑）；复制粘贴只改名的块；永远为真/假的分支。疑似保留必须写理由。
6. **开发规范**：命名一致性/注释写 Why 不写 What/类型安全（有无 any）/函数 >50 行、文件 >500 行要提（>1000 必拆；**测试文件豁免至 ≤1000 行**）/提交信息格式；并对照宪法 §11「代码生成硬标准」六条逐一复核（结构/命名/注释 Why/防御/可测试/环境注入）。
7. **安全**：新接口都鉴权了吗（前端隐藏≠后端校验，查水平越权）/SQL 参数化/**XSS——用户输入渲染前转义了吗；CSRF——写操作有 token/SameSite 防护吗**/上传验类型大小/路径防 ../ /密码用强哈希（bcrypt/argon2/scrypt），禁 MD5/SHA1/明文/密钥硬编码/日志脱敏（密码手机号 token）/CORS 非 */debug 关闭/**本次新增依赖查已知漏洞（npm audit / pip-audit 输出）且 lockfile 已提交**。

**四个条件维度（按触发启用；不适用写 N/A + 原因，不许留空）：**
⑧ UI 可访问性（含前端时）：状态齐全/对比度/触摸目标 44px/空态错误态
⑨ 外部调用（新改第三方时）：适配层/显式超时/降级/Webhook 验签+幂等
⑩ 性能预算（热路径改动时）：有预算文件则对照 P95/包体积/查询耗时；**项目无预算文件 → 按维度 4 六类定性判断并标注"无预算基线"**
⑪ 数据隐私（涉个人信息时）：D3/D4 字段加密/日志脱敏/用途限定

**错误码闸**：新增错误码必须能在 `docs/registry/APIS.md` 查到并已登记，给 grep 输出。

**越界检查（违反即红旗）：**
- diff 里出现**语义性**"顺手/顺便优化"（改逻辑/重命名/重构无关代码）→ 建议一律 revert
- **纯机械格式化**（prettier/black 等工具产物）→ 不 revert：说明工具来源，建议拆为独立格式化提交（revert 了 lint 还会要求它，死循环）
- 出现 SCOPE 从未讨论的文件 → 红旗，要求解释

**取代与废弃检查（命中即红灯，直接判建议色 🔴；本卡只审不修，修复回 23）：**
1. **并行实现未删**：本批触及的文件里出现"被取代但未删除"的旧实现（旧文件/旧函数/旧分支/旧常量），且 `STATE.md` 的并行态登记簿无对应登记行 → 红灯。
   登记行格式固定（列名一字不改）：`并行态 | 旧实现 | 新实现 | 删除条件（可判定） | 到期 | 登记批次`。
   有登记行也要核两条：删除条件可判定吗？到期批次是否已过（已过仍未删 → 红灯）？
   合法保留理由只有三种：①灰度/回滚（带期限）②对外兼容契约（带弃用期）③证据留存——**证据留存的答案是 git 历史**，工作树里出现 `.bak`、`旧版/`、`副本 2` 即违规。
2. **废弃标记未申报**：本批**新增行**命中 `_old|_legacy|_v2|Deprecated|暂时保留|废弃|TODO: 删|TODO: remove` 任一 → 必须在报告里写明保留理由与（若有）删除条件，否则红灯。

```powershell
git diff -U0 <起点锚点>..HEAD | Select-String '^\+' | Select-String '_old\b|_legacy|_v2\b|Deprecated|暂时保留|废弃|TODO[:：]\s*(删|remove|delete)'
```
（`<起点锚点>` 从 STATE.md 读；它覆盖整批的全部提交，`HEAD~1` 只看最后一笔会漏。命中行逐条贴进问题清单，每条给出"已申报/未申报"判定。）

**严重级判据（只用这四级，不确定按 P2）：**

| 级 | 含义 | 处置 |
| :-- | :-- | :-- |
| P0 | 崩溃/数据丢失/安全漏洞 | 必须清零，禁止合入 |
| P1 | 核心功能不可用（含装配断链） | 必须清零，禁止合入 |
| P2 | 边缘功能报错/体验不佳 | 登记 `docs/TECH_DEBT.md`（来源=本报告编号），报告内保留编号引用 |
| P3 | 拼写/样式/非关键提示 | 同上，登记台账可延后 |

**建议色矩阵（唯一判色依据）：**
- 🔴 红 = P0≥1 或 P1≥1（**含旧报告未核销的 P0/P1**）或"取代与废弃检查"命中（登记簿缺行 / 废弃标记未申报）
- 🟡 黄 = P0=P1=0，但存在 P2/P3 或有待用户裁决的取舍
- 🟢 绿 = P0=P1=0 且旧报告 P0/P1 全部核销

**禁令：**
- 禁止修改任何代码（本卡只审不修；修复回 23）
- 禁止只给结论不给依据（必须文件:行 + 触发条件）
- 禁止跳过维度或阶段（不适用写 N/A + 原因）
- 禁止自行宣布通过（只给建议色，裁决是人）
- P3 也要列出来，不许"问题太小"省略
- 禁止把"被取代未删除"降级成 P2 放过（它是红灯，只有删除或登记两条路）
- 禁止只看到废弃标记不给判定（每条命中都要写"已申报（理由 X）/未申报=红灯"）
