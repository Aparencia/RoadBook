# 卡 6-7 · 度量与质量报告（每季度或每个里程碑一次）
> 触发：每季度 / 里程碑收尾 ｜ 产物：docs/decisions/QUALITY_<日期>_<主题>.md ｜ 下一张：6-8 决策复盘（决策卡满 5 张 / 里程碑后 / 复核日到期）→ 6-6 流程体检（要调流程时）；无提案 = 5-1 归档
> 过程域：QA

---

## ① 开工确认

1. **人话复述与落点**：把本期（本季度或本里程碑）的质量数据统成一份报告，并给出至少一条流程调整建议；产物 = `docs/decisions/QUALITY_<日期>_<主题>.md`（7 个指标 + 一条流程建议；过程明细可另放 `docs/reviews/QUALITY_<日期>.md`）；下一张卡 = 6-6 流程体检（报告里要动流程时）。
2. **假设清单**：逐条写"我假设 X；若错则 Y 失效"（例："本期发布次数可以从 git tag 数出来"），每条注明验证方式；能从 git log / CI 记录 / STATE.md 查到的不许写进假设。
3. **澄清问题（≤5 个，能删则删）**：默认三问——统计窗口的起止日期？口径与上一份报告是否一致（不一致先说明）？报告给谁看（决定要不要附原始输出）？一个都没有就写"无"。
4. **数据源声明**：先说清 7 个指标各自的采集命令与本期缺口；缺口写 `N/A（理由）`，不许估。
5. **引用本卡检查清单原文**（逐字粘贴 §② 的"报告四查"）：
   - [ ] 7 个指标各有数据来源 + 采集命令 + 本期实测值（缺值写 `N/A（理由）`）
   - [ ] 报告含 ≥1 条流程调整建议（确实没有就写"无调整，依据是…"）
   - [ ] 每个指标附"数字变好但方式不对"的反例警示，全文无个人排名
   - [ ] 报告与 STATE.md 进同一次提交，提交后复跑 check.ps1 取退出码 0
6. **边界声明**：指标是雷达不是 KPI；是否调整流程由用户裁决，agent 只出报告与建议。

## ② 执行

**本卡检查清单（报告四查，逐条勾选）：**
- [ ] 7 个指标各有数据来源 + 采集命令 + 本期实测值（缺值写 `N/A（理由）`）
- [ ] 报告含 ≥1 条流程调整建议（确实没有就写"无调整，依据是…"）
- [ ] 每个指标附"数字变好但方式不对"的反例警示，全文无个人排名
- [ ] 报告与 STATE.md 进同一次提交，提交后复跑 check.ps1 取退出码 0

**动作 1：跑七指标采集表（指标 / 数据来源 / 采集命令）**

1. 部署频率（本期发布了几次）——来源：git tag 与 CHANGELOG.md 的版本索引
```powershell
git for-each-ref --sort=-creatordate --format='%(creatordate:short) %(refname:short)' refs/tags
```
- Expected：每行一个 tag，形如 `2026-10-06 v0.9.1`（创建日期 + tag 名），按创建日期倒序；**一个 tag 都没有 = 空输出**——那"部署频率"写 0 次并写明"无 tag"，不是 N/A。
2. 变更前置时间（从开工到发布用了几天）——来源：STATE.md `起点锚点` 到发布 tag 的距离
```powershell
$anchor = ((Select-String -Path STATE.md -Pattern '起点锚点').Line -replace '.*?([0-9a-f]{7,40}).*', '$1')
if ($anchor -notmatch '^[0-9a-f]{7,40}$') { "锚点为空或非哈希：本指标写 N/A（无锚点，理由…），跳过 git log" } else { git log --date=short --pretty=format:'%h %ad %s' "$anchor..HEAD" }
```
- Expected：逐行形如 `5328309 2026-10-07 4-1 fix(process): …`（短哈希 + 日期 + 提交信息）；锚点读不出时**只**打印那句"锚点为空或非哈希…"，一行提交都不打（本指标写 `N/A（无锚点）`）。
3. 变更失败率（发布后必须回滚或热修的比例）——来源：docs/specs/ 下 INCIDENT.md 份数 ÷ 本期发布次数
```powershell
Get-ChildItem docs/specs -Recurse -Filter INCIDENT.md | Select-Object FullName, LastWriteTime
```
- Expected：一表两列（`FullName` / `LastWriteTime`），每份事故报告一行；**没有 `INCIDENT.md` 时不打印任何行**——此时变更失败率写「0 份 ÷ N 次发布」，别把"本期没出事故"与"命令没跑"混成一句话。
4. 恢复时间（发现到恢复的时长）——来源：每份 INCIDENT.md 的四时点
```powershell
Get-ChildItem docs/specs -Recurse -Filter INCIDENT.md | Select-String -Pattern '发现|止血|恢复'
```
- Expected：逐行 `docs\specs\<任务目录>\INCIDENT.md:<行号>:<含"发现/止血/恢复"的原文>`；无事故报告 = 空输出 → 恢复时间写 `N/A（本期无事故）`。
5. 缺陷逃逸率（发布后才发现的缺陷 ÷ 本期缺陷总数）——来源：docs/specs/ 下 RCA.md（发布后报的）与 docs/reviews/ 下 CODE_*.md（发布前抓到的）
```powershell
Get-ChildItem docs/specs -Recurse -Filter RCA.md | Select-String -Pattern '定级'
Get-ChildItem docs/reviews -Filter 'CODE_*.md' | Select-String -Pattern '建议色'
```
- Expected：第一条逐行 `…\RCA.md:<行号>:<含"定级"的原文>`，第二条逐行 `docs\reviews\CODE_*.md:<行号>:<含"建议色"的原文>`；**两条都可以是空输出**——空 = 本期无样本（分子写 0 并写明），不是 `N/A`。
6. 覆盖率趋势（本期 vs 上一份报告）——来源：项目里已有覆盖率工具时取其命令输出；工作区没有覆盖率工具就写 `N/A（无覆盖率工具，理由…）`，禁止估；趋势对比上一份 QUALITY 报告
```powershell
Get-ChildItem docs/decisions -Filter 'QUALITY_*.md' | Sort-Object Name | Select-Object -Last 3
```
- Expected：最多 3 行（`FullName` 表格）——历史质量报告按文件名排序的末三份；**首期是空输出**（还没有上一份），趋势列写 `N/A（首期，无上期值）`。
7. 门禁绿率与停问热点——来源：docs/reviews/ 下 CODE_*.md 的"建议色"分布；docs/TECH_DEBT.md 的来源列分组
```powershell
Select-String -Path docs/reviews/CODE_*.md -Pattern '建议色' | Select-Object Filename, Line
Select-String -Path docs/TECH_DEBT.md -Pattern '^\|\s*TD-' | ForEach-Object { ($_.Line -split '\|')[4].Trim() } | Group-Object | Where-Object { $_.Count -ge 2 } | Select-Object Count, Name
```
- Expected：第一条逐份审查报告出"建议色"行（`Filename` / `Line` 两列表格），第二条只出跨 ≥2 条债重复的**来源列**取值（`Count` / `Name` 两列）；**两条都可能是空输出 = 本期无样本**——别把"还没有审查报告"读成"绿率 100%"。

**动作 2：写报告 `docs/decisions/QUALITY_<日期>_<主题>.md`**（主落点；过程明细可另放 `docs/reviews/QUALITY_<日期>.md`），固定七节：
1. 窗口与口径（起止日期、与上期口径的差异）
2. 七指标表（指标 / 本期值 / 上期值 / 数据来源 / 采集命令）
3. 异常与解释（哪个数字不对劲，先查口径再下结论）
4. 反例警示（每个指标一句"数字变好但方式不对"）
5. 流程调整建议（≥1 条，落点写到具体文件 + 具体条目）
6. 未采纳项与理由（没有就写"无"）
7. 数据缺口（缺什么、为什么缺、下次怎么补）

**动作 3：节奏**：每季度一次，或每个里程碑收尾时一次；相邻两份报告间隔 > 4 个月 → 在报告第 1 节写明原因。

**动作 4：禁止度量游戏化**
- ❌ 反例："把变更失败率纳入个人绩效排名；为了部署频率好看，把一个改动拆成 5 次发布"
- ✅ 正例："部署频率只用来判断批次大小是否合适；异常只在流程层面找原因（如门禁判据缺失），不评价人"
- ❌ 反例："数字不好看，把口径从'发布后 7 天内的回滚'悄悄改成'发布后 24 小时内'"
- ✅ 正例："口径要变，必须在报告第 1 节写明变更前后定义，并把上期值按新口径重算"
- 无数据的指标：禁止估一个数填上，写 `N/A（理由）`。

**禁令（违反任意一条 = 本轮输出作废）：**
- 禁止只贴数字不给数据来源与采集命令（无法复核的报告 = 没有报告）
- 禁止报告不含任何流程调整建议（写"无调整，依据是…"也要写）
- 禁止把指标当 KPI 排名、禁止为好看改口径而不留痕
- 禁止编造估计值：缺值写 `N/A（理由）`
