# 卡 8-1 · 智能体团队编排（多文件/可并行任务开工前读）
> 触发：一次要改多个文件、任务可切成互不重叠的块、或要跑长命令。 ｜ 产物：任务板回执 + `STATE.md` 并行态登记簿。 ｜ 下一张：回当前档位主线（S→4-1 / M→2-x 或 4-1 / L→3-1；事故线→6-1）。

---

## ① 开工确认

开工先回执，五行以内，缺一行不许动手：

1. 任务复述与落点：改哪几个文件（写全路径）、每个文件归谁。
2. 形态选择：照「动作 1」的表选一个主形态，写出名字（单线程 / subagent / subagent_fork / teammate / workflow / 后台 job）与一句理由。
3. 并行块清单：块名 + 写作用域（文件或目录前缀）+ 依赖关系。
4. 澄清问题（≤5）：写作用域冲突、共享文件归属、验收命令。
5. 声明产物与下一张卡：任务板回执 + `STATE.md` 并行态登记簿。

回执里出现「大概」「应该」「先看看」= 没选形态，退回重写。

---

## ② 执行

### 动作 1 · 选形态（一次任务只选一个主形态）

| 形态 | 什么时候用 | 什么时候不用 |
| :-- | :-- | :-- |
| 单线程 | 只有 1 个文件，或改动互相牵制 | 有 ≥2 个互不依赖的文件（白等） |
| `subagent` | 一次性独立任务：查资料、跑一次审计、写互不相关的报告 | 后面还要追问同一话题（它不记得上一轮） |
| `subagent_fork` | 要它继承当前上下文做后续分析或复核 | 任务与该会话无关（白烧上下文） |
| `teammate` | 持久角色：多轮返工、要收别人回执、要任务板协调 | 一次就完的事（建队成本 > 收益） |
| `workflow` | 同一套流程扇出到很多项（每个文件一次审计、批量迁移） | 项数 <5，或步骤之间有强顺序 |
| 后台 job | 单条长命令（全量测试、构建、装依赖） | 短命令（开 job 比直接跑还慢） |

❌ 用 `teammate` 改一个文件。 ✅ 一个文件自己改。
❌ 为了「显得并行」给 3 个 agent 派同一份报告。 ✅ 每个 agent 一个互不重叠的写作用域。

### 动作 2 · 建队与写作用域（用 `teammate` 时才做）

判据：并发 writer ≤5；一人一个写作用域且不重叠；共享文件（`STATE.md`、`AGENTS.md`、`README.md`、门禁脚本、设计文档）由 Lead 独占，writer 只能提请求。

建队用 `spawn_teammate`，派单与追问用 `send_message`，等人回话用 `wait_agent`，任务板见动作 3。

派单消息必须含五格：任务 id / 目标与验收命令 / 写作用域（路径列表）/ 契约文件路径（规格原文）/ 回执格式。五格缺一 = 该 agent 的输出作废。

写作用域是建议不是锁：两人同时改一个文件，后写的覆盖先写的且不报错——所以派单前把文件列全。

### 动作 3 · 任务板流程（先建后领，领要带版本号）

```powershell
# Lead 建任务：team_task_create（写清验收命令与写作用域）
# writer 领取：team_task_get 取最新 revision → team_task_update(action=claim, expected_revision)
# writer 完成：再取一次最新 revision → team_task_update(action=complete, expected_revision)
# 查板：team_task_list；依赖：blocked_by 登记前置任务 id；ready=false 的任务不许开工
```

❌ 领取时不带 revision（并发下覆盖别人的状态）。 ✅ 每次动作前重取最新 revision。
❌ 依赖只在聊天里口头说。 ✅ 写进任务的 `blocked_by`。

### 动作 4 · 回执（每个任务 ≤10 行，失败也必须回）

固定五格：任务 id / 状态（完成｜阻塞｜失败）/ 改动文件（全路径 + 行数）/ 证据（真实命令输出关键行、提交哈希）/ 阻塞点（一句话 + 需要谁做什么）。回执用 `send_message` 发给派单人。

❌ 没收到回执就派下一个任务。 ✅ 确认「已收到回执」再派下一件。
❌ 把「已发送」当「已收到」。 ✅ 对方回执到了才算送达。
❌ 失败后静默重试。 ✅ 回执写阻塞点，换形态或停下来问。

### 动作 5 · 验收（Lead 亲自做，自报不算）

1. 跑全量门禁：`powershell -NoProfile -File check.ps1`，退出码 0 才算过（粘真实输出）。
2. 抽查 diff：`git diff --stat`，再逐行看至少两个非 Lead 写的文件。
3. 对齐清单：改动文件逐个点名，与派单的写作用域对得上。
4. 任一项不过 → 任务退回给作者改；不替它改。

❌ 相信「我改完了，应该没问题」。 ✅ 门禁输出 + 逐行看过 diff。
❌ 只跑与改动文件相关的检查。 ✅ 全量门禁 + 抽查 diff。

### 动作 6 · 上下文预算与成本

- 每个 teammate 上下文独立；Lead 只保留摘要与回执，不搬原文。
- 一个阶段收尾就压缩一次再开下一块；压缩摘要必含：全路径 + 行号、原文关键句、决策与理由、未完成项。
- 先看 `cost-meter` 读数再定并发：并发越高 token 涨得越快；阶段一完就停掉没活的 teammate。
- 模型选择：机械改写与校验用便宜快模型，设计与裁决用强模型。

### 动作 7 · 反模式（撞上任何一条 = 本阶段返工）

1. 两个 writer 同改一个文件（后写覆盖先写，无报错）。
2. 没收到回执就继续派活。
3. 把「已发送」当「已收到」。
4. Lead 只汇总、不验证（自报当完成）。
5. 用团队干单文件的活（协调成本 > 干活成本）。
6. 共享文件交给 writer 改。
7. 派单消息缺验收命令（做完不知道对不对）。

**禁令（违反任一条 = 本轮输出作废）**

- 不许把写作用域重叠当成「人多力量大」。
- 不许用「我这边过了」代替 Lead 的全量门禁。
- 不许把密钥、凭据写进派单消息或回执。

边界声明：本卡不选档位、不改主线顺序，只在「多文件可并行」时加走。

## ③ 证据回执

只认三种证据：真实命令输出 / 文件路径 / 提交哈希。逐条给：

1. 形态与理由（一行）。
2. 任务板：任务 id + 状态（`team_task_list` 输出关键行）。
3. 每个 writer：写作用域 + 回执五格。
4. 门禁：`check.ps1` 退出码 + 关键输出行。
5. diff 抽查：文件路径 + 看了哪几行。
6. 并行态登记簿：新增或置空的行。

---

## ④ 状态回写

1. 先回写：有新旧实现并存，就在 `STATE.md` 并行态登记簿加一行（并行态 / 旧实现 / 新实现 / 删除条件（可判定）/ 到期 / 登记批次）；本阶段已清掉的并行态同批删除该行。
2. 本卡不改主线指针，除非它改动了主线产物；`STATE.md` 只更新 `最近完成`（滚动 5 条）与并行态登记簿，`下一步` 保持原来那张卡不动。
3. 再提交：`git add -A`，`git commit -m "8-1 chore(team): 智能体团队回执与并行态登记"`。
4. 最后复跑 `powershell -NoProfile -File check.ps1` 取退出码 0。
