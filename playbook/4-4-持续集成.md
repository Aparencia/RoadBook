## ② 执行

**口径唯一铁律（本卡第一判据）：CI 里跑的必须是与 `check.ps1` 完全相同的命令——少一步 = 有东西永远不被检查；多一步 = CI 绿而本地红；改参数 = 两边判的不是同一件事。三者都叫口径漂移，漂移 = 门禁永远假绿（比没有 CI 更糟：你以为它在守）。**

**动作 1：抄出本地口径（对照基准，先做这步再做别的）**
```powershell
$txt = Get-Content check.ps1 -Raw -Encoding UTF8
$steps = [regex]::Match($txt, '(?ms)^\s*\$STEPS\s*=\s*@\((.*?)\)\s*$').Groups[1].Value
$steps -split ',|\r?\n' | ForEach-Object { $_.Trim().Trim("'") } | Where-Object { $_ }
```
Expected：逐行打印 `check.ps1` 的 `$STEPS` 清单（本仓实测 3 行，每行一条命令，可直接抄进回执与 CI 的 `run:`）。
`$steps` 为空 = check.ps1 还没按 1-2 卡接入本项目命令（别猜口径，回 1-2）；非空则把每行原样抄进回执，形成"本地口径清单"。
- ❌ 反例（本机实测）：按行首抓命令的写法 `Select-String -Pattern '^\s*(npm|pnpm|yarn|...)'` → 输出 **0 行**——真实 check.ps1 的命令写在 `$STEPS = @('…')` 里，行首是 `$STEPS`；0 行被当成"本项目没有本地口径"→ 口径对照整步空转，漂移没人发现
- ✅ 正例（本机实测）：`$STEPS = @('pnpm typecheck', 'pnpm lint', 'pnpm test')` 的 check.ps1 → 上面两行正好输出 `pnpm typecheck` / `pnpm lint` / `pnpm test` 三行；逐条抄进回执后 CI 的 `run:` 也正好是这三条

**动作 2：本地先跑通（禁止跳过）**
```powershell
powershell -NoProfile -File check.ps1
```
Expected：退出码必须是 0。**本地跑不通就上 CI = 上 CI 看红，白烧时间**；退出码非 0 先修本地。

**动作 3：最小流水线（只这四步，多一步都要写理由）**

| # | 步骤 | 判据 |
| :-: | :--- | :--- |
| 1 | 装依赖 | 按 lockfile 装（`npm ci` / `pnpm install --frozen-lockfile`），不许在 CI 里升级依赖 |
| 2 | typecheck / lint / test / build | **与 §动作 1 抄出的清单逐条一致**（少一条 = 漂移） |
| 3 | 制品归档 | 产物目录 + 测试报告上传为构建产物（出红时能下载回来看） |
| 4 | 触发与通知 | 触发 = push 到主分支 + PR；失败通知责任人（写进 `docs/RUNBOOK.md` 一行） |

**动作 4：写工作流**
产物路径 `.github/workflows/ci.yml`（用别的托管平台 = 等价文件，路径写进 `docs/RUNBOOK.md`）。
固定工作流骨架（值按项目实况填，每步命令来自动作 1 的清单）：

```yaml
name: ci
on:
  push:
    branches: [main]
  pull_request:
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '22', cache: 'npm' }
      - run: npm ci
      - run: npm run typecheck
      - run: npm run lint
      - run: npm test
      - run: npm run build
```
（最后一个 `build` 步的产物目录接 `actions/upload-artifact` 归档；`check.ps1` 若还跑了别的命令，按动作 1 清单补进来。）

**动作 5：口径对照（机械核对，不靠肉眼印象）**
```powershell
if (Test-Path '.github/workflows/ci.yml') { Select-String -Path .github/workflows/ci.yml -Pattern 'run:' | ForEach-Object { $_.Line.Trim() } } else { Write-Host '本地-only：无 CI 文件，口径对照 N/A（理由已按动作 6 写进 RUNBOOK）' }
```
Expected：有 CI 文件 → 逐行打印 `run:` 开头的行（本仓实测 2 行，且与上面抄出的清单逐条相同）；无 CI 文件 → 正好一行 `本地-only：无 CI 文件，口径对照 N/A`，既不是报错也不是空输出。
把你抄出的"本地口径清单"与这条输出**逐条对齐**：多一条 / 少一条 / 参数不同 → 当场改到一致。对照结果贴进 §③ 回执；本地-only 分支 → 对照表三栏全写 `N/A（本地-only）` + 附动作 6 的 RUNBOOK 行原文。

**动作 6：RUNBOOK 登记（两种结局都要写，不许沉默）**
- 引入托管 CI → 在 `docs/RUNBOOK.md` 写三行：CI 文件路径 / 触发条件 / 失败通知谁。
- 不引入（本地-only）→ 在 `docs/RUNBOOK.md` 显式写一行，理由换成真实原因：`CI：本地-only（已裁剪）＋理由：单人项目、尚无远端仓库，改由每次提交前手跑 check.ps1 兜底`。**不写 = 沉默省略，本卡判不合格。**

**动作 7：CI 三查 + 发布面两查（提交前逐条查，任一红 = 不许提交）**
- ① 第三方 action 必须 pin 到 **commit SHA**：❌ `uses: actions/checkout@v4` / `uses: actions/checkout@main`（标签会被上游移动：实测 `refs/tags/v4` 已指向 v4.4.0 的提交，等于把执行权交给别人）｜✅ `uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683`（v4.2.2 的 40 位 commit SHA）；动作 4 骨架里的 `@v4` 是待替换形态，取 SHA 用 `git ls-remote https://github.com/actions/checkout refs/tags/v4.2.2`
- ② 工作流 `permissions:` 最小化：默认 `contents: read`；❌ 不写 `permissions:`（拿仓库默认的最大权限）/ ❌ `permissions: write-all`｜✅ 顶层写 `permissions: contents: read`，确实要写权限的那个 job 再单独升权
- ③ 禁止在 PR / issue 触发的工作流里跑不可信代码：❌ 同一文件里 `on: pull_request_target` + 引用 `secrets.` + 检出 PR 代码（`ref: ${{ github.event.pull_request.head.sha }}`）三者同现 = 红（fork 的 PR 代码拿着你的 secrets 跑）｜✅ 用 `on: pull_request`（拿不到 secrets），或 `pull_request_target` 只做只读打标、不检出 PR 代码、不引用 secrets
- ④ secret 扫描**只拦新增（基线差分）**：存量密钥留在历史里本轮不动，**新增即红**——只看本次改动引入的行，不扫全量历史。❌ 全量扫描报出几百条历史命中就整批放过（新增那条被一起淹掉，等于没扫）｜✅ diff 命中 0 条才算过；命中 → 停下、作废重来并轮换凭据（删掉文件不算处置）
- ⑤ 构建上下文夹带：发布/镜像清单（`.dockerignore` / `.npmignore` / `package.json` 的 `files` 字段）必须排除 `.env`、凭据文件（`*.pem` / `*.key` / `credentials.json`）与测试夹具——包与镜像一旦发布即可被永久下载。❌ 只写了 `.gitignore` 就当发布清单也干净（npm / docker 各有自己的清单，互不继承）｜✅ 发布清单零命中 `.env` / `.pem` / `fixtures`，且 `.dockerignore` 有对应排除行
```powershell
Select-String -Path .github/workflows/*.yml -Pattern 'uses:\s+\S+@(?![0-9a-f]{40})'                      # ① 命中 = 有 action 没 pin 到 40 位 SHA
Select-String -Path .github/workflows/*.yml -Pattern 'permissions:'                                      # ② 无输出 = 没写 permissions，红
Select-String -Path .github/workflows/*.yml -Pattern 'pull_request_target|head\.sha|secrets\.'           # ③ 同一文件三条同现 = 红
$anchor = (Select-String -Path STATE.md -Pattern '起点锚点\s*[:：]\s*([0-9a-fA-F]{7,40})').Matches[0].Groups[1].Value; git diff "$anchor..HEAD" | Select-String -Pattern 'AKIA[0-9A-Z]{16}|ghp_[A-Za-z0-9]{36}|BEGIN [A-Z ]*PRIVATE KEY'   # ④ 只扫本次新增，命中 0 才算过
npm pack --dry-run 2>&1 | Select-String -Pattern '\.env|\.pem|\.key|\.p12|credentials|fixtures|__tests__'  # ⑤ 命中 = 发布包夹带，红
```
Expected：① 无输出（有未 pin 到 40 位 SHA 的 action = 红）｜② 至少一行（本仓实测 `ci.yml:16:permissions:`；无输出 = 红）｜③ 三条字符串不同现于同一个文件（同现 = 红）｜④ 命中 0 条（只看本次新增）｜⑤ 命中 0 条 —— **本仓实测不是 0**（2 行：一份测试夹具 + 随包的 `.env.example`），先按台账 `docs/TECH_DEBT.md` 登记再提交。

**禁令（违反任一条 = 本轮输出作废）：**
- 禁止 `continue-on-error: true`，禁止 `|| true`，禁止把任何检查步骤标成"允许失败"（= 红也不拦，等于没跑）
- 禁止"CI 里多跑一步保险"或"这一步本地跑就行"——两边命令必须逐条一致
- 禁止缓存与并行改变判据：缓存只能省时间（键必须含 lockfile 哈希），并行只能省时间（分片要保证全部命令都跑到）；**省掉的检查 = 漂移**
- 禁止把密钥写进工作流文件；密钥只进 CI secrets（键名与 `.env.example` 对齐），工作流里只引用变量名
- 禁止跳过"本地先跑通"直接开 PR（本地红 = CI 必红）

**边界（与 5-2 发布流水线不重叠）**：本卡管**提交后验证**（一件事：代码能不能过门禁）；5-2 发布管**出制品与上线**（版本、tag、部署、回滚）。CI 通过 ≠ 可以发布。
