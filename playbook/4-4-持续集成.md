## ② 执行

**口径唯一铁律（本卡第一判据）：CI 里跑的必须是与 `check.ps1` 完全相同的命令——少一步 = 有东西永远不被检查；多一步 = CI 绿而本地红；改参数 = 两边判的不是同一件事。三者都叫口径漂移，漂移 = 门禁永远假绿（比没有 CI 更糟：你以为它在守）。**

**动作 1：抄出本地口径（对照基准，先做这步再做别的）**
```powershell
Get-Content check.ps1 | Select-String -Pattern '^\s*(npm|pnpm|yarn|npx|node|python|pytest|dotnet|powershell|\./)' 
```
把上面命中的每一行原样抄进本卡回执，形成"本地口径清单"。
- ❌ 反例：本地 `check.ps1` 跑了 typecheck/lint/test/build，CI 里只跑 `npm test`（少三步 → 类型错和 lint 错永远进不了主干）
- ✅ 正例：抄出的清单是 `npm run typecheck` / `npm run lint` / `npm test` / `npm run build` 四行，后面每一步都对得上这四行

**动作 2：本地先跑通（禁止跳过）**
```powershell
powershell -NoProfile -File check.ps1
```
退出码必须是 0。**本地跑不通就上 CI = 上 CI 看红，白烧时间**；退出码非 0 先修本地。

**动作 3：最小流水线（只这四步，多一步都要写理由）**

| # | 步骤 | 判据 |
| :-: | :--- | :--- |
| 1 | 装依赖 | 按 lockfile 装（`npm ci` / `pnpm install --frozen-lockfile`），不许在 CI 里升级依赖 |
| 2 | typecheck / lint / test / build | **与 §动作 1 抄出的清单逐条一致**（少一条 = 漂移） |
| 3 | 制品归档 | 产物目录 + 测试报告上传为构建产物（出红时能下载回来看） |
| 4 | 触发与通知 | 触发 = push 到主分支 + PR；失败通知责任人（写进 `docs/RUNBOOK.md` 一行） |

**动作 4：写工作流**
产物路径 `.github/workflows/ci.yml`（用别的托管平台 = 等价文件，路径写进 `docs/RUNBOOK.md`）。
固定工作流骨架（值按项目实况填，每步命令来自动作 1 的清单）：

```yaml
name: ci
on:
  push:
    branches: [main]
  pull_request:
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '22', cache: 'npm' }
      - run: npm ci
      - run: npm run typecheck
      - run: npm run lint
      - run: npm test
      - run: npm run build
```
（最后一个 `build` 步的产物目录接 `actions/upload-artifact` 归档；`check.ps1` 若还跑了别的命令，按动作 1 清单补进来。）

**动作 5：口径对照（机械核对，不靠肉眼印象）**
```powershell
Select-String -Path .github/workflows/ci.yml -Pattern 'run:' | ForEach-Object { $_.Line.Trim() }
```
把你抄出的"本地口径清单"与这条输出**逐条对齐**：多一条 / 少一条 / 参数不同 → 当场改到一致。对照结果贴进 §③ 回执。

**动作 6：RUNBOOK 登记（两种结局都要写，不许沉默）**
- 引入托管 CI → 在 `docs/RUNBOOK.md` 写三行：CI 文件路径 / 触发条件 / 失败通知谁。
- 不引入（本地-only）→ 在 `docs/RUNBOOK.md` 显式写一行，理由换成真实原因：`CI：本地-only（已裁剪）＋理由：单人项目、尚无远端仓库，改由每次提交前手跑 check.ps1 兜底`。**不写 = 沉默省略，本卡判不合格。**

**禁令（违反任一条 = 本轮输出作废）：**
- 禁止 `continue-on-error: true`，禁止 `|| true`，禁止把任何检查步骤标成"允许失败"（= 红也不拦，等于没跑）
- 禁止"CI 里多跑一步保险"或"这一步本地跑就行"——两边命令必须逐条一致
- 禁止缓存与并行改变判据：缓存只能省时间（键必须含 lockfile 哈希），并行只能省时间（分片要保证全部命令都跑到）；**省掉的检查 = 漂移**
- 禁止把密钥写进工作流文件；密钥只进 CI secrets（键名与 `.env.example` 对齐），工作流里只引用变量名
- 禁止跳过"本地先跑通"直接开 PR（本地红 = CI 必红）

**边界（与 5-2 发布流水线不重叠）**：本卡管**提交后验证**（一件事：代码能不能过门禁）；5-2 发布管**出制品与上线**（版本、tag、部署、回滚）。CI 通过 ≠ 可以发布。
