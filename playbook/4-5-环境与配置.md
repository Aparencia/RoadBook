## ② 执行

**动作 1：环境分层表（三行必须填满，空格 = 没写）**

| 环境 | 用途 | 数据来源 | 谁能碰 | 可否直连生产数据 |
| :--- | :--- | :--- | :--- | :--- |
| dev | 本地开发与调试 | 本地生成 / 种子数据 | 开发者本人 | 否 |
| staging | 上线前全量验证 | 脱敏副本或合成数据 | 开发者 + 审核者 | 否（需用户书面批准才可读只读生产快照） |
| prod | 真实用户使用 | 真实数据 | 仅用户授权者；agent 只读日志与指标 | —— |

**动作 2：staging 与 prod 同构（差异逐条显式登记，差异不写 = 隐患）**
同构 = 同一套分支/构建方式、同一种数据库引擎与主版本、同一组环境变量键名、同一套部署方式。做不到同构的每一条，按下表登记：

| 差异点 | 影响 | 是否接受（理由） |
| :--- | :--- | :--- |
| 例：staging 用 SQLite、prod 用 PostgreSQL | 迁移脚本在 staging 绿、prod 红 | 不接受 → 本次改为同引擎 |
| 例：staging 单实例、prod 双实例 | 并发类缺陷测不出 | 接受（理由：同时长跑两台成本不划算，改为上线后观测窗兜底） |

- ❌ 反例："staging 差不多就行"（差异不写 → 上线时才发现某条 SQL 只在 prod 报错，返工半天以上）
- ✅ 正例：差异表两行都填了影响与结论；"不接受"的项当场改掉，"接受"的项写明兜底手段

**动作 3：配置与密钥矩阵（逐键一行，缺一行 = 漏一个键）**

| 键名 | 默认值 | 来源（各环境） | 敏感度 |
| :--- | :--- | :--- | :--- |
| `DATABASE_URL` | 无（必须显式给） | dev: `.env` ｜ staging/prod: 平台后台 | D3 |
| `LOG_LEVEL` | `info` | 各环境 `.env` 或平台后台 | D1 |
| 例：第三方 `API_KEY` | 无 | 仅平台后台密钥库；轮换周期 90 天 | D4 |

敏感度分级固定四级：**D1 公开**（可进仓库）｜**D2 内部**（可进仓库，但不含个人信息）｜**D3 敏感**（只进 `.env` / 平台后台，禁止进仓库与日志）｜**D4 机密**（D3 待遇 + 加密存放 + 定期轮换 + 泄露即作废）。拿不准就按高一级处理。

**动作 4：`.env.example` 是唯一键名清单（同批更新，不许事后补）**
本次新增任何一个配置键 → **同一批**加进 `.env.example`（只写键名 + 一行注释 + 示例值形状，绝不写真实值），并同步进动作 3 的矩阵。
```powershell
Select-String -Path .env.example -Pattern '^[A-Z]' | ForEach-Object { $_.Line.Split('=')[0] }   # 现有键名清单
```
- ❌ 反例：代码里 `process.env.NEW_KEY` 用了，`.env.example` 没加 → 下一个人 clone 下来必跑不起来
- ✅ 正例：加键的同一批提交里 `.env.example` 有该行，且 `docs/RUNBOOK.md` 的键含义表有解释

**动作 5：数据隔离铁律（无例外）**
- **dev/test 数据严禁写入 prod**：任何从 dev/staging 指向 prod 的连接串、迁移脚本、种子脚本，一律禁止（发现即停下报红灯）
- 从 prod 拉数据到 staging：先脱敏（D3/D4 字段打码），并记录"谁批准的、从哪张表拉的"
- `git check-ignore -v .env` 必须有输出（= 已被忽略）；`git status --porcelain` 里若出现 `.env` = 停下报红灯

**动作 6：环境切换步骤（可复制一行，不许现场发挥）**
```powershell
# 以 Node 项目为例：切换环境 = 换 .env 文件 + 重跑 doctor 自检
Copy-Item .env.staging .env -Force
powershell -NoProfile -File doctor.ps1
```
每次切换都跑 `doctor.ps1`（版本/工具/键名不符会点名）；切完把"当前环境"写进 `STATE.md` 的 `未决问题` 或回执，别留在脑子里。

**动作 7：回滚需要哪些配置项（先列出来，出事时才有得改）**
写出"回滚时必须一起还原"的配置键清单（典型：特性开关、限额阈值、外部依赖指向、日志级别），并给出一行命令：
```powershell
Copy-Item .env.rollback .env -Force
powershell -NoProfile -File doctor.ps1
```

**动作 8：RUNBOOK 回写**
`docs/RUNBOOK.md` 新增/更新「环境与配置」节：环境分层表、staging 差异表、键含义表（键 / 含义 / 示例值三列，含本次新增全部键）、切换步骤、回滚配置清单。

**禁令（违反任一条 = 本轮输出作废）：**
- 禁止把真实密钥/真实连接串写进任何进仓库的文件（含注释、示例、日志）
- 禁止新增配置键却不更新 `.env.example`（键名清单只有一处，就是它）
- 禁止把 dev/test 数据写进 prod，或用 prod 数据当本地测试数据
- 禁止用"我本地是好的"解释环境问题——逐条对照差异表，没登记的先登记
- 禁止 agent 自行在生产环境执行写操作（发布/迁移/改数据属不可委托，人执行）
