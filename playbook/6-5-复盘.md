# 卡 6-5 · 复盘
> 触发：P0/P1 事故或大返工之后（日常小坑不触发，写教训卡就够） ｜ 产物：复盘文档 + 预防措施落地 ｜ 下一张：5-1 归档
> 过程域：KNOW, QA

---

## ① 开工确认

1. **事故复述**：什么坏了/影响是什么/怎么恢复的（从 STATE.md 与对话记录引用）。
2. **假设清单**：你替用户做的 3~5 条默认假设（例："损失可在 git 历史里复原""事故未触碰红线域"），每条注明验证方式。
3. **澄清问题（≤5 个，能省则省）**：默认三问——事故起止时间？谁是止损决策人？本次要不要同时改宪法？对话与 commit 里查得到的禁止问人。
4. **材料清单预告**：将收集时间线（对话/commit/RUNBOOK）。
5. **引用检查清单原文**（逐字粘贴本卡 §② 的"复盘三问"问题 1~3 的标题）。
6. 并声明：产物落点 `docs/lessons/<日期>_<事故名>.md` + 预防措施落点；下一张卡是 5-1（归档）。预防措施里的规则改动由你裁决，agent 只起草。

---

## ② 执行

**复盘三问：**

**问题 1：时间线——损失是怎么滚大的？**
逐时点列：发生 → 首次发现 → 止血 → 根因修复 → 复盘。标出两个时刻：损失最小的止损点在哪、实际止损点在哪，差值就是流程改进空间。

**问题 2：根因——≥3 层，不许停在"粗心/大意"**
❌ 反例："根因：没备份就执行了 SQL（下次注意）"——"下次注意"不是机制
✅ 正例："没备份 → 备份步骤在 RUNBOOK §3 但从未演练 → 复盘卡 6-5 只在 P0 后触发，而备份演练无人触发 → 预防：5-1 归档卡增加'备份演练超 30 天则提醒'检查项"

**问题 3：预防措施——必须落到具体文件+具体改动**
每个措施回答"它会被谁、在哪一步、强制执行"。落点三类（都必须是本项目工作区里够得到的文件）：
- 宪法 `AGENTS.md` 加禁令/检查项
- `docs/TECH_DEBT.md` 登记一条：流程卡修订建议（写明卡号与建议改法，标注"带回母版执行"——流程卡在母版工作区，本项目会话够不到，禁止在本项目里假装改卡）
- `docs/RUNBOOK.md` 流程补操作步骤；若只是想法、暂时不想立规矩 → `docs/pool/IDEAS.md` 登记
❌ 反例："复盘结论：改进某张流程卡的检查步骤"（本项目工作区没有那张卡，等于没有落点，agent 会越界去改母版）
✅ 正例："登记 `docs/TECH_DEBT.md`：流程卡建议——5-1 归档卡增加'备份演练超 30 天提醒'（带回母版执行）"
❌ 反例："以后操作前先备份"（无落点、无强制、无人执行 = 空话）
✅ 正例："宪法 §4 不可委托清单增加一条：任何 SQL 执行前必须先跑 RUNBOOK §3 备份命令并回执输出"

**动作：**
1. 复盘文档存 `docs/lessons/<日期>_<事故名>.md`（时间线+根因链+措施，超 12 行可拆两卡：现象卡+机制卡）
2. 预防措施逐条**当场起草**目标文件的修改草案（改动 = 修改规则，人确认后 agent 执行）
3. 提交排在 §④：与状态回写、复盘产物同一次提交；本段不提交

**禁令：**
- 禁止措施写"加强意识/下次注意/更小心"（一律打回重写）
- 禁止复盘完不改任何文件（没有落点的复盘 = 没有复盘）
- 禁止把责任归因于人（归因于机制：哪道检查缺失让人容易犯错）
