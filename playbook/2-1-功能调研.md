## ① 开工确认

收到开工指令后，先回执以下六项再动手（缺项不开始）：

1. **任务复述**：用一句人话说清要做什么功能。
2. **上游引用 + 假设清单**：docs/pool/IDEAS.md 里有无此想法（有 → 贴行号）；docs/ARCHITECTURE.md 里本次改动的落点约束；默认假设逐条列（如"导出格式 CSV 与 Markdown 都要支持"）。
3. **澄清问题（≤5 个）**：ARCHITECTURE / registry / IDEAS 查得到答案的禁止问人。
   ❌ 反例："用什么技术实现比较好？"（这是本卡要回答的）
   ✅ 正例："导出功能需要支持 Excel 吗，还是 Markdown 就够？"
4. **引用检查清单原文**（逐字粘贴本卡 §② 的"调研合规四查"+"新依赖三查"）。
5. **路径预判（先判后问）**：在问第一个澄清问题之前，先宣布本次按 <S/M/L> 处理，判据一句话；并补一行"本次要改的流程在仓库里已经可读吗：是/否"。判错或你不同意 → 现在改判，改完再问。

6. **可分解性先判（先拆再问）**：本次意图里若有 ≥2 个互不依赖的子系统（各有独立入口与数据），先列出子项目清单与建议顺序，本卡只研究第一个；每个子项目各自走一轮 2-1→…→4-1。拆不动就写一句"我判断它不可拆，依据是 …"。

并声明：产物落点 `docs/specs/<日期>_<slug>/RESEARCH.md`；方案与档位都由用户裁决。

## ② 执行

**动作 0：建任务工作区**
```powershell
$spec = 'docs/specs/2026-09-12_export'   # 换成 今天日期_功能slug（先赋值再调用）
New-Item -ItemType Directory -Force $spec | Out-Null
```
Expected：0 行输出（`| Out-Null` 吞掉新建项对象）、`$?` = True；**`$LASTEXITCODE` 保持空**——cmdlet 不设它（本机实测空串），所以"退出码那一栏是空的"不是失败信号，判成败只能看 `$?` 或 `Test-Path $spec`。目录已存在时重跑同样 0 行、不报错（`-Force` 幂等）。卡面里的 `2026-09-12_export` 是示例值，`$spec` 要换成 今天日期_功能slug。
日期用今天（YYYY-MM-DD），slug = 功能英文短词（如 `2026-09-12_export`）。

**动作 1：读三处上游（先查再动手，防平行新建）**
- `docs/pool/IDEAS.md`：想法已在池中 → 引用原行，禁止另起炉灶
- `docs/ARCHITECTURE.md`：本次改动落在哪层、有什么约束
- `docs/registry/` 三件套：有无现成组件/表/接口可复用
❌ 反例：没查 registry → 新建了一个与 `PrimaryButton` 重复的按钮
✅ 正例：回执"registry 查过：无现成导出组件，需新建，落点 src/lib/export.ts"

**动作 2：方案对比 ≥2 个完整方案 + 1 个被否案**
每案四列：改动面（估文件数）/ 新依赖 / 风险 / 工作量（估行数或人日），末列一句话结论。
被否案必须写出具体否决理由：
❌ 反例："方案 C：用 WebSocket——不考虑"（陪跑，无理由）
✅ 正例："方案 C（被否）：WebSocket 实时同步——单人本地应用无第二客户端，且引入常驻服务进程，改动面 ×3"

**动作 2.5：拒绝台账（被否案留痕；同一提案不许不带台账重开一轮）**
每个被否的方案留一行：`日期 | 提案 | 否决理由 | 既往请求编号`，写进 `docs/decisions/` 对应文件或 `docs/pool/IDEAS.md` 的"已否"段。
同一个提案第二次出现时**先读台账**，把上次的否决理由原文贴出来再讨论；禁止不带台账重新论证一遍。
❌ 反例：只写"这个方案不考虑"就完事
✅ 正例："2026-10-04 否掉 X：与本项目单机离线约束冲突（既往请求 #3）"

**动作 3：新依赖三查（引入任何包之前逐条过）**

```text
① registry 三件套与 ARCHITECTURE 里已有近似能力吗？（有 → 复用，禁止平行新建）
② 包真实存在吗？（打开 npm/PyPI 包页面核实：贴链接 + 最近发布时间/周下载量）
③ 官方文档链接给了吗？（只给博客/教程链接 = 不合格）
```
❌ 反例："装个 left-pad 处理补零"（未验证包是否还维护）
✅ 正例："date-fns（npm 官方页：https://www.npmjs.com/package/date-fns ，最近发布 <日期>）"

**动作 4：影响面初判**（用 `git grep`：只搜已跟踪文件，自动排除 node_modules 与 .git）
```powershell
git grep -n "相关符号名"     # 把"相关符号名"换成真实符号；无命中就写"未找到引用"
```
Expected：命中打 `<文件>:<行号>:<整行>` 三段（本机实测真符号 `chunkBoundary` 打 9 行、退出码 0）——那个行号就是回去改代码的位置；**零命中 = 一个字符都不打 + 退出码 1**（实测），这才是"未找到引用"的形态，别当成命令坏了。⚠️ 占位符原样跑会**命中卡面自己**：实测 `git grep -n "相关符号名"` 打 2 行、退出码 0，命中的正是中英两张卡的第 65 行 ⇒ 不换成真符号这条就是假绿。另：`git grep` 只搜**已跟踪**文件，未跟踪与被 ignore 的看不见。
列出预计触碰的文件 + registry 中受影响的行（有则贴行）。

**动作 5：档位提议（判据表内联；只升不降，拿不准按高一级提；中途发现隐藏复杂度（新依赖 / 跨模块 / 破坏性表结构）→ 立即停下声明升档，不许闷头做完再补）**

| 档 | 判据（满足任一即入该档） |
| :-- | :-- |
| S | ≤3 文件且 ≤100 行，无新依赖、无表结构、无新页面；**单页静态应用特例**：1 个入口页 + 无后端 + 无依赖 → 放宽到 ≤5 文件且 ≤400 行（含 3-4/3-5/3-6 三份设计文档）；命中任一**红线域**（认证/鉴权、支付/计费、删除真实数据、改表结构、新增对外接口）→ **不得判 S** |
| M | 普通功能：限 1~2 个模块内，不新增外部包、无破坏性表结构 |
| L | 引入新依赖 / 跨模块 / 破坏性表结构 / 新页面体系 → **3-1 设计 + 5-2 发布强制**；触碰**红线域**（认证/鉴权、支付/计费、删除真实数据、改表结构、新增对外接口）→ **判 L，且必须走 3-2 威胁建模**；第三方技能 / 插件 / MCP server 的引入按「引入新依赖」计入本档，并必须先走 7-9 准入（结论由用户裁决） |

❌ 反例：M 档含新依赖 = 错判（写"可能新增 1 个低风险依赖"就是误判；有依赖一律归 L）
❌ 反例：跨 3 个模块、还要改表结构，仍判 M（L 判据满足任一即入；拿不准按高一级提）
✅ 正例：给已有页面加导出按钮，改 2 个文件约 60 行、不新增外部包 → M
❌ 反例：只加一个登录按钮、改 3 个文件 → 判 S（文件数不是判据：触碰认证即红线域）
✅ 正例：同样 3 个文件但触碰认证 → 判 L 并走 3-2 威胁建模

给出建议档位 + 依据，停下等用户确认。

**动作 6：S 档提示**
建议为 S 时在 RESEARCH.md 末尾写一行：`S 档简版链：2-2（简版）→ 4-1 → 4-3 → 5-1`。

**调研合规四查（收尾前自检，逐条回答）：**

```text
① 每个方案都齐了改动面/依赖/风险/工作量四列吗？
② 被否案写出具体否决理由了吗（不是陪跑）？
③ 新增依赖全过了"新依赖三查"吗？
④ 档位建议是按判据表给的吗？
```

**禁令：**
- 禁止跳过读 ARCHITECTURE / registry 直接出方案
- 禁止推荐未验证存在的包（记忆里的包名 = 编造）
- 禁止自行定档、自行定方案（只建议 + 依据，裁决是人）
