## ② 执行

**动作 1：观测三件套（最小可观测，缺一件 = 出事只能猜）**

| # | 件 | 要回答的问题 | 落点（写具体路径） | 已就绪吗 |
| :-: | :--- | :--- | :--- | :-: |
| 1 | 健康检查端点 | 现在活着吗 | 例：`GET /health` 返回 200 与版本号 | 是/否 |
| 2 | 结构化错误日志 | 刚才那次失败为什么失败 | 例：`logs/app.jsonl`（或平台日志面板），每行含时间/级别/请求 ID/错误原文 | 是/否 |
| 3 | 核心业务指标 | 业务在正常运转吗 | 例：登录成功率、下单成功率；落点写出来 | 是/否 |

- **没有监控不等于不需要监控**：给不出某项 → 在 `docs/OBSERVABILITY.md` 写 `N/A（理由：本地-only 项目，无托管监控平台，暂以日志文件代替）`，并在 `STATE.md` 的 `未决问题` 里留一条；**留空 = 本卡判不合格**（留空是"没想过"，`N/A + 理由` 是"想过且认账"）
- ❌ 反例：只写"有日志"（出事后要 grep 半天才知道哪个文件）
- ✅ 正例：三件的落点都是可直接打开/可直接执行的路径或命令，回执里贴一次真实读数

**动作 2：告警阈值与通知对象（四要素缺一不可）**

| 监控项 | 阈值（超了才响） | 通知对象（人 / 渠道） | 多久响应 |
| :--- | :--- | :--- | :--- |
| 健康检查失败 | 连续 3 次探测失败 | 例：用户本人（邮箱/IM） | 15 分钟内看 |
| 错误率 | > 上一版本基线 ×1.5 | 例：用户本人 | 30 分钟内看 |
| 延迟 P95 | > 基线 ×1.5 | 例：用户本人 | 4 小时内看 |
| 核心业务指标 | 比基线低 20% | 例：用户本人 | 4 小时内看 |

- **必须写"谁收"**：告警发到一个没人看的群 = 没有告警；通知对象默认 = 用户本人
- 阈值必须带数字与比较基准（基线是哪一版、什么时候测的）；写不出基线 → 写"以本次观测窗首日读数为基线"，并注明是估的
- 响应时限写死：不写 = 收到也可以不看
- **两档阈值的关系（先紧后松，故意的）**：发布期阈值 = 放量阶梯每级用的 ×1.2（快速止损线）；全量放完 24 小时起进入**观测窗阈值** ×1.5（本动作的阈值，宽一档、防稳态误报）——别把 ×1.5 当成发布期的闸门，也别在观测窗里用 ×1.2 天天误报
- 单人模式（个人档）：通知对象固定 = 你本人，不必搭渠道矩阵；在 STATE.md `裁剪记录` 写一行理由（通知到本人 = 响应到位）

**动作 3：发布后观测窗（时长 / 看什么 / 巡检节奏 / 异常即回滚的判据）**
- **时长**：默认 24 小时（L 档或高风险发布 ≥48 小时）；写进版本详情
- **看什么**：动作 1 三件套 + 动作 2 四条阈值，逐条对着看，不许只看"页面能不能打开"
- **巡检节奏**：每 4 小时一次，每次记一行读数（时间 / 三项指标读数 / 结论）；发现异常 → 立刻按下方判据处理
- **异常即回滚的判据（写死，不许临场判断）**：健康检查连续失败 3 次 ｜ 错误率 > 基线 ×1.5 且持续 10 分钟 ｜ 核心业务指标比基线低 20% 且持续 30 分钟 → 触发回滚（回滚命令位置写进 `docs/RUNBOOK.md`；回滚本身是人裁决，agent 只报证据并建议）
- **不可委托**：观测窗收尾判定、是否回滚 = 人裁决；agent 负责按节奏巡检并如实报读数
- ❌ 反例："发布完盯了十分钟没炸，收工"（十分钟 ≈ 没观测；多数失败在真实流量下才暴露）
- ✅ 正例：观测窗内每次巡检都留下时间 + 读数 + 结论，收尾时给出"窗口内无异常"或"某时刻触发了哪条判据"

**动作 4：SLI/SLO 最小定义（三项，各给一个数字）**

| 指标 | 定义（怎么量） | 目标（具体数字） | 测量方法（可复制的一条） |
| :--- | :--- | :--- | :--- |
| 可用性 | 健康检查成功次数 ÷ 总探测次数 | 如 99.5%/月 | 例：`curl -s -o NUL -w "%{http_code}" http://localhost:3000/health` |
| 延迟 | P95 响应时间 | 如 ≤400ms | 例：日志里取 `duration_ms` 排序取 P95 |
| 错误率 | 5xx 次数 ÷ 总请求次数 | 如 ≤0.5% | 例：`Select-String -Path logs/app.jsonl -Pattern '"status":5' \| Measure-Object` |

- 目标数字必须是**可测阈值**（一个数），不是"尽量低"；测量方法必须写成能直接复制执行的命令或查询
- 达不到 99.9% 就老实写 99.5%，**写不到做不到的数字比不写更糟**（以后所有判定都会拿假目标当尺子）

**动作 5：日志与指标保留期（出事要翻得到）**
写清日志与指标各自保留多久（默认：日志 ≥30 天、指标 ≥90 天），以及超期后还能不能翻到（归档到哪）；出事后复盘要翻到当时的读数，保留期不够 = 复盘无据。

**动作 6：衔接（三条线写明白）**
- **5-2 发布收尾**：观测窗无异常才算本次发布收尾；有异常 → 回滚或转 6-1 事件响应
- **6-1 事件响应**：超阈值且影响用户 → 按 `docs/RUNBOOK.md`「出事先看哪」走，先止血再定位
- **6-7 度量**：观测窗的读数（部署频率 / 变更失败率 / 恢复时间）本身就是度量原料，收尾时把读数交出去，别丢

**动作 7：落档**
`docs/OBSERVABILITY.md`（三件套 + 阈值表 + SLI/SLO 表 + 保留期）；`docs/RUNBOOK.md`「观测与告警」节写阈值与告警去向（明细指向 `docs/OBSERVABILITY.md`）；「出事先看哪」节补上：先看哪个面板/文件 → 三条最常见的处置动作 → 回滚命令位置。

**禁令（违反任一条 = 本轮输出作废）：**
- 禁止把没落点的观测写进文档（"有监控"不算，要写清面板/文件路径或可执行命令）
- 禁止留空观测项：给不出就写 `N/A + 理由`
- 禁止编造读数——每次巡检的读数要么贴真实输出，要么写"未采到 + 原因"
- 禁止 agent 自行宣布观测窗通过或自行回滚（人裁决）
- 禁止把密钥/令牌/用户个人信息写进观测文档或日志示例
