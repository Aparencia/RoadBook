## ① 开工确认

1. **人话复述与落点**：把项目写成"别人照着能打开、能问、能接手"的一份文档；产物 = `docs/USER_GUIDE.md`（六节，含交接清单六列）；下一张卡 = 5-1 归档。
2. **假设清单**：逐条写"我假设 X；若错则 Y 失效"（例："接手人用的也是 Windows"，每条注明验证方式）；能从项目根 `README.md` 的启动 3 步 / 文档地图查到的不许写进假设。
3. **澄清问题（≤5 个，能删则删）**：默认三问——交付对象是谁（自己用 / 同事接手 / 外部客户）？谁是接管人（决定交接清单联系人列）？几号要做完交接（决定到期时间）？一个都没有就写"无"。
4. **引用本卡检查清单原文**（逐字粘贴 §② 的"交付五查"）：
   - [ ] 快速上手 ≤3 步，每步是不可再分的动作，全部用用户词写
   - [ ] 常见问题 ≥5 条，每条附真实来源（工单 / 技术债行号），按出现次数排序
   - [ ] 术语表两列齐全（用户词 ↔ 程序词），程序词与注册表"人话标识"列同源
   - [ ] 交接清单六列（账号 / 密钥 / 环境 / 待办 / 联系人 / 到期时间）无空格，密钥只写存放位置不写值
   - [ ] 接手人在自己机器上按快速上手跑通，文档与代码同批提交
5. **边界声明**：交接确认由用户裁决；账号与密钥的实际移交由人执行，agent 只出清单与证据。

## ② 执行

**本卡检查清单（交付五查，逐条勾选）：**
- [ ] 快速上手 ≤3 步，每步是不可再分的动作，全部用用户词写
- [ ] 常见问题 ≥5 条，每条附真实来源（工单 / 技术债行号），按出现次数排序
- [ ] 术语表两列齐全（用户词 ↔ 程序词），程序词与注册表"人话标识"列同源
- [ ] 交接清单六列（账号 / 密钥 / 环境 / 待办 / 联系人 / 到期时间）无空格，密钥只写存放位置不写值
- [ ] 接手人在自己机器上按快速上手跑通，文档与代码同批提交

**动作 1：快速上手（≤3 步，用户视角）**
- 一步 = 一个不可再分的动作；禁用"环境变量""依赖""迁移""部署"这类词。
- ❌ 反例："先 clone 仓库，装 Node，跑 npm i，配好 .env，执行迁移，再 npm run dev"
- ✅ 正例："① 照项目根 README.md 的启动 3 步做第 1 步 ② 看到"可以开始用了"③ 打不开就看常见问题第 1 条"

**动作 2：常见问题（≥5 条，每条附真实来源）**
```powershell
Get-ChildItem docs/specs -Recurse -Filter INCIDENT.md | Select-String -Pattern '现象|一句话'
Select-String -Path docs/TECH_DEBT.md -Pattern '^\|\s*TD-'
```
- 每条写四行：现象（用户原话）→ 原因（一句人话）→ 怎么办（可复制命令或点哪里）→ 来源（文件名 + 行号）。
- ❌ 反例："可能网络问题，重试即可"（没有来源、没有可执行动作）
- ✅ 正例："打不开页面｜端口被占用｜换项目根 README.md 的启动 3 步里的备用端口命令｜来源：docs/TECH_DEBT.md:12"
- 命中同一现象的工单 ≥2 条 → 排在前面，并在来源列标出现次数。

**动作 3：术语表（用户词 ↔ 程序词）**
```powershell
Select-String -Path docs/registry/COMPONENTS.md -Pattern '人话标识'
```
- 两列，程序词必须与注册表"人话标识"列同源，不许另造一套说法。
- ❌ 反例："订单状态机"（用户搜不到）｜✅ 正例："还没发货 ↔ 待发货状态"

**动作 4：交接清单（六列，缺一列 = 未完成）**

| 账号 | 密钥 | 环境 | 待办 | 联系人 | 到期时间 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 谁的系统账号、在哪登录 | 只写"在密码管理器 X 的 Y 条目" | 装什么、跑什么命令 | 未完成的事 | 出事找谁 | 每项一个日期 |

- 密钥行只写存放位置与接管人，**禁止写任何值**（真实密钥 = 红线，立即停下问用户）。
- 待办行没有到期时间去问用户要，不许留空。
- ❌ 反例："服务器密码：abc123"｜✅ 正例："服务器登录：密码管理器『项目 X』条目，接管人 @小李，到期 2026-11-01"

**动作 5：漂移检查（文档与代码同批更新）**
- 每份文档头部写"最近核对：<日期> @ <提交哈希>"；界面或命令变了没同步 → 登记 `docs/TECH_DEBT.md`。
- ❌ 反例："文档早就写好了"｜✅ 正例："USER_GUIDE 最近核对 2026-10-01 @ a1b2c3d；界面改了没跟上 → 登记 TD-013，到期 2026-10-20"

**动作 6：接手人独立跑通（确认由人做）**
- 把"快速上手 + 失败怎么办"交给接手人，在他自己机器上从零走一遍；agent 只准备命令与记录表。
- 跑不通 → 停下来问用户（同错二次即停），禁止替接手人操作。

**动作 7：写 `docs/USER_GUIDE.md`（六节，一份就够）**
- 六节：这是什么 / 快速上手 3 步 / 常见问题 / 术语表 / 交接清单（六列）/ 最近核对（日期 + 提交哈希）。
- 前四节面向"用的人"，交接清单一节面向"接的人"；同一事实只写一处，别处给路径。
- ❌ 反例：把交接清单另抄成一份文档（同一事实两处维护，必然漂移）｜✅ 正例：交接清单就是 `docs/USER_GUIDE.md` 的"交接清单"节，六列齐全、密钥只写位置

**禁令（违反任意一条 = 本轮输出作废）：**
- 禁止用户文档里出现程序员词（依赖 / 环境变量 / 迁移 / 部署）
- 禁止 FAQ 无来源（编造的问答 = 幻觉）
- 禁止在交接清单写密钥或密码的值，禁止无到期时间的待办
- 禁止只改代码不回写文档（漂移不登记 = 判红）
- 禁止 agent 宣布"交接完成"：确认只能由人做
