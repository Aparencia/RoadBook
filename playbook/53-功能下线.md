## ① 开工确认

1. **下线对象复述**：下线哪个功能/接口/页面（从用户原话引用），涉及哪些用户可见的东西。
2. **影响面预告**：将 grep 核对"被谁调用"，先回执清单再动手。
3. **数据处置问题（必须问）**：相关数据是保留（导出后删）、只隐藏入口、还是彻底删？——人拍板后才动手。
4. **引用检查清单原文**（逐字粘贴"下线四步"）。

---

## ② 执行

**下线四步：**

**第 1 步 影响面盘点（先看后删）**
```powershell
grep -rn "<接口路径/组件名/表名>" src
```
列出：接口被哪些前端调用 / 组件被哪些页面引用 / 表被哪些代码读写。有遗漏 = 删除后炸别处。
❌ 反例：只删了页面文件，接口还挂着 → 变成没人用的裸接口（安全面）
✅ 正例：前端入口、后端接口、表、错误码、文档五行一起列，逐项划掉

**第 2 步 先通告后删除**（有真实用户才需要；记录到 docs/RUNBOOK.md §1）
- 给出下线通告文案草案（什么时候下线/替代方案是什么/数据怎么领回）。
- 通告期结束前不动手。

**第 3 步 数据处置（按用户拍板执行）**
- 保留导出：给导出命令草案，**人执行**导出并确认文件存在后才进删除。
- 彻底删表/删列：属于破坏性变更，agent 只生成迁移草案，**人执行 SQL**（宪法不可委托）。

**第 4 步 删除与同步**
- 删代码 → `git add <精确文件>` + `git commit -m "feat(<slug>): remove <功能名>"`
- 同步清理：`docs/registry/APIS.md`（删行或标注 503 负向契约）/ `COMPONENTS.md` / `DATA_DICT.md` 对应行
- 根 `CHANGELOG.md` "废弃"节追加一行（含替代方案与数据领取方式）

**禁令：**
- 禁止"先删再说"——影响面没核对完不许动第一行代码
- 禁止替用户决定数据处置方式
- 禁止删除共用组件/工具函数（先确认无他人引用）
