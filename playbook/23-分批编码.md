# 卡 23 · 分批编码（全档必走；批级知会 + 需求级 gate）
> 触发：21 需求范围获用户确认后（L 档先过 22 设计）｜ 产物：代码 + 分批提交 ｜ 下一张：24 代码审查（S 档 → 25）

## ① 开工确认

收到开工指令后，先回执以下七项再动手：

1. **任务复述**：本次实现 SCOPE 的哪些 Must 项（逐条列出）。
2. **起点锚点声明**：执行 `git rev-parse HEAD` 并原样回显哈希（这行哈希是审查 diff 和回滚的基准）。
3. **分批计划**：把 Must 项切成批次，每批 ≤300 行或 1 个 Must 项，列表回执。**并行判定**（按任务量机械判定，不许临场发挥）：预估总改动 ≥500 行 且 能按 Files 域切出 ≥2 个互斥单元（每单元 ≥150 行）且 每单元有独立可验证判据 → 提出并行派单方案（分几片/各片 Files/各片判据）等用户一次性确认；不满足任一条 → 串行。
4. **引用检查清单原文**（逐字粘贴本卡 §② 的"每批必念五查" + "条件触发暂停清单"）。
5. **声明生成标准**：本次所有生成代码对照宪法 §11「代码生成硬标准」逐条自检——结构（≤500 行/**测试文件豁免至 ≤1000 行**/纯逻辑与副作用分离/依赖显式传入）、命名（业务术语一致/入参出参有类型契约/禁 any）、注释写 Why、防御（外部调用有超时和失败分支/禁空 catch）、核心逻辑纯函数、禁硬编码配置。
6. **教训检索（JIT）**：`grep -l "<本任务涉及模块/关键词>" docs/lessons/`（无该目录则声明"无历史教训"），命中则回执卡名+要点一行——这些是本模块的已知雷区，写代码时逐条对照。
7. **基线记账（净增量账本的 0 点）**：回执三个基线数字——`git rev-parse --short HEAD` 的短哈希、`(git ls-files).Count` 的文件数、`git diff --numstat` 输出为空（工作树干净）。基线不干净 → 先问用户怎么办，不许在脏树上开账。

并声明：**本需求执行期间采用"批级知会、需求级 gate"**——每批结束发一行进度知会，不等回复继续下一批；全需求完成后进 24 审查做一次裁决。中途仅在触发"条件触发暂停清单"任一条时停下。

## ② 执行

**第 0 步（禁止跳过）：记录起点锚点**

```powershell
git rev-parse HEAD
```

把输出的哈希写入 STATE.md 的 `起点锚点` 字段。丢了它 = 24 卡无法审 diff、出问题无法精确回滚。

**动作 1：写代码，按批次推进（并行车道见附则）**
- 每批只做计划里的一个批次。
- 落点规则：新文件放哪，先查 `docs/ARCHITECTURE.md` 的"新代码落点表"；要新建组件/模块，先查 `docs/registry/` 三件套——**已有近似物就复用，禁止平行新建**。
  ❌ 反例：找不到旧按钮组件 → 新建 `Button2.tsx`
  ✅ 正例：搜到 `PrimaryButton` 复用之；确实不适用 → 在回执里写"为何不用已有组件"再新建

**每批必念五查（念完，结果写进本批知会）：**

```text
① 只动了 SCOPE 涉及的文件吗？（git status 逐文件核对）
② 有没有顺手改了 SCOPE 外的东西？（发现了就还原，想修就登记 TECH_DEBT）
③ 新建的每个文件，都说明了"为何不能用已有文件"吗？
④ 依赖有变化吗？lockfile 变了要单独说明（禁止未请求的依赖升级）
⑤ 碰到 Won't Have 清单里的功能了吗？（碰到就停，那是越界）
```

**动作 2：每批提交 + 进度知会**
提交前：本批若触碰 UI/表/接口 → **当场更新 registry 对应行（COMPONENTS/DATA_DICT/APIS），随本批一起提交**。回写随批走——在上下文最新鲜时干最需要记忆的活，禁止攒到归档时凭回忆追赶。

```powershell
git add <本批精确文件列表>
git commit -m "feat(<slug>): <本批做了什么>"
```

提交后发一行**进度知会**（批号 + 五查结果摘要 + registry 回写情况），**不等回复，继续下一批**。

提交前后跑**机械门禁**（零 token 检查，替代人工逐条核对五查的①④）：

```powershell
powershell -File gate.ps1 -Anchor <起点哈希> -ScopeFiles "本批文件1","本批文件2"
```

红（exit 1）→ 停下修；黄（lockfile/行数）→ 随知会转述给用户。

**动作 3：净增量账本（每批提交后当场算，禁止攒到收尾凭回忆补）**
五个数字一次报全：**新增文件数 / 删除文件数 / 新增行 / 删除行 / 净行数**（净行数 = 新增行 − 删除行），并贴命令真实输出。

```powershell
$stat = git diff --numstat <起点锚点>..HEAD -- .; $add=0;$del=0;$nf=0;$bin=0
foreach ($l in $stat) { $p = $l -split "`t"; if ($p[0] -eq '-') { $bin++; continue }; $add += [int]$p[0]; $del += [int]$p[1]; $nf++ }
"文件 $nf（二进制 $bin）｜新增 $add 行｜删除 $del 行｜净 $($add-$del) 行"
if ($del -eq 0 -and $add -gt 50) { "红灯：改存量批次删除行为 0" }
$ns = git diff --name-status <起点锚点>..HEAD -- .; "新增文件 $(($ns | Where-Object { $_ -like 'A*' }).Count)｜删除文件 $(($ns | Where-Object { $_ -like 'D*' }).Count)"
```

红灯判据（内联，不许解释性豁免）：**改存量批次"删除行 = 0 且新增行 > 50" → 红灯**，停下补删再提交；纯新建文件批次豁免，但回执必须写一句"本批为纯新增"。命令里的 `<起点锚点>` 从 STATE.md 读：`<起点锚点>..HEAD` 覆盖本批全部提交；只看 `HEAD~1` 会漏掉前面几笔，等于伪造账本。

**动作 4：取代即删除 + 并行态登记簿**
规则一句话：**新实现落地的那一批，必须删掉被取代的旧实现**（旧文件/旧函数/旧分支/旧常量一起走）。
做不到（灰度/回滚/兼容契约）→ 必须在 `STATE.md` 的"并行态登记簿"里登记，列固定：
`并行态 | 旧实现 | 新实现 | 删除条件（可判定） | 到期 | 登记批次`
只有三种合法保留理由（没有第四种，其余一律删除）：
① **灰度/回滚** —— 必须带期限（到哪个批次、什么条件到期）
② **对外兼容契约** —— 必须带弃用期
③ **证据留存** —— 答案是 git 历史，工作树不许留第二份（同时禁止 `.bak`、`旧版/`、`副本 2`）
❌ 反例：新建 `xxx_v2.ts` 实现一遍，旧 `xxx.ts` 留着"以防万一"
✅ 正例：同批删旧 + 回执贴删除行证据 + 并行态登记簿无新增行

**动作 5：文件登记与膨胀（新增文件不是可选项）**
新增任何文件（含脚本/文档/测试）→ 必须在本批内于 `docs/registry/COMPONENTS.md` 登记 `路径 + 用途 + 归属批次`，随本批提交。
回执必须贴 `powershell -File orphans.ps1` 的汇总行（格式：`孤儿 X 项｜零引用导出 Y 项｜文档幽灵 Z 项｜反向幽灵 W 项｜未登记 V 项｜文件数 N`）。
红灯：本批新增文件 > 20 个 → 停下先合并，或说明为什么必须拆这么多（说明写进本批知会）。

**条件触发暂停清单（出现任一条，立即停下等用户，禁止"做完这批再说"）：**
- 触碰红线域（认证 / 支付 / 删除数据）
- 停问规则触发（同一错误第二次出现）
- 累计变更行数超过 SCOPE 预估 ×1.5（范围蔓延的量化信号）
- 需要新增依赖或修改共享配置
- 触及 Won't Have 清单（越界）

**禁令：**
- 禁止 `git add -A` / `git add .`
- 禁止升依赖、改全局配置、动宪法（AGENTS.md）
- 禁止"顺手重构"——看到别处有问题，登记 `docs/TECH_DEBT.md`，不许顺手修
- 禁止跳过条件触发暂停（"就快写完了"不是理由）
- 禁止新实现落地却把被取代的旧实现留在树里（未登记进并行态登记簿 = 违规）
- 禁止在工作树里留第二份证据副本（`.bak`、`旧版/`、`副本 2`；证据在 git 历史里）

**并行车道附则（① 第 3 项判定通过且用户确认派单后才可开）：**
- 每单元开 **git worktree**（独立目录独立分支）各自实施+提交；**多单元直写同一工作树 = 禁止**（防互踩，评估过不采纳）
- 共享文件（registry / STATE / 宪法 / CHANGELOG）**只由主 agent 写**——单元发现需要改共享文件 → 停下报主 agent
- 主 agent 依序合并各单元分支，冲突 → STOP 问人；全部合并后走 24（一次审全部）
