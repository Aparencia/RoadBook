# 卡 6-1 · 事件响应（线上故障必走；止血优先于根因）
> 触发：线上故障 / 用户报障 / 监控告警 ｜ 产物：docs/specs/<日期>_<slug>/INCIDENT.md ｜ 下一张：6-2 根因分析

---

## ① 开工确认

收到故障报告后，先回执以下六项：

1. **人话复述与落点**：哪条线上功能坏了、谁受影响（一句话）；产物 = `docs/specs/<日期>_<slug>/INCIDENT.md`；下一张卡 = 6-2 根因分析（本卡不查根因）。
2. **假设清单**：逐条写"我假设 X；若错则 Y 失效"——能从 STATE.md / docs/RUNBOOK.md / git log 查到的不许写进假设，先去查。
3. **澄清问题（≤5 个，能删则删）**：默认三问——影响面（谁受影响、大概多少用户）？最近一次发布或改动是什么（时间+内容）？谁有权拍板回滚（人名或角色）？一个都没有就写"无"。
4. **定级依据预告**：会按本卡定级判据落 P0/P1/P2，并写明命中的是哪一条；不确定从 P2 起，15 分钟内定稿。
5. **引用本卡检查清单原文**（逐字粘贴 §② 的"事件响应五查清单"）：
   - [ ] 定级：P0/P1/P2 已按判据落定，并写明命中的条件
   - [ ] 止血：回滚/降级/关开关/限流已完成，恢复证据已回执
   - [ ] 四时点（发生/发现/止血/恢复）已写进 INCIDENT.md，时间精确到分钟
   - [ ] 通告已按一句话模板发出，对象与内容已留底
   - [ ] 已转 6-2 根因分析；P0/P1 已标注触发 6-5 复盘
6. **边界声明**：定级与止血手段由用户裁决；agent 只做取证与起草，回滚、改数据、删数据必须人执行。

## ② 执行

**本卡检查清单（事件响应五查清单，逐条勾选）：**
- [ ] 定级：P0/P1/P2 已按判据落定，并写明命中的条件
- [ ] 止血：回滚/降级/关开关/限流已完成，恢复证据已回执
- [ ] 四时点（发生/发现/止血/恢复）已写进 INCIDENT.md，时间精确到分钟
- [ ] 通告已按一句话模板发出，对象与内容已留底
- [ ] 已转 6-2 根因分析；P0/P1 已标注触发 6-5 复盘

**动作 1：定级（判据内联）**
- P0 = 全站不可用 / 数据损坏或丢失 / 安全漏洞被利用
- P1 = 核心功能不可用（登录、下单、支付等主路径走不通）
- P2 = 局部降级（非核心页面报错、性能下降、个别用户受影响）
- ❌ 反例："感觉挺严重的，按 P0 处理吧"（没有判据，无法复核）
- ✅ 正例："全部用户登录接口返回 500 → 命中 P1（核心功能不可用）"
- 定级只给建议，最终级别由用户裁决；级别中途升降必须写进 INCIDENT.md（谁在几点改的）。

**动作 2：止血优先于根因（先恢复，再查）**
- 手段四选一或并用：回滚到上一个可用版本、降级（关掉非核心功能）、关特性开关、限流。
- 读本项目写好的回滚步骤：
```powershell
Select-String -Path docs/RUNBOOK.md -Pattern '回滚' -Context 0,12
```
- ❌ 反例："先定位报错原因，找到根因再决定要不要回滚"（故障每多一分钟，用户多损失一分钟）
- ✅ 正例："先按 docs/RUNBOOK.md 的回滚节恢复服务，恢复后再进 6-2 查根因"
- 本卡禁止查根因、禁止改代码、禁止边止血边重构。

**动作 3：时间线留痕四时点**
- 四时点各写"日期 时:分 + 来源"：发生（第一条异常日志或告警的时间）、发现（人第一次看到的时间）、止血（恢复动作开始的时间）、恢复（服务可用的确认时间）。
- ❌ 反例："下午坏的，傍晚恢复了"（算不出故障时长，复盘没有基线）
- ✅ 正例："发生 2026-10-03 14:20（告警 CH-1187）；发现 14:31；止血 14:38；恢复 14:47"
- 时间不许凭记忆写：取监控、日志、聊天记录原话。

**动作 4：通告**
- 对象三类：受影响用户、项目负责人、对外渠道（客服或群公告）。
- 一句话模板：`谁受影响 + 现在什么状态 + 下一步`。
- ❌ 反例："系统有点问题，正在处理"（没说影响谁、什么时候好）
- ✅ 正例："14:20 起全部用户无法登录；已回滚到上一版本，14:47 起登录恢复；正在定位原因，今天 17:00 前给结论。"
- 每条通告留底：时间 + 对象 + 原文，写进 INCIDENT.md。

**动作 5：写 `docs/specs/<日期>_<slug>/INCIDENT.md`**
六节：现象 / 时点表 / 定级与依据 / 止血动作与结果 / 通告留底 / 影响面（受影响用户、数据损失、对外承诺）。路径里的 `<slug>` 与 STATE.md 的 `当前任务` 用同一个，不许一处叫故障名一处叫 slug。

**动作 6：转 6-2**
止血且服务稳定后立即转 6-2 根因分析，把 INCIDENT.md 路径带过去；P0/P1 必须在 STATE.md 标注"触发 6-5 复盘"。

**禁令（违反任意一条 = 本轮输出作废）：**
- 禁止 agent 执行回滚、修改数据、删除数据（不可委托：只能人执行，agent 出草案与证据）
- 禁止在止血前做根因定位或改代码
- 禁止无时间戳的时点、禁止凭记忆写时间
- 禁止 P0 未通告就进入下一步
- 禁止对用户淡化影响面（"小问题"不是级别）
