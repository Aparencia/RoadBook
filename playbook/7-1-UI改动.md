# 卡 7-1 · UI 改动

## ① 开工确认

1. **元素定位回执**：把用户的人话描述翻译成"哪个页面/哪个元素"，用 ❌✅ 标准帮用户说清楚：
   ❌ 反例："首页那个东西不好看"（agent 无法定位，必须追问）
   ✅ 正例："首页顶部的搜索按钮，白底圆角，文字 Search → 我想改成图标+文字"
2. **假设清单**：你替用户做的 3~5 条默认假设（例："这是共用组件""只改样式不动布局"），每条注明验证方式。
3. **澄清问题（≤5 个，能省则省）**：默认三问——改到什么程度（只改文案还是连样式一起）？共用组件波及的其他页面要不要一起改？要不要截图留底？注册表与代码里查得到的禁止问人。
4. **查 `docs/registry/COMPONENTS.md`**：用"人话标识"列找目标组件，回执找到的行（或"没找到，将反查"）。
5. **引用检查清单原文**（逐字粘贴本卡 §② 的"UI 改动四步"）。
6. 并声明：产物落点 = 代码改动 + `docs/registry/COMPONENTS.md` 回写行；下一张卡是 5-1（归档）。

## ② 执行

**UI 改动四步：**

**第 1 步 定位组件**
- 注册表有 → 直接用文件与搜索词。
- 注册表没有 → 反查路径按序试：
  1. 浏览器 F12 → 选中元素 → 看 class/id/组件根元素名
  2. 框架 devtools 组件树 → 组件名（告诉用户怎么开：F12 → Components/Vue 面板）
  3. 界面文案全仓库搜：
```powershell
$text = 'Search'        # 界面上的文字，逐个试
Select-String -Path src -Recurse -Pattern $text | Select-Object Path, LineNumber, Line
```
   - ❌ 反例：`grep -rn "<界面上的文字>" src`（bash 专用命令 + 占位符，Windows 上直接报错）
   - ✅ 正例：上面那条 `Select-String -Path src -Recurse -Pattern $text`（PowerShell 5.1 可跑）
- **定位成功立刻建注册表行**（下次 3 秒找到），哪怕本次不改这个组件的卡。

**第 2 步 改前状态确认**
- 用文字或截图描述"现在的样子"+影响面（注册表"影响面"列：谁还引用它、改样式会不会两处同变）。
- 用户确认后动手。共用组件改外观 = 影响多个页面，必须明示。

**第 3 步 改动**
- 遵守宪法"禁平行新建"：能用现有组件的属性/变体解决就不新建。
- 提交动作放 §④（先回写状态再提交）；本步只把改动与注册表行准备好，并确认没有顺手改到别的组件。

**第 4 步 回写与验收**
- **回写注册表**：程序名变了改行，影响面变了更新列，"最近确认"填今天。
- 给验收描述："打开哪页 → 应看到什么"（一行）。

**禁令：**
- 禁止只改代码不回写注册表（下次又是"那个东西在哪"的轮回）
- 禁止改共用组件而不报告波及页面
- 禁止引入新 UI 库/设计体系（那是 L 档立项）

## ④ 状态回写

**顺序铁律：先回写状态 → 再提交 → 再复跑 check.ps1 取 0。**

先回写注册表与 STATE.md：
- `docs/registry/COMPONENTS.md`：程序名变了改行，影响面变了更新列，"最近确认"填今天
- STATE.md：`当前任务` 清空（S 档小改动）或保留；`下一步` = 5-1 归档
- ❌ 反例：改完代码不回写注册表就提交（下次又是"那个东西在哪"的轮回）
- ✅ 正例：注册表行与代码改动进同一次提交，回执贴"改前 → 改后"两行

然后提交与复跑：
```powershell
$page = 'home'; $what = 'search-button'
git add STATE.md docs/registry/COMPONENTS.md src/components/SearchBox.tsx
git commit -m "7-1 style($page): $what 改为图标加文字"
powershell -NoProfile -File check.ps1
```
（§③ 的验收描述写成"打开哪页 → 应看到什么"，请用户目检确认后再进 5-1 归档。）

固定收尾语：
`等待你裁决。回复"继续"执行下一张卡，或说新指令。`
