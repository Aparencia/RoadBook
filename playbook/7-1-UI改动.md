## ② 执行

**合理化红旗表（开工时逐条念；出现任一条 = 停下按本卡补做）**

| 你会想 | 事实 |
| :-- | :-- |
| 就改一个颜色，不用查令牌 | 写死颜色 = 第二套设计体系；改完必须能在 `docs/DESIGN_TOKENS.md` 里找到同名令牌 |
| 顺手把圆角/字体一起统一了 | 顺手改 = 越界；只动 SCOPE 里的元素，其他改动另开一张卡 |
| 这套界面早该换新风格了 | 换设计体系是 L 档立项（3-4 / 3-5 / 3-6），不是 7-1 |

**UI 改动四步：**

**第 1 步 定位组件**
- 注册表有 → 直接用文件与搜索词。
- 注册表没有 → 反查路径按序试：
  1. 浏览器 F12 → 选中元素 → 看 class/id/组件根元素名
  2. 框架 devtools 组件树 → 组件名（告诉用户怎么开：F12 → Components/Vue 面板）
  3. 界面文案全仓库搜：
```powershell
$text = 'Search'        # 界面上的文字，逐个试
Get-ChildItem -Path src -Recurse -File | Select-String -Pattern $text | Select-Object Path, LineNumber, Line
```
Expected：本仓无 `src/` ⇒ 这条管道**零输出且 `$null`**（实测：`-Recurse -File` 形态连「找不到路径…因为该路径不存在。」都不打，去掉 `-Recurse` 才报出同一句）⇒ 空输出既可能是「没命中」也可能是「目录不存在」，先 `Test-Path src` 分辨；有命中时每行形态是 `<文件路径>:<行号>:<整行原文>`，再接 `Select-Object Path, LineNumber, Line` 会渲染成三列表格（`Path` 是绝对路径）。
   - ❌ 反例：`grep -rn "<界面上的文字>" src`（bash 专用命令 + 占位符，Windows 上直接报错）
   - ✅ 正例：上面那条 `Get-ChildItem -Path src -Recurse -File | Select-String -Pattern $text`（本机 PowerShell 5.1 实测命中 2 行：`SearchBox.tsx:1 export function SearchBox() {`、`SearchBox.tsx:2   return <input placeholder="Search" aria-label="Search" />;`）
   - （注：本机 PowerShell 5.1 里 `-Recurse` 不是 `Select-String` 的合法形参，只有上面的管道式递归可跑；误写会报「找不到与参数名称"Recurse"匹配的参数」）
- **定位成功立刻建注册表行**（下次 3 秒找到），哪怕本次不改这个组件的卡。

**第 2 步 改前状态确认**
- 用文字或截图描述"现在的样子"+影响面（注册表"影响面"列：谁还引用它、改样式会不会两处同变）。
- 用户确认后动手。共用组件改外观 = 影响多个页面，必须明示。

**第 3 步 改动**
- 遵守宪法"禁平行新建"：能用现有组件的属性/变体解决就不新建。
- 改动按 §① 第 5 条的三份判据落地：颜色/间距引 `docs/DESIGN_TOKENS.md` 的令牌名，动效从 `docs/MOTION.md` 的选项表里选，组件规格对齐 `docs/UI.md`；要加新令牌或新动效 → 停手，回 3-5 / 3-6 立项。
- 提交动作放 §④（先回写状态再提交）；本步只把改动与注册表行准备好，并确认没有顺手改到别的组件。

**第 4 步 回写与验收**
- **复跑三份界面自检**：改动落地后跑下面这条，命中处必须要么是令牌定义本身、要么已写成 `var(--…)`；出现写死值 = 停手回 3-5 / 3-6 补令牌。
```powershell
$changed = git diff --name-only HEAD~1..HEAD
$pat = '#[0-9a-fA-F]{3,8}\b','font-family\s*:','border-radius\s*:','box-shadow\s*:'
$hit = Select-String -Path $changed -Pattern $pat -ErrorAction SilentlyContinue
$hit | Select-Object Path, LineNumber, Line
"命中 $($hit.Count) 处"
```
Expected：本仓实测对上一笔提交（4 个文件）打出 **1 处**命中 `docs/TECH_DEBT.md:23`、末行 `命中 1 处` —— 命中的是**讲令牌的散文里引用的 4 个色值**（`#8a8a8a` / `#3b82f6` / `#0000000a` / `#ffffff0f`），既不是令牌定义、也没写成 `var(--…)` ⇒ 判据按「命中数 = 已解释数」逐处给理由，不能把「命中 1 处」直接当红；`$changed` 为空（本笔没改文件 / `HEAD~1` 不存在）时 `Select-String` 先报参数绑定错误 `无法将参数绑定到参数"Path"，因为该参数为空数组。`，随后仍打 `命中 0 处`（`$null.Count` = 0）—— 这两者要分辨，别把「没查」读成「干净」。
  判定：命中数 = 已解释数（令牌定义处 / 已改 `var(--…)`）即通过；有未解释命中 = 本卡未完成。
- **一套制式**：一个界面只允许一套圆角、一档阴影、一个图标库、≤3 个字体族（见 `docs/DESIGN_TOKENS.md` 与 `docs/UI.md`）。
- **回写注册表**：程序名变了改行，影响面变了更新列，"最近确认"填今天。
- 给验收描述："打开哪页 → 应看到什么"（一行）。

**禁令：**
- 禁止只改代码不回写注册表（下次又是"那个东西在哪"的轮回）
- 禁止改共用组件而不报告波及页面
- 禁止引入新 UI 库/设计体系（那是 L 档立项）
- 禁止在组件里写死颜色/字号/圆角/阴影/时长（一律引令牌名）
- 禁止引入第二套圆角/阴影/图标库/字体族
- 禁止跳过第 4 步的三份界面自检（没跑 = 本卡未完成）

## ④ 状态回写

**顺序铁律：先回写状态 → 再提交 → 再复跑 check.ps1 取 0。**

先回写注册表与 STATE.md：
- `docs/registry/COMPONENTS.md`：程序名变了改行，影响面变了更新列，"最近确认"填今天
- STATE.md：`当前任务` 清空（S 档小改动）或保留；`下一步` = 5-1 归档
- ❌ 反例：改完代码不回写注册表就提交（下次又是"那个东西在哪"的轮回）
- ✅ 正例：注册表行与代码改动进同一次提交，回执贴"改前 → 改后"两行

然后提交与复跑：
```powershell
$page = 'home'; $what = 'search-button'
git add STATE.md docs/registry/COMPONENTS.md src/components/SearchBox.tsx
git commit -m "7-1 style($page): $what 改为图标加文字"
powershell -NoProfile -File check.ps1
```
Expected：`git add` 走这条显式清单（`src/components/SearchBox.tsx` 是示例路径，本仓无 `src/` ⇒ 照抄必报 `fatal: pathspec '...' did not match any files`、退出码 128）；`git commit` 退出码 0、提交信息逐字为 `7-1 style(<页面>): <元素> 改为图标加文字`；`check.ps1` 末行 `全部通过（退出码 0）：完成声明成立。`、退出码 0（非 0 = 停下，不许宣布完成）。
