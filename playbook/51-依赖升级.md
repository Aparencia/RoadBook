# 卡 51 · 依赖升级
> 触发：需要升级依赖（用户要求或安全补丁） ｜ 产物：升级提交 + 兼容性结论 ｜ 下一张：40 归档

---

## ① 开工确认

1. **升级动机三选一**（前两者才值得动手，"主动追新"要劝退）：
   - 安全补丁（有 CVE/漏洞通报）
   - 新功能需要（某个 Must 依赖新版本 API）
   - 主动追新（❌ 默认拒绝：没有收益只有回归风险）
2. **假设清单**：你替用户做的 3~5 条默认假设（例："本次只动这一个包""不跨大版本"），每条注明验证方式。
3. **澄清问题（≤5 个，能省则省）**：默认三问——升到哪个**具体版本号**（不接受"最新"）？能否接受 breaking change？回滚窗口留多长？`.tool-versions` 与 lockfile 里查得到的禁止问人。
4. **影响面预告**：将用 `Select-String` 核对当前依赖被谁用（含 src 之外的 test/配置目录）。
5. **引用检查清单原文**（逐字粘贴本卡 §② 的"升级四查"）。
6. 并声明：产物落点 = 升级提交（lockfile 与代码适配分开两次）+ 兼容性结论；下一张卡是 40（归档）。

---

## ② 执行

**升级四查：**

**① 理由核实**：读官方 changelog / release notes / 安全通告，回执摘要（改了什么/破坏性变更有哪些/为什么本项目需要）。
❌ 反例："最新版性能更好"（没有数据、没有本项目的痛点对应）
✅ 正例："v3.2 修复了本项目正在用的 `parse()` 的内存泄漏（issue #123，我们的导出接口周报里出现过）"

**② 兼容性影响面**：
```powershell
$dep = 'requests'          # 本次要升的依赖名
Select-String -Path src, tests -Recurse -Pattern $dep | Select-Object Path, LineNumber, Line
```
列出全部调用点，对照 changelog 的 breaking changes 逐条判断"本项目受不受影响"。
❌ 反例：`grep -rn "<依赖名>" src`（bash 专用命令 + 占位符，Windows 上跑不动，还会漏掉 src 之外的调用点）
✅ 正例：上面那条 `Select-String -Path src, tests -Recurse -Pattern $dep`（PowerShell 5.1 可跑，输出 Path/LineNumber/Line）

**③ 准备升级改动（lockfile 与代码适配分开提交；提交动作放 §④，本段不提交）**：
```powershell
$dep = 'requests'; $old = '2.30.0'; $new = '2.31.0'
# 升级命令按 .tool-versions 的包管理器填，例：pnpm add requests@2.31.0 ／ pip install -U requests==2.31.0
$lock = 'pnpm-lock.yaml'          # lockfile 文件名按实际包管理器换
$adapter = 'src/export_limit.py'  # 本次代码适配文件，逐个列出
```
- lockfile 单独一个提交（保住回滚粒度），代码适配另起一个提交
- 破坏性变更的适配必须写明"改前行为 → 改后行为"

**④ 全量验证**：`powershell -NoProfile -File check.ps1` 退出码 0 + 粘贴输出（在 §④ 提交后跑）。不过 → 回滚 lockfile 提交（`git revert`），升级失败也是有效结论。

**禁令：**
- 禁止在一次任务里升多个**大版本**（互相干扰没法定位）
- 禁止跳过 lockfile 单独提交（回滚粒度没了）
- 禁止把目标写成"升到最新版"（版本号必须具体）
- 破坏性大版本升级 → 不是本卡的事，立项走 L 档全流程

---

## ③ 证据回执

1. 版本变化：依赖名 + 旧版本 → 新版本（具体号），动机归类
2. 兼容性结论：breaking changes 逐条"受/不受影响"+依据
3. lockfile commit + 适配 commit 哈希（在 §④ 提交后回填）
4. `check.ps1` 输出 + 退出码

---

## ④ 状态回写

**顺序铁律：先回写状态 → 再提交 → 再复跑 check.ps1 取 0。**

更新 STATE.md：`当前任务` 清空；`下一步` = 40 归档；`.tool-versions` 若有版本行变化需同步更新并注明。

然后提交与复跑（提交信息里的 `$dep` / `$old` / `$new` 沿用 §③ 的赋值）：
```powershell
git add STATE.md .tool-versions $lock
git commit -m "51 chore(deps): bump $dep $old -> $new"
git add $adapter
git commit -m "51 fix(deps): adapt to $dep $new"
powershell -NoProfile -File check.ps1
```

固定收尾语：
`等待你裁决。回复"继续"执行下一张卡，或说新指令。`
