## ① 开工确认

收到开工指令后，先回执：

1. **触发确认**：读 STATE.md `体检计数`（≥15 才继续；数字对不上则先与用户核对）。
2. **假设清单**：你替用户做的 3~5 条默认假设（例："上一轮提案都已落地或已否决""最近 2 次归档的汇总行可读"），每条注明验证方式。
3. **澄清问题（≤5 个，能省则省）**：默认三问——本轮要不要动宪法？上一轮未决提案怎么处理？提案落地由谁裁决？STATE.md 与报告里查得到的禁止问人。
4. **扫描范围声明**：将扫十四类信号（门禁绿率 / 停问热点 / 教训复发 / 宪法沉默项 / 文档孤儿行率 / 并行态到期 / 孤儿清单收敛 / 文件数膨胀 / 提交节奏 / 远端与推送滞后 / 演练记录过期 / 卡行为 baseline 产物无人消费 / 路由漂移 / no-op 规则），数据源 = docs/reviews/、docs/TECH_DEBT.md、docs/lessons/、docs/archive/、docs/registry/ + STATE.md（并行态登记簿 / 文件数基线 / 最近归档 / 起点锚点）+ `orphans.ps1` 汇总行 + `git log --oneline`、`git status -sb`、`git remote -v`。
5. **观察窗口声明**：信号 9、10 的窗口 = **最近 2 次归档 / 最近 2 个任务**，与本卡触发周期（每 15 次归档）**解耦**——窗口短，才抓得住"最近两次收尾是不是都没落历史"。
6. **提案纪律声明**（逐字粘贴本卡 §② 的"提案三纪律"）。
7. **边界声明**：本卡只能**起草提案**，宪法与流程的每一条修订都由人裁决；agent 禁止自行修改宪法。产物落点 `docs/decisions/PROCESS_<日期>_体检.md` + 提案落地；下一张卡是 5-1（归档）。

## ② 执行
**信号 1：门禁绿率（门禁太松 or 上游太糙）**——统计全部审查报告的建议色分布：
```powershell
Select-String -Path "docs/reviews/*.md" -Pattern "建议色" | Select-Object Filename, Line
```
- 连续 ≥10 个绿、且期间发生过返工 → 提案："审查门禁太松"（对症下药：给对应维度加判据）
- 红/黄率 > 50% → 提案："上游有系统性问题"（对症：2-1 / 2-2 卡加检查项，或该类任务档位该升）
**信号 2：停问热点（哪张卡最费劲）**
```powershell
Select-String -Path "docs/TECH_DEBT.md" -Pattern '^\|\s*TD-' | ForEach-Object { ($_.Line -split '\|')[4].Trim() } | Group-Object | Where-Object { $_.Count -ge 2 } | Select-Object Count, Name
```
判据只看**数据行**：编号行以 `| TD-` 开头，按 `|` 切分后第 4 列（来源列）分组；同一来源出现 **≥2 次**才算热点 → 提案："该卡或该类任务需要加前置检查项"。
- 表头（含"来源"二字）与 `（示例）` 行不参与计数；列数不足 5 的行先补全列再统计，不许当噪声跳过。
- ❌ 反例：`Select-String -Pattern "来源"`（只命中表头，同一来源永远统计不出 ≥2 次）
- ✅ 正例：上面按列分组的命令（输出 Count ≥2 的来源名单，附在报告里）
**信号 3：教训复发（知识该升格了）**
```powershell
$kw = '备份'          # 逐个主题换关键词
Select-String -Path "docs/lessons/*.md" -Pattern $kw | Select-Object Filename, Line
```
按主题关键词逐个聚类：同主题命中 ≥2 张卡、或某卡"最近确认"被更新 ≥2 次 → 提案："升格为宪法禁令/对应卡检查项"（与 6-2 卡的复发升格同一出口）。
**信号 4：宪法沉默项（该删的规则）**：逐条问宪法里的禁令与检查项——archive/reviews/lessons 里**举不出任何一条因它拦截或使用的记录** → 废除候选。
**信号 5：文档孤儿行率（观察项）**
抽样规则固定：取 `docs/registry/APIS.md` 与 `docs/registry/DATA_DICT.md` **各末尾 10 行**（最新登记条目在文件末尾；同一规则每轮可复现）：
```powershell
@(Get-Content docs/registry/APIS.md -Tail 10) + @(Get-Content docs/registry/DATA_DICT.md -Tail 10) | Where-Object { $_ -match '\S' }
```
抽出行里的路由/字段/搜索词逐个赋值给 `$word`，在源码里做存在性检查（`Get-ChildItem -Path $srcRoot -Recurse -File | Select-String -Pattern $word`，`$srcRoot` 填本项目源码根；注：本机 PowerShell 5.1 的 `Select-String` 没有递归形参，必须用上面的管道式递归）：零命中行占比 > 20% → 提案："registry 已过期"（对症：强化 4-1 卡随批回写纪律，或给 check.ps1 加孤儿行检测）。
**信号 6：并行态到期未清（旧实现该死了没死）**：读 `STATE.md` 的"并行态登记簿"表（列：`并行态 | 旧实现 | 新实现 | 删除条件（可判定） | 到期 | 登记批次`）：
- 有**到期未清**条目 → 提案："到期的旧实现立即清理"（落点：7-3 卡开一次清理批）
- 「删除条件」写成不可判定的（如"确认没人用了"）→ 提案："该条重写为可判定条件"
**信号 7：孤儿清单不收敛（清了但没清干净）**：跑 `powershell -NoProfile -File orphans.ps1`，与上一轮体检报告里的汇总行对比：孤儿 / 零引用导出 / 文档幽灵 / 反向幽灵 / 未登记**五类中任一类连续两轮不减** → 提案："清理机制失效"（对症：查 5-1 卡的处置规则是否被执行，或 4-1 卡的登记纪律）；**首轮无上一轮汇总行** → 把本轮汇总行原文写进报告当基线，结论写"首轮只记基线，无对比"，本轮不提案。
**信号 8：文件数膨胀（AI 生成多、删除少的总账）**
```powershell
(Select-String -Path STATE.md -Pattern '文件数基线').Line; "当前文件数 " + @(git ls-files).Count
```
判据：**当前文件数 - 文件数基线 > 20** → 提案："安排一次清理批收敛"（落点：7-3 卡）；`最近归档` 里的文件数快照作趋势证据。
- `文件数基线` 只在接入/首批设一次，4-1 卡不再随批重置；基线为 0（未初始化）→ 先按接入收尾补设，本轮不判红。
- ❌ 反例：每批编码后把基线改成当前文件数（差值恒为 0，预算机制空转、永不触发）
- ✅ 正例：基线设一次不动，每轮体检算差值与趋势，超 20 才提案
**信号 9：提交节奏失效（做完没落历史）**
读 STATE.md 的 `起点锚点`、`工作树状态` 与 `最近归档`（6 字段：日期/slug/提交哈希/起点锚点/当前文件数/推送结果，滚动 2 条），跑：
```powershell
$anchor = ((Select-String -Path STATE.md -Pattern '起点锚点').Line -replace '.*?([0-9a-f]{7,40}).*', '$1')
if ($anchor -notmatch '^[0-9a-f]{7,40}$') { $anchor = '' }
"anchor=[$anchor]"; git status --short; if ($anchor) { git rev-list --count "$anchor..HEAD" }
```
窗口 = **最近 2 次归档 / 最近 2 个任务**（与每 15 次归档的触发周期解耦）：
- `最近归档` 两条记录的起点锚点相同（连收两次尾锚点都没前移）→ 提案："收尾没写锚点"
- 锚点读不出哈希（STATE.md 里还是模板占位符文字，或从未设过）→ 本项记"锚点未设"；**连续两轮**如此同样算"收尾没写锚点"（`起点锚点` 归档不清空、保留上一任务的值，正常情况下永远读得出哈希）
- 工作树跨会话非空、STATE 却记"干净" → 提案："完成定义被绕过"（对症：查 check.ps1 的 git 断言为何没拦住、卡收尾是否跳过了提交）
- ❌ 反例：锚点两个任务没动、`git status` 有未提交文件，回执仍写"提交节奏正常"
- ✅ 正例：两条 `最近归档` 的起点锚点各不相同，且 `git status --short` 为空 → 无提案
**信号 10：远端与推送滞后（历史只在本机）**
```powershell
git remote -v; git status -sb
```
窗口 = **最近 2 次归档**：`git remote -v` 为空、或 STATE.md `远端仓库` 写"本地-only"、或 `git status -sb` 显示 `ahead N` 且 `最近归档` 两条的 `推送结果` 字段都没有推送成功记录 → 提案："远端与推送节奏未落地"（落点：1-2 / 1-3 卡接入收尾、5-1 卡归档收尾的远端同步）。
- ❌ 反例：porcelain 干净就当推过了（干净只说明没有未提交改动，不说明推过；远端要看 `git status -sb` 的 ahead 计数）
- ✅ 正例：`git status -sb` 无 ahead、`最近归档` 每条 `推送结果` 都写明已推送 → 无提案
**信号 11：演练记录过期（承接 5-5 卡的 90 天回看）**：读 `docs/RUNBOOK.md` §5 的「下次到期」字段与 STATE.md `最近归档`（6 字段：日期/slug/提交哈希/起点锚点/当前文件数/推送结果）：
```powershell
Select-String -Path docs/RUNBOOK.md -Pattern '下次到期'; (Select-String -Path STATE.md -Pattern '最近归档').Line
```
「下次到期」已过期、为空、或仍是模板占位符 → 提案："演练记录过期未复演"（落点：走一次 5-5 卡补演，并把新到期日回填 RUNBOOK §5）；❌ 反例：「下次到期」写着 2026-01-01 早已逾期，报告仍写"备份演练正常"；✅ 正例：写明逾期天数 + 提案补演 + 回填新到期日。
**信号 12：卡行为 baseline 产物无人消费**：若 `_qc/baseline/runs/` 下存在 run 目录，而本次体检报告未引用其任一行号 → 记"baseline 空转"；提案："把该 run 的失败类型与结论并入本次体检"。
**信号 13：路由漂移**——常驻入口（`SKILL.md` 与驱动卡）里指向的卡号、文件名、命令与磁盘现状不一致 = 路由在骗人。体检动作：入口逐条对账（命令见下），列出对不上的条目并要求同批修正。
```powershell
$entry = 'SKILL.md'   # 换成常驻入口文件；如有多个就逐个跑；每行取出的卡号/文件名/命令逐条 Test-Path
Get-Content $entry | Select-String -Pattern '\d+-\d+'
```
判据：入口条目写出的卡号/文件名/命令在磁盘上 `Test-Path` 为假，或卡号实际指向另一张卡 → 记一条"路由漂移"；≥2 条 → 提案："同批修正入口与卡"（落点：入口文件 + 被指错的卡同一次提交，禁止只改一边）。❌ 卡已改名、入口仍写旧名，报告却写"入口正常"｜✅ 入口 14 条逐条 `Test-Path` 全为真 → 无提案
**信号 14：no-op 规则**——一条规则删掉之后行为完全不变（相对模型默认值没有改变任何东西）= 该删，或该改写成可执行判据。"读起来有道理"不算数；判据是删掉它跑一次对照，行为无变化即 no-op。体检动作：挑候选规则临时删掉跑一次同类任务，与保留时对照。
判据：删掉后那次任务行为与保留时**完全一致** → 记一条"no-op 规则"；同一条被记 ≥2 轮 → 提案："废除它，或改写成可执行判据（命令 + 期望输出）"（落点：该规则所在文件的具体条目）。❌ "读起来有道理，先留着"（没跑删掉对照）｜✅ 删掉跑一次、两次行为一致 → 记 no-op 并附两次输出原文

**提案三纪律（每条提案必须过）：**
1. **信号 ≥2 次才有提案资格**——一次红灯就改规则 = 过度拟合单次事故，规则会爆炸
2. **废除类至少 1 条**——加与删必须对称；一条都提不出 → 明确写"本轮无废除候选"并说明扫过什么
3. **落到具体文件+具体条目**——❌"以后编码要更小心" ✅"宪法 §2 增加：写接口必须先在 APIS.md 登记错误码"

产出 `docs/decisions/PROCESS_<日期>_体检.md`：信号统计原文 + 提案表（信号/证据/提案/落点/类型）。
**落地分两类**：
- 宪法修订（本项目的 AGENTS.md）→ 人逐条裁决后当场改（宪法修改需人在场确认）
- **母版卡组修订** → 只写进提案文件，标注"带回母版执行"——卡在母版工作区，本项目会话够不到，禁止改本项目文档冒充落地

**改卡前三问（改卡前必答，源 baseline meta-test）**：改卡前先问被绕过的那个 agent —— "How could that skill have been written differently to make it crystal clear that Option A was the only acceptable answer?" 三种回答 → 三种修法：① 卡很清楚但我无视 → 加根本原则；② 本该说 X → 把它的建议逐字写进卡；③ 没看见 Y 节 → 提高该节显著度。判定人把这三类回答填进 `judge.md` 的「结论」列。

**禁令：**
- 禁止 agent 自行修改宪法或宣布提案通过（裁决是人）
- 禁止无信号支撑的提案（"我觉得"不合格）
- 禁止本次体检不产生任何书面结论（哪怕结论是"系统健康，无需修订"也要写明依据）
