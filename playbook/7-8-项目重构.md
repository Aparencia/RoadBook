# 卡 7-8 · 项目重构（行为不变，只换实现）
> 触发：重复代码成片 / 上帝类 / 循环依赖 / 技术栈或框架迁移 / 性能改造必须换实现 ｜ 产物：docs/refactor/REFACTOR_<日期>_<slug>.md + 分批提交（每批一个回滚点） ｜ 下一张：4-2 自检与守卫（每批结束）/ 5-1 归档（整体收尾）

---

## ① 开工确认

1. **人话复述与落点**：把"换掉哪块实现、换完外部行为一模一样"讲成人话；产物 = `docs/refactor/REFACTOR_<日期>_<slug>.md`（含不变项、安全带清单、批次表、验收四件、回滚预案）；下一张卡 = 4-2 自检与守卫（每批结束）/ 5-1 归档（整体收尾）。
2. **触发判定（对上才开工）**：
   - 同一段逻辑在三处以上重复、改一次要改多处 → 本卡
   - 一个大类/函数同时干三种以上职责（上帝类）→ 本卡
   - 模块之间互相引用成环（A→B→A）→ 本卡
   - 换语言/框架/存储（技术栈或框架迁移）→ 本卡（先在 3-3 出选型结论）
   - 改四处只为让一个性能指标达标 → 本卡
   - ❌ 反例：只是想加一个按钮/一个字段 → 走 2-1 需求澄清，别包装成重构
   - ✅ 正例：限流逻辑在 5 个文件里各抄一遍，改一次要改 5 处 → 本卡
3. **边界声明（写进报告"不变项"节）**：外部契约不变——接口路径与字段、错误码、页面主路径、表名列名、命令与配置键；行为不变——同一输入给同一输出。
   - 要改行为（哪怕只是错误文案变了）= 新功能 → 回 2-1 立项，不在本卡夹带。
4. **假设清单**：逐条"我假设 X；若错则 Y 失效"（例："旧实现的调用方都能在仓库里查到，没有外部调用者"），每条注明验证方式。
5. **澄清问题（≤5 个，能删则删）**：默认三问——不变项清单由谁逐条确认？可接受的双跑/停机窗口多久？先做哪一块？代码与注册表里查得到的禁止问人。
6. **引用本卡检查清单原文**（逐字粘贴 §② 的"重构六步"）。

## ② 执行

**重构六步：**

**第 1 步 算改造面，定路线（先算比例再选）**
```powershell
$target = 'src/export'      # 本次改造涉及的目录/文件
(Get-ChildItem -Path $target -Recurse -File | Measure-Object).Count
(Get-ChildItem -Path src -Recurse -File | Measure-Object).Count
```
改造面 = 受影响文件数 ÷ 项目文件数：
- **<40% → 就地改**（Strangler 分阶段替换，本卡默认路线）
- **≥40% → 写明理由 + 用户确认**后才动手（比例越大越要拆批）
- **>60% 且旧实现无复用价值**（无其他模块依赖、无保留价值）→ 才允许重写，且照样走第 2~5 步
- ❌ 反例：先删后写、一步到位全量重写（没有回滚点、没有等价证据）
- ✅ 正例：算出 12/180 ≈ 7% → 就地改，先替换一个调用点

**第 2 步 安全带先行（先绿再动）**
- 特征测试：把旧实现的当前行为（含怪行为）写成断言，跑到全绿。
- 黄金样例：挑 3~5 组真实输入，存下旧实现的输出，作为"同输入同输出"基线。
- 契约测试：在接口/命令层验外部契约（路径、字段名、错误码）。
- 安全带没绿，不许动第一行实现代码。
- ❌ 反例：无测试直接换实现，"改完再说"（等价性事后无法证明）
- ✅ 正例：先补 6 条特征测试 + 1 组黄金样例，全绿后才开始替换

**第 3 步 Strangler 五阶段（一阶段一批，一批一提交）**
1. **并行实现**：新旧实现同时存在，旧实现继续对外服务。
2. **影子/双写校验**：同一输入同时喂新旧两侧，比对输出差异，差异清单贴回执。
3. **切读**：读取路径逐个切到新实现（先内部分支、再主路径），每切一个留一个回滚点。
4. **删旧**：新实现全绿且新旧差异为零后删掉旧实现；删不掉的登记 STATE.md `并行态登记簿`（含删除条件与到期）。
5. **收尾消除开关**：删掉双写/影子代码与开关配置，确认无残留分支。
- ❌ 反例：开关留着"以后再清"（开关 = 永久分叉，半年后没人敢删）
- ✅ 正例：切读完成后当批删旧、下一批消开关，回执贴开关搜索零命中

**第 4 步 每批纪律（不守就不算一批）**
- 一批 = 一次提交 = 一个回滚点；批与批之间 `git status --short` 必须无输出。
- 净增量为负目标：**净减 ≥200 行 或 ≥3 个文件**，用下面的命令自证：
```powershell
$anchor = 'abc1234'        # 起点锚点，从 STATE.md 读
git diff --numstat "$anchor..HEAD"
```
- 一批里禁止夹带功能改动、升依赖、改配置；发现新问题 → 登记 `docs/TECH_DEBT.md`。
- 多人条款：单人模式跳过，在 STATE.md `裁剪记录` 写一行理由（例："单人重构，无并行批次"）。

**第 5 步 验收四件（缺一件不算完成）**
1. **行为等价证据**：黄金样例新旧输出逐组比对，差异为零，比对原文贴回执。
2. **全量 guardrail 绿**：`powershell -NoProfile -File check.ps1` 退出码 0 + 粘贴输出。
3. **旧实现退役**：仓库里搜不到 `_old` / `_legacy` 残留，或已全部登记 `并行态登记簿`：
```powershell
Get-ChildItem -Path src -Recurse -File | Select-String -Pattern '_old|_legacy'
```
   （注：本机 PowerShell 5.1 的 `Select-String` 没有递归形参，只有上面的管道式递归可跑）
4. **依赖方向无环**：不出现 A→B→A，给检查命令并贴输出：
```powershell
Get-ChildItem -Path src -Recurse -Filter *.py | Select-String -Pattern '^from |^import '
```

**第 6 步 回滚预案（开工就写）**
- 单批回滚：对该批提交哈希执行 `git revert`（每个回滚点一个哈希，写进批次表）。
- 整体回滚：切回旧实现 + 撤掉新实现提交；涉及数据迁移必须附 down 脚本。
- ❌ 反例：报告只写"有问题就回滚"（没有哈希、没有 down 脚本）
- ✅ 正例：批次表 5 行，每行"批次 / 提交哈希 / 净增删行数 / 回滚命令"，数据迁移批附 down 脚本路径

**接缝判据（重构前先判这里该不该抽接口）**
- **一个适配器 = 假设的接缝；两个适配器 = 真接缝**：只有一个实现时抽出的抽象层是猜测，登记为技术债，等第二个实现出现时再做；两个实现出现时才为它抽接口/适配器。
- 落点：猜测性抽象写进 `docs/TECH_DEBT.md`（写清"第二个实现出现时抽接口"），不写进本批代码。
- ❌ 反例："以后可能还要接一个支付渠道，先把接口抽出来"（只有一个实现，抽出来的形状必错）
- ✅ 正例：第二个支付渠道确定要接 → 本批抽接口，两个适配器同批写，特征测试对两者都跑

**禁令（违反任意一条 = 本轮输出作废）：**
- 禁止改变外部契约与可观测行为（要改行为 → 回 2-1 立项）
- 禁止在三件安全带（特征测试/黄金样例/契约测试）全无时动实现代码
- 禁止一批里混功能改动或升依赖
- 禁止把删不掉的旧实现留在仓库里不登记
- 禁止在报告里承诺"以后补测试"

## ③ 证据回执

逐条给出：
1. 改造面比例（受影响文件数 ÷ 项目文件数）+ 选定路线（就地改 / 确认后大改 / 重写）
2. 批次表：每批提交哈希、净增删行数、回滚点
3. 安全带证据：特征测试与契约测试运行输出、黄金样例差异为零的比对原文
4. 验收四件逐条：等价证据 / `check.ps1` 退出码与输出 / 退役搜索结果 / 依赖无环命令输出
5. 回滚预案：单批回滚命令与整体回滚步骤（含数据迁移 down 脚本路径）
6. 用户对"不变项清单"的裁决原文

## ④ 状态回写

**顺序铁律：先回写状态 → 再提交 → 再复跑 check.ps1 取 0。**

更新 STATE.md：
- `当前任务` 保留（还有下一批）或清空（整体收尾）
- `下一步` = 4-2 自检与守卫（还有下一批）/ 5-1 归档（收尾）
- `未决问题` = 未退役的旧实现与到期、待用户裁决的契约变更
- `档位` = 改造面 <40% 就地改记 M 档；≥40% 或重写记 L 档并写理由
- `工作树状态` = 干净（批与批之间必须干净）

```powershell
$slug = 'export-strangler'; $msg = '导出模块限流收敛为单一实现'
git add STATE.md docs/refactor/REFACTOR_2026-10-03_export-strangler.md src/export

powershell -NoProfile -File check.ps1
```
