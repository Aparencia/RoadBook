## ② 执行

**回归验证三件事（缺一不可）：**

**第一件：负面测试（防复发，这是修复验证与功能验证的区别）**
写一个"让原 Bug 复现"的测试——输入触发 Bug 的条件，断言得到正确结果（旧代码会挂、新代码要过）。
```powershell
# 运行并粘贴输出
<项目测试命令，如 pytest tests/test_bugfix_xxx.py -v>
```
❌ 反例：只在控制台试了试说"好了"（没有防复发的测试，下次改代码还会炸）
✅ 正例：`test_bugfix_export_empty_data` 断言空数据导出返回空文件而非崩溃

**第二件：回归清单（受影响面逐项过）**
1. `grep -rn "<被改函数/接口名>" src` 列出全部调用方
2. 逐个调用方写"怎么验证它没被改坏"（一条可观察行为）
3. 逐项执行并在清单上打勾

**第三件：全量收工仪式**

```powershell
powershell -File check.ps1
```

退出码 0 + 完整粘贴输出。不通过 → 回 31 修，不许带病归档。

结果全部写入 `docs/specs/<日期>_<bug名>/VERIFY.md`（负面测试输出/回归清单勾选/check 输出）。

**禁令：**
- 禁止跳过负面测试（"改动很小不会有回归"是最常见的借口）
- 禁止弱化断言让测试通过（发现自己在这么干 → 立即停下声明）
- 禁止替用户宣布验收通过
