> 触发：项目已有代码但缺 AGENTS.md/STATE.md/docs 结构 ｜ 产物：宪法+STATE+docs 骨架+起点 commit ｜ 下一张：待新意图

---

## ① 开工确认

收到开工指令后，先回执以下四项再动手（缺项不开始）：

1. **任务复述**：一句话说明接的是哪个目录、大概是什么项目（用户原话）。
2. **假设清单**：从目录名/README 推断的假设逐条列。
3. **澄清问题（≤5 个）**：能靠扫描目录得出答案的禁止问人。
   ❌ 反例："这个项目用什么技术栈？"（扫描 package.json / requirements.txt 就知道）
   ✅ 正例："这个项目里 docs/ 下的旧文档，接入后还维护吗？"
4. **引用检查清单原文**（逐字粘贴本卡 §② 的"裁剪五问"）。

并声明：本卡只反推文档、不动业务代码；产出落到项目根。

## ② 执行

**动作 1：扫描实际目录树**

**变量名一律 ASCII**：Windows PowerShell 5.1 读无 BOM 的 .ps1 时中文变量名会报『字符串缺少终止符』；脚本必须存成 UTF-8 带 BOM。
```powershell
Get-ChildItem -Recurse -Depth 3 -Force | Where-Object { $_.FullName -notmatch 'node_modules|\\\.git\\|dist|build|__pycache__|\.venv|coverage' } | Select-Object FullName
```
```powershell
Get-ChildItem -Recurse -File | Group-Object Extension | Sort-Object Count -Descending | Select-Object Count,Name -First 15
```

**动作 2：探测实际栈（证据 = 文件，不许猜）**
存在 package.json → Node/前端栈；存在 requirements.txt / pyproject.toml → Python；存在 go.mod → Go。
打开这些文件读关键行（框架名/版本），把"依据文件 + 关键行原文"写进回执。
❌ 反例："看目录名是个 React 项目"（记忆/猜测）
✅ 正例："React 18——依据 package.json 第 12 行 `"react": "^18.2.0"`"

**动作 3：生成 AGENTS.md（≤240 行）**
从母版 template/AGENTS.md 复制全文，然后替换：§0 一句话/技术栈（用动作 2 的证据）、§10 环境速查（启动/检查/测试命令按实际栈填，写实际验证过能跑的命令）。

**动作 4：生成 STATE.md（≤45 行）**
从母版 template/STATE.md 复制，替换：项目名/一句话/技术栈（链不到 STACK 决策卡时写"存量项目反推"）/当前阶段=接入完成/下一步=待新意图。

**动作 5：生成 docs/ 骨架 + registry 三件套格式头（只建头，不建全）**
```powershell
New-Item -ItemType Directory -Force docs/registry, docs/pool, docs/specs, docs/decisions, docs/reviews, docs/versions, docs/lessons, docs/archive | Out-Null
```
三个 registry 文件各只写表头 + 一行提示，首次触碰对应对象时再补行：
- `docs/registry/COMPONENTS.md`：`| 页面 | 界面元素 | 人话标识 | 程序名 | 文件 | 搜索词 | 影响面 |`
- `docs/registry/DATA_DICT.md`：`| 表 | 字段 | 类型 | 校验 | 敏感度 D1~D4 |`
- `docs/registry/APIS.md`：`| 路径 | 方法 | 用途 | 错误码 | 鉴权 |`

**动作 5.5：安装守护脚本五件（从母版 `template/` 复制到项目根）**
```powershell
$master = 'D:/path/to/roadbook'   # 母版根绝对路径（先问用户母版放在哪，禁止照抄这一行），先赋值再调用
$proj = 'C:/code/myapp'           # 目标项目根绝对路径
foreach ($f in @('check.ps1','doctor.ps1','gate.ps1','orphans.ps1','security.ps1')) {
  $dst = Join-Path $proj $f
  if (Test-Path $dst) { "已有同名脚本，本次不覆盖：$f（把差异给用户看，由他决定合并还是保留原有）" }
  else { Copy-Item "$master/template/$f" $dst }
}
Get-ChildItem "$proj/*.ps1" | Select-Object Name, Length
```
- `check.ps1` 顶部 `$STEPS` 替换为本项目真实命令（跑得通才算装好）——**只对本次新装的文件做**；`.tool-versions` 按本项目栈写真实工具名与版本（doctor.ps1 读它逐项比对，名字写错 = 缺工具红灯）。
- 项目已有同名脚本 → **不覆盖**：上面的循环会打印跳过项；要升级/合并必须逐个人工比对后手动替换，把差异给用户看，由他决定合并还是保留原有。
- 本步只跑 `powershell -NoProfile -File orphans.ps1`：此刻新文件全未提交，它会打 `[FAIL] 未跟踪 N 个文件` 且退出码 1——那是"清单不完整"（先 `git add`），**不是孤儿**；`check.ps1` 必然 `[FAIL] 工作树不干净`——**同属预期**，留到动作 8 提交后在 ④ 复跑取 0。
- `文件数基线` 的口径 = `@(git ls-files).Count`（含 `docs/` 与五个守护脚本），**必须在动作 8 首次提交之后采样**再写进 STATE.md；`orphans.ps1` 汇总行的"文件数"是排除 `docs/` 与守护脚本后的口径，**不得**写进基线。模板整份接入会让文件数一次跳升远超 check.ps1 允许的 20，所以提交前采样必然判红——唯一合法时机是接入完成的那次提交之后，用当轮实测值，**不是**接入前的旧值。
- 用户裁剪掉本机制 → 在 STATE.md"裁剪记录"写明"孤儿五张清单与文件数预算不适用 + 原因"。

**动作 6：反推 ARCHITECTURE.md 初版（≤120 行）**
内容三节：模块图（mermaid，框=实际顶层目录）+ 分层说明（每层一句：干什么）+ 数据流（一句话：用户操作 → 哪层 → 存到哪）。每个模块必须标注真实目录路径，写不准的标 `<!-- 待确认 -->`，禁止编造。
❌ 反例：画了三层架构图但目录里根本没有 service 层
✅ 正例："src/components（UI）→ src/lib（逻辑）→ IndexedDB（存储）——与目录树一致"

**动作 7：裁剪五问（照着念给用户，每答一项立即写进 STATE.md"裁剪记录"）**

```text
① 本项目有数据库/表结构吗？（无 → 迁移类检查永久跳过，DATA_DICT 表头下写"无"）
② 本项目有图形界面吗？（无 → 跳过 7-1 UI 改动卡：该卡只管界面元素与页面的改动）
③ 本项目要部署到公网吗？（不 → 5-2 发布卡按"本地演示"级走：只在本机验证，不推生产）
④ 本项目有对外接口供他人调用吗？（无 → APIS.md 表头下写"无"）
⑤ 还有哪些卡明显用不上？（用户说出的都记入裁剪记录）
```

**动作 8：git 起点**
- 已有 .git：禁止重新 init。先跑 `git status --short`，有未提交改动 → 停下问用户"提交还是搁置"，干净后记锚点：
```powershell
$anchor = git rev-parse HEAD
```
- 无 .git：
```powershell
git init
$files = @('AGENTS.md','STATE.md','docs')   # 改成实际生成的条目，逐个列出
git add $files
git commit -m "1-3 chore: onboard existing project to V6 flow"
$anchor = git rev-parse HEAD
```
哈希写入 STATE.md"最近完成"第一条。禁止 `git add -A` / `git add .`。

**动作 8.5：远端（判据内联，不跳卡）** 先 `git remote -v`：有 origin → 记下 URL，`$branch = git rev-parse --abbrev-ref HEAD; git push -u origin $branch` 确认能推；没有 origin → 三选一（**私有或公开由人裁决**）：
1. 建远端并首推：先赋值 `$owner = 'aparencia'; $name = 'my-app'`（改成你自己的账号/仓库名），再调用 `gh repo create "$owner/$name" --private --source . --push`（要公开改 `--public`）
2. 已有远端：先赋值 `$url = 'https://github.com/aparencia/my-app.git'`（改成你自己的仓库地址），再调用 `git remote add origin $url; $branch = git rev-parse --abbrev-ref HEAD; git push -u origin $branch`
3. 暂不设远端：写进 STATE.md 裁剪记录「本地-only，风险：磁盘故障 = 全部历史清零」
首推前确认 `git status --porcelain` 为空，且已跟踪文件无密钥：`git ls-files | Select-String '\.env|\.key$|\.pem$'` 有命中即停（推出去不可逆）。**推送不进 DoD**，失败只记裁留不判红。

首推前还要跑两条 git 历史检查（`git ls-files` 只看得到当前索引，看不到已经提交进历史的密钥）：`git log --all --oneline -- .env` 必须无输出（有输出 = 历史里提交过 `.env`，密钥已进历史，**推出去不可逆**，停下报用户）；`git check-ignore -v .env` 必须有输出（`.env` 已在 .gitignore 里，被忽略的文件永远不会进提交）。

**禁令：**
- 禁止修改任何业务代码（发现 bug 记 docs/TECH_DEBT.md，不许顺手修）
- 禁止 ARCHITECTURE/AGENTS 里写没验证过的命令
- 禁止把 registry 建全（只建表头，防编造；首次触碰再补）
- 禁止 `git add -A` / `git add .`
