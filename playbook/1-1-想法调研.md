# 卡 1-1 · 想法调研（项目期唯一入口；Kill 是合法结局）
> 触发：用户对一个具体想法说"启动/立项/调研一下"，或只问"这能不能做 / 可不可行"（→ §② 动作 0.5 探针分支） ｜ 产物：docs/decisions/IDEA_<日期>_<主题>.md ｜ 下一张：Go → 1-2 选型初始化；Pivot → 本卡重跑（≤2 轮）；Kill → 流程结束
> 过程域：REQ

---

## ① 开工确认

收到开工指令后，先回执以下四项再动手（缺项不开始）：

1. **任务复述**：用一句人话复述这个想法——给谁、解决什么问题。
2. **假设清单**：你替用户做的默认假设逐条列出（如"单人使用""不做支付"）。
3. **澄清问题（≤5 个，能省则省）**：只问调研方向必需的；对话里已能推断的禁止再问。
   ❌ 反例："你觉得这个想法有前途吗？"（这是调研要回答的问题，不是澄清）
   ✅ 正例："这个工具只给你自己用，还是打算给其他人用？你的投入节奏是？（周末集中 / 全天 / 碎片时间）你打算给验证期多少时间预算？（默认 2 周）"
4. **引用检查清单原文**（逐字粘贴本卡 §② 的"Kill 判据六问"）。

并声明：产物落点 `docs/decisions/IDEA_<日期>_<主题>.md`；本卡只产出报告与建议，Go/Kill/Pivot 由用户裁决。**限时：① 记开始时间戳、③ 记结束时间戳；超时（>60 分钟）仍出不了建议 → 停下问用户**——澄清最多一轮，未决项显式标注。

## ② 执行

**动作 0：建目录与池**（在目标项目目录执行——先用 `$proj` 记下该绝对路径；母版仓库内禁止新建 docs/）

**变量名一律 ASCII**：Windows PowerShell 5.1 读无 BOM 的 .ps1 时中文变量名会报『字符串缺少终止符』；脚本必须存成 UTF-8 带 BOM。
```powershell
$proj = 'C:/code/myapp'   # 目标项目根绝对路径，先赋值再调用
Set-Location $proj
New-Item -ItemType Directory -Force docs/decisions, docs/pool | Out-Null
if (-not (Test-Path docs/pool/IDEAS.md)) { Set-Content docs/pool/IDEAS.md @('# IDEAS · 需求池', '', '| 日期 | 想法 | 状态 | 复活条件 / 结论 |', '|---|---|---|---|') }
```
Expected：首次执行后 `docs/decisions` 与 `docs/pool` 存在、`docs/pool/IDEAS.md` 恰 4 行（表头 2 行 + 表格 2 行，本机沙箱实测），而且 `if (-not (Test-Path …))` 让重跑**不覆盖**已有池（实测往池里加一行后重跑仍是 5 行）；`$proj` 写错时 `Set-Location` 只报非终止错误 `Cannot find path '…' because it does not exist.`（报错文案随宿主语言变：中文宿主打「找不到路径…」），**后续三条命令照跑** —— 实测它会把 `docs/decisions, docs/pool` 建在**当前目录**（所以在母版仓库里手滑跑一次就等于违规新建 docs/）。跑前先 `Test-Path $proj` 确认真有那个项目目录。

**动作 0.5：探针分支（只问"能不能/可不可行"时走这里；没说立项也走）**
用户没说立项、只问可行性 → 走本分支，不跑动作 1~5、不念 Kill 六问：
1. 先给三句：要回答的问题 / 打算怎么试 / 预期花多久，然后**停下等一个点头**（个人档：用户回"可以/试"即可）；没点头不许动手。
2. 在系统临时目录做；禁止在项目仓库里新建业务文件、禁止拷贝 template/、禁止 `git init`（与下方禁令一致）。
3. 用最便宜的方式拿到答案：允许跑命令、贴真实输出；探针产物收尾删除。
4. 产物是答案不是代码。回执写：答案 + 一句话建议 + 落点（`docs/pool/IDEAS.md` 该想法行的"复活条件 / 结论"列）；确实留了代码 → 补一句"一次性探针，结论已入 <文件>，代码不保留"。
5. 这只是建议；是否转正式调研由用户裁决（同意 → 从动作 1 起跑）。

**动作 1：市场与现状数据（每个数字必须可溯源）**
规则一条：数字后面必须跟来源链接，或标"⚠️ 估算：依据"。
- 查得到 → 写数字 + 来源链接 + 检索日期（写今天，禁止照抄示例日期）。
- 只有二手转述 → 标 ⚠️ 估算 + 写明推算依据。
- 查不到 → 原文写"未查到公开数据"；无检索能力 → 全部标"⚠️ 待验证：需联网核实"。
❌ 反例："笔记市场规模达百亿级，增长迅猛"（无来源，编造嫌疑）
✅ 正例："目标关键词月搜索量约 1.2 万（来源：https://… ，检索日 <今天>）"

**动作 2：竞品 ≥2 个**（表格写进 IDEA 文件）
列：竞品名 / 一句话定位 / 与本想法的差异 / 信息来源链接。
不足 2 个 → 写"未找到竞品"，附你用过的检索关键词清单（证明真找过）。

**动作 3：SWOT（每格 1~3 条，宁少勿凑；每条必须可验证）**
❌ 反例：S："技术先进，体验流畅"（不可验证的形容词）
✅ 正例：S："单人本地运行、零服务器成本——与竞品 X 订阅制（$5/月，来源链接）形成差异"
某格不足 2 条 → 写"仅找到 1 条可验证项"，**禁止为凑数造弱项**。
**无法验证的创新判断不丢弃**：写进 IDEA 文件末尾「⚠️ 待验证直觉」节，每条注明"为什么现在无法验证 + 用什么最小实验能验证"。它们不是证据，不参与判分——是留给 MVP 去检验的假设。

**动作 4：MVP 最薄切片定义**（先切再判：六问 ④ 的答案取决于这一步）
一句话说清：做出来的是什么 + 首个用户怎么用它 + 明确排除什么。
❌ 反例："一个功能完善的笔记应用"
✅ 正例："单页网页：粘贴文本→按段落生成卡片→导出 Markdown；不做账号、不同步、不做移动端"

**动作 5：Kill 判据六问（照着念给用户，逐条记录回答原文）**

```text
① 这解决的是你自己真实遇到的问题吗？（不是想象中"别人可能需要"）
② 按你的投入节奏，你愿意为它投入验证预算吗？
③ 现有工具（含竞品）为什么满足不了？能说出一条硬理由吗？
④ 按你的投入节奏，最薄切片能在验证预算内做出来给真人用吗？
⑤ 它废掉了你会损失什么？（答案可以是"零损失"，但要诚实）
⑥ 一年后它对你还有用吗？
```
判读（各问含义不同，不许一票合并）：
- ② 答"否" → 建议 Kill（投入意愿不足，价值无从谈起）
- ③ 答不出硬理由 → 建议 Kill 或 Pivot（换目标人群/场景再想）
- ④ 答"否" → **先回动作 4 重切切片，再判一次**；已是最薄仍做不出 → 建议 Pivot（缩范围/换形态），切片与预算实在谈不拢才建议 Kill
- 全部通过 → 建议 Go

**动作 6：裁决（人是唯一裁决者）**
汇总：建议（Go/Kill/Pivot）+ 一句话依据 + IDEA 文件路径。然后停下等用户裁决。
用户说 Go → 本卡结束；说 Kill → 执行动作 7；
说 Pivot → 想法一句话改写后**重跑动作 1~5（含重切切片），最多 2 轮**；第 2 轮仍未 Go → 建议 Kill，并附两轮依据对比。

**动作 7：Kill 收尾（仅 Kill 时执行）**
在 `docs/pool/IDEAS.md` 找到该想法行，状态改 `killed` 并追加复活条件；**没有该行则按表头格式追加一行**：
`| <日期> | <想法一句话> | killed | 复活条件：<具体条件> |`
❌ 反例：复活条件："以后再说"
✅ 正例：复活条件："出现支持本地离线同步的成熟开源库时重启"

**禁令：**
- 禁止编造数字、来源、竞品功能——查不到就写"未查到公开数据"
- 禁止用形容词代替数据（"很大""很快""前景广阔"）
- 禁止自行宣布 Go/Kill/Pivot（只给建议 + 依据，裁决是人）
- 禁止在裁决前创建项目代码、拷贝 template/、git init

## ③ 证据回执

收尾逐条给出：
1. IDEA 文件完整路径 + 行数
2. 数据溯源清单：文件中每个数字 → 来源链接 / ⚠️ 估算 / "未查到公开数据"，逐条列出
3. Kill 判据六问的用户回答原文；④ 若触发重切，附前后两个切片
4. 建议 + 一句话依据；用户裁决原文（Go/Kill/Pivot）
5. Kill 时：`docs/pool/IDEAS.md` 修改后该行的原文
