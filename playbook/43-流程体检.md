4. **边界声明**：本卡只能**起草提案**，宪法与流程的每一条修订都由人裁决；agent 禁止自行修改宪法。

## ② 执行

**信号 1：门禁绿率（门禁太松 or 上游太糙）**
```powershell
Select-String -Path "docs\reviews\*.md" -Pattern "建议色" | Select-Object Filename, Line
```
统计全部审查报告的建议色分布：
- 连续 ≥10 个绿、且期间发生过返工 → 提案："审查门禁太松"（对症下药：给对应维度加判据）
- 红/黄率 > 50% → 提案："上游有系统性问题"（对症：20/21 卡加检查项，或该类任务档位该升）

**信号 2：停问热点（哪张卡最费劲）**
```powershell
Select-String -Path "docs\TECH_DEBT.md" -Pattern "来源" | Select-Object Line
```
按"来源"列统计：同一来源（同卡/同类任务）贡献债务 ≥2 次 → 提案："该卡或该类任务需要加前置检查项"。

**信号 3：教训复发（知识该升格了）**
grep docs/lessons/ 按主题关键词聚类：同主题命中 ≥2 张卡、或某卡"最近确认"被更新 ≥2 次 → 提案："升格为宪法禁令/对应卡检查项"（与 30 卡的复发升格同一出口）。

**信号 4：宪法沉默项（该删的规则）**
逐条问宪法里的禁令与检查项：archive/reviews/lessons 里**举不出任何一条因它拦截或使用的记录** → 废除候选。

**信号 5：文档孤儿行率（观察项）**
抽 docs/registry/APIS.md 与 DATA_DICT.md 各 10 行，对其路由/字段/搜索词做存在性 grep（在 src 里）：零命中行占比 > 20% → 提案："registry 已过期"（对症：强化 23 卡随批回写纪律，或给 check.ps1 加孤儿行检测脚本）。

**信号 6：并行态到期未清（旧实现该死了没死）**
读 `STATE.md` 的"并行态登记簿"表（列：`并行态 | 旧实现 | 新实现 | 删除条件（可判定） | 到期 | 登记批次`）：
- 有**到期未清**条目 → 提案："到期的旧实现立即清理"（落点：52 卡开一次清理批）
- 「删除条件」写成不可判定的（如"确认没人用了"）→ 提案："该条重写为可判定条件"

**信号 7：孤儿三查不收敛（清了但没清干净）**
跑 `powershell -File orphans.ps1`，与上一轮体检报告里的汇总行对比：孤儿 / 幽灵 / 未登记项**连续两轮不减** → 提案："清理机制失效"（对症：查 40 卡的处置规则是否被执行，或 23 卡的登记纪律）。

**信号 8：文件数膨胀（AI 生成多、删除少的总账）**
`STATE.md` 的"文件数基线" vs 当前 `git ls-files` 计数：增长超阈值（`check.ps1` 会判红）→ 提案："安排一次清理批收敛"（落点：52 卡）。阈值口径以 `check.ps1` 输出为准，体检不另立口径。

**信号 9：提交节奏失效（做完没落历史）**
读 STATE.md 的 `起点锚点` 与 `工作树状态`，跑 `git status --short` 与 `git rev-list --count <锚点>..HEAD`：
- 起点锚点连续两个任务未前移（还是上一任务的哈希）→ 提案："收尾没写锚点"
- 工作树跨会话非空（STATE 记"干净"但 `git status` 不空）→ 提案："完成定义被绕过"（对症：查 check.ps1 的 git 断言为何没拦住、卡收尾是否跳过了提交）

**信号 10：远端与推送滞后（历史只在本机）**
`git remote -v` 为空、或 STATE.md `远端仓库` 写"本地-only"、或 `git status -sb` 连续两个归档周期 `ahead N`：
- → 提案："远端与推送节奏未落地"（落点：11/12 卡接入收尾、40 卡归档收尾的远端同步）

**提案三纪律（每条提案必须过）：**
1. **信号 ≥2 次才有提案资格**——一次红灯就改规则 = 过度拟合单次事故，规则会爆炸
2. **废除类至少 1 条**——加与删必须对称；一条都提不出 → 明确写"本轮无废除候选"并说明扫过什么
3. **落到具体文件+具体条目**——❌"以后编码要更小心" ✅"宪法 §2 增加：写接口必须先在 APIS.md 登记错误码"

产出 `docs/decisions/PROCESS_<日期>_体检.md`：信号统计原文 + 提案表（信号/证据/提案/落点/类型）。
**落地分两类**：
- 宪法修订（本项目的 AGENTS.md）→ 人逐条裁决后当场改（宪法修改需人在场确认）
- **母版 playbook 修订** → 只写进提案文件，标注"带回母版执行"——卡在母版工作区，不在本项目

**禁令：**
- 禁止 agent 自行修改宪法或宣布提案通过（裁决是人）
- 禁止无信号支撑的提案（"我觉得"不合格）
- 禁止本次体检不产生任何书面结论（哪怕结论是"系统健康，无需修订"也要写明依据）
