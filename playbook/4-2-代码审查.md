## ① 开工确认

本卡必须在**没有参与编码的新会话**执行（或派一个新鲜上下文的子代理）——实现者不复核自己。

**人审替代车道（用户可选；M 档以下且变更总行数 ≤150 行、不触碰红线域时开放）**：用户说"我自己看" → 本卡降级为：整理 `git diff $anchor..HEAD` 为易读形态 + 三句话变更摘要 + 点出两个最值得人看的点，然后等用户回"过/不过"（4-3 卡 guardrail 照跑兜底）。红线域（认证/支付/删数据）不适用此车道。
**"变更总行数"的机械判据**：把 STATE.md 的起点锚点读进 `$anchor`，再跑 `git diff --shortstat "$anchor..HEAD"`——输出形如 `3 files changed, 120 insertions(+), 30 deletions(-)`，**变更总行数 = insertions + deletions 两数之和**（不用净行数：删 200 改 200 会被算成 0，掩盖大改），≤150 才开放本车道。
**人审车道的出口（三段，照此写）**：① 用户回"过" → 免交四节完整报告，只落一份 3 行替代记录（变更摘要 / 两个看点 / 用户裁决原文）到 `docs/reviews/CODE_<日期>_<slug>.md`，STATE.md `下一步` 写 4-3 验证；② 用户回"不过" → 把用户指出的位置写成 P1/P2 条目（文件:行 + 触发条件），STATE.md `下一步` 写回 4-1 修复，建议色 🔴/🟡；③ 车道走完，收尾语前的正文写 `下一步：4-3 验证（回复"继续"即执行）`。

不走路道则先回执九项，缺项不开始：

1. **人话复述与落点**：本次审的是哪个功能、哪批 diff（一句话）；产物 = `docs/reviews/CODE_<日期>_<slug>.md`；下一张卡 = 4-3 验证（红/黄回 4-1 修复）。
2. **假设清单**：逐条写"我假设 X；若错则 Y 失效"——能从项目文件查到的不许写进假设，先去查。
3. **澄清问题（≤5 个，能删则删）**：只问 STATE.md / SCOPE.md 查不到、又决定审查口径的事；一个都没有就写"无"。
4. **锚点校验**：从 STATE.md 的 `起点锚点` 读入 `$anchor` → `git log --oneline $anchor -1` 证明该提交真实存在；读不出/无效 → **停下问用户**（禁止凭 STATE 记忆硬审）。
5. **diff 读取确认**：`git diff --stat "$anchor..HEAD"` 完整输出 + **完整读取 `git diff "$anchor..HEAD"`**（回执只报"已读全量 diff，共 N 行"——未读全 diff 禁止判任何维度）。
6. **审查范围声明**：仅限本次 diff 及其直接关联调用；diff 之外一律不审（范围蔓延 = 无效审查）。
7. **引用报告清单**：docs/reviews/ 下本次相关旧报告（无则写"无"）。有旧报告 → 回执其 P0/P1 现状（已修/未修），**未核销的旧 P0/P1 沿用原编号计入本次计数**；旧 P2/P3 逐条标注（已修/未修/误报）。
   **"误报"升级为有据驳回**：标注"误报"必须同时给出反驳依据（技术理由 + 代码位置或实测输出）；写不出依据的条目按"未修"计入本轮计数，禁止用"误报"清账。
8. **引用检查清单原文**（逐字粘贴本卡 §② 的"七个固定维度"名称列表 + 严重级判据 + 建议色矩阵 + 取代与废弃检查）。
9. **派单输入单**（派子代理时逐字照抄，缺一项不许派；双轴派单各抄一份）：`DESCRIPTION` = 本次实现了什么（≤3 行）｜`PLAN_OR_REQUIREMENTS` = `docs/specs/<日期>_<slug>/SCOPE.md` 路径 + 验收标准原文｜`BASE_SHA` = `$anchor`｜`HEAD_SHA` = HEAD（`git rev-parse HEAD` 原文）。**禁令：禁止把本次会话历史、你的推理过程、你的自查结论、另一轴的发现塞给审查者——它只审工作产物。**

## ② 执行

**双轴并行审查**（每个轴一个子代理，两轴范围互不重叠）：
- **标准轴** = 本仓库已写下的标准 + 下面的气味基线表
- **规格轴** = 需求缺失或写了一半、范围外行为、实现与需求不符
- 聚合时**禁止跨轴合并**或重排发现项：分轴正是为了防止把两类问题揉成一个糊涂账而失去可判断性；报告分两节列，各轴各自编号。
- 派单仍用 ① 的派单输入单，**不在派单里塞另一轴的发现**（交叉污染 = 两轴退化成一次普通审查）。

**气味基线**（≥6 行，逐行给判据；审查者照着判，不靠感觉）：

| 气味 | 判据 |
| :-- | :-- |
| 长函数 | 超过本仓行数上限（见维度 6 的 50/500/1000 行阈值） |
| 重复代码 | 同一段逻辑出现第 2 次 |
| 参数过多 | 参数 >4 个 |
| 发散式变化 | 一个文件因多个不相关原因被改 |
| 霰弹式修改 | 一个改动要动 >3 个文件 |
| 命名不达意 | 读名字猜不出行为 |

**这些是判断题，不是硬违规**——审查者给判断与理由，不给"违规"裁定；工具已能机械强制的项（行数、格式、lint）不在审查范围内。

**AI 生成声明与查重**：审查报告若由 AI 生成，开头必须写一行 `> 本条由 AI 生成（代码审查）`；派单前先查两件事——① 同一问题是否已被提过（查 `docs/reviews/` 与 `docs/TECH_DEBT.md`）② 是否属于已被否决的提案（查 `docs/decisions/` 的被否方案段）；命中就不重复论证，只引用原记录（原记录路径 + 结论一行）。

审查按依赖拓扑分三阶段，每阶段跑完全部适用维度并独立给结论：阶段 1 数据层与后端 → 阶段 2 前端与接口集成 → 阶段 3 测试、配置、脚本、文档同步。
**阶段无 diff 覆盖 → 覆盖地图声明"无变更，跳过"，不算违规**（纯后端项目没有阶段 2 是正常现象）。

**越界的唯一出口——命名风险定点检查**：确需看 diff 之外的代码时，必须先写出「风险名 + 我要查什么」再查，一次风险查一处，报告里同时写出风险名与该处结论；说不出风险名就查 = 范围蔓延 = 无效审查。跨切面改动（锁顺序、共享可变状态、函数或接口契约变更）是合法的命名风险，按此出口走。

**七个固定维度（审查对象 = 新增与被修改的代码；被删除的符号要确认全仓库零残留引用。每阶段跑适用的，逐条给结论）：**

1. **接入性与装配**：每个新增/被修改符号有调用点（文件:行）吗？路由/依赖注入注册了吗？**有 UI 时按 SCOPE 的 UI 描述走查三层链路——①路由/挂载注册 ②入口可达（哪个已有界面能点到它？说不出具体入口 = 断）③交互元素绑定了 handler 且链到业务逻辑吗。任一层断 = P1（核心功能不可用），不是 P2**——"功能写好了但用户进不去"就栽在这。前后端项目加查：请求/响应结构与 registry/APIS.md 登记的契约一致吗（字段名/层级/类型）？
   ❌ 反例：页面组件与接口都写完了，路由表里没挂 → 判 P2"小问题，下批再说"
   ✅ 正例：走三层链路发现第 ① 层断 → 判 P1，写"文件:行 + 缺哪一层"
   **SCOPE 沉默 ≠ 许可**：diff 内出现而 SCOPE 未写的输入/环境/边界（空值、超长、未登录、慢网、重复提交、越权访问），按"一个合理用户会期待什么"判——合理期待即需求；按其对用户的实际影响定级，不因"SCOPE 没提"就不报。
2. **逻辑性**：空值/越界/并发重复提交/失败路径（不是空 catch）/入参校验，逐个新增与被修改的函数过一遍；**多步写操作（如创建+扣减）有事务边界吗——要么全成要么全败，禁止半完成状态**；异步竞态与写接口幂等（重试/重复提交不产生脏数据）；时区与日期边界、金额精度（禁浮点存钱）。
3. **牵连性**：先赋值再搜——`$sym = '新符号名'; Get-ChildItem -Path src -Recurse -File | Select-String -Pattern $sym | Select-Object Path,LineNumber` 找全调用方；**被修改符号的既有调用方逐个确认行为兼容（签名变了/默认值变了/返回结构变了 → 调用方跟上了吗）**；被删除符号确认零残留引用；核对**四份文档**需同步未同步：registry/APIS.md（接口与错误码一并）、CHANGELOG.md、registry/DATA_DICT.md、docs/TECH_DEBT.md——**任一不存在 → N/A + 原因**（禁止静默跳过或编造"已核对"）。
4. **性能**：六类典型——N+1 查询/无界查询（缺 LIMIT）/循环内 IO/大列表重复渲染/请求路径里的同步长任务/无索引 WHERE；**资源泄漏——未关闭的连接/文件/定时器/事件订阅，前端 effect 未清理**。
5. **冗余死代码**：统计每个新增与被修改符号的使用次数（用同一个搜索结果，不重复跑）；复制粘贴只改名的块；永远为真/假的分支。疑似保留必须写理由。
6. **开发规范**：命名一致性/注释写 Why 不写 What/类型安全（有无 any）/函数 >50 行、文件 >500 行要提（>1000 必拆；**测试文件豁免至 ≤1000 行**）/提交信息格式；并对照宪法 §11「代码生成硬标准」六条逐一复核（结构/命名/注释 Why/防御/可测试/环境注入）。
   ❌ 反例：页面状态写 `PENDING`、接口返回 `pending`，审查写"能跑就行"
   ✅ 正例：按"前后端业务术语同字典"判 P2，写清两处文件:行 + 统一到哪个拼法
7. **安全**：新接口都鉴权了吗（前端隐藏≠后端校验，查水平越权）/SQL 参数化/**XSS——用户输入渲染前转义了吗；CSRF——写操作有 token/SameSite 防护吗**/上传验类型大小/路径防 ../ /密码用强哈希（bcrypt/argon2/scrypt），禁 MD5/SHA1/明文/密钥硬编码/日志脱敏（密码手机号 token）/CORS 非 */debug 关闭/**本次新增依赖查已知漏洞（npm audit / pip-audit 输出）且 lockfile 已提交**。

**四个条件维度（按触发启用；不适用写 N/A + 原因，不许留空）：**
⑧ UI 可访问性（含前端时）：状态齐全/对比度/触摸目标 44px/空态错误态
⑨ 外部调用（新改第三方时）：适配层/显式超时/降级/Webhook 验签+幂等
⑩ 性能预算（热路径改动时）：有预算文件则对照 P95/包体积/查询耗时；**项目无预算文件 → 按维度 4 六类定性判断并标注"无预算基线"**
⑪ 数据隐私（涉个人信息时）：D3/D4 字段加密/日志脱敏/用途限定

**错误码闸**：新增错误码必须能在 `docs/registry/APIS.md` 查到并已登记，给 `Select-String` 搜索结果。

**越界检查（违反即红旗）：** 语义性"顺手/顺便优化"（改逻辑/重命名/重构无关代码）→ 建议一律 revert；**纯机械格式化**（prettier/black 等工具产物）→ 不 revert，说明工具来源，建议拆为独立格式化提交（revert 了 lint 还会要求它，死循环）；出现 SCOPE 从未讨论的文件 → 红旗，要求解释。

**取代与废弃检查（命中即红灯，直接判建议色 🔴；本卡只审不修，修复回 4-1）：**
1. **并行实现未删**：本批触及的文件里出现"被取代但未删除"的旧实现（旧文件/旧函数/旧分支/旧常量），且 `STATE.md` 的并行态登记簿无对应登记行 → 红灯。
   登记行格式固定（列名一字不改）：`并行态 | 旧实现 | 新实现 | 删除条件（可判定） | 到期 | 登记批次`。
   有登记行也要核两条：删除条件可判定吗？到期批次是否已过（已过仍未删 → 红灯）？
   合法保留理由只有三种：①灰度/回滚（带期限）②对外兼容契约（带弃用期）③证据留存——**证据留存的答案是 git 历史**，工作树里出现第二份证据副本（`.bak`、`旧版/`、`副本 2`）即违规（本卡内联：本批新建 `xxx_v2.ts` 又留旧 `xxx.ts` 都算）。
   ❌ 反例：新建 `xxx_v2.ts` 实现一遍、旧 `xxx.ts` 留着"以防万一"，登记簿无行 → 判 P2 放过
   ✅ 正例：同批删旧 + 登记行删除条件可判定 + 到期批次未过 → 通过项里写明核销证据
2. **废弃标记未申报**：本批**新增行**命中 `_old\b|_legacy|_v2\b|Deprecated|暂时保留|废弃|TODO[:：]\s*(删|remove|delete)` 任一（正文与命令逐字同一套正则，不许宽严不一）→ 必须在报告里写明保留理由与（若有）删除条件，否则红灯。

```powershell
$anchor = (Select-String -Path STATE.md -Pattern '起点锚点\s*[:：]\s*([0-9a-fA-F]{7,40})').Matches[0].Groups[1].Value   # $anchor 从 STATE.md 的「起点锚点」字段读，不许手打
git rev-parse --verify "$anchor^{commit}"; if ($LASTEXITCODE -ne 0) { throw "锚点无效：停下问用户——空输出 ≠ 0 命中" }
git diff -U0 "$anchor..HEAD" | Select-String '^\+' | Select-String '_old\b|_legacy|_v2\b|Deprecated|暂时保留|废弃|TODO[:：]\s*(删|remove|delete)'
```
（它覆盖整批全部提交，`HEAD~1` 只看最后一笔会漏。**空输出也是证据**：命令原文与输出一起贴进回执与报告并写明"锚点断言已通过"——否则"0 命中"与"命令失败"不可区分；命中行逐条贴进问题清单，每条给"已申报/未申报"判定。）

**严重级判据（只用这四级，不确定按 P2）：**
- P0 = 崩溃/数据丢失/安全漏洞 ｜ P1 = 核心功能不可用（含装配断链）→ 两者**必须清零，禁止合入**
- P2 = 边缘功能报错/体验不佳 ｜ P3 = 拼写/样式/非关键提示 → 登记 `docs/TECH_DEBT.md`（来源=本报告编号），报告内保留编号引用；P3 台账登记可延后

**建议色矩阵（唯一判色依据）：** 🔴 红 = P0≥1 或 P1≥1（**含旧报告未核销的 P0/P1**）或"取代与废弃检查"命中（登记簿缺行 / 废弃标记未申报）｜ 🟡 黄 = P0=P1=0，但有 P2/P3 或待用户裁决的取舍｜ 🟢 绿 = P0=P1=0 且旧报告 P0/P1 全部核销。

**禁令：**
- 禁止修改任何代码（本卡只审不修；修复回 4-1）
- 禁止只给结论不给依据（必须文件:行 + 触发条件）；禁止跳过维度或阶段（不适用写 N/A + 原因）
- 禁止自行宣布通过（只给建议色，裁决是人）；P3 也要列出来，不许"问题太小"省略
- 禁止把"被取代未删除"降级成 P2 放过（它是红灯，只有删除或登记两条路）
- 禁止只看到废弃标记不给判定（每条命中都要写"已申报（理由 X）/未申报=红灯"）
- 禁止审查者再派子代理（**唯一的例外是 ② 段双轴并行审查的标准轴与规格轴这两个子代理**；两轴之外无论审 diff 的一部分还是要第二意见都不许派）——审查席位只有这一次，再派的结论不计入证据；审查期间禁止动工作树/索引/HEAD/分支状态

## ③ 证据回执

报告写入 `docs/reviews/CODE_<日期>_<slug>.md`（重审时新建文件，头部引用前次报告路径），格式固定四节：
1. **覆盖地图**：文件 × 维度勾选表（✓ 已审 / — N/A+原因 / ○ 未审+必须给原因；含阶段跳过声明）
2. **问题清单**：按 P0→P3 排序，每条含 编号(新 R-01…；旧问题沿用原编号)/级别/位置(文件:行)/描述/影响(触发条件)/修复建议
3. **通过项**：逐维度 ✅ 通过（覆盖范围）+ 双轴各自的通过项（两轴分节，不合并）
4. **结论**：四级计数（含旧问题核销结果）+ 按"建议色矩阵"给出的建议色 + 取代与废弃检查结论（并行态登记行数 / 废弃标记命中数 / 各条是否已申报）

对话中回执：报告路径 + 四级计数 + 建议色 + 取代与废弃检查结论 + **废弃扫描命令原文与其完整输出（空输出也照贴，并注明锚点断言已通过）**；然后写 `下一步：4-3 验证（回复"继续"即执行）`。

## ④ 状态回写

**先回写，后提交**（状态回写必须早于提交；顺序反了 = STATE.md 游离未提交，4-3 卡的收工仪式必判红）。更新 STATE.md：
- `下一步` = 4-3 验证（建议绿）或 回 4-1 修复（建议红/黄，注明修复哪些条目编号）
- `未决问题` = 需要用户裁决的 P2 及以上取舍

回写完再收尾三连（顺序不可换：回写状态 → 提交 → 复跑收工仪式取 0）：
