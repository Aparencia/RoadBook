> 触发：项目首次成型 / 结构变更（新增或移除模块、换存储、拆或合服务） ｜ 产物：docs/ARCHITECTURE.md ｜ 下一张：3-1 设计（L 档）或 4-1 分批编码
> 过程域：ARCH

## ① 开工确认

收到开工指令后，先回执以下五项再动手（缺项不开始）：

1. **任务复述**：用一句人话说清"这个系统的边界画在哪、由哪几块组成、哪条质量要求决定了现在的形状"。
2. **假设清单**：逐条写"我假设 X；若错则 Y 失效"（例：我假设只跑在单机上；若错则数据视图与部署视图都要重画）。能从 package.json、SCOPE.md 查到的不许写进假设。
3. **澄清问题（≤5 个，能删则删）**：只问决定形状的硬信息——这东西最终给谁用？会不会有第二个进程／第二台机器？数据丢了要能从哪恢复？哪一项指标一旦不达标整件事就废？
4. **本卡检查清单原文（开工时逐字复述这十一条，收工前逐条勾）**：
   - [ ] ① 边界三问写全：**是什么**（一句话，≤40 字）／**不做什么**（≥3 条，含最容易被顺手加进来的那一条）／**外面有什么**（外部系统与人的清单）
   - [ ] ② 干系人与关注点表：每个干系人给 ≥1 条关注点，每条关注点指明"哪个视图回答它"（没有视图认领的关注点 = 本卡未完成）
   - [ ] ③ 视图四张齐：上下文 / 模块 / 运行时 / 数据；一张一屏；纯后端无界面也要给上下文与运行时
   - [ ] ④ 模块视图里每个组件给"职责一句话 + 依赖方向"；**依赖方向画成有向图，禁双向、禁环**
   - [ ] ⑤ 运行时视图给 ≥3 条关键场景的时序（触发 → 步骤 → 落点），含一条失败路径
   - [ ] ⑥ 数据视图写清"数据住在哪 / 谁是事实源 / 副本有几份 / 备份与恢复粒度"
   - [ ] ⑦ 质量属性场景 ≤5 条，每条三要素：**刺激 → 响应 → 度量**；度量必须能对上 2-4 的 NFR 阈值或显式写"暂无阈值"
   - [ ] ⑧ 权衡记录 ≥3 条：选了 A 就要放弃 B、"获取一个好处要付的代价"写在同一行
   - [ ] ⑨ 演化口子 ≥2 条：现在不做、但以后要做时改哪一处（不许写"以后再说"）
   - [ ] ⑩ 与设计/注册表分界：架构答"系统是什么"（半年不变），设计答"这次怎么做"（这次变）；两份文档不得互相抄同一段
   - [ ] ⑪ 落点 `docs/ARCHITECTURE.md` 落盘，STATE.md `下一步` 写明去 3-1 还是 4-1
5. **落点声明**：产物 = `docs/ARCHITECTURE.md`；下一张卡 = L 档走 3-1 设计，其余直接 4-1 分批编码。

## ② 执行

**合理化红旗表（开工时逐条念；出现任一条 = 停下按本卡补做）**

| 你会想 | 事实 |
| :-- | :-- |
| 画个模块图就够了 | 模块图只回答"由什么组成"，回答不了"为什么是这样"。没有权衡记录的架构图 = 一张装饰图 |
| 架构一次定好就不用再改 | 结构变更时**必须**回来增量更新，否则文档与代码分家——分家后第一件事就是没人再看它 |
| 我脑子里清楚，不用写 | 架构的受益人是**下一个会话的你和下一个 agent**；不落盘的架构等于不存在 |
| 这属于设计细节，留给 3-1 写 | 3-1 是"这次改动怎么做"的施工图；把它当架构用，会导致每次改动都要重读一遍全库 |

**动作 1：边界三问（先钉边界，再谈里面）**

| 问题 | 写法 | 反例 |
| :-- | :-- | :-- |
| 这是什么 | 一句话 ≤40 字，不带技术名词 | "一个用 React 写的看板"（说的是实现，不是系统） |
| 不做什么 | ≥3 条，含最容易被顺手加进来的那条 | 只写"不做移动端"——漏掉"不做多租户" |
| 外面有什么 | 外部系统／人／定时任务，逐条写谁主动谁被动 | 把数据库算成外部系统（它是系统内部的数据视图） |

**动作 2：干系人与关注点（每一个关注点都要有视图认领）**

单人档不跳过这一步——**干系人是"未来的自己"这一类角色**，不是组织架构：

| 干系人 | 典型关注点 | 由哪个视图回答 |
| :-- | :-- | :-- |
| 用户 | 打开就能用吗、错了知道怎么办吗 | 上下文视图 + 运行时视图（失败路径） |
| 未来的我 | 改一处要动几处、加个功能会不会塌 | 模块视图（依赖方向） |
| 运维的我 | 挂了怎么知道、数据丢了怎么回来 | 数据视图 + 运行时视图 |
| 下一个 agent | 从哪开始读、哪些是禁区 | 全部视图 + 边界三问 |

**动作 3：视图四张（一张一屏，多了就是没抽象）**

| 视图 | 必须回答 | 最小画法 |
| :-- | :-- | :-- |
| 上下文 | 系统边界、外部参与者、数据怎么进出 | 一个框 + 外部实体 + 带方向箭头的连线，每条线写清传什么 |
| 模块 | 由哪几块组成、各自职责、谁依赖谁 | 组件清单表 + 依赖有向图；**箭头只有一个方向** |
| 运行时 | 关键场景跑起来是什么顺序 | ≥3 条时序（含一条失败路径），每步写清落在哪个组件 |
| 数据 | 数据住在哪、谁是事实源、怎么备份 | 实体表 + 事实源标注 + 副本与恢复粒度 |

**动作 4：质量属性场景（架构存在的理由；阈值不许自己编）**

每条三要素写全：**刺激**（谁在什么条件下触发）→ **响应**（系统做什么）→ **度量**（多少秒／多少条／多大概率）。

| 属性 | 场景示例（刺激 → 响应 → 度量） |
| :-- | :-- |
| 性能 | 首屏请求到达 → 返回列表页 → P95 ≤ NFR 里写的那个毫秒数 |
| 可用性 | 单个依赖超时 → 降级返回缓存并提示 → 30s 内自恢复，用户不看到白屏 |
| 可维护 | 换掉存储实现 → 只改适配层一处 → 调用方零改动 |
| 安全 | 未登录直达内部页 → 跳登录并回到原地址 → 无数据泄漏 |
| 容量 | 数据涨到 N 倍 → 列表仍分页 → 单页查询耗时不超过基线 2 倍 |

**阈值来源铁律**：能对上 `2-4 非功能需求` 的阈值就逐字引用；对不上就写 `暂无阈值（理由）`——**禁止现编一个好看的数**（编出来的阈值会在半年后被人当成事实）。

**动作 5：依赖方向（架构里唯一能用机器判定的一条）**
- 依赖必须是一个方向：`A → B` 表示"用 B 不改 B 的契约"
- **禁双向**：A 用 B 而 B 又用 A = 两块其实是一块，合并或抽出第三个中间件
- **禁环**：A → B → C → A 的环上任何一处改动都会牵动全环
- **禁跨层**：界面层不许直接连数据层；跨了就必须有适配器，且适配器只能有一个
- 画完图跑一次自查（动作 8），环与双向会被脚本点名

**动作 6：权衡记录（没有代价的架构方案不存在）**

每条写成一行：`选了 X ｜ 换来 Y ｜ 代价 Z ｜ 什么条件下翻案`。

| 例子 | 换来 | 代价 | 何时翻案 |
| :-- | :-- | :-- | :-- |
| 单进程单体 | 部署与调试简单 | 无法单独扩容某一块 | 单块 CPU 长期打满 |
| 本地文件当存储 | 零运维 | 换机器要搬文件 | 出现第二个写入者 |
| 同步调用 | 结果确定、好测 | 慢依赖拖慢全局 | P95 超阈值且降级无效 |

**动作 7：演化口子与决策留痕（现在不做的事，要留一条缝）**
- 演化口子 ≥2 条：写清"以后要做时改哪一处"，例如"多用户 → 在数据视图的 X 实体加 owner 字段并只改适配层"
- 关键决策逐条进 `docs/decisions/`（走 `3-1 设计的决策记录`口径）；被否的方案也要留名，否则半年后会有人（就是你自己）再提一次
- 决策的复核日期写进卡片，到期由 `6-8 决策复盘` 收

**动作 8：架构自查（在项目根跑；非开发者只看退出码：exit 1 = 本卡未完成）**
变量名一律 ASCII：Windows PowerShell 5.1 读无 BOM 的 .ps1 时中文变量名会报『字符串缺少终止符』；脚本必须存成 UTF-8 带 BOM。
```powershell
$m = 'docs/ARCHITECTURE.md'
$l = @(Get-Content $m -Encoding UTF8)
$txt = $l -join "`n"
$views = @('上下文','模块','运行时','数据') | Where-Object { $txt -match $_ }
$tri   = @($l | Where-Object { $_ -match '刺激|响应|度量' }).Count
$tr    = @($l | Where-Object { $_ -match '代价' }).Count
$gap   = @($l | Where-Object { $_ -match '演化口子|以后要做' }).Count
"ARCHITECTURE.md 行数 $($l.Count)（要求 ≤150）"
"视图命中 $($views.Count)/4（要求 4）：$($views -join ' ')"
"质量属性三要素行 $tri（要求 ≥5）；权衡代价行 $tr（要求 ≥3）；演化口子行 $gap（要求 ≥2）"
if ($l.Count -gt 150 -or $views.Count -lt 4 -or $tri -lt 5 -or $tr -lt 3 -or $gap -lt 2) { Write-Host '[FAIL] 本卡自查未过'; exit 1 } else { Write-Host '[OK] 本卡自查通过' }
```

**禁令（违反任意一条 = 本轮输出作废）：**
- 禁止把架构写成实现清单（列框架、列库、列文件不算架构）
- 禁止无度量的质量属性（"要快""要稳"= 没写）
- 禁止出现双向依赖或依赖环——被脚本点名就必须改结构或改图，不许改脚本
- 禁止现编阈值：对不上 NFR 就写 `暂无阈值（理由）`
- 禁止只画一张图就宣布完成（四张视图缺一即未完成）
- 禁止把架构文档写成设计文档（两份不得出现同一段正文）
- ❌ 反例：一页目录树 + "采用分层架构" ｜ ✅ 正例：四张视图 + 五条带度量的场景 + 三条带代价的权衡
