**动作 1：文案外置（禁止界面硬编码字符串）**
```powershell
Get-ChildItem -Path src -Recurse -File | Select-String -Pattern '[\u4e00-\u9fa5]' | Where-Object { $_.Path -notmatch 'locales|i18n' } | Select-Object Path, LineNumber
```
Expected：⚠️ 这条围栏**在本机是空转**：`Get-ChildItem … | Select-String` 吃不到文件内容——`Select-String` 的 `-Path` 不吃管道（实测 `ValueFromPipeline = False`），FileInfo 走 `-InputObject` 时既不读内容也不匹配文件名。三组实测：内容含中文的 `ascii-name.ts` 0 命中、**文件名**含中文的 `这个文件名是中文.ts` 0 命中、`-Pattern 'ascii-name'` 也 0 命中；同一批文件改成 `Select-String -LiteralPath $_.FullName` 立刻命中 1 条（`const t = '保存成功';`）。⇒ 屏上那张**空表**不等于"没有硬编码中文"：`$?` 仍 True、`$LASTEXITCODE` 保持空。`src` 不存在时同样静默 0 项（`-Recurse` 会把 not-found 吞掉；去掉 `-Recurse` 才打 `找不到路径…`）。修法见 TD-033。
（注：本机 PowerShell 5.1 里 `-Recurse` 不是 `Select-String` 的合法形参，只有上面的管道式递归可跑）
- 命中行逐条处理：搬进语言包（`locales/zh-CN.json` 等），组件里改成取键；确实不该外置的（正则、日志）写进白名单并注明理由。
- ❌ 反例：`<button>保存</button>`（界面字符串写死在组件里）
- ✅ 正例：`<button>{{ t('common.save') }}</button>` + `locales/zh-CN.json` 里 `"common.save": "保存"`

**动作 2：语言与区域表（4 列 5 行，写进 docs/I18N.md）**

| 项 | 中文（zh-CN） | 第二语言示例（en-US） | 口径 |
| :-- | :-- | :-- | :-- |
| 界面语言 | 中文 | English | 默认跟随系统，可手动切换 |
| 日期 | 2026-10-03 | Oct 3, 2026 | 一律用语言包格式化，禁止手拼 |
| 数字 | 1,234.56 | 1,234.56 | 千分位与小数分隔符按地区，不写死 |
| 货币 | ¥1,234.56 | $1,234.56 | 金额必须带币种代码（CNY/USD），不靠符号猜 |
| 时区 | UTC+8 展示 | 用户时区展示 | 存储一律 UTC，展示时转换 |

**动作 3：三个经典陷阱（每个给 ❌✅）**
1. 复数：
   ❌ `count + ' items'`（英文会出现 "1 items"）
   ✅ `t('items', { count })` + 语言包按 `one/other` 分支
2. 时区：
   ❌ 直存本地时间（`DateTime.Now` / `new Date()`），换个时区看就错一天
   ✅ 存储 UTC，展示时按用户时区转换；跨天统计写明以 UTC 为口径
3. 字符串拼接：
   ❌ `'删除 ' + name + ' 吗？'`（语序因语言而异，翻译必错）
   ✅ 整句模板 `t('confirm.delete', { name })`

**动作 4：可访问性七条（每条给验证方式）**

| 项 | 判据 | 验证方式 |
| :-- | :-- | :-- |
| 键盘可达 | Tab 能到所有可交互元素，焦点不丢 | 只用键盘走完主路径（Tab / Shift+Tab / Enter / Esc），记录卡住的位置 |
| 对比度 | 正文 ≥4.5:1，大字 ≥3:1 | 浏览器 F12 取色器核对前景与背景色值，或用 axe DevTools 扫描 |
| 语义标签 | 用 button/nav/main/h1~h3，不用 div 冒充 | F12 看标签名；`<div onclick` 命中即不合格 |
| 图片替代文本 | 有意义的图有 alt，装饰图 `alt=""` | `Get-ChildItem -Path src -Recurse -File | Select-String -Pattern '<img'` 后逐行看 alt |
| 焦点可见 | 聚焦态有可见样式（outline 或边框） | `Get-ChildItem -Path src -Recurse -File | Select-String -Pattern 'outline:\s*none'`；再用 Tab 目检焦点环 |
| 表单标签 | 每个输入有 label 或 aria-label | F12 或 axe 扫描；`<input` 逐行核对 |
| 触摸目标 | 可点区域 ≥44×44 px | F12 量元素盒子尺寸；不足则在 CSS 补 padding 或 min-height |

**动作 7：可访问性实测三条命令（在项目根跑；先把本地服务起起来，端口按实际改）**
```powershell
npx --yes @axe-core/cli http://localhost:3000 --exit
npx --yes pa11y http://localhost:3000 --standard WCAG2AA
npx --yes lhci autorun --only-categories=accessibility --collect.url=http://localhost:3000
```
Expected：三条命令之间**没有任何退出码检查**，看得见的只有各自输出、能取到的退出码只有最后一条 ⇒ 必须逐条单独跑并各记一次 `$LASTEXITCODE`。本机实测：`@axe-core/cli --help` 退出码 0（首次 npx 解析下载约 20 秒）；`@axe-core/cli http://localhost:3000 --exit` 在**没装 Chrome** 的机器上 3 秒后退出码 **1**（`SessionNotCreatedError: session not created / from unknown error: cannot find Chrome binary`，输出带 ANSI 转义）；`pa11y http://localhost:3000` 无服务时约 34 秒后退出码 **1**（puppeteer 连不上，尾部是 `CdpPage.goto` 栈）。⚠️ **`lhci` 不是 Lighthouse CI**：npm 上那个 `lhci` 是占位包（`description: placeholder …`、4.1.2、339 字节），原样跑只打一行 `Hello, this is AnupamAS01!` 并**退出码 0**——整条围栏的退出码因此是 0（假绿）；真包是 `@lhci/cli`（0.15.1，命令名才叫 `lhci`）。修法见 TD-034。
- 判据：axe 退出码 0（零 violations）／pa11y 退出码 ≤1 且错误逐条登记／lighthouse 可访问性分 ≥90。
- 三条命令的完整输出贴进 ③ 回执；每条失败项写进 `docs/I18N.md` 未达标表（含到期与责任人）。
- ❌ 反例：贴一张截图说"看起来没问题"（没有命令输出 = 没有证据）
- ✅ 正例：贴 axe 的 `0 violations` 那一行 + pa11y 的 `0 errors` 那一行 + lighthouse 分数行
