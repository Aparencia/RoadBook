# 卡 4-6 · 可用性验证（把做出来的东西拿给人用，看他在哪卡住）
> 触发：交付前要给人用（有界面 / 有真实使用者） ｜ 产物：docs/specs/<日期>_<slug>/USABILITY.md ｜ 下一张：5-1 归档
> 过程域：VER

---

## ① 开工确认

收到开工指令后，先回执以下五项再动手（缺项不开始）：

1. **任务复述**：用一句人话说清"让谁、在什么起点上、做哪几件事，我怎么判断他做没做明白"。
2. **假设清单**：逐条写"我假设 X；若错则 Y 失效"（例：我假设测试者从没见过这个界面；若错则任务 1 测不出问题）。能从 SCOPE.md、UI.md 查到的不许写进假设。
3. **澄清问题（≤5 个，能删则删）**：只问决定任务设计的硬信息——第一次打开时他手上有什么？他为什么要用（自己的目标是什么）？有没有不能失败的场景？能录屏吗？多久内要结论？
4. **本卡检查清单原文（开工时逐字复述这十二条，收工前逐条勾）**：
   - [ ] ① 与 `4-3 验证` 的分界写明：4-3 答"功能是否跑通"（命令退出码），本卡答"人是否用得下去"（行为观察）；**两边的证据不得互相顶替**
   - [ ] ② 任务设计 3–5 个，每个写全四件：**场景一句话 + 起点状态 + 成功判据 + 停止条件**
   - [ ] ③ 至少一个任务是"第一次用它"的冷启动路径（从零开始，不许先教）
   - [ ] ④ 参与者 ≥1 人且**不是写代码的人**；单人档没有第二个人时走"冷启动自测"分支并显式声明（见动作 3）
   - [ ] ⑤ 观测表按任务逐行记六列：完成/放弃、用时、求助次数、卡住的确切位置、**原话**、我的猜测
   - [ ] ⑥ 只记**行为与原话**，不记"你觉得好不好用"这类意见题（意见题答案不作证据）
   - [ ] ⑦ 每个问题定级：**阻断**（做不完）/ **摩擦**（做得慢或做错一次）/ **皮痛**（抱怨但不影响完成）
   - [ ] ⑧ 每个问题落三选一处置：改 / 登记为技术债 / 显式接受并写理由——**不许有"待观察"这种不落地状态**
   - [ ] ⑨ 结论至少给一条**可执行改动**（写清改哪个文件或哪个控件），或写"本次不改 + 理由"
   - [ ] ⑩ 未达标项必须留在文档里，不许因为后来改好了就删（删除 = 抹掉本轮结论）
   - [ ] ⑪ 落点 `docs/specs/<日期>_<slug>/USABILITY.md`，STATE.md `下一步` 写 5-1 归档
   - [ ] ⑫ 走动作 8 自查命令，退出码 0
5. **落点声明**：产物 = `docs/specs/<日期>_<slug>/USABILITY.md`；下一张卡 = 5-1 归档。

## ② 执行

**合理化红旗表（开工时逐条念；出现任一条 = 停下按本卡补做）**

| 你会想 | 事实 |
| :-- | :-- |
| 我自己点了一遍，都通 | 你自己点的路径是你自己设计的；你知道每个按钮在哪。**知道答案的人测不出可发现性** |
| 4-3 已经全绿了，不用再测 | 4-3 的绿证明"能跑通"，证明不了"看得懂"。大量失败发生在功能全对而人找不到入口时 |
| 问一句"你觉得怎么样"就够了 | 意见题拿到的是礼貌，不是数据。要拿的是"他在哪一步停了 8 秒" |
| 他做错了，是用户不会用 | 默认判据正好相反：**人做错了先假设界面没写清**，除非你能指出他看到过正确提示 |
| 就一个人，样本太小没意义 | 5 个人能抓到 ~85% 的可用性问题，1 个人也能抓到最粗的那一类；**0 个人什么都抓不到** |

**动作 1：先划清与 4-3 的界（防证据顶替）**

| | `4-3 验证` | 本卡（4-6） |
| :-- | :-- | :-- |
| 问的问题 | 功能对不对、命令退不退出 0 | 人能不能自己做完 |
| 证据形态 | 命令输出、断言、覆盖 | 行为记录、原话、卡住位置 |
| 失败长什么样 | 红 | 人停在原地、反复点、放弃 |

一句话：**4-3 的绿不能当本卡的证据，本卡的观察也不能推翻 4-3 的红**。两者都绿才算交付前过关。

**动作 2：任务设计（3–5 个，写全四件）**

| 字段 | 写法 | 反例 |
| :-- | :-- | :-- |
| 场景一句话 | 用使用者的目标说，不用功能名 | "测试导出功能"（这是功能名，不是目标）。正例："把上个月的记录交给同事" |
| 起点状态 | 从哪个页面、什么数据量、登录还是没登录 | 不写 → 每次跑的结果不可比 |
| 成功判据 | 可观察的结果（界面上出现什么 / 文件落在哪） | "他觉得好用" |
| 停止条件 | 多少分钟 / 求助几次后停 | 不写 → 会一直陪着测完，测不出问题 |

**任务配额铁律**：至少 1 个冷启动任务（第一次用它，没人教）+ 至少 1 个**高频任务**（用户每天要做的那个）+ 至多 1 个边角功能。**边角功能不许占多数**——测边角最省事，也最没用。

**动作 3：参与者（人从哪来）**

| 分支 | 何时用 | 怎么做 | 证据强度 |
| :-- | :-- | :-- | :-- |
| 真人旁观 | 能找到非开发者（同事、朋友、目标用户） | 1–3 人，**≥1 人**；只念任务，不解释界面 | 强 |
| 冷启动自测 | 单人档且找不到第二个人 | 关掉全部上下文（不看代码、不看本轮改动记录、不看本卡），隔 ≥1 天后再走一遍；**全程录屏或逐屏截图** | 中（必须显式声明，不许伪装成真人测试） |
| 远程异步 | 时间对不上 | 给任务卡 + 让对方录屏回传，自己按观测表回看 | 中 |

**冷启动自测的硬要求**：不许一边看代码一边测（那是复查，不是可用性验证）；每卡住一次，先写"我卡在哪、我期待看到什么"，再去查原因。

**动作 4：观测表（只记行为与原话，六列）**

| 任务 | 结果 | 用时 | 求助次数 | 卡住的确切位置 | 原话 | 我的猜测 |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- |
| T1 第一次打开 | 完成／放弃 | 秒 | 次 | 页面 + 控件 + 他在找什么 | 逐字记 | 先记完再猜 |

规则：
- **原话逐字记**，不要转述成"他表示找不到"——转述会丢掉线索（"那个…保存的东西" 说明他不记得这个功能叫什么，这是命名问题）
- **猜测单独一列**，与观察分开；两种混在一起写 = 证据被解释污染
- 沉默也算数据：**停住 ≥8 秒**就在"卡住的确切位置"里记一笔，并写下他当时盯的是哪一块
- 求助要分两种：问"这个按钮是什么意思"（文案问题）与问"我该去哪"（信息架构问题）

**动作 5：定级与处置（每个问题都要落地，三选一）**

| 级别 | 判据 | 处置倾向 |
| :-- | :-- | :-- |
| 阻断 | 任务做不完，或做完了但结果错 | 本批必须改；改不了就登记技术债并写清影响谁 |
| 摩擦 | 做完了，但慢、绕路、要重试 | 能改就改；改不动登记技术债 |
| 皮痛 | 抱怨了，但没影响完成 | 显式接受并写理由（别为了消抱怨改坏别的东西） |

处置写法：`问题 → 级别 → 改哪个文件/控件 或 登记到 TECH_DEBT.md 第几行 或 接受（理由）`。

**动作 6：结论（必须可执行，或明确不改）**
- 结论段落至少一句是**动宾结构 + 落点**："把 X 页面的 Y 按钮文案从 A 改成 B"，或"本次不改（理由：目标用户是本人，冷启动自测未出现阻断）"
- 把最刺眼的那一条放第一行——报告是给自己未来看的，先给结论再给数据
- 禁止把结论写成"整体体验良好"这类无落点的话

**动作 7：与相邻卡的接线**

| 情形 | 去哪 |
| :-- | :-- |
| 观察暴露的是需求没定清（两拨人要做的事不一样） | 回 `2-2 需求范围` 补范围，不在本卡改 |
| 暴露的是文案、层级、控件规格 | 走 `7-1 UI 改动`（带本卡文档当输入） |
| 暴露的是功能缺失 | 回 `2-1 功能调研` 立项 |
| 暴露的是无障碍问题（键盘走不通、对比度不足） | 走 `7-6 国际化与可访问性` |

**动作 8：可用性验证自查（在项目根跑；非开发者只看退出码：exit 1 = 本卡未完成）**
变量名一律 ASCII：Windows PowerShell 5.1 读无 BOM 的 .ps1 时中文变量名会报『字符串缺少终止符』；脚本必须存成 UTF-8 带 BOM。
```powershell
$m = 'docs/specs'
$f = @(Get-ChildItem $m -Recurse -Filter 'USABILITY.md' -ErrorAction SilentlyContinue | Sort-Object LastWriteTime -Descending)
if ($f.Count -eq 0) { Write-Host '[FAIL] 找不到 USABILITY.md'; exit 1 }
$p = $f[0].FullName
$l = @(Get-Content $p -Encoding UTF8)
$txt = $l -join "`n"
$task = @($l | Where-Object { $_ -match '^\|\s*T[0-9]' }).Count
$lvl  = @('阻断','摩擦','皮痛') | Where-Object { $txt -match $_ }
$act  = @($l | Where-Object { $_ -match '改哪个|登记到|接受（理由' }).Count
$cold = @($l | Where-Object { $_ -match '冷启动' }).Count
"USABILITY.md $p 行数 $($l.Count)"
"任务行 $task（要求 3-5）；级别命中 $($lvl.Count)/3；处置行 $act（要求 ≥1）；冷启动命中 $cold（要求 ≥1）"
if ($task -lt 3 -or $task -gt 5 -or $lvl.Count -lt 3 -or $act -lt 1 -or $cold -lt 1) { Write-Host '[FAIL] 本卡自查未过'; exit 1 } else { Write-Host '[OK] 本卡自查通过' }
```

**禁令（违反任意一条 = 本轮输出作废）：**
- 禁止把 `4-3 验证` 的命令输出当可用性证据
- 禁止只测自己（唯一的例外是显式声明的冷启动自测分支，且必须有录屏或逐屏截图）
- 禁止引导：不许在任务里说按钮叫什么、在哪一栏、先点哪里
- 禁止用"你觉得好用吗"代替行为观察
- 禁止在观察列里写猜测（猜测只能进"我的猜测"列）
- 禁止把未达标项从文档里删掉
- ❌ 反例：自己点了三遍都通，写一句"体验流畅" ｜ ✅ 正例：3 个任务 + 1 人旁观 + 六列记录 + 2 条阻断定级 + 2 条带落点的改动
