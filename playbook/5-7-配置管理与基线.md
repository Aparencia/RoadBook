# 卡 5-7 · 配置管理与基线（同一个事实只许写一处；写下来的东西必须有人读）
> 触发：发版前 / 新增或删除配置项 / 发现同一事实在两处说法不一致 ｜ 产物：docs/BASELINE.md ｜ 下一张：5-2 发布 或 5-1 归档
> 过程域：CM

---

## ① 开工确认

收到开工指令后，先回执以下五项再动手（缺项不开始）：

1. **任务复述**：用一句人话说清"哪些东西算受控项、它们的版本/口径由谁说了算、这次要定在哪一个点上"。
2. **假设清单**：逐条写"我假设 X；若错则 Y 失效"（例：我假设只有一处写版本号；若错则基线要重打）。能从仓库文件里查到的不许写进假设。
3. **澄清问题（≤5 个，能删则删）**：只问决定受控范围的硬信息——这次要发的是哪几个产物？有没有两个地方都写着版本／清单？有没有人（或脚本）在读这些字段？
4. **本卡检查清单原文（开工时逐字复述这十二条，收工前逐条勾）**：
   - [ ] ① 配置项清单列出并**逐条给识别判据**（改了要通知别人／别人靠它工作／它有两份以上副本——命中任一即受控）
   - [ ] ② **单一事实源表**：每类事实指明唯一权威位置，其余位置标注"派生视图（从 X 生成）"
   - [ ] ③ **死元数据排查**：写出长期不变、且没有任何代码／流程读它的字段，逐条给"删除／接上机器检查"的结论
   - [ ] ④ 副本一致性检查跑过，输出逐条列在文档里（一致 / 不一致 + 实际值）
   - [ ] ⑤ 基线四要素齐：**tag + 变更日志节 + 归档目录 + 校验和（或可复现的取值命令）**
   - [ ] ⑥ 基线声明写清"基线一旦发布不许移动"（打错就发新号，历史不动）
   - [ ] ⑦ 变更控制表：列出**必须走 `2-1 功能调研` 的改动**（改门禁口径／改判据／改宪法／改卡头格式／改对外契约），其余归"可直接改"
   - [ ] ⑧ 变更影响面三问答全（谁在读它／几处副本／怎么验证改对了）
   - [ ] ⑨ **状态记账**：STATE.md 的并行态登记簿逐条核对（到期未清的写处置），未清项不许静默留在表里
   - [ ] ⑩ 落点 `docs/BASELINE.md` 落盘，STATE.md `下一步` 写明去 5-2 还是 5-1
   - [ ] ⑪ 走动作 8 自查命令，退出码 0
   - [ ] ⑫ 未决问题（用户没定的受控范围）逐条进 STATE.md
5. **落点声明**：产物 = `docs/BASELINE.md`；下一张卡 = 5-2 发布（要发版）或 5-1 归档（不发版）。

## ② 执行

**合理化红旗表（开工时逐条念；出现任一条 = 停下按本卡补做）**

| 你会想 | 事实 |
| :-- | :-- |
| 就我一个人开发，不用配置管理 | 死元数据正是单人项目的高发症：**没人读的字段会一直留在那里，长得很像事实**。本仓实测过一次——四个子包版本号长期停在 `0.1.x`，而伞包已经 `0.7.2`，半年里每次看到都以为它是真的 |
| 版本号在各自文件里写各自的，互不干扰 | 只要有两处写同一个事实，就必然有一天不一致；不一致的那天你信哪一处？**先定谁是源** |
| 备份了就是有基线 | 基线 = 一个可复现的**点**（tag + 日志节 + 归档 + 校验和）。只有一份文件副本，说不出它是哪个版本 |
| 变更控制是团队才需要的流程 | 单人档的变更控制只有一条：**改判据前先停下问用户**。这条不做，判据会随实现一路漂 |
| 字段现在没用，先留着以后可能用 | "以后可能用"= 今天没人读。留着就要维护，维护错一次就是一次假事实 |

**动作 1：配置项清单（先定"哪些算"，再定"谁是源"）**

识别判据（命中任一即受控，逐条写清命中哪条）：

| 判据 | 说明 | 例子 |
| :-- | :-- | :-- |
| 改了要通知别人 | 外部依赖它的形状 | 对外接口契约、配置文件字段名 |
| 别人靠它工作 | 读了它才知道怎么做事 | 门禁脚本、阅读顺序文档、约定 |
| 有多份副本 | 同一事实出现在 ≥2 处 | 版本号、组件清单、依赖清单 |

**不是受控项的**：一次性的临时脚本、生成物、缓存、草稿。写清楚"不列入"的理由，比列进清单更重要。

**动作 2：单一事实源表（本卡的核心；一张表消灭一类漂移）**

| 事实类别 | 唯一权威位置 | 派生位置（从权威生成） | 怎么验一致 |
| :-- | :-- | :-- | :-- |
| 版本号 | 根包清单的 `version` | 子包清单、界面上的版本显示 | 跑动作 3 的脚本逐处比对 |
| 组件清单 | 注册表 COMPONENTS.md | 架构文档的模块视图 | 文件数 vs 表行数 |
| 数据字典 | 注册表 DATA_DICT.md | 架构文档的数据视图 | 实体数比对 |
| 接口 | 注册表 APIS.md | 用户文档 | 路径去重 |
| 门禁口径 | 唯一的检查脚本 | CI 工作流 | **两边必须是同一条命令**（不同 = 永远假绿） |
| 受控词表 | 写作契约第 1.1 节 | 各文档的表头标签 | 取值是否在词表内 |

规则三条：
1. **每类事实只允许一个权威位置**；找不到权威位置 = 这类事实还没受控，本卡未完成
2. 派生位置必须能**从权威重新生成**（命令或脚本），不能靠手抄
3. 两边不一致时，**先修派生、再查权威**；权威确实错了才改权威，并记一行变更

**动作 3：副本一致性检查（跑出来，别靠眼看）**

```powershell
# 版本号副本一致性（Windows PowerShell 5.1 直接可跑；变量名一律 ASCII）
$root = (Get-Content package.json -Raw -Encoding UTF8 | ConvertFrom-Json).version
$rows = @()
$rows += [pscustomobject]@{ Where = 'package.json'; Value = $root }
foreach ($sp in @(Get-ChildItem -Path . -Recurse -Filter package.json -File -ErrorAction SilentlyContinue |
                  Where-Object { $_.FullName -notmatch '\\node_modules\\' -and $_.DirectoryName -ne (Get-Location).Path })) {
    $v = (Get-Content $sp.FullName -Raw -Encoding UTF8 | ConvertFrom-Json).version
    $rows += [pscustomobject]@{ Where = $sp.FullName.Replace((Get-Location).Path + '\', ''); Value = $v }
}
$rows | Format-Table -AutoSize
$bad = @($rows | Where-Object { $_.Value -ne $root })
if ($bad.Count -gt 0) { Write-Host "[FAIL] 版本号副本不一致 $($bad.Count) 处"; exit 1 } else { Write-Host '[OK] 版本号单一事实源一致' }
```

把真实输出逐条贴进 `docs/BASELINE.md`——**贴结论不贴证据 = 本卡未完成**。

**动作 4：死元数据排查（本卡最省钱的一步）**

对每个"写下来的字段"问三句：
1. **有代码读它吗？** 全库搜一次字段名（含构建脚本、门禁脚本、发布脚本）
2. **有人看吗？** 最近三次相关改动里，它是否被引用过
3. **它对不对？** 抽查一处：它写的内容与当前事实是否一致

三问全否 = 死元数据。处置只有两种：
- **删除**（首选）——没有读者就没有价值，删掉比维护便宜
- **接上机器检查**——如果它确实该存在（比如给外部看的版本号），就加一条断言让它红，红不了的东西会一直错下去

不允许第三种处置"留着再说"——那正是死元数据的定义。

**动作 5：基线（发布前打一个点，之后不许移动）**

| 要素 | 内容 | 反例 |
| :-- | :-- | :-- |
| tag | 形如 `vX.Y.Z`，**已发布的 tag 不许移动或删除**（禁 `git tag -f`） | 打错就 `-f` 覆盖 → 历史没了 |
| 变更日志节 | 那一版正式节的四类条目（新增／变更／修复／升级注意） | 只写"若干修复" |
| 归档目录 | 本任务产物落在 `archive/<日期>_<slug>/` | 只有代码，没有当时的产物 |
| 校验和 | 一份可复现的取值命令或哈希清单（哪几个文件、什么算法） | 存一份文件副本，说不出它是哪个版本 |

基线声明模板（逐字写进文档）：
```
基线 vX.Y.Z ｜ 日期 YYYY-MM-DD ｜ 权威提交 <短哈希>
含：<产物清单> ｜ 校验：<命令或哈希>
本基线已发布，不移动、不删除；打错发放新号。
```

**动作 6：变更控制（一件事只有两种待遇）**

| 改动内容 | 待遇 | 理由 |
| :-- | :-- | :-- |
| 改门禁口径（断言、阈值、命令） | **停下问用户** | 门禁是"完成的定义"本身，改它等于改判据 |
| 改卡头的判据／阈值／命令 | **停下问用户** | 判据是路线的路基 |
| 改宪法（AGENTS.md 的硬规则） | **停下问用户** | 它管的是所有后续轮次 |
| 改卡头格式（段数、段标题、标签取值域） | **停下问用户** | 全库同时受影响，且校验器按它判 |
| 改对外契约（接口、配置字段名、数据结构） | **停下问用户** | 会打断已有使用者 |
| 其余（内部实现、文案、样式、测试） | 可直接改，随批提交 | 影响面在单批内可验证 |

**变更影响面三问**（任何受控项改动都要答，写在提交信息或文档里）：
1. **谁在读它？**（列出脚本／文档／外部使用者）
2. **有几处副本？**（按动作 2 的表逐处点名）
3. **怎么验证改对了？**（哪条命令会红）

**动作 7：状态记账（未清项不许静默躺在表里）**

| 记账字段 | 写在哪 | 到期规则 |
| :-- | :-- | :-- |
| 并行态（新旧实现同时在库） | STATE.md 并行态登记簿 | 登记时写到期批次；到期未清必须给处置 |
| 技术债 | TECH_DEBT.md | 每条给优先级；连续两轮不动就重定级 |
| 未决问题 | STATE.md 未决问题 | 每轮收尾复读一次，别让它变成默认值 |

**动作 8：配置管理自查（在项目根跑；非开发者只看退出码：exit 1 = 本卡未完成）**
变量名一律 ASCII：Windows PowerShell 5.1 读无 BOM 的 .ps1 时中文变量名会报『字符串缺少终止符』；脚本必须存成 UTF-8 带 BOM。
```powershell
$m = 'docs/BASELINE.md'
if (-not (Test-Path $m)) { Write-Host '[FAIL] 缺 docs/BASELINE.md'; exit 1 }
$l = @(Get-Content $m -Encoding UTF8)
$txt = $l -join "`n"
$src  = @($l | Where-Object { $_ -match '唯一权威|单一事实源' }).Count
$dead = @($l | Where-Object { $_ -match '死元数据' }).Count
$chg  = @($l | Where-Object { $_ -match '变更控制|停下问用户' }).Count
$base = @($l | Where-Object { $_ -match '基线' }).Count
$acc  = @($l | Where-Object { $_ -match '状态记账|并行态' }).Count
"BASELINE.md 行数 $($l.Count)（要求 ≤120）"
"单一事实源行 $src（≥1）；死元数据行 $dead（≥1）；变更控制行 $chg（≥1）；基线行 $base（≥1）；记账行 $acc（≥1）"
if ($l.Count -gt 120 -or $src -lt 1 -or $dead -lt 1 -or $chg -lt 1 -or $base -lt 1 -or $acc -lt 1) { Write-Host '[FAIL] 本卡自查未过'; exit 1 } else { Write-Host '[OK] 本卡自查通过' }
```

**禁令（违反任意一条 = 本轮输出作废）：**
- 禁止同一事实保留两处权威（要么定源，要么合并）
- 禁止用"以后可能有用"当保留死元数据的理由
- 禁止移动或删除已发布的 tag（禁 `git tag -f`）
- 禁止单方面修改门禁口径、判据、宪法、卡头格式、对外契约——这五类必须停下问用户
- 禁止只贴结论不贴命令输出（"已核对一致" 不算证据）
- ❌ 反例：写一份没人读的配置管理计划书 ｜ ✅ 正例：一张单一事实源表 + 一条比对命令的真实输出 + 一条被删掉的死字段 + 一个不移动的基线

## ④ 状态回写

**先回写状态，后提交**。更新 STATE.md：
- `当前任务` = 本任务名（链接 `docs/BASELINE.md`）
- `未决问题` = 没定的受控范围（哪些字段该删、基线里要不要含归档目录，逐条）
- `裁剪记录` = 单人模式：不做配置控制委员会，写一行理由；`下一步` = 5-2 发布 或 5-1 归档

```powershell
$m = 'docs/BASELINE.md'
git add STATE.md $m
git commit -m "5-7 docs(config): 单一事实源与基线"
powershell -NoProfile -File check.ps1
```
退出码必须是 0；非 0 → 停下问用户，禁止宣布本卡完成。
