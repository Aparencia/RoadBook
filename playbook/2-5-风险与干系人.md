## ② 执行

**动作 1：风险登记册（六列，一条一行）**

| 风险 | 概率 | 影响 | 缓解／显式接受 | 触发信号（可观测） | 责任 |
| :-- | :-: | :-: | :-- | :-- | :-- |
| 第三方物流接口超时导致下单卡住 | 中 | 高 | 缓解：调用加 3 s 超时 + 失败降级为"稍后查询" | 5 分钟内 5xx 比例 > 5% 或 P95 > 3 s | agent 出草案／用户放行 |

定级判据（照着念，逐字写进 RISK.md）：
- 概率：高 = 已见苗头或 ≥50%；中 = 10–50%；低 = <10%
- 影响：高 = 任务作废／数据损坏／上线推迟 ≥1 周；中 = 返工 1–3 天或部分功能降级；低 = 小返工 ≤1 天
- 等级：高×高 = 红（当轮必须处理）；含一个高 = 黄（缓解 + 触发信号 + 责任三样齐）；其余 = 绿（显式接受即可）

❌ 反例：风险"接口不稳定"，信号"接口可能会挂"（不可观测，没人能判定）
✅ 正例：信号"连续 5 分钟 5xx 比例 > 5%"，任何人打开监控都能判定

**动作 2：缓解与显式接受二选一（没有第三条路）**
❌ 反例：风险"误删账单"，缓解"注意备份"（口号，既没动作也没责任人）
✅ 正例一（缓解）："删除前自动导出 snapshot 到 docs/archive/；责任 = agent 出草案、用户执行删除"
✅ 正例二（显式接受）："单机单用户，删错重录约 5 分钟，用户已于 2026-10-03 确认接受"

**动作 3：干系人表（四列）**

| 谁 | 关心什么 | 通知方式 | 何时通知 |
| :-- | :-- | :-- | :-- |
| 最终用户（N 人） | 功能会不会打断现有用法 | README 变更说明 + 群公告 | 上线当天 |
| 数据提供方 | 表结构变没变、要不要改接口 | 邮件／群 + docs/registry/APIS.md 变更行 | 设计批准后 |

通知方式必须在本项目里可执行（邮件／群／README 变更说明／口头），禁止"适时沟通""保持同步"；"何时通知"写具体时点（设计批准后／编码完成／上线当天／出事故 30 分钟内）。
禁令：禁止把真实手机号、私人邮箱、住址写进仓库；只写角色名 + 渠道名。

**动作 4：上线通告对象（写进 RISK.md「上线通告」节，三行）**
① 谁会用到它；② 谁会被它影响（"没变化、不用管"的人也要说一声）；③ 谁必须在此之前知道（例：负责备份的人、下游接口对接人）。
单人模式（用户之外无他人／团队／外部系统参与）：干系人表与上线通告两节跳过，在 STATE.md `裁剪记录` 写一行理由。

**动作 5：一行摘要进 STATE.md**
把最高等级的 1 条风险写成 STATE.md `风险摘要` 的一行（= 最大风险 + 缓解 + 触发信号；无红黄则写 `无`）；等用户裁决接受度的未决问题另行登记到 `未决问题`。命中红线域时同步补 `红线摘要`。

**动作 6：命令（先赋值再调用；命中一行 = 一处不可观测信号或口号式缓解）**
```powershell
$spec = 'docs/specs/20261003_export'
New-Item -ItemType Directory -Force -Path $spec | Out-Null
Select-String -Path "$spec/RISK.md" -Pattern '注意|留意|适时|大概|尽量|可能'
```

**禁令：**
- 禁止把"风险"写成"担心"（不可观测、无责任人的句子 = 未完成）
- 禁止只列风险不改动作：红／黄风险必须落到本任务的批次动作或触发信号上
- 禁止替用户宣布"接受"——显式接受必须有用户原话与日期
- 禁止写"以上都是小问题"这类整体结论（逐条定级，不许打包）
