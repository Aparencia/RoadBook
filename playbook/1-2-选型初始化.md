# 卡 1-2 · 选型初始化（Go 裁决后的施工卡；一个项目只跑一次）
> 触发：1-1 想法调研获用户"Go" ｜ 产物：项目本体 + docs/decisions/STACK_<日期>_<主题>.md ｜ 下一张：待新意图（首个功能走 2-1 功能调研）

---

## ① 开工确认

收到开工指令后，先回执以下四项再动手（缺项不开始）：

1. **任务复述**：项目一句话 + 引用 IDEA 决策卡路径（docs/decisions/IDEA_*.md）。
2. **假设清单**：默认假设逐条列（如"单人用、免费托管、Node 栈优先"）。
3. **澄清问题（≤5 个，能省则省）**：IDEA 决策卡里已有的答案禁止再问。
   ❌ 反例："这个项目是做什么的？"（IDEA 卡里有）
   ✅ 正例："项目代码想放在哪个目录？（如 C:\code\<项目名>）"
4. **引用检查清单原文**（逐字粘贴本卡 §② 的"绿灯四证"）。

并声明：产物 = 完整项目目录 + STACK 决策卡；栈的最终选择由用户裁决。

---

## ② 执行

**动作 1：候选栈 2~3 个，四维打分（每维 1~5 分，5 最好）**

| 维度 | 打分问句 |
| :-- | :-- |
| 现有知识 | 用户以前用这个栈跑通过项目吗？从没用过 = 1~2 分 |
| 部署难度 | 静态托管能一键部署 = 5；要自己管服务器 = 1 |
| 成本 | 免费额度够单人项目跑一年 = 5；必须付费 = 写数字 + 来源链接 |
| AI 生态 | 主流框架、AI 训练语料多 = 5；小众框架 = 1~2 |

成本一栏禁止空泛：查得到就写"免费额度 <数字>（来源链接）"，查不到写"未查到公开数据"。
❌ 反例："Vercel 成本低"（无来源）
✅ 正例："Vercel Hobby 计划免费（来源：https://vercel.com/pricing，检索日 <日期>）"
打分表汇总后给出**建议栈 + 一句话依据**，停下让用户选。

**动作 2：写 STACK 决策卡** `docs/decisions/STACK_<日期>_<主题>.md`（≤60 行）：选了什么 / 每个被否栈及否决理由 / 四维打分表 / 成本来源链接。

**动作 3：从母版 template/ 生成项目全套**
```powershell
$母版 = 'D:/path/to/roadbook'   # 母版根绝对路径（其下含 template/），先赋值再调用
$dest = 'C:\code\myapp'         # 目标目录必须不存在或为空：已存在且非空会嵌套成 $dest\template
if (Test-Path $dest) { throw "目标目录已存在：$dest —— 确认它为空，或换一个不存在的路径" }
Copy-Item -Recurse "$母版/template" $dest
Set-Location $dest
Get-ChildItem -Force
```
`Get-ChildItem -Force` 逐项核对 .gitignore/.tool-versions/.env.example 都在。然后逐文件替换占位符：

| 文件 | 替换什么 |
| :-- | :-- |
| README.md | `<项目名>`、`<这个项目做什么、给谁用>`、启动命令注释 |
| AGENTS.md | §0 一句话/技术栈、§10 环境速查四行 |
| STATE.md | 项目名/一句话/技术栈（链 STACK 卡）/当前阶段=项目期/下一步=待新意图 |
| CHANGELOG.md | 首版版本号（如 0.1.0）与「未发布」节说明 |
| .tool-versions | asdf/mise 语法：逐行 `<工具名> <版本>`，工具名用 asdf 插件名（nodejs/python/postgres…）；doctor.ps1 逐项比对，名字写错 = 缺工具红灯 |
| .env.example | 按栈填真实键名（只键名+注释，禁止写真值） |
| check.ps1 | `$STEPS` 数组按动作 4 填 |
| doctor.ps1 | 无需替换：读 `.tool-versions` 逐项比对（动作 5）；缺工具/版本不符/占位符残留 = 红灯 |
| orphans.ps1 | 无需替换：孤儿与幽灵五张清单工具（五张清单只报不拦；但有**未跟踪文件**或读取失败 = 退出码 1——那代表清单不完整，先 `git add`） |
| gate.ps1 | 无需替换：提交前门禁（只拦不修；退出码 1 = 拦下）。`-Anchor`/`-ScopeFiles` **必填**，装完按动作 7 自检一次 |
| docs/ARCHITECTURE.md | 模块图 / 分层目录 / 新代码落点表——三块都要填真实内容，留占位 = 本卡未完成 |
| docs/registry/ 三件套 | 保留空表头即可，首次触碰再补行 |
**动作 4：check.ps1 的 STEPS 按栈填真实命令**（数组留空 = "完成"永远无法成立）
```powershell
# Node/TS： $STEPS = @('pnpm typecheck', 'pnpm lint', 'pnpm test')   # Python： $STEPS = @('python -m mypy .', 'python -m pytest -q')
# 纯静态页： $STEPS = @('node --check src/index.js')   # 至少一行真实检查；该文件/命令不存在就换成本项目真实的
```
**动作 5：doctor 自检（绿灯证据一）**
```powershell
powershell -NoProfile -File doctor.ps1
```
`$REQUIRED` 已废弃：doctor.ps1 读 `.tool-versions` 逐项比对（缺文件/非 UTF-8/占位符/版本不符全部红灯）。退出码 0 才算过；缺工具先装，禁止跳过。
**动作 6：装依赖 + git init + 首次提交（锚点绿）**
```powershell
pnpm install          # 或 pip install -r requirements.txt（按栈）
git init
git add README.md AGENTS.md STATE.md CHANGELOG.md .tool-versions .env.example .gitignore .gitattributes check.ps1 doctor.ps1 gate.ps1 orphans.ps1 docs
$n = (git ls-files).Count    # 写进 STATE.md 的「文件数基线」与「当前文件数」（基线只写这一次）
git commit -m "1-2 chore(init): init project from V6 template"
$anchor = git rev-parse HEAD
```
清单 = 根目录全部受管文件（含 gate.ps1、orphans.ps1、CHANGELOG.md、.gitattributes）；提交后 `git status --porcelain` 必须为空（非空 = 有文件从未入库）。`$anchor` 记入 STATE.md"最近完成"第一条。
**动作 7：check / gate / orphans 首跑（guardrail 绿）**
```powershell
powershell -NoProfile -File check.ps1
powershell -NoProfile -File gate.ps1 -Anchor HEAD -ScopeFiles "README.md,AGENTS.md,STATE.md,CHANGELOG.md,.tool-versions,.env.example,.gitignore,.gitattributes,check.ps1,doctor.ps1,gate.ps1,orphans.ps1,docs/" -RepoRoot .
powershell -NoProfile -File orphans.ps1
```
三条退出码必须 0（gate 此刻只可能绿或黄：`-Anchor HEAD` 划出空清单，黄但仍 exit 0）。**必须在 `git init` 之后、且已写基线**：check.ps1 在非 git 或基线为 0 时判红，旧版在 `git init` 前跑 = 必然失败。禁止"先跳过以后再跑"；三条非 0 = 守护脚本装错，先修再往下。
**动作 8：远端仓库（三选一，私有/公开由人裁决）**
1. 建远端并首推：先赋值 `$owner = 'aparencia'; $name = 'my-app'`（改成你自己的账号/仓库名），再调用 `gh repo create "$owner/$name" --private --source . --push`（要公开改 `--public`——**可见性不许 agent 自己定**）
2. 已有远端：先赋值 `$url = 'https://github.com/aparencia/my-app.git'`（改成你自己的仓库地址），再调用 `git remote add origin $url; $branch = git rev-parse --abbrev-ref HEAD; git push -u origin $branch`
3. 暂不设远端：必须写进 STATE.md 裁剪记录「本地-only，风险：磁盘故障 = 全部历史清零」

首推前先跑 `git status --porcelain`：出现 `.env` / `*.key` / `*.pem` → 停（推出去不可逆）。**推送不进 DoD**（网络或凭据失败会造成假红），它归 5-1 卡归档收尾与 6-6 卡信号 10。

**绿灯四证（缺一 = 初始化未完成）：**
```text
① doctor.ps1 退出码 0（环境绿）
② check.ps1 退出码 0 且 STEPS 非空（guardrail 绿）
③ 首次 commit 哈希已记入 STATE.md（锚点绿）
④ 远端已落地或已明确裁剪（远端绿）
```

**禁令：**
- 禁止 `$STEPS` 留空数组 / `.tool-versions` 留空或写占位符
- 禁止选用户没跑通过的栈（除非用户裁决时明说"我就要学新栈"）
- 禁止跳过 doctor / check 首跑直接开工
- 禁止 `git add -A` / `git add .`
- 禁止在 .env.example 写真实密钥值

## ③ 证据回执

收尾逐条给出：
1. 四维打分表 + 每条成本数据的来源链接（或"未查到公开数据"）
2. STACK 决策卡完整路径
3. `powershell -NoProfile -File doctor.ps1` 完整输出（退出码）
4. 动作 6 写下的 `文件数基线`/`当前文件数`（`$n` 原文）+ 动作 7 三条命令的完整输出与退出码（check.ps1 / gate.ps1 / orphans.ps1 汇总行；文件数基线缺失或 0 → check.ps1 判红 FAIL，`[--]` 只在起点锚点为空时出现并跳过本批提交计数断言；gate.ps1 不带 `-ScopeFiles` 会直接判红）
5. 首次 commit 哈希（`$anchor` 原样输出）+ 远端判定（`git remote -v` 原文，或"本地-only + 裁剪记录原文"）
6. 提交后 `git status --porcelain` 的完整输出（**必须为空**；非空 = 有受管文件从未入库）
7. 占位符核对清单：template 中每个尖括号标记 → 已替换为（贴替换后的行）/ 保留原因（须用户确认）

## ④ 状态回写

更新项目根 STATE.md：
- `技术栈` = 选定栈（决策卡：docs/decisions/STACK_*.md）
- `当前阶段` = 项目期；`下一步` = 待新意图
- `文件数基线` = 动作 6 的 `$n`（防膨胀预算的 0 点；**只在这一次写死**，4-1 卡此后不再改写，每批只更新 `当前文件数`）
- `当前文件数` = 初始化收尾时的 `(git ls-files).Count`（此后每批由 4-1 卡收尾更新）
- `最近完成` 第一条 = 初始化完成 + commit 哈希
- `远端仓库` = <url 或"本地-only（已裁剪）">；`工作树状态` = 干净

回写后按固定三步收尾（回写 → 提交 → 复跑 check.ps1）：
```powershell
git add STATE.md
git commit -m "1-2 chore(state): record init result"
powershell -NoProfile -File check.ps1
```
`git status --porcelain` 为空 + check.ps1 退出码 0 = 收尾完成。
