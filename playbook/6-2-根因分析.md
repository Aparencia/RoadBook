## ① 开工确认

收到 Bug 报告后，先回执以下六项：

1. **人话复述与落点**：哪个功能出了什么问题（一句话）；产物 = `docs/specs/<日期>_<slug>/RCA.md`；下一张卡 = 6-3 修复。
2. **假设清单**：逐条写"我假设 X；若错则 Y 失效"——能从代码/STATE.md 查到的不许写进假设，先去查。
3. **澄清问题（≤5 个，能删则删）**：只问用户才知道、又决定定位方向的事；一个都没有就写"无"。
4. **诊断四问**（用户答不出就陪他找，不许跳过直接猜原因）：
   - 预期行为是什么？
   - 实际行为是什么？
   - 报错原文（完整粘贴，一张截图一行字都不许省）
   - 最近一次改动（大概时间/内容；从 STATE.md 的"最近完成"辅助回忆）
5. **复现方案**：提出怎么复现（哪个页面/什么操作/什么数据）。
6. **引用检查清单原文**（逐字粘贴本卡 §② 的"五问法对照"）。

## ② 执行

**动作 1：人工复现（禁止跳过）**
- 用户亲自复现，或用户操作、agent 同屏看输出。
- agent 不许"根据代码推断已复现"。
  ❌ 反例："从代码看这里必然报错，无需复现"
  ✅ 正例："请在登录后点击'导出'按钮，我同时在终端看日志——你点了吗？看到了什么？"
- **第一阶段就是复现（无此不许进第二阶段）**：先找到一条"改动前红、改动后绿"的命令，并把该命令的原文输出贴进 RCA.md——**没有能变红的命令，就没有第二阶段**；找不到就停在第一阶段问人，禁止凭猜改代码。
  ❌ 反例："我已经知道原因了，直接改"
  ✅ 正例：`npm test -- export` 改动前 1 failed（红），改动后 0 failed（绿）——原文输出已贴
- 复现不出来 → 登记 `docs/TECH_DEBT.md`（known-issue），给出收集信息方案（如截图+操作步骤+时间点），本卡结束。

**动作 2：定位（按序试，命中最前面的就停）**
1. 报错串里的文件/模块名 → 先赋值再搜：`$kw = '报错关键字'; Get-ChildItem -Path src -Recurse -File | Select-String -Pattern $kw | Select-Object Path,LineNumber`（注：本机 PowerShell 5.1 的 `Select-String` 没有递归形参，只有上面的管道式递归可跑）
2. 界面文案 → 全仓库搜文案（同上，换成文案关键字）
3. 查 `docs/registry/COMPONENTS.md` 的"人话标识"列反查程序名
4. 查 `docs/lessons/` 教训卡是否同症状（有 → 先按旧卡修法试，成功则在旧卡上更新「最近确认」字段 = 日期 + 本次确认的证据；**旧卡没有这个字段 → 先补字段再更新**，不许因为没字段就跳过更新）；**若命中已有教训卡（同症状第二次发生）→ 修复完成后必须起草"升格提案"：把这条教训从知识升格为规则（写进宪法禁令或对应流程卡的检查项，落到具体文件+具体条目），交用户裁决——踩两次的坑，第三次还会来**
5. **反向追链**：从报错行沿调用链向上追，直到找到"输入到这里还是对的"的那一层——根因在它的下一层；回执必须写出这条链（报错点 file:line → 调用方 file:line → … → 原始触发点 file:line）。**禁令：未写出反向调用链不许动手改代码——只修报错行 = 症状修复、本卡作废。**
6. **宿主级 / 环境级故障五步**（报错指向环境、或"代码看着没问题"时走这条；与 C1 红灯三问同一出口）：
   - **多通道对照矩阵**：同一件事用 ≥2 条独立启动通道跑（不同宿主 / 不同账户 / 不同数据目录），把"必然挂"降级成"某种组合下挂"；单通道结论不算。
   - **最小配置**：先关掉一切可选件（自动加载 / 插件 / 注入参数）跑最小配置；仍红 ⇒ 问题不在配置层。
   - **零依赖探针**：写一个不 import 本项目的探针（临时目录里几行脚本）——它能红 ⇒ 与本项目代码无关。
   - **系统级审计**：ACL / 完整性标签 / 策略用只读读取器读（如 `scripts/envcheck.ps1`）；**每条结论必须带一个健康对照样本**（同探针在别的目录或账户下是绿的）——没有对照样本 = 结论没成立。
   - **五步走完仍不可满足** → 登记 `docs/TECH_DEBT.md`，或按 B1 第三态 `BLOCKED_BY_ENV` 结项（本机不可满足 ≠ 代码没做完）；**连续 2 轮未解除 → 停本机尝试，转换机 + 人工动作清单**。
7. **定位手法四条**（省时间的那几种，按需取用）：① **同 SHA256 二进制换个位置**——一句话把"代码问题"排除；② **2×2 剥离（路径 × 内容）**——把"位置"从"内容"里剥出来；③ **换访问路径**（`subst` / 目录符号链接）——区分"路径字符串策略"与"目录对象属性"；④ **合成复现**——见动作 6 的 ④。

**动作 3：五问法对照 —— ≥3 层（问到底，不许一层就停）**

```text
❌ 反例（1 层就停）：
   为什么白屏？→ 因为 data 是 undefined。（完）
✅ 正例（4 层到底）：
   为什么白屏？→ data 是 undefined
   为什么是 undefined？→ 接口返回结构变了
   为什么结构变了？→ 上周改接口的人不知道前端在用旧字段
   为什么会不知道？→ docs/registry/APIS.md 里没登记这个接口
   → 根因：接口未登记（修 APIS 登记 + 修代码，两个都要做）
```

**动作 4：Bug 定级（判据内联，不确定按 P2）**
- P0 系统崩溃/数据丢失/安全漏洞 → 先止血：回滚优先于修复（步骤在 docs/RUNBOOK.md 回滚节）
- P1 核心功能不可用 → 立即修复
- P2 边缘功能报错/体验不佳 → 正常修复
- P3 拼写/样式/非关键 → 不进修复流程，登记 TECH_DEBT.md 攒批，本卡结束

**动作 5：写 `docs/specs/<日期>_<slug>/RCA.md`**：现象/复现步骤/根因（≥3 层）/影响面/修复方案建议。路径里的 `<slug>` 与卡头、STATE.md 的 `当前任务` 用同一个 slug，不许一处叫 bug 名一处叫 slug。

**动作 6：仪器与实验纪律（下结论前先证明仪器可信；这些不是"要更仔细"，是判据）**
- **甲 · 实验设计（防"我自己造的假信号"）**：① **每臂隔离 + 每臂前断言前置态**——长驻进程 / 共享数据目录 / 缓存 / 端口必须每臂独立，且每臂开头断言前置状态为 0（上一臂的残留会同时污染两个对照臂）；② **一次只动一个变量**（"目录内容"与"目录位置"混在一个对照里，做 2×2 才剥得开）；③ **相关性 >90% 也要盯住那个反例**（16 次挂 15 次，唯一通过的那次正是机制来源；把"必挂"写成结论就掐掉了机制）；④ **合成复现是因果的唯一步骤**（自己在全新目录打造故障 → 撤掉 → 转绿）。
- **乙 · 仪器纪律（先自校准，再下结论）**：⑤ **仪器先自校准**——造一个已知状态当标尺，看仪器读不读得出来；⑥ **"排除"必须点名被排除的具体字段**（说"ACL 已排除"时只排了 DACL，而答案恰在 DACL 之外）；⑦ **外层错误码只用于分桶，不当判据**（同一根因可以给三个不同的码，那只是不同失败点）；⑧ **注入类参数要先验通道**（塞一个可见哨兵确认参数真的进了命令行，否则那轮实验无效——无效实验不算证据）。
- **丙 · 归因与建议纪律**：⑨ **说"最可能"之前先清点"已被控制住的变量"**，且**给操作建议前先验证它在本机可执行**（"你换个非提权终端跑"在造不出 Medium 进程的机器上等于没建议）；⑩ **归因外部前先量它**（运行时版本 / 杀软 / 提权 / 宿主上下文逐个实测否掉；真因可能不在任何日志、事件或错误码里，只有主动写仪器去读那一层才看得见）。

| 你会想 | 事实 |
| :-- | :-- |
| "错误码说资源在用，那就是占用问题" | 那是外层包装；先定分桶规则，别当判据 |
| "ACL 已经排除了" | 排除的是哪一段？（DACL / SACL / 标签 / owner） |
| "复刻了 ACE 还是能跑，所以跟 ACL 无关" | `Set-Acl` 只搬 DACL，标签没搬过去 |
| "6/6 挂、6/6 过，确定性了" | 我的实验顺序可能正在污染下一臂 |
| "先押最可能的原因" | 押之前先清点已经被控制住的变量 |
| "建议他用非提权终端跑" | 本机造得出 Medium 进程吗？先验 |
