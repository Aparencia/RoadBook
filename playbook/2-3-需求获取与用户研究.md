## ② 执行

**动作 1：五法择一（只选一种；选两种以上先写清为什么一种不够）**

| 方法 | 什么时候用 | 成本 | 产出 |
| :-- | :-- | :-- | :-- |
| 访谈（一对一 30–45 分钟） | 已认识 1–3 个真实用户，想知道"为什么" | 低 | 原话 + 具体故事 |
| 现场观察 | 用户说不清步骤，或"说的"与"做的"不一样 | 中 | 真实操作顺序与卡点 |
| 问卷 | 要覆盖 ≥10 人、问题能预设选项 | 中 | 分布与频次 |
| 可用性测试 | 已有原型或半成品，看人能不能用起来 | 中 | 卡壳点记录 |
| 原型（可点／纸面） | 需求抽象，用户自己也不知道要什么 | 高 | 反馈与取舍 |

照着念的选择判据：用户 <3 人且要"为什么" → 访谈；重复手工活 → 现场观察；要排序或占比 → 问卷；已有可点的东西 → 可用性测试；连"做什么"都说不清 → 原型。
❌ 反例：五法全上一遍（成本爆炸，结论互相打架）
✅ 正例：先访谈 2 人 → 发现都卡在手工抄数字 → 选访谈，不追加问卷

**动作 2：提问纪律（三条，违反 = 记录作废）**
- 禁诱导性提问：❌"你是不是觉得导出太慢？" ✅"上次导出的时候发生了什么？"
- 要原话不要转述：❌"用户希望导出更快" ✅"我点了导出去泡了杯咖啡，回来还没好"（用户原话）
- 连问 3 个为什么（≥3 层，问到出现钱／时间／合规这类硬约束，或对方答"不知道"为止）：
  想导出 → 因为要发周报 → 周报数字靠手抄 → 因为系统没有能分享的链接

**动作 3：原始记录表（每条诉求一行，五列；取不到的写"未获取"，不许留空）**

| 诉求原话 | 使用场景 | 发生频率 | 现在的替代做法 | 反例 |
| :-- | :-- | :-- | :-- | :-- |
| "回来还没好" | 每月底导月度账单发财务 | 每周 3 次 | 手工抄进 Excel | 只有财务要日报，其余 3 人反对优先做导出 |

频率只认数字；反例写"谁在什么情况下会反对这条"——写不出反例 = 这条没问透。

**动作 4：把"用户说的"与"用户真正要的"分列（本卡核心动作，禁止合并成一列）**

| 用户说的 | 用户真正要的（我的判断） | 依据（原话／行为） | 若判断错了的代价 |
| :-- | :-- | :-- | :-- |
| "要导出 Excel" | "周报别再手抄数字" | 连问三层都落在手抄上 | 若给分享链接，Excel 需求可能消失，范围能小一半 |

❌ 反例：把"用户要导出"直接写成 Must 就开工
✅ 正例：把判断写成待裁决的假设，连"错了的代价"一起写，用户才知道该盯哪一条

**动作 6：建任务目录（先赋值再调用）**
```powershell
$spec = 'docs/specs/2026-10-03_export'
New-Item -ItemType Directory -Force -Path $spec | Out-Null
```
Expected：`New-Item -ItemType Directory -Force … | Out-Null` 成功时**一个字符都不打**（本机沙箱实测 stdout 0 行、`$?` 为 True）；`-Force` 的作用是让"目录已存在"不再算错 —— 同一条再跑一次实测同样 0 行、退出码 0，去掉 `-Force` 才打 `New-Item : 具有指定名称 <绝对路径> 的项已存在。`（英文宿主打 `An item with the specified name <绝对路径> already exists.`）+ `$?` 变 False（非终止错误，进程退出码仍是 0）；那个 `| Out-Null` 也不是装饰：不加它就把一个 `DirectoryInfo` 对象当输出混进回执（控制台里渲染成一张目录表）。路径按**当前目录**展开 —— 实测建出来的绝对路径是 `<当前目录>\docs\specs\2026-10-03_export`，所以在别的目录里手滑跑一次就等于把 specs 建到那儿去了。
