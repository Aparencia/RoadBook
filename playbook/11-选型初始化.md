# 卡 11 · 选型初始化（Go 裁决后的施工卡；一个项目只跑一次）
> 触发：10 想法调研获用户"Go" ｜ 产物：项目本体 + docs/decisions/STACK_<日期>_<主题>.md ｜ 下一张：待新意图（首个功能走 20 功能调研）

---

## ① 开工确认

收到开工指令后，先回执以下四项再动手（缺项不开始）：

1. **任务复述**：项目一句话 + 引用 IDEA 决策卡路径（docs/decisions/IDEA_*.md）。
2. **假设清单**：默认假设逐条列（如"单人用、免费托管、Node 栈优先"）。
3. **澄清问题（≤5 个，能省则省）**：IDEA 决策卡里已有的答案禁止再问。
   ❌ 反例："这个项目是做什么的？"（IDEA 卡里有）
   ✅ 正例："项目代码想放在哪个目录？（如 C:\code\<项目名>）"
4. **引用检查清单原文**（逐字粘贴本卡 §② 的"绿灯三证"）。

并声明：产物 = 完整项目目录 + STACK 决策卡；栈的最终选择由用户裁决。

---

## ② 执行

**动作 1：候选栈 2~3 个，四维打分（每维 1~5 分，5 最好）**

| 维度 | 打分问句 |
| :-- | :-- |
| 现有知识 | 用户以前用这个栈跑通过项目吗？从没用过 = 1~2 分 |
| 部署难度 | 静态托管能一键部署 = 5；要自己管服务器 = 1 |
| 成本 | 免费额度够单人项目跑一年 = 5；必须付费 = 写数字 + 来源链接 |
| AI 生态 | 主流框架、AI 训练语料多 = 5；小众框架 = 1~2 |

成本一栏禁止空泛：查得到就写"免费额度 <数字>（来源链接）"，查不到写"未查到公开数据"。
❌ 反例："Vercel 成本低"（无来源）
✅ 正例："Vercel Hobby 计划免费（来源：https://vercel.com/pricing，检索日 <日期>）"
打分表汇总后给出**建议栈 + 一句话依据**，停下让用户选。

**动作 2：写 STACK 决策卡** `docs/decisions/STACK_<日期>_<主题>.md`（≤60 行）
内容：选了什么 / 每个被否栈及否决理由 / 四维打分表 / 成本来源链接。

**动作 3：从母版 template/ 生成项目全套**
```powershell
Copy-Item -Recurse template "C:\code\<项目名>"
Set-Location "C:\code\<项目名>"
Get-ChildItem -Force
```
`Get-ChildItem -Force` 逐项核对 .gitignore/.tool-versions/.env.example 都在。然后逐文件替换占位符：

| 文件 | 替换什么 |
| :-- | :-- |
| README.md | `<项目名>`、`<这个项目做什么、给谁用>`、启动命令注释 |
| AGENTS.md | §0 一句话/技术栈、§10 环境速查四行 |
| STATE.md | 项目名/一句话/技术栈（链 STACK 卡）/当前阶段=项目期/下一步=待新意图 |
| CHANGELOG.md | 首版版本号（如 0.1.0）与「未发布」节说明 |
| .tool-versions | language/package-manager/runtime/database 四行按实际栈填 |
| .env.example | 按栈填真实键名（只键名+注释，禁止写真值） |
| check.ps1 | `$STEPS` 数组按动作 4 填 |
| doctor.ps1 | `$REQUIRED` 数组按动作 5 填 |
| orphans.ps1 | 无需替换：孤儿与幽灵三查工具（只报不拦，退出码恒 0，随时可跑） |
| docs/registry/ 三件套 | 保留空表头即可，首次触碰再补行 |

**动作 4：check.ps1 的 STEPS 按栈填真实命令**（数组留空 = "完成"永远无法成立）
```powershell
# Node/TS：  $STEPS = @('pnpm typecheck', 'pnpm lint', 'pnpm test')
# Python：   $STEPS = @('python -m mypy .', 'python -m pytest -q')
# 纯静态页： $STEPS = @('node --check index.js')   # 至少一行真实检查
```

**动作 5：doctor 自检（绿灯证据一）**
```powershell
powershell -File doctor.ps1
```
`$REQUIRED` 按栈填（如 `@('node','git')`）。退出码 0 才算过；缺工具先装，禁止跳过。

**动作 6：装依赖 + check 首跑（绿灯证据二）**
```powershell
pnpm install        # 或 pip install -r requirements.txt（按栈）
powershell -File check.ps1
```
退出码必须 0。项目还没代码就失败 = 环境问题，修环境；禁止"先跳过以后再跑"。

**动作 7：git init + 首次提交（锚点证据三）**
```powershell
git init
git add README.md AGENTS.md STATE.md .tool-versions .env.example .gitignore check.ps1 doctor.ps1 docs
git commit -m "chore: init project from V6 template"
git rev-parse HEAD
```
输出哈希记入 STATE.md"最近完成"第一条。

**绿灯三证（缺一 = 初始化未完成）：**
```text
① doctor.ps1 退出码 0（环境绿）
② check.ps1 退出码 0 且 STEPS 非空（guardrail 绿）
③ 首次 commit 哈希已记入 STATE.md（锚点绿）
```

**禁令：**
- 禁止 STEPS / REQUIRED 留空数组
- 禁止选用户没跑通过的栈（除非用户裁决时明说"我就要学新栈"）
- 禁止跳过 doctor / check 首跑直接开工
- 禁止 `git add -A` / `git add .`
- 禁止在 .env.example 写真实密钥值

## ③ 证据回执

收尾逐条给出：
1. 四维打分表 + 每条成本数据的来源链接（或"未查到公开数据"）
2. STACK 决策卡完整路径
3. `powershell -File doctor.ps1` 完整输出（退出码）
4. 先在 STATE.md 写入 `文件数基线` = 当前文件数（`(git ls-files).Count`，或 `orphans.ps1` 汇总行的"文件数"）——**再**跑 `powershell -File check.ps1` 完整输出（退出码）+ `powershell -File orphans.ps1` 汇总行（基线不写时 check.ps1 会打 `[--]` 跳过预算断言）
5. 首次 commit 哈希（`git rev-parse HEAD` 原始输出）
6. 占位符核对清单：每个 `<占位符>` → 已替换为 / 保留原因
