# 卡 41 · 发布
> 触发：里程碑/攒了一批功能/用户说"发布/上线/让别人用" ｜ 产物：docs/versions/vX.Y.Z.md + tag（人打）+ RUNBOOK 更新 ｜ 下一张：待新意图（出事故 → 42 复盘）

---

## ① 开工确认

1. **发布内容复述**：本次发布包含哪些已完成任务（STATE.md 最近完成 + CHANGELOG 未发布节对照）。
2. **部署路线澄清（三问）**：部署到哪（本地演示/静态托管/托管平台/云服务器）？有没有真实用户？数据要不要迁移？
3. **引用检查清单原文**（逐字粘贴"发布七查"）。

---

## ② 执行

**发布七查：**

**① 部署路线（按项目实况选，写进 RUNBOOK）**

| 路线 | 适用 | 要点 |
| :-- | :-- | :-- |
| 本地演示 | 只有自己用 | doctor + check 通过即算发布 |
| 静态托管 | 纯前端 | Vercel/Netlify 连仓库自动部署；配好环境变量 |
| 托管平台 | 带后端 | Railway/Render/Fly.io；数据库用平台托管实例；秘钥进平台后台不进代码 |
| 云服务器 | 自管 | 域名+HTTPS 必配；服务器加固另立任务 |

**② 前置全绿**：`check.ps1` 退出码 0 + 行为验收清单（最近任务的）过一遍。

**③ 数据与迁移**：本次含表结构变更？迁移由**人执行**（不可委托）；执行前先跑 RUNBOOK §3 备份。

**④ 回滚预案（先写预案再发布）**：写清"发布坏了怎么退"——上一版本重部署命令 / 数据回滚路径，存入版本详情。
❌ 反例："回滚：git revert（到时候再说）"（没有具体命令与数据处置，出事时只能临场发挥）
✅ 正例："回滚：`git checkout v0.2.0` 重部署；数据无破坏性迁移（L1 追加），无需回滚数据；确认点：打开 /health 返回 200"

**⑤ 版本三对齐**：
- 根 `CHANGELOG.md`：把"未发布"节整理成正式版本节（新增/变更/废弃/修复）
- 版本号：0.x 阶段随意；1.x 起破坏性变更升 MAJOR 并写"升级注意"
- `docs/versions/vX.Y.Z.md` 详情：做了什么/为什么/已知问题/部署动作/回滚点
- 三处版本号一致（CHANGELOG = 详情文件名 = tag）

**⑥ 打 tag（人执行，agent 只给命令）**：
```powershell
git tag v<X.Y.Z>
git push origin v<X.Y.Z>   # 有远端时
```

**⑦ 收尾同步**：docs/RUNBOOK.md §1 部署节更新；条件文档触发检查——有真实用户→建 USER_GUIDE；收集 PII 且公开→PRIVACY；开源→LICENSE。

**禁令：**
- 禁止 agent 执行部署/打 tag（不可委托，人执行）
- 禁止跳过回滚预案直接发（"应该没问题"不是预案）
- 禁止版本三处对不上就发布
