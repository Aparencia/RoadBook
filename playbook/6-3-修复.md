# 卡 6-3 · 修复（全档必走）
> 触发：6-2 根因分析获用户确认后 ｜ 产物：修复代码 + 提交 ｜ 下一张：6-4 回归验证

---

## ① 开工确认

收到开工指令后，先回执以下七项：

1. **人话复述与落点**：修哪个 Bug、根因一句话（从 RCA.md 引用）；产物 = 修复代码 + 本卡收尾提交；下一张卡 = 6-4 回归验证。
2. **假设清单**：逐条写"我假设 X；若错则 Y 失效"——能从 RCA.md / 代码查到的不许写进假设。
3. **澄清问题（≤5 个，能删则删）**：只问用户才知道、又决定改法的事；一个都没有就写"无"。
4. **根因复述**：一句话（从 RCA.md 引用）。
5. **修复方案**：改哪些文件/怎么改，以及"为什么这是最小改动"。
6. **起点锚点声明**：执行 `git rev-parse HEAD` 并回显（写进 STATE.md）。
7. **引用检查清单原文**（逐字粘贴本卡 §② 的"修复范围双维锁"阈值表）。

---

## ② 执行

**第 0 步：记录起点锚点（禁止跳过）**：`$anchor = git rev-parse HEAD`，把输出的哈希写进 STATE.md 的 `起点锚点` 字段——本卡的门禁、③ 的改动范围自评、6-4 卡的回归基准都用它；丢了它 = 划不出"本卡改了什么"、出问题无法精确回滚。

**动作 1：最小改动修复**
- 只修根因指向的问题，不做任何"顺手"的事。
- **修复范围双维锁**（**行 = 新增行 + 删除行**，即 `git diff --stat "$anchor..HEAD"` 末行 `N insertions(+), M deletions(-)` 的 N+M；不用净行数——"删 200 行改 200 行"会被净行数算成 0，掩盖大改）：

| 信号 | 判定 | 处置 |
| :-- | :-- | :-- |
| ≤3 文件 且 ≤100 行 | ✅ 正常 | 继续修 |
| >3 文件 或 >100 行 | ⚠️ 黄牌 | 停下，向用户解释为什么最小修复需要这么大，获批再继续 |
| >600 行 或 要动表结构 | 🔴 红牌 | 拆成独立任务，回用户重新规划 |

  ❌ 反例：顺手重排 import，把 diff 从 30 行吹到 200 行，还按"正常"继续修
  ✅ 正例：只改根因指向的 2 个文件（新增 12 行 + 删除 6 行 = 18 行）→ ✅ 正常
- 修复方案有多个时，先列候选（A/B + 取舍）再推荐，由人挑。

**动作 2：顺手问题登记制**
修 A 时发现 B 有问题 → 登记 `docs/TECH_DEBT.md`（TD-序号 + 来源=BUG-xxx 修复过程），**不许顺手修**。
❌ 反例："反正路过这个文件了，把那个过时写法也改了"
✅ 正例："TD-012 已登记：同文件存在过时写法，建议另行清偿"

**动作 3：机械门禁（修完立刻跑；方案 A/B 无论选哪个，落地后都要跑——门禁有牙，不靠自觉）**

```powershell
$anchor = (Select-String -Path STATE.md -Pattern '起点锚点\s*[:：]\s*([0-9a-fA-F]{7,40})').Matches[0].Groups[1].Value   # $anchor 从 STATE.md 的「起点锚点」字段读，不许手打
git rev-parse --verify "$anchor^{commit}"; if ($LASTEXITCODE -ne 0) { throw "锚点无效：停下问用户" }
$scopeFiles = @('src/a.ts','src/b.ts')   # 换成本卡真实改动文件清单
powershell -NoProfile -File gate.ps1 -Anchor $anchor -ScopeFiles ($scopeFiles -join ',') -RepoRoot .
```

判词：**红 = exit 1**（非 git 工作树 / 锚点无效 / 缺 -Anchor / 缺 -ScopeFiles / 越界改动 / 行数超限 / lockfile 变更）→ 停下修，禁止提交；**黄 = exit 0 但有需注意项**（重命名条目、变更清单为空）→ 随回执转述给用户；绿 = exit 0。门禁自己打印的"通过"不算证据，必须贴命令原文 + 完整输出。

**动作 4：改动留在工作树，先别提交**——本卡的提交在 ④ 与状态回写一起做（顺序铁律：回写状态 → 提交 → 复跑收工仪式取 0），避免 STATE.md 游离未提交。

**禁令：**
- 禁止提交前跳过动作 3 的门禁
- 禁止 `git add -A` / `git add .`
- 禁止顺手重构/顺手升级依赖/改无关文件
- 禁止跳过"黄牌确认"直接大改

## ④ 状态回写

**先回写，后提交**（状态回写必须早于提交；顺序反了 = STATE.md 游离未提交，6-4 卡的收工仪式必判红）。更新 STATE.md：
- `起点锚点` = 修复起点哈希
- `下一步` = 6-4 回归验证
- `未决问题` = 黄牌获批记录（如有）

回写完再收尾三连（顺序不可换：回写状态 → 提交 → 复跑收工仪式取 0）：

```powershell
$scopeFiles = @('src/a.ts','src/b.ts')   # 本卡改动的精确文件清单（与动作 3 一致）
git add $scopeFiles STATE.md
git commit -m "6-3 fix(<slug>): <修了什么> (BUG-001)"
powershell -NoProfile -File check.ps1
```

退出码必须是 0；若为 2（`$STEPS` 未配置，环境未初始化）或非 0 → 停下问用户，禁止宣布修复完成。

固定收尾语：
`修复完成。等待你裁决。回复"继续"进入 6-4 回归验证，或说要调整哪里。`
