## ① 开工确认

收到开工指令后，先回执以下五项再动手（缺项不开始）：

1. **任务复述**：用一句人话说清"这个功能在什么条件下才算能用"（多快、多稳、能扛多少、谁能看）。
2. **假设清单**：逐条写"我假设 X；若错则阈值 Y 失效"——先查 `docs/ARCHITECTURE.md`、`docs/RUNBOOK.md`、`docs/registry/DATA_DICT.md`、SCOPE.md。
3. **澄清问题（≤5 个，能删则删）**：只问决定阈值的硬数字。
   ❌ 反例："性能有什么要求吗？"（用户答不出，等于白问）
   ✅ 正例："这个页面慢到几秒你会觉得不能接受？峰值大概几个人同时用？"
   用户答不出 → 用现状基线实测当依据（动作 3），禁止自己拍一个数字。
4. **本卡检查清单原文（开工时逐字复述这五条，收工前逐条勾）**：
   - [ ] ① 六维逐维都写了：可测阈值（数字 + 单位）+ 验证方式，两样缺一不可
   - [ ] ② 给不出阈值的写 `N/A（理由）`，没有留空、没有"尽量/差不多/待定"
   - [ ] ③ 每条阈值都配一条 4-3 能直接执行的验证动作（原文写在本卡产物里）
   - [ ] ④ 阈值是可测边界（P95 ≤ 800 ms），不是形容词（响应要快）
   - [ ] ⑤ 用户已逐条看过阈值并确认（原话引用；未确认不许进 4-1）
5. **落点声明**：产物 = `docs/specs/<日期>_<slug>/NFR.md`；下一张卡 = 2-5 风险与干系人（L 档／多方参与），否则 3-3 测试策略（M/L）。

## ② 执行

**动作 1：六维清单逐维填（表格化，一维一行；六行缺一不可）**

| 维度 | 必须回答的问题 | 典型阈值示例（按项目实际改数，禁止照抄） | 验证方式 |
| :-- | :-- | :-- | :-- |
| 性能 | 多久算慢？ | 列表页 P95 ≤ 800 ms；单次导出 ≤ 5 s | 压测或计时脚本连跑 3 次取中位数 |
| 容量 | 数据／并发涨到多少还撑得住？ | 单表 ≤ 100 万行；上传单文件 ≤ 50 MB；峰值并发 ≤ 200 | 造数脚本 + 压测 |
| 可用性 | 允许停多久？ | 月可用性 ≥ 99.5%（月度停机 ≤ 3.6 h）；启动 ≤ 3 s | 健康检查与运行日志统计 |
| 安全 | 谁能看、谁能改？ | 未登录返回 401；越权访问他人数据返回 403；日志不含手机号 | 用例逐条跑（威胁建模的检查项逐条落成用例） |
| 可维护 | 新人多久能跑起来？ | 干净机器 ≤ 30 分钟跑起来；单文件 ≤ 500 行 | 照 docs/RUNBOOK.md 实跑一次并计时 |
| 兼容 | 在哪些环境必须能用？ | Chrome/Edge 最近 2 个大版本；Windows 10+；安装包 ≤ 20 MB | 目标环境逐个目检 |

❌ 反例：`性能：响应要快，体验要好`（不可测，等于没写）
✅ 正例：`性能：列表页 P95 ≤ 800 ms（1000 行数据）；验证：脚本连跑 3 次取中位数`

**动作 2：每条阈值配一条 4-3 能直接执行的动作**
在 NFR.md 每条阈值后追加一行：`验证动作：<命令／打开哪页 → 做什么 → 看什么>`。
判据：把这一行原样粘进 4-3 的 VERIFY.md 就能执行，不需要再查别的文件。
❌ 反例：`验证动作：测一下性能`（没法执行，也没法判红）
✅ 正例：`验证动作：起服务后跑 scripts/bench.ps1 -Rows 1000，读输出 P95 ≤ 800`

**动作 3：阈值只能来自三处（至少写出依据，禁止拍脑袋）**
① 用户给过的硬数字（原话引用）；② 现状基线实测（先测再定，命令写进 NFR.md）；③ 同类产品公开做法（写出来源）。
❌ 反例：阈值定 800 ms，因为"看着顺眼"
✅ 正例：现状基线实测 P95 = 2.3 s，目标取 1/3 → 定 800 ms

**动作 4：给不出阈值的写 `N/A（理由）`**
例：`可用性：N/A（本地单人桌面工具，无服务端，不存在停机概念）`。
S 档只填「性能」「安全」两行，其余四维写 `N/A（S 档豁免）`。禁止写"待定""后续再补"。

**动作 5：两行命令（先赋值再调用；第二条命中一行 = 一处不可测表述）**
```powershell
$spec = 'docs/specs/20261003_export'
New-Item -ItemType Directory -Force -Path $spec | Out-Null
Select-String -Path "$spec/NFR.md" -Pattern '待定|尽量|差不多|可能|应该'
```

**禁令：**
- 禁止留空：每一维必须有阈值或 `N/A（理由）`（空着 = 这条需求没人管）
- 禁止把档位当借口编数字（档位只决定填几行，不决定真假；编 = 假阈值）
- 禁止拿"写了测试"当验证动作的替身（写了测试 ≠ 跑过阈值验证）
- 禁止在用户确认阈值前进入 4-1
