# INDEX · 归档索引（docs/archive/ 的唯一入口）
> 最近核对 —（骨架未核对；核对后填 <日期> @ <提交哈希>）
> **为什么有这张表**：归档此前只做 `git mv`，半年后想找"当年为什么否掉方案 X"只能翻目录名——索引是归档唯一的可检索面。
> **读归档先读本表**：一行说清"当时做了什么、结论是什么、什么条件复活"。归档目录里的文档是**历史证据、不是现行判据**（与现行卡或 `docs/` 现行层冲突时，一律以现行判据为准）。
> 谁维护：5-1 归档卡（每次归档**同批**追加一行，新行加到表末——按时间顺序，追加命令就是一条 `Add-Content`）；行数上限 ≤120。

## 目录里还有什么

- `<日期>_<slug>/tech-debt.md`：归档当时的债务快照（open / carried / closed 三个计数 + 关键项一行），**首行是机器可读的归档头**：`> 归档 <YYYY-MM-DD> ｜ 结论 <一句话> ｜ 复活条件 <无|…>`。
- 其余文件 = 该任务 `docs/specs/<日期>_<slug>/` 的原样快照（`git mv` 保留历史）。

## 淘汰 ≠ 归档（别把这两件事混在同一张表里）

- **归档**=任务快照进 `docs/archive/`，本表登记一行。
- **淘汰**（`docs/lessons/` 里同症状合并、`docs/decisions/` 里被 supersede）**不搬进来**——搬进来等于永久保留，那不是淘汰。教训卡的做法是"合并或删除"，决策卡的做法是"标注被取代"，都留在原地。
