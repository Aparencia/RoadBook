# 数字没有口径 / CRLF 让对拍与门禁失真
现象：两个工具数同一文件行数差几十；逐字节对拍永远不等；`git hash-object` 相等**且** `git diff` 为空却仍掩盖 EOL 差异；`git stash` 后 Vite 拒绝构建；`Get-Content` 读中文日志 GBK 吞行（"新增 6 条"实为"新增 0"）。
根因：core.autocrlf=true 下工作区与仓库行尾不同；计数口径不一——**唯一有效口径 = `[IO.File]::ReadAllLines($p,[Text.Encoding]::UTF8).Count`（含空行）；禁 Get-Content（GBK 少算可达 56 行）、禁 Measure-Object -Line、禁字节 0x0A 计数**。
修法（实测）：数字带四元组（值+口径+时点+域），声明贴命令原文；字节对拍必须先行尾归一；判提交树门禁用 `git -c core.autocrlf=false archive <commit>`；autocrlf=true 的仓库禁 `git stash`。
下次定位：对拍失败；两处数字对不上；"行数/条数"类声明。
