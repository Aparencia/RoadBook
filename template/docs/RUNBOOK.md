## 1. 部署（5-2 发布卡首次部署后填实）

- 部署方式：（待填：5-2 卡）本地演示 / 静态托管（Vercel、Netlify）/ 托管平台（Railway、Render、Fly.io）/ 云服务器。
- 部署步骤：（待填：5-2 卡）首次部署后逐行写真实命令；没填 = 还没发布过，不是欠账。
- 生产环境地址：（待填：5-2 卡）URL 或"暂无"。
- 生产环境变量：哪些键要在平台后台配置（键名见 `.env.example`）。

## 2. 回滚（发布坏了 3 步退回）

1. 回到上一个 tag/版本：（待填：5-2 卡）首次发布后在此写可执行命令。
2. 数据怎么办：（待填：5-2 卡）有迁移 down / 用备份恢复 / 无需处理。
3. 确认恢复：（待填：5-2 卡）打开哪个地址、看什么。

## 3. 环境与配置（4-5 卡建新环境时填；每加一个环境加一行）

| 环境 | 用途 | 地址/入口 | 配置来源 | 谁能改 |
| :-- | :-- | :-- | :-- | :-- |
| dev | 本地开发，怎么崩都行 | 本机 | .env（不进库） | 开发者本人 |
| staging | 上线前走查，只用假数据 | （待填：4-5 卡） | 平台环境变量 | （待填：4-5 卡） |
| prod | 真实用户与真实数据 | （待填：4-5 卡） | 平台环境变量（权限最小化） | （待填：4-5 卡） |

- 配置差异表：同名键在不同环境取值不同就逐行列出（键 / dev / staging / prod）；无差异写"无差异"（待填：4-5 卡）。
- 密钥来源与轮换：（待填：4-5 卡）平台密钥管理还是 .env 文件、谁在什么时候轮换；`.env.example` 只放键名，真实值只进 `.env`。
- 环境切换步骤：（待填：4-5 卡）改哪个文件或变量、怎么确认真的切过去了。

## 4. 观测与告警（5-4 卡发布后观测窗填；明细表见 `docs/OBSERVABILITY.md`）

- 健康检查：（待填：5-4 卡）URL 或命令，期望状态码/输出（怎么跑见 OBSERVABILITY.md §1）。
- 错误日志：（待填：5-4 卡）去哪看 + 过滤最近 10 分钟错误的命令或面板筛选条件。
- 三项核心指标：（待填：5-4 卡）指标名 + 去哪看 + 正常范围；指标、阈值、通知对象改动必须同批回写 `docs/OBSERVABILITY.md`。
- 告警阈值与通知对象：（待填：5-4 卡）阈值 → 通知谁（人名/群）；观测窗时长与巡检节奏也写这里。

## 5. 备份与恢复演练（5-5 卡跑；改数据结构后必须重跑）

| 项 | 填什么 |
| :-- | :-- |
| 备份对象 | （待填：5-5 卡）数据库 / 上传文件 / 配置 / 无（写清为什么不需要） |
| 备份频率与保留期 | （待填：5-5 卡）多久一次 / 留几份 / 存哪 / 谁有权限 |
| 备份方式 | （待填：5-5 卡）可复制命令；或"平台自动备份，位置：…" |
| 最近演练日期 | （待填：5-5 卡）YYYY-MM-DD；没做过写"未演练"——这是欠账，登记 `docs/TECH_DEBT.md` |
| 实测 RTO / RPO | （待填：5-5 卡）恢复耗时实测值 / 可容忍的数据丢失窗口实测值 |
| 过期与失效检查 | （待填：5-5 卡）最近一次检查日期 + 结论：备份文件能不能真的读出来 |

- 演练必须**真跑一次恢复**（不是看备份文件在不在）：步骤、耗时、踩到的坑记进 `docs/versions/`，由 5-5 卡收尾。
