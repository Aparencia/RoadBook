# refactor/ · 重构记录（Refactoring Records；7-8 卡产物；≤40 行）
> 最近核对 —（骨架未核对；核对后填 <日期> @ <提交哈希>）
> 谁写：7-8 结构重构 ｜ 谁读：4-2 代码审查、5-1 归档、6-6 流程体检 ｜ 何时更新：每次立项重构、每批净减结算、旧实现退役时
> 不适用时怎么写：没有重构项目 → 本目录留空骨架即可（不是欠账）；一次重构做完把记录留在本目录，不要删。

## 1. 命名与一记录一文件

- 文件名：`REFACTOR_日期_slug.md`，日期写 `YYYY-MM-DD`，slug 用小写连字符（例：`REFACTOR_2026-10-03_split-billing.md`）。
- 一记录 = 一次重构立项；跨批进度写在同一条记录的批次表里，不新开文件。

## 2. 五阶段（Strangler；每阶段都要能独立回滚）

| 阶段 | 做什么 | 完成判据 |
| :-- | :-- | :-- |
| 1 并行实现 | 新旧并存，新路径只被测试调用 | 新实现单测绿，旧路径不受影响 |
| 2 影子/双写校验 | 同一输入同时走新旧，比对输出 | 差异为 0（有差异先修，不切读） |
| 3 切读 | 流量或调用点逐个切到新实现 | 全量切完，观察窗无回归 |
| 4 删旧 | 删掉旧实现、死代码与开关 | 旧文件与分支清零，测试仍绿 |
| 5 消开关 | 清掉临时开关、双写逻辑与迁移开关 | 搜不到开关名，依赖方向无环 |

## 3. 每批纪律

- 小步提交：每批一个回滚点（能单独 revert）；禁止把功能改动混进重构批次；**每批净减 ≥200 行 或 ≥3 个文件**（`git diff --stat` 上能数出来，达不到说明这批不算重构收尾）。

## 4. 验收四件（缺一件不算做完）

| 验收件 | 证据 |
| :-- | :-- |
| 行为等价 | 特征测试/黄金样例/契约测试全绿，且有对照输出 |
| guardrail 绿 | 全量 guardrail（`powershell -NoProfile -File gate.ps1`）退出码 0 |
| 旧实现退役 | 旧文件、开关、并行登记簿条目同批删除 |
| 依赖无环 | 依赖方向检查命令输出无环，结构约束回写 `docs/ARCHITECTURE.md` |

## 5. 本目录记录模板骨架（复制开工；写完删掉本节示例）

- 骨架五段：触发（重复代码/上帝类/循环依赖/技术栈迁移/框架升级/性能）｜边界（行为不变、外部契约不变；要改行为 = 新功能回 2-1）｜安全带先行（特征测试/黄金样例/契约测试先绿再动第一行）｜判据（改动面 <40% 就地改；≥40% 需理由 + 用户确认；>60% 且无复用价值才重写）。
- 批次与回滚：批次表（范围 / 净减行数 / 回滚点 commit / 验收证据）；回滚预案分单批与整体，数据迁移写 down 步骤。

## 更新义务

- 每批结算与旧实现退役：同批更新 `STATE.md` 并行态登记簿与 `docs/ARCHITECTURE.md`；提交前跑 `powershell -NoProfile -File check.ps1` 取退出码 0。
