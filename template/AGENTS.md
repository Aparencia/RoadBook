# AGENTS.md · 项目宪法

> 本文件是 agent 每次会话自动读取的最高行为准则。修改本文件 = 修改项目规则，需要人在场确认。
> 行数硬上限 240 行：加一条规则前先问"这条防止过哪次真实返工"，答不出就别加。

## 0. 项目身份

- 一句话：<这个项目做什么、给谁用>
- 技术栈：<按选型填>；版本锁定见 `.tool-versions`——**开工跑 doctor.ps1 时它被逐行读取比对**（装不上或版本不符会点名）；人装依赖、排查"我这能跑他那不能跑"也以它为准；改它任何一行都算环境变更，归档回执必须说明
- 文档地图：`docs/ARCHITECTURE.md`（系统怎么组成）｜`docs/RUNBOOK.md`（部署/回滚/备份/恢复演练）｜`docs/UI.md`（屏幕与交互）｜`docs/DESIGN_TOKENS.md`（色彩/字号/间距）｜`docs/MOTION.md`（动效时长与缓动）｜`docs/OBSERVABILITY.md`（观测与告警）｜`docs/PRIVACY.md`（数据与合规）｜`docs/I18N.md`（语言与可访问性）｜`docs/USER_GUIDE.md`（上手与交接）｜`docs/refactor/`（重构记录）——其中带「由卡触发」的几份未触发时留骨架；谁创建、谁维护、谁读见 `docs/README.md` 对应表
- 开发流程：**Roadbook V6 母版**——动作照母版流程卡逐张走（卡号与顺序见根 `START-HERE.md`）；状态写在根 `STATE.md`（唯一事实源）

## 1. 完成的唯一定义（DoD）

**"完成" = `powershell -NoProfile -File check.ps1` 退出码 0 + 完整粘贴真实输出。**
其他一切形式的"完成了/应该可以了/逻辑上没问题"一律视为未完成。
type-check 干净 ≠ 验证；没跑过的测试等于没有测试。
**收尾顺序（铁律，不许颠倒）：先回写状态**（STATE.md / registry 三件套 / 账本 / 计数）→ **再 `git add` + `git commit`** → **最后复跑 `check.ps1` 取退出码 0**。先提交后回写 = 状态没进历史；提交前跑门禁 = 脏树判红是假的。

## 2. 范围四禁

1. **禁越任务范围**：只动当前任务 SCOPE 涉及的文件。发现范围外的问题 → 登记 `docs/TECH_DEBT.md`，不许顺手修。
2. **禁平行新建**：新建任何文件/组件/函数前，先查 `docs/registry/` 三件套与 `docs/ARCHITECTURE.md`；已有近似物必须复用；确实要新建，回执里写清"为何不能用已有的"。
3. **禁未请求的依赖变更**：不升级、不替换、不新增依赖，lockfile 变更必须单独说明。
4. **禁顺手重构**："路过就改" = 越界。重构只能来自专门立项的任务。

## 3. 停问规则（宁可多问，不许硬猜）

- **同一个错误第二次出现**：停止尝试，输出诊断四项——做了什么/预期是什么/实际是什么/报错原文——然后向用户提问。
- 用户意图模糊（"把它弄好""优化一下"）：不许猜，列出你理解的两三种可能让人选。
- 不确定数据/接口/文件是否存在：实际打开确认，禁止凭记忆写。
- 任何红灯判据触发：停下，输出"红灯+依据"，等待人处理。禁止输出"如果你坚持我可以继续"。

## 4. 不可委托清单（只能人做，agent 只出草案和证据）

- 执行 SQL / 数据库迁移 / 删除或修改真实数据
- 执行发布部署 / 打 git tag
- 门禁裁决（红/黄/绿的最终判定）
- 确认验收（照行为验收清单点检）
- 宪法（本文件）与 STATE.md 重大字段的修改确认

## 5. 防幻觉三查（每次声明前自检）

1. 引用的文件路径真实存在吗？（不确定 → 实际打开）
2. 数字/哈希/版本号来自命令输出还是记忆？（记忆 → 不许写）
3. "已完成/已验证"有对应证据吗？（没证据 → 说"未完成"）

## 6. 回执契约

- 每个开发动作开工前：宣布"正在执行 <卡号-名称>"，并粘贴该卡开工确认要求的检查清单原文。粘贴不出来 = 没读卡 = 本轮作废。
- **会话内已读声明制**：本会话已读过且未变化的文件/清单，回执"已读，状态未变"即可，**禁止重复粘贴长内容**（省 token，不省核验——跨会话必须真读）。
- 收工必须给证据：命令真实输出 / 文件路径 / 提交哈希，逐条对应"完成"声明。
- **主张必须过这张表**（写不出"需要什么"那一列 = 这条主张不许说）：

| 你会主张 | 需要什么（才算数） | 不算数 |
| :-- | :-- | :-- |
| 完成 / 通过 | **本轮（同一条消息内）真跑的 `check.ps1` 完整输出 + 退出码** | "跑过了"、"应该是绿的"、只贴最后一行、引用上一批/别处贴过的输出、引用子代理贴的输出 |
| 测试通过 | 真跑命令 + 失败转绿的前后两次输出 | 只跑一次、跳过失败项、mock 掉被测物 |
| 收到审查或用户反馈 | 复述要求 + 到代码里核对事实 + 采纳或带技术理由驳回 | "你说得对"、"好建议"、"谢谢" 等表演性回应；未核对代码就承诺照改；只改懂的那几条 |
| 修好了 bug | 先复现（红）+ 修后转绿 | "逻辑上应该好了"、只改代码没复现 |
| 已读完某个文件 | 行号级原文引用 | "已读"、凭印象概括 |
| 只改了 SCOPE 内文件 | `git diff --name-only` 与 SCOPE 逐条对齐 | "我只动了这一处" |
| 完成但有疑虑 | 明写"完成但有疑虑" + 疑虑点（文件:行）+ 为什么不确定 | "应该没问题"、"我按 X 假设做的"（假设没写进回执 = 不算） |
| 需求满足 | SCOPE 验收标准逐条核销（每条给证据或写"未满足"），并单列缺口 | "测试全绿，阶段完成" |
| 已提交 / 已推送 | `git rev-parse HEAD` + `git status --short` 空；push 另附 `git ls-remote` 同哈希 | "提交了"、把本地 commit 当 push |
| 界面符合设计 | 截图或样式取值 + 对应 token 名 | "看起来像了"、"差不多" |
| 数字 / 度量改善 | 同一条命令的前后数字 | 估算、别处抄来的数字 |

## 8. 密钥与数据卫生

- 密钥/凭证只进 `.env`（已被 .gitignore 挡住）；代码、日志、提交信息里禁止出现真实密钥。
- `.env.example` 只放键名和注释；泄露过的密钥立即作废轮换（git 历史永远可读）。
- dev/test 数据严禁写入 prod 环境。

## 10. 环境速查

- 启动 / 检查 / 测试：1-2 卡选型后在这里各写一行真实命令（本行还没填 = 尚未选型，不是欠账）
- 数据库连接：<本地 dev 的连接方式，一行>（迁移怎么跑见 docs/RUNBOOK.md）
- 已知环境坑：<Windows 端口占用/依赖版本 等，踩过的记这里>
- 编码坑（默认就要知道）：Windows PowerShell 5.1 按系统码页读**无 BOM** 的 .ps1 → 中文判词乱码甚至 ParserError ⇒ .ps1 一律存 UTF-8 **带 BOM**；`>` / `2>` 重定向默认写 UTF-16LE，别拿它生成报告/日志
- 远端与推送：`git push` **不进 DoD**——DoD 必须本机可判定，断网/没凭据不该让"完成"变假红；没有远端就在 STATE.md「远端仓库」写"本地-only（已裁剪）"，推送挂在 5-1 卡归档收尾
- DSH（DeepSeek Harness）**0.2.0-rc2**：装了什么插件、怎么关，记在本节（原 8-3 卡与 `docs/TOOLING.md` 已按用户裁决删除）。**不要把 `dsh` 写进 `.tool-versions`**——doctor.ps1 会把"工具不在 PATH"判红，而没有 DSH 的机器也要能跑完这套流程

## 11. 代码生成硬标准（生成代码时逐条自检；4-2 代码审查卡按此复核）

1. **结构**：单文件 ≤500 行（**测试文件豁免至 ≤1000 行**）、函数 ≤50 行；纯逻辑与副作用分文件；依赖显式传入（禁止函数深处直连全局单例/隐式全局状态）
2. **命名**：前后端业务术语同字典（如 `OrderStatus.PENDING` 两端拼法一致）；禁 `data/info/handle` 等空泛名；禁 `any`/无类型 Dict——入参出参必须有类型契约（Interface / Pydantic / TypedDict）
3. **注释写 Why 不写 What**：业务背景、边界条件、副作用必须写进注释；Magic Number 与 Hack 必须解释原因；解释代码在做什么的废话注释不加
4. **防御**：假设一切外部依赖会失败——网络/DB/第三方调用必须有显式超时和失败分支；失败路径禁止空 catch 或静默吞错；错误信息要能指向根因（带上下文，不只是 "error"）
5. **可测试**：核心业务逻辑写成纯函数（同输入必同输出，无隐藏状态）；副作用集中到边界层，便于 mock
6. **环境**：生成代码时禁止硬编码路径/URL/端口/密钥——一律走配置注入（.env / 环境变量）

## 12. 个人档（默认；单人 + AI 执行）

- 上文所有"多方 / 干系人 / 沟通节奏"条款走单人分支：结论一行写进 `STATE.md` 的 `裁剪记录`，理由一行即可，不写会议纪要。
- 门禁默认「轻确认」（说一句就继续）；只有 L 档与红线域才升级为「裁决」（等人确认再动）。
- 不可委托五条不打折：执行 SQL / 发布部署 / 删除或修改真实数据 / 打 tag / 门禁裁决。
- 多 agent 并行（Agent Teams / 子 agent）：写作用域互斥、共享文件由主线程独占、并发写者 ≤5；**验收必须由主线程亲自跑门禁并抽查 diff**，子 agent 自报不算证据。
- **子 agent 不得自派子 agent**：实现者不得派帮手，尤其**不得自派审查者**（=同一条审查位上重复占位，判缺陷而非严谨）；审查者不得为"第二意见"再派审查者。
- **子 agent 每次重新构造、禁止继承历史**：派单 = 本任务的要求 + 要碰的接口 + 全局约束三样；粘"前几批状态摘要"= 作废重发。回执只回四行（状态 / 提交短哈希+主题 / 一行测试摘要 / 疑虑），正文写进报告文件。
- **派单必须自带证据原文**（报错原文 / 测试名 + 期望 vs 实际 / 文件:行）与期望产出形式；"有个测试挂了"这种派单作废。
- 长任务用 goal 持续轮次 + 里程碑回执；上下文吃紧时压缩前先把证据落盘，交接靠 STATE.md（只写稳定事实，读出的证据不回写）。
