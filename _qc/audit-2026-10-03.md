## 一、P0 —— 机制会假绿 / 假红 / 静默失效

### P0-1 `orphans.ps1` 在非 ASCII 文件名上抛异常并**静默丢文件**，退出码仍 0
- **[实跑]** `git ls-files` 对含中文的路径输出带引号的八进制转义串，例：`"docs/lessons/2026-09-11_UTF-16LE\347\274\226\347\240\201\347\240\264\345\235\217.md"`。模板的 7 张种子教训卡**全部**是这种形态（32 个文件里 7 个）。
- **[实跑]** `template/orphans.ps1:27` 的 `[IO.Path]::GetFileName($_)` 对这 7 条抛 `ArgumentException: 路径中具有非法字符`（stderr 里出现 **7 次**）。它写在 `Where-Object` 脚本块里 → 异常被当成"条件为假"吞掉，条目直接消失。
- **[实跑]** 汇总行照打 `孤儿 0 项｜零引用导出 0 项｜文档幽灵 0 项｜反向幽灵 0 项｜未登记 0 项｜文件数 7`，`ORPH_EXIT=0`。→ **静默漏报 + 计数失真**（真值 32，报 7）。母版自己靠 repo-local `core.quotepath=false` 侥幸躲过，**新项目一建就中**。
- **修法**：`git -c core.quotepath=false ls-files`（或 `ls-files -z` + `-split "`0"`），并对残留引号做 unquote 容错；`catch` 里把"读取失败"计入清单而不是置空。

### P0-2 `gate.ps1` 有 **6 条独立假绿路径**，全部 `exit 0`
- **[转述，含实跑输出]** 未传 `-Anchor` 时 `:19-22` 整段跳过（**连同变更清单与行数检查**）→ 601 行文件 + 未跟踪文件仍输出 `[GREEN]`，exit 0。
- **[转述]** 非 git 目录 / `-RepoRoot` 写错时 `:24-25` 的两条 `2>$null` 把失败吞成"无变更" → `[GREEN]`，exit 0。
- **[转述]** 未传 `-ScopeFiles` 时 `:29` 的范围检查整段跳过 → 脏树 `[GREEN]`。
- **[转述]** `:38-42` 行数超限只进 `$warn` → `[YELLOW]` exit 0（AGENTS.md §11 是硬标准，`design/v6-design.md:103` 明说行数下沉 gate.ps1）。
- **[转述]** `:14` 的 `IsTest` 正则无词边界 → `src/contest.ts`、`src/latest.ts`、`src/spectrum.ts`、`src/inspector.py` 实测全部 `Test=True`，豁免到 1000 行。
- **[实跑]** 中文路径下 `:39` 的 `Test-Path $full` 抛 `ItemExistsArgumentError`（被 `if` 吞）→ 该文件行数检查被跳过。
- **修法**：先 `git rev-parse --is-inside-work-tree` 判据失败即 exit 1；无锚点降级为"只查工作树 + 行数"而非整体空转；`-ScopeFiles` 缺失时打 `[--] 范围未校验`（或直接 RED）；行数超限进 `$fail`；`IsTest` 收紧为 `(?i)(\.|/)(test|spec)s?(\.|/)|\.(test|spec)\.`。

### P0-3 `_qc/check.ps1` 的 **149/149 是纯文本断言**，从不执行被检脚本
- **[转述]** `:88/:120/:124/:131` 与插件段等 17 项全是"字符串出现即通过"。所以上面 P0-1/P0-2 那 10 条实测假绿，母版自己的 QC **一条也发现不了**——它保证的是"卡和文本长得对"，不是"脚本行为对"。
- **修法**：加一条**冒烟执行**——在临时目录跑 `gate.ps1` / `orphans.ps1` / `check.ps1` 的已知失败样本，断言退出码与关键字（例如：非 git 目录必须 exit 1；中文文件名仓库的汇总行"文件数"必须等于 `git ls-files` 计数）。

### P0-4 编码：70/75 个文件无 UTF-8 BOM，而本机 PS 5.1 按 GB2312 读文件
- **[实跑]** 仓库 75 个文件里**只有 5 个带 BOM**——恰好是 `_qc/check.ps1` + 4 个 `template/*.ps1`；其余 **70 个（全部 .md/.json/.js/.mjs/.yml/.svg）无 BOM**。
- **[实跑]** 危害 A：写一个 UTF-8 无 BOM、含中文的 .ps1 去跑，PS 5.1 直接 `ParserError: UnexpectedToken / 字符串缺少终止符`。5 个脚本靠 BOM 活着，但**没有任何断言要求 .ps1 必须带 BOM**——BOM 被编辑器剥掉就静默变乱码判词。
- **[实跑]** 危害 B：`[Console]::OutputEncoding = gb2312`，而 5 个脚本**全部 0 处**设置输出编码 → `check.ps1` 的输出是 `[FAIL] ���������ɾ���1 ��δ�ύ�Ķ������`。中文 Windows 上，DoD 要求的"粘贴真实输出"粘出来是乱码，**门禁判词读不出来**。
- **修法**：① 脚本顶部统一 `chcp 65001 > $null` + `[Console]::OutputEncoding = [Text.Encoding]::UTF8`；② `_qc/check.ps1` 加断言"所有 .ps1 必须带 UTF-8 BOM"；③ `.gitattributes` 或文档写明 BOM 约定。
- **[实跑] 2026-10-03 修复过程中亲验（本条的"活证据"）**：用编辑工具改写 `_qc/check.ps1`（反转 `_archive` 断言 + 用法行改正斜杠）后，**BOM 被工具剥掉**，紧接着跑 QC 直接 `ParserError: UnexpectedToken`，报错停在 `$cards = @('00-驱动卡','10-想法调研',…`——PS 5.1 按 GB2312 解码把字符串的收尾引号吃掉。也就是说"BOM 被编辑器剥掉就静默变乱码判词"不是假设，是**几分钟内就会真实发生**的事：`_qc/check.ps1` 的"所有 .ps1 必须带 BOM"断言应当作 P0 修，而不是建议。

### P0-5 git 重命名被 `gate.ps1` 判**假红**
- **[实跑]** `git mv a.ts b.ts` 后 `status --porcelain` 输出 `R  src_old_name.ts -> src_new_name.ts`；`:25` 的 `$_.Substring(3).Trim()` 抽出 `src_old_name.ts -> src_new_name.ts`（**新旧名粘成一条**）。
- **[实跑]** `gate.ps1 -Anchor HEAD -ScopeFiles 'src_new_name.ts'` → `exit=1`，报 `[RED] 越界：src_old_name.ts -> src_new_name.ts 不在 SCOPE 文件清单内`。**合法重命名被判越界。**
- **修法**：改 `git status --porcelain -z` 解析，状态码 `R`/`C` 时取两个路径分别入清单。

### P0-6 `check.ps1` 的预算断言在**模板默认状态**下永久空转
- **[转述]** `template/STATE.md:16` 的默认值就是 `文件数基线: 0（0 = 未初始化）`，而 `template/check.ps1:27-28` 对 `0` 与"字段缺失"同样只打 `[--]` 跳过。→ 未初始化的新项目**永远绕过文件数预算**。
- 同族问题：`:33` 在非 git 仓库跳过**全部** git 断言，DoD 仍可能成立（`design/v6-design.md:245` 把 git 断言当"完成必已提交"的机械真相来源）。
- **修法**：`0` 判 `[FAIL] 基线未初始化`（只有字段缺失才 `[--]`）；非 git 仓库判 FAIL。

### P0-7 `doctor.ps1` 环境自检**永远 exit 0**
- **[转述]** `template/doctor.ps1:5` 的 `$REQUIRED = @()` 默认为空，`:9-16` 只判"命令有没有输出"，且只在 `$REQUIRED -contains $t` 时才 FAIL；全文**没有**与 `.tool-versions` 比对版本的代码。→ "环境自检：每项输出版本号=通过"（`design/v6-design.md:115`）名存实亡。
- **修法**：从 `.tool-versions` 读期望版本，缺项/版本不符计入 `$miss`。

### P0-8 卡 40 / 32 / 42 / 43 的**"回写状态在提交之后"**结构缺陷
四张卡的骨架都是 `② 执行（含 git add/commit）` → `③ 证据回执` → `④ 状态回写（改 STATE.md）`，**状态改动永远落在提交之后**：
- `playbook/40-归档.md:62-67`（⑨ 原子提交）先提交，`:93-98`（④）再改 STATE.md → 归档后 **STATE.md 必然游离未提交**，而同卡 `:97` 却写"`工作树状态` = 干净"；下一张卡跑 `check.ps1` 见脏树判 `[FAIL]`（`template/check.ps1:35-40`）。
- **[转述]** `playbook/32-回归验证.md:37-42`：在"写完负面测试 + 改完 STATE"之后才跑 `check.ps1`，而全卡**没有任何提交动作** → 按卡执行必 FAIL，`:40` 又写"不通过 → 回 31 修"，会把"没提交"误判成"修复失败"。
- **[转述]** `playbook/42-复盘.md:36`（提交）先于 `:55`（改 STATE）→ 同构假绿。
- **[转述]** `playbook/43-流程体检.md:94` 声明"体检本身也要落一次提交"，全卡无 `git add/commit` 命令。
- **修法**：把 ④ 的状态回写并入 ⑨ 的 `git add` 清单（或 ④ 之后补一次 `git commit -m "40 docs(state): ..."`），并在 ③ 回执里附 `git status --porcelain` 为空的原文。

### P0-9 S 档流程：卡 25 的触发条件在 S 档下**无法满足**
- `playbook/24-代码审查.md:1`：24 卡"M/L 档必走；**S 档跳过本卡**"；`playbook/23-分批编码.md:138`：S 档 → 25 **跳过 24**；`design/v6-design.md:98`：S 档 = 21→23→25→40。

- **修法**：`playbook/25-验证.md:2` 改为"S 档 23 卡末批完成｜M/L 档 24 卡绿灯且用户放行"。

### P0-10 `check.ps1` 空 `STEPS` 无断言（下游门禁空心）
- **[实跑]** `template/check.ps1:9` `$STEPS = @()` 时脚本**不会**因 STEPS 为空而失败；防线只有 `playbook/11-选型初始化.md:100` 要求回执写"check.ps1 退出码 0 **且 STEPS 非空**"——靠人眼。
- **修法**：`if ($STEPS.Count -eq 0) { [FAIL] STEPS 为空（未接本项目命令）; $fail++ }`。

### P0-11 卡 31 的修复门禁**没有接线到脚本**
- **[转述]** `playbook/31-修复.md:23-29` 的"双维锁"是 31 卡的核心门禁、`:56` 要求"对照双维锁自评 红黄绿"，全卡**不调用** `gate.ps1`（其 `-Anchor/-ScopeFiles/-LineLimit` 正是为此而生）→ `design/v6-design.md:103/246` 的"门禁有牙"在修复路径上空转。
- **修法**：31 卡加入 `powershell -File gate.ps1 -Anchor <起点锚点> -ScopeFiles "文件1","文件2"`，红=停、黄=随知会转述。

### P0-12 卡 43 两条体检信号判据缺失，**永远不可观测**
- **[转述]** `:29` 信号 2 用 `Select-String -Pattern "来源"`，只命中 TECH_DEBT 表头（数据行是 `BUG-003 修复过程` 这类值，不含"来源"二字）→ "同一来源 ≥2 次"恒为 0。
- **[转述]** `:54/:59` 信号 9（起点锚点连续两个任务未前移）与信号 10（连续两个归档周期 ahead）所需观察窗口（2 个任务 / 2 个归档周期）**短于**本卡触发周期（每 15 次归档），且 `起点锚点` 在 `playbook/40-归档.md:97` 被清空 → 两个兜底信号是死的。

### P0-13 文件数基线被**每批重置**，`43 卡信号 8` 永不触发
- **[转述]** `playbook/23-分批编码.md:136` 要求每批收尾把 `文件数基线` 更新为当时的 `git ls-files` 计数；`template/check.ps1:26-30` 只用"当前 ≤ 基线 + 20" → **差值恒约等于 0**，累计膨胀（生成多删除少的总账）永远抓不到，只能抓单批 >20。
