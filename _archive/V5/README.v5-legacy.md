# PROCESS V5 · 开发流程母版

> 来源：PROCESS.md V5.0.0 · 文件 `README.md`（本母版的**总入口与导航**）
> 定位：告诉第一次拿到这套母版的人——它由哪四部分组成、各自干什么、怎么装进项目、从哪开始读。
> 生成日期：2026-01-01 · 维护者：人
>
> **这是什么**：一套"人是操作者、AI 是工具"的软件开发标准。它把四件事装进一份自包含的母版——
> ① **流程**（4 条轨道、28 个带门禁的步骤）；② **骨架**（可复制的项目目录树）；③ **文档体系**（规范/模板/沉淀机制）；④ **Agent 条款**（AI 怎么干、不能干什么）。
> **文档版本**：V5.0.0 · **生成日期**：2026-09-10
> **重构来源**：`PROCESS_V4.md`（单文件 3368 行）+ `E:\New_program_standar_folder_structuretree`（骨架）+ `E:\Head_docs`（文档体系）
> **状态**：V4 的任何条款都没有被删除；并入清单见 `APPENDIX/01-v4-to-v5-migration.md` 与 `02-skeleton/MIGRATION.md`。
>
> **为什么版本号仍是 V5.0.0**：并入骨架与文档体系属于**物理并入**（复制文件 + 补缺口），没有改变任何流程规则或门禁判据。而全套文档的溯源注释写的都是 `来源：PROCESS.md V5.0.0 · 步骤 X-n`——为一次不涉及规则的并入而全局改版本号，会让所有已生成工件的回指失效。按 `PROCESS.md · 5.1` 的分级，这类变更记在并入清单里，不动版本号。

## 执行顺序（注意：不是文件编号顺序）

```
A 轨（一次性） → B 轨（每功能）┐
                              ├→ E 轨（每轮收尾）→ 下一个 B-0
C 轨（每 Bug）  ──────────────┘
```

**文件编号按执行顺序编排**：阶段一准备 → A → B → E → C。
**E 轨编号在 C 轨之前**，因为它每轮必过，而 C 轨是按需触发。

## 四个组成部分怎么配合

| 组成 | 管什么 | 什么时候用 |
| :--- | :--- | :--- |
| **流程文档集**（`PROCESS.md` + `01-shared/` + `02`~`07`） | 一件工作怎么走：步骤、门禁、证据、产物格式 | 每个功能、每个 Bug 都要走 |
| **骨架**（`02-skeleton/`） | 工程怎么组织：目录、分层、配置、CI | 新项目初始化时复制一次 |
| **文档体系**（`08-docs-system/`） | 知识怎么攒：规范、模板、决策、教训、定位卡 | 每次踩坑、决策、改组件时写 |
| **Agent 条款**（`07-agent-native.md`） | AI 怎么干、不能干什么、怎么并行 | 用 Agent 开发时每步都读 |

**冲突时以流程文档集为准**（详见 `08-docs-system/00-文档体系契约.md · §5` 的五处裁决）。

## 使用这条标准的三条底线

1. **人工铁律不可委托**：执行 SQL、验表、发布、裁决门禁、勾选归档、签署风险——只有人能拍板。AI 只能生成草案和证据。
2. **红灯不可绕行**：红灯就是停。AI 输出"不过如果你坚持我也可以继续"属于越权，该输出整体作废。
3. **证据不可编造**：任何"已完成 / 已验证 / 已通过"的声明必须能回指到文件路径、提交哈希或命令输出。没有证据的声明一律视为未完成。

## 把它装进你的项目

```bash
# 1. 复制骨架（项目目录结构）
cp -r V5/02-skeleton/*  <你的项目>/

# 2. 复制流程文档集（建议放 docs/sop/）
mkdir -p <你的项目>/docs/sop
cp -r V5/PROCESS.md V5/01-shared V5/02-phase-0-foundation.md \
      V5/03-track-A-initiation.md V5/04-track-B-feature.md \
      V5/05-track-E-closeout.md V5/06-track-C-bugfix.md \
      V5/07-agent-native.md  <你的项目>/docs/sop/

# 3. 复制文档体系
cp -r V5/08-docs-system/*  <你的项目>/docs/

# 4. 改占位名 your-project → 你的项目名；填写 .env 与 docs/ 各文件头部
# 5. 从 docs/sop/03-track-A-initiation.md · A-1 开始
```

**裁剪**：小项目（脚本 / 库 / 无后端）可以裁掉部分步骤与规范，但**裁剪必须留痕**——在 `docs/README.md` 记录"裁了什么、为什么、复核日期"（`01-shared/00-README.md · §4`）。

## 文档集自身的维护

- 新增步骤 / 门禁 / 工件：**先在 `APPENDIX/02-completeness-checklist.md` 的注册表登记**，再写进对应文件。
- 修改判据阈值：改 `01-shared/02-gate.md` → 在 `APPENDIX/01 · §4` 追加改动记录 → 升流程文档版本号。
- 每次修改后跑两道校验：
  - `powershell -File _qc\check-v5.ps1`（流程文档一致性）
  - `node docs/scripts/docs-check.mjs`（文档体系链接与索引，需在项目里运行）
