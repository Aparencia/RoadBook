# 编辑工具改写 .ps1 会静默丢 BOM；"重建 BOM"的补丁会静默吃掉第一个字符
复发次数: 3
作用域: 全局（所有 .ps1 入口：check / doctor / gate / orphans / security / _qc）
最近复发: 2026-10-07
现象（两种皮肤，症状完全不同，都不指向自己）：**A 丢 BOM** —— `check.ps1` 先被判「禁止运行脚本」，加 `-ExecutionPolicy Bypass` 后炸 ParserError，中文判词显示成 `鏈壒 0 鎻愪氦`（UTF-8 被按 GBK 读）；2026-10-07 实测前三字节 `23 20 5F`（`# _`，BOM 没了），报错却落在**第 90 行**（改的是第 640 行），症状离改动点 550 行。**B 丢首字符（2026-10-07 本轮新皮肤，更隐蔽）** —— BOM 在、第一个字符没了（实测 `EF BB BF 20 5F 71` = 空格 + `_q`，`#` 被吃掉）：首行于是被当成**命令**执行；`_qc/check.ps1` 带斜杠 ⇒ 被解析成相对路径 ⇒ **自己递归调用自己** ⇒ `The script failed due to call depth overflow` 且**零输出**；不带斜杠的 `check.ps1` 只报非终止性 CommandNotFound ⇒ **门禁照旧打印全绿、退出码 0（假绿）**。
根因：① 脚手架写入的 .ps1 带 UTF-8 BOM，通用编辑/写入工具按「UTF-8 无 BOM」落盘，BOM 被静默丢弃；PS 5.1 对无 BOM 的 .ps1 一律按系统码页（中文机 = GBK）解码。② **皮肤 B 是我自己的"重建 BOM"那行代码造成的**：`$t.StartsWith([char]0xFEFF)` 在 PS 5.1 上把 char 强制成 string 后判断为真 ⇒ `$t.Substring(1)` **无条件砍掉第一个字符** —— 补丁本身成了第二个 bug，上一轮那张卡把它当"修法"推荐了出去。
修法（实测）：改完任何 .ps1 立刻验**前四字节**（`EF BB BF` + 首字符）**并且逐行比对首行**（`node -e "readFileSync(f) 的首行 vs git show <base>:f 的首行"`）—— 只验 `EF BB BF` 挡不住皮肤 B。重建一律用逐字符判断，**禁用 `StartsWith([char]…)` + `Substring(1)` 组合**：`while ($t.Length -gt 0 -and $t[0] -eq [char]0xFEFF) { $t = $t.Substring(1) }`，再 `[IO.File]::WriteAllText($p,$t,(New-Object Text.UTF8Encoding($true)))`。
下次定位：.ps1 报 ParserError / 中文乱码 / 禁止运行脚本 / **call depth overflow 且没有任何输出**，且只有"被编辑过的那几个"出问题 → 先看前四字节与首行，别去改脚本逻辑；**报错行号与本次改动位置对不上时尤其要先怀疑它**。
证据：2026-10-06 实测 `check.ps1` 前三字节 = `23 20 63`（`# c`），其余六个 .ps1 入口 = `EF BB BF`；重建后 ParserError 消失。2026-10-07 `_qc/check.ps1` = `23 20 5F` → 重建后 `通过 360 项；失败 0 项`、退出码 0。**2026-10-07 本轮**：`_qc/check.ps1` = `EF BB BF 20 5F 71`；检出损坏共 **4 个**（`check.ps1` / `template/check.ps1` 丢 `#`，`STATE.md` / `template/STATE.md` 丢 `# `），**全部落在我跑过那段 BOM 重建脚本的 5 个文件里** —— 相关性直接指认元凶；修复后 15/15 文件首行比对一致。**第六次（2026-10-07 批 6 第六刀）**：`edit` 改写 `_qc/check.ps1` 的**一行**（`$rootOverride` 里的数字）后前三字节 = `23 20 5F`；按字节前置 `EF BB BF` 复原，`git diff --numstat` 由 **2 增 2 删** 回到 **1 增 1 删**（证明只动了那一行、没有换行符级重写）。**修法固定为字节级**：`[IO.File]::WriteAllBytes` 前置 `EF BB BF`，不走 `StartsWith([char]0xFEFF)` 那套字符串判断（皮肤 B 就是它造的）。
