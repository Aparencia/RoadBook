# 目录上的 Low 完整性标签杀死 WebView2 —— 而它不在任何日志里
复发次数: 1
作用域: 全局（Windows 上任何"进程起不来但错误码五花八门"的故障）
最近复发: 2026-10-07
现象：宿主反复启动失败，同一根因给出过 `0x800700AA` / `0x8000FFFF` / `0x80070005` 三种错误码；"资源被占用"是最容易先信的读法（实测真身之一是**上一臂残留进程占着用户数据目录**）。
根因：**用户数据目录上带 Low 完整性标签**——它不在日志、事件或错误码里，只有主动写仪器去读那一层才看得见；`Get-Acl -Audit` 与 `GetNamedSecurityInfo` 按设计看不到强制完整性标签（要 `LABEL_SECURITY_INFORMATION`），`Set-Acl` 也只搬 DACL。
修法：① 先分清被排除的是哪一段（DACL / SACL / 标签 / owner 是四段不同的事实）；② 用 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/envcheck.ps1 -Path <目录>` 读四段 + 健康对照样本；③ 确认是标签就移除标签，不是去改代码。
下次定位：错误码说"资源在用"、但占用进程已清干净 → 换读完整性标签那一层；**外层错误码只用于分桶，不当判据**。
证据：同 SHA256 二进制换位置即好（一句话排除代码问题）；2×2（路径 × 内容）把"位置"从"内容"里剥出来；`subst` 换访问路径区分"路径字符串策略"与"目录对象属性"；合成复现（新目录打造故障 → 撤掉 → 转绿）是因果的唯一步骤。
