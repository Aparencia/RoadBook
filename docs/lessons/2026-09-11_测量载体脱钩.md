# 测量载体与源码脱钩 = 读数是假的（陈旧产物 / 运行器缓存 / 异树对照 / 逐字节无损）
复发次数: 14
作用域: 全局
最近复发: 2026-10-07
现象：构建/测试读数与源码对不上；`Copy-Item` 还原文件保留 mtime ⇒ cargo 回放陈旧警告（假读数，A-5）；陈旧产物照样 `judged=true` 且 `pass=true`（B-37）；盘上文件逐字节还原后 vitest 仍报上一个变异的失败（#28，`--no-cache` 不够：vitest 4 把缓存写进 node_modules）；CONTROL 与 MUTANT 读数不在同一棵树 ⇒ 两侧结论不可比；**拆文件时「逐字节无损」自检通过 ≠ import 闭包完整** ⇒ 缺失标识符被宽 `catch` 吞成 `null`（2026-10-07，`docs/specs/2026-10-07_split-import-closure/RCA.md`）；**记在闸/事实源里的读数自己脱钩**——`lib/client.js` 被记成 2359 行、真实 2524 行，而闸只判阈值（2359 > 500 照样算"仍然超限"）⇒ 假数字一路写进 `STATE.md`／方案 §11.2／`CHANGELOG`（2026-10-07，`test/d14-lines.test.mjs` 的豁免清单）。
根因：测量对象不是"本次源码"——旧 dist/未重建产物、测试运行器缓存、异树对照；**测量维度也不是缺陷所在的那个维度**（量的是字节有没有丢，缺陷在依赖闭包）；连带 mtime 被误当时点证据（P-37）。
修法（实测）：测量前先重建；**懒侧数字必须与产物内容哈希绑定**（内容指纹变了读数才算数，batch08-groundwork-2.md:37）；时点证据用 git log/命令输出时间戳，mtime 不可当时点载体；每个变异体在**新解的干净副本**上跑（`git -c core.autocrlf=false archive` 落盘再解包），CONTROL 必须同一棵树取读数；文本扫描类判据的"0 命中"必须点名仪器 + 双侧自证（先剥注释再扫，R8.7 家族）；**搬移/拆分代码后按"新文件实际用到的顶层标识符"重算 import，只证明字节没丢不算过**；**判据里的记录值必须由判据自己比对**（豁免清单记的行数 ≠ 实测行数 ⇒ 判红并报出实测值，回写照抄），凭记忆写的数字一律当"未验证"。
下次定位：读数与源码矛盾；性能/体积/覆盖率声明；变异体或复跑读数诡异；还原后仍红；对照结论可疑；**"函数体一字未改却恒返回同一个异常值" ⇒ 先查缺失标识符 + 宽 `catch`**（差集：新文件用到的标识符 − 本文件定义/import 的标识符）。
