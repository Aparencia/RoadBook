# 测量载体与源码脱钩 = 读数是假的（陈旧产物 / 运行器缓存 / 异树对照）
复发次数: 12
作用域: 全局
最近复发: 2026-09-11
现象：构建/测试读数与源码对不上；`Copy-Item` 还原文件保留 mtime ⇒ cargo 回放陈旧警告（假读数，A-5）；陈旧产物照样 `judged=true` 且 `pass=true`（B-37）；盘上文件逐字节还原后 vitest 仍报上一个变异的失败（#28，`--no-cache` 不够：vitest 4 把缓存写进 node_modules）；CONTROL 与 MUTANT 读数不在同一棵树 ⇒ 两侧结论不可比。
根因：测量对象不是"本次源码"——旧 dist/未重建产物、测试运行器缓存、异树对照；连带 mtime 被误当时点证据（P-37）。
修法（实测）：测量前先重建；**懒侧数字必须与产物内容哈希绑定**（内容指纹变了读数才算数，batch08-groundwork-2.md:37）；时点证据用 git log/命令输出时间戳，mtime 不可当时点载体；每个变异体在**新解的干净副本**上跑（`git -c core.autocrlf=false archive` 落盘再解包），CONTROL 必须同一棵树取读数；文本扫描类判据的"0 命中"必须点名仪器 + 双侧自证（先剥注释再扫，R8.7 家族）。
下次定位：读数与源码矛盾；性能/体积/覆盖率声明；变异体或复跑读数诡异；还原后仍红；对照结论可疑。
