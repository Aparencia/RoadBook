## 落地形状（三件机械事实，全在 `skills/roadbook/bin/route*.mjs`）

| 面 | 入口 | 输出 | 判据（红 / 用法错误） |
| :-- | :-- | :-- | :-- |
| 链状态 | `route --chain --facts … [--done '…']` | 每张卡 `done / current / todo` + 当前卡 + 下一张的派单命令行 | `--done` 里出现**链外卡** = 判红 1（你记的链与工具算的链不是同一条）；`--done` 写法非法 / 写给别的模式 = 2 |
| 派单包 | `route --dispatch <卡号>[:<起>-<止>] --facts … [--out <path>]` | 内嵌卡正文**逐字节切片**（行号 + sha256，与 `--quote` 同一实现）+ 门禁类型化结果 + 停点行号 + 3 行回执模板 | 幽灵卡 = 1；切片越界/起止颠倒 = 1；缺事实 = 2 |
| 停 | `needVerdict{required,gate,why,stopLines}`（**数据**，不是散文） | 子 agent 拿不到人 ⇒ 门禁必须以数据返回，由主线程决定停不停 | 链外卡按最严口径处理（`required:true`） |

停点在 `route-core.mjs` 的 `gateWhyOf` 里与门禁**同一个分支**产出（理由另写一张表 = 迟早对不上）；停点行号来自 `route-cards.mjs` 的 `STOP_MARK_RE` —— 与账本 `stops` **同一份正则**，否则「账本说 2 处停」与「派单说没有停点」会同时成立。

## 台账 #27 的冲突：不放松 `includeSubagents`（裁决 + 机械断言）

- **事实**：`plugin/roadbook-autoload/index.js:151` 的 schema `includeSubagents` 默认 `false` ⇒ 子 agent 那边**没有注入**，它不知道自己在按卡干活、也不知道哪一步要停。
- **被否方案**：①「对这条路径放行 `includeSubagents`」——等于打开「子代理不受卡约束」的口子（`SKILL.md` 铁律 5 的边界被绕开）；②「派单内嵌卡正文（无哈希）」——派单变长以后没人核得了那段文字到底是不是卡原文。
- **采用**：内嵌**逐字节切片 + 行号 + sha256**（`route-quote.mjs`），派发方与收件方各自都能独立复核「这段文字 = 卡文件第 N~M 行」。
- **机械断言**（把这句话从文档变成判据）：`test/route-cli.test.mjs` 的 **A15e** —— ① 插件 schema 里 `includeSubagents` 默认必须仍是 `false`；② 派单包内嵌的正文必须逐字节等于卡文件全文。两半缺一，这个裁决的前提就不成立（改默认 = 打开口子；不内嵌 = 子 agent 手里没有卡）。

## 门槛实测（#28 上半：把预估换成读数）

| 量 | 实测 | 怎么量的 |
| :-- | --: | :-- |
| L 链（27 张）的常驻成本 | 3589 行 / 162227 字符 / **≈81114 tokens** | `route --scenario endpoint-chart --json` 的 `ledger`（现盘复算） |
| 单张卡（4-3） | 139 行 / 5275 字符 / ≈2638 tokens | `--dispatch 4-3 --json` 的 `slice` |
| 派单包整段进 stdout | 6831 字符 | 实测 |
| **`--out` 后主线程拿到的** | **284 字符 / 2 行** | 实测：`--dispatch … --out` 的 stdout |
| 回执模板 | 91 字符 / 3 行 | 常量 |

⇒ 一张卡的**常驻**成本 ≈284 字符（≈142 tokens）而不是 6831（≈3416 tokens）；27 张链 ≈3.8k tokens 对 81.1k tokens ⇒ **P0 声称的「77k → 个位数 k」量级成立**（实测比声称更高，因为这条链是 27 张不是 26 张）。**由实测得到的一条新判据**：派单包一旦整段印进主线程自己的上下文，省下的 token 就还回去了 ⇒ `--out` 不是便利选项，是 P0 成立的条件（A15f 断言 `--out` 模式下 stdout 一个正文字符都不许出现）。

## 单卡子 agent 对照实验（#28 下半）

**设计**：卡 = 4-3（全档必走；判据 = 门禁退出码；门禁 = 裁决）。两臂各一个**干净上下文**的子代理，只读、不许派子代理。A 臂 = 现行做法（卡号 + 卡路径 + 回执形状 + 一句「门禁是裁决」，子 agent 自己读卡）；B 臂 = P0（`--dispatch --out` 落盘的派单包 + 一行指针）。两臂都要求**恰好三行**回执。

| 度量（两臂回执都从子代理会话记录机读量出，不是肉眼估） | A 臂（现状） | B 臂（P0） |
| :-- | :-- | :-- |
| 回执行数 / 字符数 | **3** / 249 | **3** / 664 |
| 含真实退出码 + 证据原文 | ✅ `退出码 1`；`[FAIL] 工作树不干净：6 个未提交改动（完成 = 已提交）` | ✅ 同左，**另加输出文件:行 + 末行 + `EXITCODE=1`** |
| 越权自判 ／ 第 ③ 行是否把裁决交回人 | ❌ 没有 ／ ✅ 交回（问「先提交再复跑，还是本轮作废」） | ❌ 没有 ／ ✅ 交回（问「留待提交后重跑」） |
| 主线程为此手写的提示词 | ≈400 字符（卡路径 + 形状 + 门禁提示） | 一行指针（工具生成，≈80 字符） |

**读法（如实，含两条不利于本机制的）**：① 两臂回执都恰好 3 行、都带真实退出码、都没越权自判 ⇒ **「回执形状」不是 P0 的增量**（主线程手写一句提示词也能拿到合规回执）。
② B 臂证据更可核（多了输出文件:行、末行、`EXITCODE`），代价是回执**长 415 字符** ⇒ **「三行」挡不住「每行很长」**（见 TD-011）。
③ P0 的增量剩下三条**机械事实**：提示词由工具生成（每条一致，不靠记性）、逐字节 + sha256 可复核、停点行号与 `needVerdict` 是**数据**（主线程不必读回执猜该不该停）。
④ **两臂都报 `退出码 1` 是预期**：实验跑在施工中的脏工作树上，`check.ps1` 的结构断言第一条就是「工作树干净」⇒ 这正合 B1（回执携带真实退出码而不是「应该没问题」），也证明红灯会**穿过**子 agent 这一层，不会被吞成 PASS。

## 边界（不做什么）

- **不自动派单、不自动推进链**：命令只出数据与包；「派不派、停不停」仍是主线程（= 人）的动作。
- **不做状态字段化（P4）**：链状态靠 `--done` 显式传入；工具**不解析** `STATE.md` 的散文 —— 猜出来的状态不可校验（落差 5）。**不碰 A4 / A5**：门禁裁决与验收确认仍是人的事，`needVerdict` 只做传递；并发上限与失败重试也不在本卡（仍按 D10 与 `SKILL.md` 铁律 5）。
