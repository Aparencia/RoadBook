# IDEAS · 需求池（Idea Pool；1-2 建骨架、1-1 调研卡维护；≤40 行）
> 最近核对 —（骨架未核对；核对后填 <日期> @ <提交哈希>）
> 谁写：1-1 想法调研（登记与结论）、5-1 归档（写 done）｜ 谁读：1-1、2-1 需求与范围、6-6 流程体检
> 用法：一切想法先进池（驱动卡自动登记），不打断当前工作；启动某个想法 = 复制驱动卡后说"启动 某想法"。
> 状态词表（只用这五个，出现别的词 = 状态不明）：idea（随口想法）→ researching（调研中，链 specs）→ approved（已批准，链 specs）→ done（已实现，链 commit）/ killed（死亡，必须写复活条件）

| 状态 | 含义 | 进入条件 | 下一步去哪 |
| :-- | :-- | :-- | :-- |
| idea | 随口想法，还没查 | 任何人随时登记一行 | 值得做 → 1-1 调研 |
| researching | 调研中 | 1-1 卡立项，产物落 `docs/specs/日期_slug/RESEARCH.md` | 结论 Go → approved |
| approved | 已批准，等排期 | 有 specs 依据与范围 | 进 2-1 需求与范围 |
| done | 已实现 | 5-1 归档写 commit 哈希 | 结案，留在池里备查 |
| killed | 死亡 | 调研判 Kill 或长期不做 | 必须写复活条件，否则等于没结论 |

- 1-1 调研结论映射：Go → approved ｜ Kill → killed（写复活条件）｜ Pivot → idea（换个想法重新进池）。
